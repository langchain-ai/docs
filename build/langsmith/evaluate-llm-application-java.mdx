The LangSmith Java SDK lets you test your application on a [dataset](/langsmith/evaluation-concepts#datasets) and save the results as an [experiment](/langsmith/evaluation-concepts#experiment) in LangSmith. You describe what your app does, how to score each answer, and which test cases to use. LangSmith runs the tests, records traces, and stores your scores so you can compare versions over time.

This guide covers `evaluate()` and the related helpers added in `langsmith-java` 0.1.0-beta.11.

<Note>
Requires `com.langchain.smith:langsmith-java:0.1.0-beta.11` or later.
</Note>

## What you need

Before you call `evaluate()`, gather three pieces:

1. **A dataset** — test questions (and optional expected answers) stored in LangSmith, or a list of examples you pass in code.
2. **A target** — the part of your app you want to test. It receives one row of inputs and returns an output map.
3. **At least one evaluator** — a function that scores how well the output matches what you expect.

Set `LANGSMITH_API_KEY` in your environment. See [Create an API key](/langsmith/create-account-api-key) if you do not have one yet.

## Run your first evaluation

The flow is simple: connect to LangSmith, define your app and scorer, then call `evaluate()`.

<EvaluateBasicKt />

What happens when you run this:

1. LangSmith loads each row from `my-dataset`.
2. Your app runs on each row. Every run is traced automatically.
3. Your evaluator scores each answer.
4. Results appear as a new experiment in the LangSmith UI.

<Check>
`evaluate()` traces your target function. Any traced code inside the target appears as child spans on the run.
</Check>

## Configure the evaluation

Use `EvaluateParams.builder()` to control how the evaluation runs. You only need to set the options that matter for your use case.

| Option | What it does |
| ------ | ------------ |
| `data(...)` | **Required.** Dataset name, dataset id, or a list of in-memory examples. |
| `addEvaluator(...)` | Score each individual answer. You can add more than one. |
| `addSummaryEvaluator(...)` | Score the whole experiment at once (for example, average accuracy across all rows). |
| `experimentPrefix(...)` | A short label used to name the experiment. LangSmith adds a unique suffix. |
| `experimentName(...)` | Set the full experiment name yourself. Do not use with `experimentId`. |
| `experimentId(...)` | Add more runs to an existing experiment instead of creating a new one. |
| `description(...)` | A note that shows up on the experiment in LangSmith. |
| `metadata(...)` | Extra key-value data attached to the experiment. |
| `maxConcurrency(...)` | How many rows to test at the same time. `0` means one at a time. |
| `numRepetitions(...)` | Run each test case more than once. Useful when outputs can vary. |
| `uploadResults(false)` | Run locally without saving anything to LangSmith. Good for quick checks. |
| `errorHandling(...)` | What to do when your app fails on a row. See [Handle errors](#handle-errors). |

## Write evaluators

Evaluators turn a prediction into a score. The SDK offers a few shapes so you can start with the simplest one that fits.

### Compare outputs to expected answers

Use this when your dataset has reference answers and you only need the model output and the expected output:

```kotlin
val concise = runEvaluator { outputs, reference ->
    val pred = outputs["answer"]?.toString() ?: ""
    val ref = reference["output"]?.toString() ?: ""
    val score = if (pred.length < 3 * ref.length) 1.0 else 0.0
    EvaluationResult(key = "concise", score = score)
}
```

### Use the full run and example

Use this when you need trace details or example metadata:

```kotlin
val overlap = runEvaluator { run, example ->
    // Score using run outputs and the dataset row
    EvaluationResult(key = "custom", score = 1.0)
}
```

### Score the whole experiment

Summary evaluators run after all rows finish. They receive every run and example:

```kotlin
val avgRows = summaryEvaluator { runs, _ ->
    EvaluationResult(
        key = "row_count",
        score = runs.size,
        comment = "Total rows evaluated",
    )
}
```

Each evaluator returns an `EvaluationResult` with a `key` (metric name), an optional `score`, and an optional `comment`.

## Run evaluations in the background

By default, `evaluate()` waits until every row finishes. To start the work and continue your program, use `evaluateAsync()`:

```kotlin
val future = evaluateAsync(client, myApp, params)
// Do other work here
val results = future.join()
```

In Java, import `com.langchain.smith.evaluation.Evaluation` and call `Evaluation.evaluateAsync(...)`.

## Re-score an existing experiment

If you already ran an experiment and want to add new scores without re-running your app, use `evaluateExisting()`:

```kotlin
val rescored =
    evaluateExisting(
        client,
        experimentId = "your-experiment-id",
        EvaluateExistingParams.builder()
            .addEvaluator(myNewEvaluator)
            .build(),
    )
```

You can also pass an experiment id to `evaluate()` as a convenience shortcut:

```kotlin
evaluate(client, "your-experiment-id", params)
```

## Compare two experiments

To pick a winner between two versions, use `evaluateComparative()`:

```kotlin
val comparison =
    evaluateComparative(
        client,
        experimentAId to experimentBId,
        EvaluateComparativeParams.builder()
            .addEvaluator(
                comparativeEvaluator { runs, example ->
                    ComparisonEvaluationResult(
                        key = "prefer_shorter",
                        scores = mapOf(
                            runs[0].id().get() to 1,
                            runs[1].id().get() to 0,
                        ),
                    )
                }
            )
            .build(),
    )
```

This creates a pairwise experiment in LangSmith where each row shows both versions side by side.

## Handle errors

If your app throws an error on a dataset row, choose what happens next:

- `EvaluateErrorHandling.LOG` (default) — record the error and keep the row in the experiment.
- `EvaluateErrorHandling.IGNORE` — skip the row and continue with the rest.

```kotlin
EvaluateParams.builder()
    .data("my-dataset")
    .errorHandling(EvaluateErrorHandling.IGNORE)
    .addEvaluator(myEvaluator)
    .build()
```

## Test without uploading

Set `uploadResults(false)` to run your app and evaluators locally. Nothing is saved to LangSmith: no experiment, no traces. Use this for quick smoke tests while you are still wiring things up.

```kotlin
EvaluateParams.builder()
    .data("my-dataset")
    .uploadResults(false)
    .addEvaluator(myEvaluator)
    .build()
```

## Read the results

`evaluate()` returns `ExperimentResults` with:

- `experimentName` and `experimentId` — find the run in the LangSmith UI
- `datasetId` — which dataset was used
- `rows` — one entry per test case, each with the run, example, and scores
- `summaryResults` — scores from summary evaluators, if any

Open the experiment in LangSmith to compare scores, inspect traces, and share results with your team.
