LangSmith organizes a workspace around its [agents](/langsmith/agents), and one control in the top bar moves between them. This page covers that control, the two views it moves between, the addresses behind those views, and what an agent's Overview shows.

## Switch between agents

The agent switcher sits at the left of the top bar, after the workspace switcher and the panel collapse toggle. It reads either `All agents` or the name of the agent you are in.

The address behind it is `/o/<workspace>/a/<agentId>/...`. A hyphen in the agent slot means all agents, so `/a/-` is the agent list and `/a/<agentId>` is a single agent. Either state can be set from the address bar, which is how to link directly to one of the two views.

## The two views

The switcher moves between two views:

- **All agents**: The agents in the workspace, one card each.
- **A single agent**: That agent's Overview.

The left navigation lists the same items in both views, but two things differ. Its badge counts appear on the agent list, where they count the whole workspace, and are not shown once you select an agent, so a count beside a navigation item never describes the agent you are in. And several sections cannot be opened without an agent.

## Sections that require an agent

**All agents** is a resting state for the Overview, not for the whole product. Tracing, Monitoring, Engine, Build, Studio, and Deployments each need a specific agent, and what you get when you open one with **All agents** selected depends on whether the workspace has any agents yet.

With agents to choose from, a **Pick an agent to view** screen replaces the section. It holds a searchable list, and the top bar stays above it, so the switcher is still there. Build and Studio each add one action below the list, **+ New agent** and **Connect Agent Server**.

With no agents in the workspace, Build and Studio show that same screen reading **No agents available.**, while Tracing, Monitoring, Engine, and Deployments show a get-started screen for the section instead of asking you to pick.

Once you are inside a section, the switcher returns and stops offering **All agents**.

Once you pick one, LangSmith remembers it, so moving between these sections does not ask again.

## Settings replaces the shell

Settings is not a third view of an agent. Opening it replaces the shell: the top bar and the agent switcher are gone, the navigation splits into Organizations and Workspace sections, and a link returns to the agent views, reading `Back to LangSmith` or, from Fleet, `Back to Fleet`.

## Read the agent Overview

Selecting a single agent lands on its Overview, which shows the following, in order:

- **Metrics**: Traces over time as a line chart, then trace count, error rate, token count, and total cost, each over the period named above them.
- **Tracing**: One row per environment, with the most recent run, trace count, error rate, P50 latency, P99 latency, and description.
- **Engine**: How many active issues [Engine](/langsmith/engine-overview) has found across this agent's environments, and a link into Engine. With no issues found, the section describes Engine rather than listing them.
- **Evaluate your agent**: A pointer into [evaluators](/langsmith/evaluators).
- **Monitor your agent**: A pointer into [dashboards](/langsmith/dashboards).
- **Deployments**: The [deployments](/langsmith/deployment) bound to this agent, and a link to all of them. This section appears only for an agent that has deployments, so an agent [built in the UI](/langsmith/build-an-agent) does not show it.

Everything on this screen is scoped to the agent you have selected. A line above the metrics states the window and the scope they cover, reading **Showing data from the last 7 days across all environments**, so the metrics include local and staging runs rather than production alone. The tracing section below them breaks the same period out by environment.

More than one identifier for the same agent appears on this screen, and they are not interchangeable. The heading is the display name, the switcher shows the agent's identifier, and a copyable field labeled `ID` holds the internal UUID for the record.

The copy button beside `ID` is the easiest of the three to reach and the wrong one for tracing. [Agent addressing](/langsmith/log-traces-to-agent) takes the identifier, not the UUID. For which value is which, see [Identifiers and display names](/langsmith/agents#identifiers-and-display-names).

## Create an agent

Two controls open the same panel. `+ New Agent` sits above the agent list, and `Build new Agent` sits on the creation card at the end of it. Both open the `New Agent` panel, and the choice made there forks into four different parts of this documentation:

- **`Builder`**, "Build with AI inside LangSmith". This opens the **Build** tab, which creates a Managed Deep Agent from a name and a description rather than from code. See [Build an agent in the UI](/langsmith/build-an-agent).
- **`Managed Deep Agent`**, "Build locally and deploy". See [Managed Deep Agents](/langsmith/python/managed-deep-agents-overview). This route requires a paid plan, and the panel marks it with a `Plus` badge.
- **`Open Source`**, "Build an agent with our open source frameworks". See [LangChain](/oss/python/langchain/overview).
- **`Observability`**, "Trace an existing agent". See the [tracing quickstart](/langsmith/observability-quickstart).

Creating an agent for an application that is traced from outside LangSmith uses a separate control. The agent switcher's `New agent` action opens a `Create a new agent` dialog, which takes an agent name and creates the agent from it. That action requires permission to create projects, and it renders on the classic project routes rather than on the agent views.
