_Agent addressing_ names the [agent](/langsmith/agents) and the [environment](/langsmith/agent-environments) a trace belongs to, rather than the tracing project it lands in. The agent and the environment travel with every run, so the application that produced a trace and the deployment it ran on are recorded at ingestion instead of being recovered later from a project name.

Agent addressing and [project addressing](/langsmith/log-traces-to-project) are alternatives. A trace uses one or the other, never both.

<Note>
Agent addressing applies to agent-based workspaces, which are in [beta](/langsmith/release-stages) for a private group of customers. It is not yet available in the LangSmith SDKs. This page describes the addressing model. For working tracing setup today, see [Log traces to a specific project](/langsmith/log-traces-to-project).
</Note>

## Addressing variables

Two environment variables carry agent addressing:

- **`LANGSMITH_AGENT_ID`**: The agent to address. The value is the agent's identifier, a human-readable slug such as `my-agent`, not the UUID from the browser address bar. It is sent with every run.
- **`LANGSMITH_AGENT_ENVIRONMENT`**: The environment the run belongs to. Optional. When it is unset, nothing is sent and the backend applies the default.

Note the asymmetry with the variable it replaces. `LANGSMITH_PROJECT` holds a project's name, while `LANGSMITH_AGENT_ID` holds an agent's identifier. An agent's [display name is a separate, editable value](/langsmith/agents#identifiers-and-display-names) and is not what tracing configuration takes.

## Addressing modes are mutually exclusive

Combining the two modes is an error rather than a precedence rule, so there is no case where one silently wins:

- **An agent and a project together** are rejected. Setting `LANGSMITH_AGENT_ID` alongside `LANGSMITH_PROJECT`, `LANGCHAIN_PROJECT`, or `LANGCHAIN_SESSION` raises an error when the client starts, so the conflict surfaces locally rather than once per batch of traces.
- **An environment without an agent** is rejected. `LANGSMITH_AGENT_ENVIRONMENT` has no meaning on its own, because an environment belongs to an agent.

## Addressing an agent that does not exist

An identifier that matches no agent in the workspace creates one rather than failing. Traces from a new service therefore arrive under their own agent from the first run, without a setup step.

Agent identifiers are limited to 255 characters. A longer value is rejected.
