Setting up [LangSmith Engine](/langsmith/engine) takes two steps. An [Organization Admin](/langsmith/rbac#organization-admin) first enables Engine for the organization. Then a [Workspace Admin or Workspace Editor](/langsmith/rbac#workspace-roles), or a user with a custom role that includes `issues:create`, turns on Engine for each agent environment. Once Engine is running, Workspace Admins, Workspace Editors, and custom roles that include `issues:update` can [configure it](#configure-engine) to focus on specific traces.

<Note>
On self-hosted LangSmith, an operator must enable Engine in the LangSmith Helm chart before either step is available. On [BYOC](/langsmith/byoc), an Organization Admin must also add model provider credentials before Engine runs. See [Engine on self-hosted and BYOC](/langsmith/engine-self-hosted).
</Note>

## Enable Engine for your organization

<Note>You must be an [**Organization Admin**](/langsmith/rbac#organization-admin) to enable Engine. To find your admins, open **Settings**, select **Members** under **Access and Security**, and look for members with the **Organization Admin** role.</Note>

<Steps>
  <Step title="Open Engine settings">
    In the [LangSmith console](https://smith.langchain.com?utm_source=docs&utm_medium=cta&utm_campaign=langsmith-signup&utm_content=langsmith-engine-setup), click **Settings** in the bottom-left corner, then select **Engine** under **Engine**.
  </Step>
  <Step title="Toggle Enable Engine">
    Toggle **Enable Engine** on and acknowledge the AI features terms of use. The dialog displays the following in-product notice verbatim:

    > LangSmith AI features, powered by LangChain-managed inference, bring intelligence to your observability workflow. With LangSmith AI enabled, your team can surface issues faster, run smarter evaluations, and build more reliable LLM applications. By enabling this feature, your organization's trace data will be processed using LangChain-managed LLM keys. Subject to our Terms of Service.

  </Step>
</Steps>

Once Engine is enabled, a Workspace Admin or Workspace Editor, or a user with a custom role that includes `issues:create`, can set it up for an agent environment. Changing its settings afterwards requires `issues:update`, which Workspace Admins and Workspace Editors also have. Workspace Viewers can do neither.

## Turn on Engine for an agent environment

<Steps>
  <Step title="Open Engine">
    In the [LangSmith console](https://smith.langchain.com?utm_source=docs&utm_medium=cta&utm_campaign=langsmith-signup&utm_content=langsmith-engine-setup), select your agent and go to **Engine**. Select the environment from the environment switcher at the top of the page, then click **Set up Engine**.
  </Step>
  <Step title="Add a repository (optional)">
    Connecting a repository is optional but recommended, because Engine makes better recommendations when it can read your source code. See [Why connect a repository](/langsmith/engine#why-connect-a-repository). Under **Select Repository**, search for and select the repositories Engine should use, and optionally set a subfolder and branch for each. Only repositories the GitHub App can access are shown. Click **Manage app access** to update permissions. For GitHub App setup, GitLab, and organization approval, see [Connect Engine to your repository](/langsmith/engine-repositories). To continue without a repository, select **Skip connecting for now**. Click **Next**.

    Also set `revision_id` on your traces so Engine can match each trace to the commit that produced it. Engine then reasons from the code that ran, for example by comparing the commits shipped between two releases when a metric regresses. See [Record the code version on traces](/langsmith/add-metadata-tags#record-the-code-version-on-traces).
  </Step>
  <Step title="Set up Slack notifications (optional)">
    Click **Connect Slack** and select a channel. Under **Notify when**, choose which events to send: **Recommendation created** (optionally limited by severity), **New traces linked to recommendation**, or **Fix PR ready**. Click **Add channel**. To continue without Slack, select **Skip connecting for now**. For other destinations, see [Engine notifications](/langsmith/engine-notifications).
  </Step>
  <Step title="Start analyzing">
    Click **Start analyzing**. The page may show an estimated monthly cost range based on your agent's usage. Engine analyzes at the **Standard** [analysis level](/langsmith/engine#set-the-analysis-level), which you can change later. The first analysis can take up to 30 minutes. During it, Engine generates an agent overview document that it uses as context for all later analysis.
  </Step>
  <Step title="Create a goal">
    While the first analysis runs, click **Create goal** under **Create a new goal** to tell Engine what you want your agent to improve. See [Set goals](/langsmith/engine-goals).
  </Step>
</Steps>

You can change any of these choices later in [Configure Engine](#configure-engine). To review and correct the agent overview document, see [Give context on your agent](#give-context-on-your-agent).

## Turn on Engine on self-hosted LangSmith

Goals are available only on LangSmith Cloud, so self-hosted LangSmith uses a different setup flow:

<Steps>
  <Step title="Open Engine and select a project">
    Select **Engine** in the UI sidebar. The project selector lists projects that are already configured. To set up a project that is not listed, select **Set up another project**, then choose the project to analyze.
  </Step>
  <Step title="Connect a code repository (optional)">
    Under **Connect your agent's code repository**, select the repositories Engine should use. To have Engine open a pull request for each fix automatically, select **Open a pull request for every fix**. To give Engine additional project context, select a repository under **Context Hub repository**. See [Connect Engine to your repository](/langsmith/engine-repositories).
  </Step>
  <Step title="Select priorities (optional)">
    Under **What matters most to you?**, select categories to prioritize for your review, such as **Tool Call Failures** or **Latency**, or add your own. See [Tell Engine what to focus on](#tell-engine-what-to-focus-on).
  </Step>
  <Step title="Choose an analysis level">
    Under **Analysis level**, choose **Reduced**, **Standard** (the default), or **Expanded**. Higher levels analyze more traces and cost more. See [Set the analysis level](/langsmith/engine#set-the-analysis-level).
  </Step>
  <Step title="Focus on specific traces (optional)">
    Under **Focus on specific traces**, narrow Engine's attention to a subset of runs by run name or metadata. Leave it empty to analyze all traces. See [Tell Engine which traces to focus on](#tell-engine-which-traces-to-focus-on).
  </Step>
  <Step title="Start analyzing">
    Click **Start Analyzing**. The panel may show an estimated monthly cost range based on your project's usage. Engine can take up to 30 minutes to analyze your project's traces and generate the agent overview document. To get alerted when Engine finds issues, [set up notifications](/langsmith/engine-notifications).
  </Step>
</Steps>

For operator prerequisites, see [Engine on self-hosted and BYOC](/langsmith/engine-self-hosted).

## Configure Engine

On the agent's **Engine** page, select the environment from the environment switcher at the top of the page, then click the **Configure Engine** <Icon icon="settings"/> (gear) icon to open the **Engine settings** panel. Use it to give Engine context on your agent and connect Linear. The panel also holds settings covered elsewhere:

- **Code repository** and **Context repository**: Connect or update the GitHub repositories and GitLab projects Engine reads when diagnosing issues. Each repository or project can have its own **Subfolder** and **Branch** (defaults to the repository default). A Context Hub repository lets Engine propose fixes to instructions, docs, and linked skills. See [Connect Engine to your repository](/langsmith/engine-repositories).
- **Notifications**: See [Engine notifications](/langsmith/engine-notifications).
- **Agent Server**: Set the baseline Agent Server Engine replays issue traces against. To verify Engine's proposed fixes automatically, select **Verify fixes with preview Agent Servers**. See [Validate fixes automatically](/langsmith/engine-fix-validation).
- **Analysis level**: See [Set the analysis level](/langsmith/engine#set-the-analysis-level).
- **Spend limit**: Changing the environment's spend limit requires an [Organization Admin](/langsmith/rbac#organization-admin). See [Set spend limits and monitor usage](/langsmith/engine#set-spend-limits-and-monitor-usage).
- **Pause** and **Delete all issues**: See [Pause Engine or delete its recommendations](#pause-engine-or-delete-its-recommendations).

### Give context on your agent

During its first analysis, Engine generates an agent overview document describing your agent's purpose, architecture, and key metrics. Engine uses it as context for all analysis, so its accuracy affects the quality of its recommendations. Under **Agent overview**, edit the document to add any relevant context Engine cannot infer from your traces and to make sure it is accurate. The document's **User Preferences** section also collects what Engine has [learned from your actions on recommendations](/langsmith/engine#how-engine-learns-from-your-actions-on-recommendations), so you can review and correct those calibrations here.

### Tell Engine what to focus on

To focus Engine on an outcome you want to improve, [set a goal](/langsmith/engine-goals). To give Engine other guidance, such as areas to prioritize or ignore, edit the **User Preferences** section of the [agent overview](#give-context-on-your-agent). On self-hosted LangSmith, where goals are not available, select categories under **Preferences** in the **Engine settings** panel instead.

### Tell Engine which traces to focus on

Focus Engine on the traces that matter to keep analysis precise and reduce wasted LSU spend. Use trace scope (the **Focus on specific traces** control) when a project mixes several agents or workloads and you want Engine to analyze only some of them. For example, if a project runs both a production chatbot and a nightly batch job, scope to `Run Name is chatbot` so Engine ignores the batch runs. By default, Engine analyzes all of a project's traces.

Set the scope in the **Trace filters** section of the [**Engine settings**](#configure-engine) panel. Edits save automatically.

Add scope conditions with the filter editor. You can add one condition of each kind, **up to two**:

- **Run Name**: Pick a run or agent name. The value field autocompletes from the run names in your project's recent traces.
- **Metadata**: Pick a metadata key, then a value. Both autocomplete from the metadata present on your project's recent runs.

To add a condition, choose its kind from the field selector, fill in the values, then click **Add**. Each condition appears as a chip, for example `Run Name is chatbot` or `env is prod`. Click the **×** on a chip to remove that condition.

<Note>
**Scope limitation:** The scope filter only accepts run name and metadata conditions. You cannot scope Engine's scan by feedback key, evaluator name, or score threshold. To focus Engine on traces with a specific evaluator's low scores, set a [goal](/langsmith/engine-goals) whose metric reads that feedback, or describe it in your [agent overview](#give-context-on-your-agent). Engine already factors in all feedback signals automatically. See [How Engine selects traces](/langsmith/engine#how-engine-selects-traces).
</Note>

Scope determines which traces Engine analyzes to make recommendations and build the agent overview document. Changing the scope does not re-run Engine immediately. It applies to Engine's next analysis.

### Connect to Linear

Under **Linear**, click **Connect**, select a team, optionally select a project for new issues, then click **Save changes**. Engine retains durable links to the Linear issues it creates, but does not synchronize later edits from Linear. Deleting all of Engine's recommendations does not delete existing Linear tickets. See [Create a Linear issue](/langsmith/engine-issues#create-a-linear-issue).

## Pause Engine or delete its recommendations

Engine scans your traces on a dynamic schedule tuned to balance cost and performance. To stop scanning an agent environment without deleting its existing recommendations, click **Pause** in the [**Engine settings**](#configure-engine) panel. Click **Resume** to start scanning again.

Click **Delete all issues** in the same panel to permanently remove the agent environment's recommendations and Engine settings. This cannot be undone.

To turn off Engine for the whole organization, an Organization Admin toggles **Enable Engine** off under **Settings** > **Engine**. This stops all automatic Engine runs and future Engine billing for the organization.
