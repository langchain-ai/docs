<Note>
SmithDB is an opt-in datastore for self-hosted LangSmith. ClickHouse is required on LangSmith 0.16 and remains the default on 0.17. Do not disable ClickHouse on any version below 0.17. The minimum LangSmith version depends on your cloud. See [Check cloud support](#check-cloud-support).
</Note>

SmithDB is a columnar datastore built for agent trace data: deeply nested spans, multi-modal content, and spans that stay open for hours. It keeps durable data in object storage with node-local SSD caching, and serves LangSmith trace ingestion and queries alongside the existing ClickHouse datastore.

You can enable SmithDB on any supported LangSmith Kubernetes installation, whether it is brand new or already serving traffic. See [Check cloud support](#check-cloud-support). [Self-host LangSmith on Kubernetes](/langsmith/kubernetes) covers the base installation; this section covers everything SmithDB adds on top of it.

## Check cloud support

SmithDB examples in this section cover managed Kubernetes on AWS, GCP, and Azure. They do not cover self-managed clusters.

| Cloud | Minimum version |
|---|---|
| AWS (EKS) | LangSmith 0.16, Helm chart `0.16.14` or later |
| GCP (GKE) | LangSmith 0.16, Helm chart `0.16.14` or later |
| Azure (AKS) | LangSmith 0.17 |

## Components

Enabling SmithDB adds the following workloads to your cluster. Three of them cache trace data on disk and belong on local SSD nodes; the other two are small and run on general compute. See [Schedule SmithDB workloads](/langsmith/self-host-smithdb-infrastructure#schedule-smithdb-workloads).

| Component | What it does | Node pool | Scaling |
| --- | --- | --- | --- |
| Ingestion | Writes incoming traces to object storage | Local SSD | Horizontal |
| Query | Serves trace reads for the LangSmith UI and API | Local SSD | Horizontal |
| Compaction worker | Reorganizes stored traces in the background so queries stay fast | Local SSD | Horizontal |
| Compaction | Schedules the background work that compaction workers carry out | Compute | Single instance |
| Cluster manager | Coordinates the other SmithDB services | Compute | Single instance |

Two more workloads run as Kubernetes Jobs rather than as services. One prepares the SmithDB metastore during installation. The other backfills ClickHouse history and runs only if you choose to [migrate historical data](/langsmith/self-host-smithdb-migrate).

## Storage requirements

A self-hosted LangSmith installation uses PostgreSQL for operational data, Redis or Valkey for queuing and caching, and optional blob storage. Traces and feedback live in ClickHouse, in SmithDB, or in both while an installation runs dual ingestion. SmithDB adds its own metastore, object store, and cache nodes.

ClickHouse is required on LangSmith 0.16 and remains the default on 0.17. Keep it configured and running through query cutover on either version. On 0.17, a new installation can run SmithDB without ClickHouse; see [Install without ClickHouse](/langsmith/self-host-smithdb-install#install-without-clickhouse). Retiring ClickHouse from an existing installation is a separate procedure; contact LangChain through the [Support Portal](https://support.langchain.com/) before considering it.

For SDK method changes that work with both ClickHouse and SmithDB, see [Migrate to SmithDB-backed SDK methods](/langsmith/smithdb-sdk-migration).
