Send traces from your team's coding agents, such as Claude Code, Codex, and Cursor, to see what they cost. Connect GitHub or GitLab to link each [thread](/langsmith/threads) to the pull requests it opened, so you can see the spend behind each pull request. From any chart, open the threads behind an unusually expensive pull request or user to see what the agent did.

<Note>
The Coding agent type is in beta. It requires an [agent-based workspace](/langsmith/migrate-to-agent-based-workspaces), which is available on LangSmith Cloud and not on self-hosted LangSmith.
</Note>

## Set up

### Create an agent with the Coding type

If an official LangSmith coding agent plugin sends the first traces to a new project, LangSmith creates an agent for that project and sets its type to **Coding**. You do not need to create the agent first.

To set the type yourself, set **Agent type** to **Coding** when you [create an agent](/langsmith/create-an-agent). To change the type of an existing agent, open the **Agent settings** menu on its Overview and select **Change agent type**.

The pull request connection and the charts on this page appear only on agents with the Coding type.

### Send traces to the agent

Set up tracing for each coding agent your team uses, and send its traces to the agent you created. Each guide shows how to set the agent ID.

| Coding agent | Set up tracing |
|---|---|
| Claude Code | [Install the plugin](/langsmith/trace-claude-code#install-the-plugin) |
| OpenAI Codex | [Install the plugin](/langsmith/trace-with-codex#install-the-plugin) |
| Cursor | [Install the plugin](/langsmith/trace-with-cursor#install-the-plugin) |
| GitHub Copilot | [Configure tracing](/langsmith/trace-with-vscode-copilot#configure-tracing) |
| Deep Agents | [Trace Deep Agents](/langsmith/trace-deep-agents) |

To trace every engineer's sessions, admins can install the Claude Code, Codex, and Cursor plugins with a mobile device management (MDM) tool such as Iru. The managed file at `~/.langsmith-plugins/managed.json` can lock `agent_id`, the workspace, and [strict auth](/langsmith/trace-claude-code#require-a-working-sign-in) so traces cannot go anywhere else. For the format and file requirements, see [Lock settings](/langsmith/trace-claude-code#lock-settings).

For the full setup, see the deployment guides for [Claude Code](/langsmith/trace-claude-code#deploy-to-your-organization), [Codex](/langsmith/trace-with-codex#deploy-to-your-organization), and [Cursor](/langsmith/trace-with-cursor#deploy-to-your-organization).

### Connect GitHub or GitLab

To connect an account, you need permission to update all of the agent's environments. Installing the GitHub App for the first time also requires permission to install it on your repositories, and your GitHub organization may require an admin to approve it. For GitLab, a workspace admin connects the account in workspace settings. For details, see [Connect repositories to Engine](/langsmith/engine-repositories).

On the agent Overview, click **Track pull requests** and connect a GitHub or GitLab account. You can reuse an installation that is already connected to another agent in the workspace.

<Note>
Pull request tracking uses the same GitHub and GitLab connections as [LangSmith Engine](/langsmith/engine). If you have already [connected repositories to Engine](/langsmith/engine-repositories), those installations appear in the connection dialog, and you can link them without authorizing GitHub again.
</Note>

LangSmith links a pull request when GitHub or GitLab reports activity on it, such as opening, updating, or merging it. Pull requests merged before you connect do not appear. Merge rate, cost per merged pull request, and the pull request cards fill in as developers open and merge pull requests.

## Read the agent Overview

The summary cards at the top show metrics such as **LLM cost**, **Tokens**, **Threads**, **Turns / thread**, **Cache rate**, **Merge rate**, and **Cost / merged PR**, each compared with the period before. Select a card to chart that metric over time. You can group the chart by pull request state, user, user group, repository, harness, provider, or model. Click a bar or category to open a filtered view of the threads behind it and see what the agent did.

Below the summary, the Overview shows these cards:

- **Work type**: Threads by the kind of work they ask for: feature, bugfix, refactor, investigation, review, or off topic. This card requires a Coding Work Type thread evaluator. The card walks you through setting it up.
- **Skill usage**: Which skills the agent calls.
- **Cost per PR by state**: Average cost of open, closed, and merged pull requests.
- **Top PRs by cost**: The most expensive pull requests in the time range, with each one's state, threads, turns, and cost. Each row links to the pull request.
- **Cost by conversation length**: Threads grouped by number of turns, with total cost and average cost per thread and per turn.

## Example uses

### Find expensive pull requests

Use **Top PRs by cost** to find the pull requests that cost the most. Open a pull request's threads to see the models and the user behind it.

### Check the effect of shorter threads

Each new turn sends the conversation so far, so long threads cost more per turn. If you ask engineers to start new threads more often, use **Cost by conversation length** to check whether long threads become less common.

### Compare models

When your team switches models, group cost over time by model to compare spend before and after. Check **Merge rate** in the same time range to see whether pull requests still get merged.
