LangSmith organizes a workspace in one of two ways. A _project-based workspace_ groups traces by [tracing project](/langsmith/observability-concepts#tracing-projects). An _agent-based workspace_ groups them by [agent](/langsmith/agents), and divides each agent's traces across four [environments](/langsmith/agent-environments).

Agent-based organization is in [beta](/langsmith/release-stages) for a private group of customers, so most workspaces are project-based. This page covers what is different in an agent-based workspace, and what changes if yours becomes one.

## Check which one you have

The sidebar tells you. An agent-based workspace has **Overview** as the first item under **Search**, and an agent picker in the top bar. A project-based workspace has an **Application** section with an application picker.

## What changes

The organizing container changes, and everything scoped to it follows:

- **Traces** group under an agent and one of its environments rather than under a tracing project you named. Nothing is re-ingested or moved: each environment keeps the tracing project that backed it, renamed to the agent identifier, a hyphen, and the environment. An agent whose identifier is `checkout` has its production traces in `checkout-production`.
- **Prebuilt dashboards** cover an environment rather than a named project. See [Monitor projects with dashboards](/langsmith/dashboards).
- **Alerts** are scoped to an environment of an agent. See [Alerts](/langsmith/alerts).
- **Evaluators** attach to an environment. See [Manage evaluators](/langsmith/evaluators).
- **Navigation** gains an agent picker in the top bar, which moves between the agent list and a single agent's Overview. See [Navigate agents](/langsmith/navigate-agents).

What does not change: your traces, datasets, prompts, and experiments are the same records, and existing tracing configuration keeps working. See [Log traces to a specific project](/langsmith/log-traces-to-project).

## What the change is worth

A tracing project holds whatever you point at it, so LangSmith can make no assumption about what is inside one. Two projects named `checkout-prod` and `checkout-staging` are unrelated containers as far as the platform is concerned, and keeping them related is a naming convention you maintain by hand.

An agent states what the application is, and an environment states which deployment of it produced a trace. That context lets LangSmith act on your behalf rather than asking you to filter every time: an alert can watch production and stay quiet about local runs, and a dashboard can compare one agent across environments without a saved filter per environment.

## How a workspace moves

LangChain enables agent-based organization per workspace for customers in the beta. There is no setting in the product for choosing between the two, and no action is required from you.

During the beta, the setting applies when a workspace is created, so a project-based workspace stays project-based. Existing workspaces are not switched automatically.

<Note>
This page describes the change, not its schedule. Timing is not published.
</Note>
