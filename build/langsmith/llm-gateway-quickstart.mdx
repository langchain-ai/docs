The LLM Gateway lets you call models across configured providers through one standard endpoint with one LangSmith API key.

<Note>
**Beta:** The LLM Gateway is in [beta](/langsmith/release-stages).
</Note>

## Prerequisites

Before you start, confirm that:

- Your [Organization admin](/langsmith/rbac#organization-admin) has enabled the LLM Gateway. For bring-your-own-key models, the admin must also add the provider API key to workspace secrets. To set this up, see [Admin setup](/langsmith/llm-gateway-admin-setup).
- You have a workspace-scoped [LangSmith API key](/langsmith/create-account-api-key) attached to a role with `gateway:invoke` and `workspaces:read` [permissions](/langsmith/organization-workspace-operations). Ask your organization admin if you are unsure.

The examples below use a bring-your-own-key Anthropic model.

<Note>
If your API key is missing the `gateway:invoke` permission, the gateway returns a `403` at call time (not at setup time). If your calls fail with `403`, check the key's role with your organization admin.
</Note>

## Make a call

<Tabs>

<Tab title="Chat completions">

OpenAI-compatible Chat Completions endpoint (`/v1/chat/completions`). Works with the OpenAI SDK and any OpenAI-compatible client.

<CodeGroup>

```bash cURL
export LANGSMITH_API_KEY="lsv2_..."

curl https://gateway.smith.langchain.com/v1/chat/completions \
    -H "Authorization: Bearer $LANGSMITH_API_KEY" \
    -H "Content-Type: application/json" \
    -d '{"model":"anthropic/claude-opus-5","messages":[{"role":"user","content":"Explain what an LLM gateway does in one sentence."}]}'
```

```python Python
import os
from openai import OpenAI

client = OpenAI(
    base_url="https://gateway.smith.langchain.com/v1",
    api_key=os.environ["LANGSMITH_API_KEY"],
)
response = client.chat.completions.create(
    model="anthropic/claude-opus-5",
    messages=[{"role": "user", "content": "Explain what an LLM gateway does in one sentence."}],
)
print(response.choices[0].message.content)
```

```typescript TypeScript
import OpenAI from "openai";

const client = new OpenAI({
  baseURL: "https://gateway.smith.langchain.com/v1",
  apiKey: process.env.LANGSMITH_API_KEY,
});
const response = await client.chat.completions.create({
  model: "anthropic/claude-opus-5",
  messages: [{ role: "user", content: "Explain what an LLM gateway does in one sentence." }],
});
console.log(response.choices[0].message.content);
```

</CodeGroup>

</Tab>

<Tab title="Messages">

Anthropic Messages API format (`/v1/messages`). Works with the Anthropic SDK pointed at the gateway root (no `/v1` — the SDK appends its own path).

<CodeGroup>

```bash cURL
export LANGSMITH_API_KEY="lsv2_..."

curl https://gateway.smith.langchain.com/v1/messages \
    -H "Authorization: Bearer $LANGSMITH_API_KEY" \
    -H "Anthropic-Version: 2023-06-01" \
    -H "Content-Type: application/json" \
    -d '{"model":"anthropic/claude-opus-5","max_tokens":1024,"messages":[{"role":"user","content":"Explain what an LLM gateway does in one sentence."}]}'
```

```python Python
import os
import anthropic

client = anthropic.Anthropic(
    base_url="https://gateway.smith.langchain.com",
    api_key=os.environ["LANGSMITH_API_KEY"],
)
message = client.messages.create(
    model="anthropic/claude-opus-5",
    max_tokens=1024,
    messages=[{"role": "user", "content": "Explain what an LLM gateway does in one sentence."}],
)
print(message.content[0].text)
```

```typescript TypeScript
import Anthropic from "@anthropic-ai/sdk";

const client = new Anthropic({
  baseURL: "https://gateway.smith.langchain.com",
  apiKey: process.env.LANGSMITH_API_KEY,
});
const message = await client.messages.create({
  model: "anthropic/claude-opus-5",
  max_tokens: 1024,
  messages: [{ role: "user", content: "Explain what an LLM gateway does in one sentence." }],
});
console.log(message.content[0].text);
```

</CodeGroup>

</Tab>

<Tab title="Deep Agents">

Set `LANGSMITH_GATEWAY=true` to route all Deep Agents calls through the gateway automatically.

<CodeGroup>

```python Python
# pip install "deepagents>=0.1.0"
# export LANGSMITH_API_KEY="lsv2_..."  export LANGSMITH_GATEWAY="true"
import os
from deepagents import create_deep_agent

agent = create_deep_agent(model="anthropic:claude-opus-5")
result = agent.invoke({"messages": [{"role": "user", "content": "Explain what an LLM gateway does in one sentence."}]})
print(result["messages"][-1].content)
```

```typescript TypeScript
// npm install deepagents
// export LANGSMITH_API_KEY="lsv2_..."  export LANGSMITH_GATEWAY="true"
import { createDeepAgent } from "deepagents";

const agent = createDeepAgent({ model: "anthropic:claude-opus-5" });
const result = await agent.invoke({
  messages: [{ role: "user", content: "Explain what an LLM gateway does in one sentence." }],
});
console.log(result.messages[result.messages.length - 1].content);
```

</CodeGroup>

</Tab>

<Tab title="LangChain / per-request">

Prefix any model with `langsmith:` to route that call through the gateway without setting `LANGSMITH_GATEWAY`. Only `LANGSMITH_API_KEY` is required. This per-request approach works in both LangChain and Deep Agents (which uses `init_chat_model` under the hood).

<CodeGroup>

```python LangChain
# pip install "langchain>=1.3.15"
# export LANGSMITH_API_KEY="lsv2_..."
from langchain.chat_models import init_chat_model

model = init_chat_model("langsmith:anthropic/claude-opus-5")
response = model.invoke("Explain what an LLM gateway does in one sentence.")
print(response.content)
```

```python Deep Agents
# pip install "deepagents>=0.1.0"
# export LANGSMITH_API_KEY="lsv2_..."
from deepagents import create_deep_agent

agent = create_deep_agent(model="langsmith:anthropic/claude-opus-5")
result = agent.invoke({"messages": [{"role": "user", "content": "Explain what an LLM gateway does in one sentence."}]})
print(result["messages"][-1].content)
```

## View your trace

Open the [LangSmith UI](https://smith.langchain.com?utm_source=docs&utm_medium=cta&utm_campaign=langsmith-signup&utm_content=langsmith-llm-gateway-quickstart) and navigate to the tracing project named `gateway` or `gateway-<short_api_key>-<api_key_id>` in the workspace associated with your API key. You should see a new trace for the call you just made.

<Note>
If your application also emits its own LangSmith traces, for example through [LangChain or LangGraph tracing](/langsmith/observability), the gateway-side trace and your application trace appear as separate runs. Linking gateway traces to the parent application run is not yet supported.
</Note>

## Set a spend policy (optional)

Go to **LLM Gateway** in LangSmith to create a spend policy. For example, you can set a daily $10 cap on your API key. When the cap is reached, the gateway returns a `402` response with the message: `"Request blocked by gateway policies: R&D Spend Cap"`.

See [Spend policies](/langsmith/llm-gateway-spend-policies) for the full guide on policy dimensions, time windows, and conflict resolution.

## Automatic routing (LangChain and Deep Agents)

Set `LANGSMITH_GATEWAY` to route all supported LangChain and Deep Agents **chat models** through the gateway automatically — no `base_url` or `api_key` wiring needed per client.

```bash
export LANGSMITH_GATEWAY="true"   # routes to the US gateway; see Regional URLs for EU / BYOC
```

<Warning>
Do not append a path (e.g. `/v1`) to the URL value. The SDK appends the provider-specific path automatically. A doubled path (`/openai/v1/v1`) will cause requests to fail.
</Warning>

<Note>
Only **chat models** are affected. `OpenAIEmbeddings`, the legacy `OpenAI` LLM, and other non-chat integrations continue to use their normal provider endpoints.
</Note>

<Note>
If you need a different API key for gateway calls than your default `LANGSMITH_API_KEY`, set `LANGSMITH_GATEWAY_API_KEY` as an override. It must be a workspace-scoped key with the `gateway:invoke` permission.
</Note>

Provider-specific base URLs (e.g. `OPENAI_API_BASE`) take precedence over the gateway setting, so you can still route individual providers elsewhere while keeping everything else on the gateway.

**Python** (`langchain-*` packages):

- [Anthropic](/oss/python/integrations/chat/anthropic) (`langchain-anthropic >= 1.5.1`)
- [Baseten](/oss/python/integrations/chat/baseten) (`langchain-baseten >= 0.2.3`)
- [Fireworks](/oss/python/integrations/chat/fireworks) (`langchain-fireworks >= 1.5.1`)
- [Google Gemini](/oss/python/integrations/chat/google_generative_ai) (`langchain-google-genai >= 4.3.2`)
- [OpenAI](/oss/python/integrations/chat/openai) (`langchain-openai >= 1.4.1`)

**TypeScript** (`@langchain/*` packages):

- [Anthropic](/oss/javascript/integrations/chat/anthropic) (`@langchain/anthropic >= 1.5.4`)
- [Fireworks](/oss/javascript/integrations/chat/fireworks) (`@langchain/fireworks >= 0.2.7`)
- [OpenAI](/oss/javascript/integrations/chat/openai) (`@langchain/openai >= 1.5.7`)

The table below shows how the base URL and key are resolved for each combination of env vars. It uses OpenAI as the example — other providers use their own `*_API_BASE` / `*_BASE_URL` and `*_API_KEY` variables. `GW default` is `https://gateway.smith.langchain.com/openai/v1`.

Python uses `OPENAI_API_BASE` and a `base_url=` constructor kwarg. TypeScript uses `OPENAI_BASE_URL` and a `configuration.baseURL` option — the column names differ but the rows are otherwise the same, except where marked with †.

| `LANGSMITH_GATEWAY` | `LANGSMITH_GATEWAY_API_KEY` | Provider base URL env var | `OPENAI_API_KEY` | Per-client base URL | Resolved base URL | Resolved key |
|---|---|---|---|---|---|---|
| unset / `false` | — | — | — | — | `api.openai.com` | none |
| unset / `false` | ✓ | — | provider-key | — | `api.openai.com` | provider-key |
| `true` | ✓ | — | — | — | GW default | gateway-key |
| `true` | — | — | — | — | GW default | none |
| `true` | ✓ | — | provider-key | — | GW default | gateway-key |
| `true` | — | — | provider-key | — | GW default | provider-key |
| `true` | ✓ | `api.openai.com/v1` | provider-key | — | `api.openai.com/v1` | provider-key |
| `true` | ✓ | `api.openai.com/v1` | — | — | `api.openai.com/v1` | gateway-key (Python) / none† (TS) |
| `true` | ✓ | `my.dev.gateway` | — | — | `my.dev.gateway` | gateway-key (Python) / none† (TS) |
| `https://eu…` | ✓ | — | — | — | `eu…/openai/v1` | gateway-key |
| `https://eu…` | ✓ | — | — | `https://apac…` | `apac…` | gateway-key (Python) / none† (TS) |
| `https://eu…` | ✓ | — | provider-key | `https://apac…` | `apac…` | provider-key |

† These rows may diverge between Python and TypeScript implementations. If you observe unexpected routing in TypeScript, verify against `@langchain/openai` directly.

## Regional URLs and endpoint styles

The base URL depends on your LangSmith instance:

| Instance | Base URL |
|---|---|
| US (default) | `https://gateway.smith.langchain.com` |
| EU | `https://eu.gateway.smith.langchain.com` |
| BYOC / self-hosted | `https://<data_plane_host>/gateway` |

The gateway exposes two endpoint styles:

- **Unified `/v1`** — an OpenAI-compatible Chat Completions endpoint that accepts any gateway model ID (e.g. `anthropic/claude-opus-5`). Append `/v1` to the base URL. Used by cURL and the OpenAI SDK. Full reference: [API formats](/langsmith/llm-gateway-api-formats).
- **Direct provider routes** — provider-native endpoints (e.g. the Anthropic Messages API). Use the base URL with no suffix — the SDK appends its own path. Full reference: [Direct model access](/langsmith/llm-gateway-direct-model-access).

When you set `LANGSMITH_GATEWAY`, LangChain and Deep Agents select the correct route automatically.
