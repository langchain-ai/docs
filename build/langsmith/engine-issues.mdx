The **Engine** page lists the recommendations [LangSmith Engine](/langsmith/engine) makes for an agent environment, each with a diagnosis, the traces that support it, and a proposed fix. A recommendation can fix a bug or optimize your agent. Engine groups recommendations by [goal](/langsmith/engine-goals). Work through them to ship fixes and to turn real failures into evaluation datasets. If Engine is not running on your agent environment yet, see [Set up Engine](/langsmith/engine-setup).

Click any recommendation to open its detail panel. At the top, a diagnosis describes the problem and its impact. Each recommendation has a toolbar for setting its priority, closing or reopening it, opening a pull request, creating a Linear issue, and watching it.

Engine learns from what you do with each recommendation: closing it, marking it as incorrectly flagged, changing its priority, or opening a pull request, along with any reason you give. For how those actions shape Engine's later analysis, see [How Engine learns from your actions on recommendations](/langsmith/engine#how-engine-learns-from-your-actions-on-recommendations).

## Review evidence

The **Evidence** section contains traces that support a diagnosis, including a snippet from each trace. From this section, you can:

- **View a trace**: Click **Open trace** to open an evidence trace. When Engine identifies the child run that caused the problem, it opens that exact run. The trace view includes a **View issue** link back to the recommendation.
- **Create offline examples**: Click [**Engine proposed N examples**](#add-offline-examples) to generate custom ground truth [dataset examples](/langsmith/manage-datasets) from the production trace inputs for offline evaluation.
- **View project evidence**: Click **View all in project** to view the evidence in the tracing project.

For more information, see [Manage a trace](/langsmith/manage-trace).

When feedback on a trace surfaces or confirms a recommendation, the recommendation lists that feedback under **Feedback cited by Engine**, below the diagnosis. Each entry shows a feedback key, such as one written by an online evaluator or a user's thumbs-down rating, and how many evidence traces cite it. Click a key to open the newest trace with that feedback. In the **Evidence** section, each trace that cites feedback also shows the cited feedback values next to **Open trace**. For how Engine uses feedback, see [How Engine selects traces](/langsmith/engine#how-engine-selects-traces).

Engine keeps tracking a recommendation after it is filed. Any new trace that matches the recommendation's failure pattern is added to **Evidence** automatically, so the recommendation reflects how often the failure is still happening without you re-running anything.

The **Proposed Fix** section describes the problem and suggests how to address it, which may include specific code or prompt changes if a repository is connected.

## Change priority and status

Select **Low**, **Medium**, or **High** from the priority dropdown to update a recommendation's priority. You can optionally provide a reason, which Engine [learns from](/langsmith/engine#how-engine-learns-from-your-actions-on-recommendations).

Closing records the outcome of your review. Click:

- **Close** to mark the recommendation as resolved.
- **Incorrectly Flagged** to dismiss the recommendation as not real or not worth fixing.

For either outcome, you can optionally provide a reason, which Engine [learns from](/langsmith/engine#how-engine-learns-from-your-actions-on-recommendations).

You can reopen a closed recommendation at any time. Click **Reopen** to clear any fix in progress and stop watching the recommendation if it was being watched. Engine also reopens a recommendation automatically when it detects the same problem recurring in a later trace.

## Open a pull request

To open a pull request with the proposed code change, first [connect a repository](/langsmith/engine-repositories), then click **Open PR**. On GitLab, Engine opens a merge request, but the buttons keep their names, **Open PR** and **View PR**. Once a pull request exists, Engine replaces **Open PR** with **View PR**. Click **View PR** to open the pull request in GitHub or the merge request in GitLab. Engine reflects the PR's status (open, merged, or closed) throughout the recommendation.

You can also copy the recommendation's fix context to your clipboard for use with an LLM or coding assistant. Engine can propose code changes to any connected repository, including agents built with [Deep Agents](/oss/python/deepagents/overview), [LangChain](/oss/python/langchain/overview), and [LangGraph](/oss/python/langgraph/overview).

## Create a Linear issue

To create a Linear issue, first [connect Linear](/langsmith/engine-setup#connect-to-linear), then click **Create in Linear** on a recommendation. Engine shows **Linear creation pending** while it creates the issue. When creation completes, Engine displays the linked Linear issue identifier on the recommendation and in the recommendation list.

The Linear issue includes the recommendation's title and description, severity, category, tags, a **View issue in LangSmith** link, and evidence trace IDs. Engine retains the link to the Linear issue. If you close the Linear ticket, Engine closes the corresponding recommendation. If you cancel the Linear ticket, Engine marks the corresponding recommendation as incorrectly flagged. Engine also tracks a pull request linked to the Linear ticket on the corresponding recommendation.

## Add offline examples

This step captures the traces that surfaced the recommendation as ground-truth [dataset examples](/langsmith/manage-datasets), so you can evaluate the fix offline before it reaches production.

1. Click **Engine proposed N examples** at the top right of the **Evidence** list to open the **Add as offline example** dialog. N is the number of examples Engine proposed for the recommendation. The button appears only when Engine has proposed examples.
2. Review each trace. The dialog shows the input, the wrong output the agent produced, and the proposed expected output as a custom ground truth example.
3. Click **Add to Dataset** to add them directly, or click **Edit in annotation queue** to review them first.
4. In the annotation queue, each example shows the run inputs alongside reference outputs proposed by Engine, structured as named [assertions](/langsmith/assertions) generated from trace analysis. Each assertion is a short claim describing what a correct answer should or should not include. Edit the assertions as needed, add new ones with **+ Add**, then click **Add to Dataset & Next** to work through each example.

For more information, refer to [Manage datasets](/langsmith/manage-datasets), [Use annotation queues](/langsmith/annotation-queues), and [Use assertions](/langsmith/assertions).

## Watch a recommendation

Watching keeps a recommendation open for monitoring without resolving it or marking it as incorrectly flagged. Click **Watch** when you are not ready to act on a recommendation but still want to know if the problem keeps happening.

To be alerted when a watched recommendation recurs, click **Alert me via Slack**, which opens the **Notifications** section of the [Engine settings](/langsmith/engine-setup#configure-engine) panel. See [Engine notifications](/langsmith/engine-notifications).

When new traces link to a watched recommendation, Engine moves it to the top of your list and shows how many new traces arrived, so you can pick up the fix or keep watching.

<Note>
Watching is only available for open recommendations without a pull request in flight: discard the fix to watch a recommendation again. Resolving a watched recommendation, or marking it as incorrectly flagged, automatically stops watching it.
</Note>

## Flag a trace for Engine

A flagged trace is one you have asked Engine to review directly, for example a trace where your agent went wrong without raising an error or receiving a low score. For how flags fit into trace selection, see [How Engine selects traces](/langsmith/engine#how-engine-selects-traces).

Flagging a trace requires Engine to be enabled for your organization and the `feedback:create` permission, which the Workspace Admin and Workspace Editor roles include. For more information, see [Feedback permissions](/langsmith/organization-workspace-operations#feedback).

To flag a trace:

1. Open the trace and click **Flag for Engine**.
2. (Optional) Add a note describing what went wrong or what Engine should look for.
3. Click **Flag for Engine** in the popover.

The button changes to **Queued** and stays that way until Engine links the trace to a recommendation. Click **Queued** to update your note, or click **Unflag** in the popover to remove the flag. When Engine links the trace to a recommendation, the trace view hides the button and shows a **View issue** link to that recommendation. If Engine is not set up yet for the tracing project or [agent environment](/langsmith/agent-environments) that contains the trace, the popover offers **Flag and set up Engine**, which saves the flag and opens its **Engine** tab to [finish setup](/langsmith/engine-setup).

## Filter and sort recommendations

### In the UI

The **Engine** page lists recommendations in the left panel, grouped by goal. Each entry shows a title, a short description, the number of contributing traces, and how recently the problem was observed. Each recommendation is tagged with a category, such as **Silent tool error** or **Hallucination**.

At the top of the list, you can click:

- **Filter recommendations** to filter by **Priority**, **Status**, and **Tags**.
- **Sort recommendations** to sort by **Severity**, **Last Updated**, and **Created**.
- **Configure Engine** <Icon icon="settings"/> (gear) icon to [configure Engine](/langsmith/engine-setup#configure-engine).

Open [LangSmith Chat](/langsmith/chat#engine) to ask questions across your recommendations, for example, which ones need the most attention or how many new ones are open.

If no recommendations appear after setup completes, Engine found no recurring patterns in the analyzed traces. Try checking back after more traces have been collected.

### With the CLI

The [LangSmith CLI](/langsmith/cli) calls recommendations issues. Use `langsmith project issues list` to list a project's recommendations. Filter with `--status` (`open`, `fixing`, `watching`, `completed`, or `ignored`) and `--priority` (`urgent`, `high`, `medium`, or `low`), and page with `--limit` and `--offset`.

```bash
# List open, high-priority recommendations for a project
langsmith project issues list --project <project-name> --status open --priority high
```
