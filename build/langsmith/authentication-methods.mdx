LangSmith supports multiple authentication methods for easy sign-up and login.

## Cloud

LangSmith Cloud supports the following sign-in methods. [BYOC](/langsmith/byoc) organizations sign in through the LangSmith Cloud control plane, so these methods apply to them too.

- **Email and password**: Users sign up and sign in to LangSmith with an email address and password.
- **Social providers**: Users sign in with their GitHub or Google credentials.
- **SAML SSO**: Enterprise customers can configure [SAML SSO](/langsmith/user-management#set-up-saml-sso-for-your-organization) and [SCIM](/langsmith/user-management#set-up-scim-for-your-organization). [Get a demo](https://www.langchain.com/contact-sales) to learn more.
- **OIDC SSO**: Enterprise customers can request [OIDC SSO](/langsmith/user-management#set-up-oidc-sso-for-your-organization) to sign in with their own OpenID Connect identity provider. [Contact support](https://support.langchain.com) to enable it.

## Self-Hosted

Self-hosted customers have more control over how their users can login to LangSmith. For more in-depth coverage of configuration options, see [the self-hosting docs](/langsmith/self-hosted) and [Helm chart](https://github.com/langchain-ai/helm/tree/main/charts/langsmith).

### SSO with OAuth 2.0 and OIDC

Production installations should configure SSO in order to use an external identity provider. This enables users to login through an identity platform like Auth0/Okta. LangSmith supports almost any OIDC-compliant provider. Learn more about configuring SSO in the [SSO configuration guide](/langsmith/self-host-sso). For an emergency credential in case your IdP becomes unavailable, see [Recovery admin login](/langsmith/self-host-sso-recovery).

### Email/Password a.k.a. basic auth

This auth method requires very little configuration as it does not require an external identity provider. It is most appropriate to use for self-hosted trials. Learn more in the [basic auth configuration guide](/langsmith/self-host-basic-auth)

### None

<Warning>
This authentication mode will be removed after the launch of Basic Auth.
</Warning>

If zero authentication methods are enabled, a self-hosted installation does not require any login/sign-up. This configuration should only be used for verifying installation at the infrastructure level, as the feature set supported in this mode is restricted with only a single organization and workspace.
