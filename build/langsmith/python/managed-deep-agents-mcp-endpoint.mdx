Every Managed Deep Agents deployment serves a [Model Context Protocol](https://modelcontextprotocol.io/introduction) (MCP) endpoint at `/mcp`. Any MCP client that supports the Streamable HTTP transport can call the deployed agent as a tool, so another assistant or agent can delegate work to it without calling the deployment API directly.

<ManagedDeepAgentsPublicBetaNote />

The endpoint is the outbound direction. An [MCP connector](/langsmith/python/managed-deep-agents-mcp-connectors) points the other way: it adds tools from a remote MCP server to your agent. A deployment can use both.

## Find the endpoint URL

The endpoint is `/mcp` on the deployment's API URL:

```text
https://<deployment>.us.langgraph.app/mcp
```

`mda deploy` prints the LangSmith deployment dashboard URL, not the API URL. Open that dashboard, copy the **API URL** from the deployment details view, then append `/mcp`.

During public beta, deployments run in the US region, so hostnames end in `.us.langgraph.app`. For the hostname of each region, see [LangSmith Cloud architecture](/langsmith/cloud).

The local server started by [`mda dev`](/langsmith/python/managed-deep-agents-local-development) serves the same endpoint. Append `/mcp` to the local server URL the CLI prints.

## Authenticate requests

The MCP endpoint uses the deployment's [identity](/langsmith/python/managed-deep-agents-identity) configuration, the same as every other route on the deployment. Send the credential that matches the configured mode:

| Identity mode | Header |
| --- | --- |
| LangSmith API key (default) | `x-api-key: <LANGSMITH_API_KEY>` |
| Supabase | `Authorization: Bearer <access_token>` |

Authentication failures return 401.

<Warning>
Anyone holding the LangSmith API key can reach the deployment, and an MCP client stores the header in its own configuration. Treat a key added to a client config as a shared secret for the whole workspace.
</Warning>

<Note>
Supabase identity expects an access token that a person obtains by signing in to your app. An MCP client that stores only static headers cannot mint one, so use the LangSmith API-key default for deployments that MCP clients call.
</Note>

## Understand what the agent exposes

The deployment exposes the agent as an MCP tool:

- **Tool name**: The agent `name` set in the [agent definition](/langsmith/python/managed-deep-agents-agent-definition#name).
- **Tool input schema**: The agent's input schema.

For the underlying server behavior, see [MCP endpoint in Agent Server](/langsmith/server-mcp).

## Add the agent to Claude Code

Register the endpoint as an HTTP MCP server:

```bash
claude mcp add --transport http research-assistant \
  https://<deployment>.us.langgraph.app/mcp \
  --header "x-api-key: $LANGSMITH_API_KEY"
```

Claude Code lists the agent as a tool once the server connects.

## Add the agent to another MCP client

Clients that read an `mcpServers` configuration accept the endpoint and header directly:

```json
{
  "mcpServers": {
    "research-assistant": {
      "type": "http",
      "url": "https://<deployment>.us.langgraph.app/mcp",
      "headers": {
        "x-api-key": "<LANGSMITH_API_KEY>"
      }
    }
  }
}
```

A client that accepts only a URL and negotiates OAuth cannot authenticate to the endpoint, which requires a header credential.

## Call the endpoint from code

Load the agent's tool through an MCP client library, then pass the tools to a model or another agent:

```python
import os

from langchain_mcp_adapters.client import MultiServerMCPClient

client = MultiServerMCPClient(
    {
        "research-assistant": {
            "transport": "streamable_http",
            "url": "https://<deployment>.us.langgraph.app/mcp",
            "headers": {"x-api-key": os.environ["LANGSMITH_API_KEY"]},
        }
    }
)

tools = await client.get_tools()
```




Read credentials from the environment. Do not hard-code them in client code.

## Understand session behavior

Each `/mcp` request is stateless and independent. The endpoint does not support sessions, so separate calls do not share thread state. To retain knowledge across calls, enable [durable memory](/langsmith/python/managed-deep-agents-memory).

## Distinguish the endpoint from other capabilities

- **MCP endpoint** exposes the deployed agent as a tool to MCP clients.
- **[MCP connectors](/langsmith/python/managed-deep-agents-mcp-connectors)** add tools hosted by remote MCP servers to the agent.
- **[Channels](/langsmith/python/managed-deep-agents-channels)** receive messages from an external messaging service that start agent runs and deliver responses.
