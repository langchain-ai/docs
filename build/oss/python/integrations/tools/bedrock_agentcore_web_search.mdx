[Amazon Bedrock AgentCore Web Search](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/web-search-api.html) gives agents current information from the web with a source URL on every result. It authenticates with the AWS credentials you already have and takes no search API key of its own. By default, the toolkit calls the Web Search API directly. It can also search through an [AgentCore Gateway](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway-target-connector-web-search-tool.html) target.

## Setup

The integration lives in the `langchain-aws` package, which wraps the `bedrock-agentcore` SDK.

<CodeGroup>
    ```bash pip
    pip install -U langchain-aws bedrock-agentcore
    ```
    ```bash uv
    uv add langchain-aws bedrock-agentcore
    ```
</CodeGroup>

Web search needs `langchain-aws` 1.7.9 or later and `bedrock-agentcore` 1.23.0 or later. Calling the Web Search API without a gateway needs `langchain-aws` 1.9.3 or later and `bedrock-agentcore` 1.26.0 or later. On earlier versions, the toolkit requires a gateway.

Install `bedrock-agentcore` explicitly, as above. `langchain_aws.tools` imports the web search toolkit inside a `try`/`except ImportError`, so on an install without `bedrock-agentcore`, or with a version below 1.23.0, the export is skipped rather than raising, and `create_web_search_toolkit` is simply absent from `langchain_aws.tools`. If the import fails, check both installed versions before anything else.

### Optional: create a gateway with a web search target

The Web Search API needs no resources, so skip this step unless you want to search through an [AgentCore Gateway](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway-target-connectors.html) target instead. You only do this once, and the same gateway serves every agent in the account.

```python
from bedrock_agentcore.gateway.client import GatewayClient

client = GatewayClient(region_name="us-east-1")

gateway = client.create_gateway_and_wait(
    name="my-web-search-gateway",
    roleArn="arn:aws:iam::111122223333:role/MyGatewayExecutionRole",
    authorizerType="AWS_IAM",
    protocolType="MCP",
)

client.create_web_search_target(gateway_identifier=gateway["gatewayId"])
```

`authorizerType="AWS_IAM"` is what makes the caller's own IAM permissions gate the gateway. `NONE` disables inbound authorization altogether, leaving the gateway callable by anyone who learns its URL and billed to your account.

The target is named `amazon-web-search` by default, and Gateway [prefixes every tool with its target name](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway-tool-naming.html), so the tool on the gateway is `amazon-web-search___WebSearch`. The toolkit finds it for you; the name matters only if you go looking for it in the gateway's tool list.

The Web Search API is available in `us-east-1`, `us-east-2`, `us-west-2`, `eu-west-1`, `ap-northeast-1`, and `ap-southeast-2`. The Web Search Tool connector is offered in a different set of Regions. The [service documentation](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/web-search-api.html#web-search-api-regions) carries the current lists.

### Credentials

With the Web Search API, your own credentials need `bedrock-agentcore:InvokeWebSearch` on `arn:aws:bedrock-agentcore:<region>:aws:tool/web-search.v1`. For the full setup, see [Get started with AgentCore Web Search](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/web-search-api-get-started.html).

Through a gateway, two different principals each need one permission, and mixing them up is the most common setup error:

- **Your own credentials** need `bedrock-agentcore:InvokeGateway` on the gateway ARN.
- **The gateway's execution role** needs `bedrock-agentcore:InvokeWebSearch` on `arn:aws:bedrock-agentcore:<region>:aws:tool/web-search.v1`, and a trust policy that lets `bedrock-agentcore.amazonaws.com` assume it. It needs nothing else.

If that trust policy narrows `aws:SourceArn` to a region, it has to be the gateway's region. A mismatch is accepted when the gateway is created and surfaces only on the first search, as `Failed to obtain execution role credentials`.

It's also helpful (but not needed) to set up LangSmith for best-in-class observability:

```python
import os

os.environ["LANGSMITH_API_KEY"] = "your-api-key"
os.environ["LANGSMITH_TRACING"] = "true"
```

## Instantiation

The factory is **synchronous**, unlike the browser and code interpreter factories in this package, because a search needs no session to be set up first.

```python
from langchain_aws.tools import create_web_search_toolkit

toolkit, tools = create_web_search_toolkit(region="us-east-1")
```

With no gateway argument, the toolkit calls the Web Search API. To search through a gateway instead, pass it:

```python
toolkit, tools = create_web_search_toolkit(
    region="us-east-1",
    gateway_id="my-web-search-gateway-abc123",
)
```

Address the gateway by `gateway_id`, by `gateway_arn`, or by `gateway_endpoint` if you already know the MCP URL. A `gateway_arn` carries its own region. With a `gateway_id`, pass `region` to match the gateway's region, or it will default to `us-east-1`.

Passing `target_name` saves a tool discovery round trip on the first search. Use it if you named the target something other than the default:

```python
toolkit, tools = create_web_search_toolkit(
    gateway_arn="arn:aws:bedrock-agentcore:us-east-1:111122223333:gateway/my-gw-abc123",
    target_name="amazon-web-search",
)
```

## Invocation

### Direct tool usage

```python
search = tools[0]

results = search.invoke({"query": "boto3 latest release changelog", "max_results": 5})
print(results)
```

Results come back as numbered text blocks, one per hit, each carrying a title, a URL, a publication date when the index reports one, and an extract:

```text
1. Releases · boto/boto3
   URL: https://github.com/boto/boto3/releases
   Published: 2023-12-16T00:00:00Z
   Additional navigation options Code Issues Pull requests ...
```

Through a gateway, the publication date comes in the connector's own form, such as `12:31PM, Friday, July 24 2026, PDT`.

### Use within an agent

```python
from langchain.agents import create_agent
from langchain.chat_models import init_chat_model
from langchain_aws.tools import create_web_search_toolkit

toolkit, tools = create_web_search_toolkit(region="us-east-1")

llm = init_chat_model(
    "us.anthropic.claude-sonnet-5-5",
    model_provider="bedrock_converse",
)

try:
    agent = create_agent(model=llm, tools=tools)
    result = agent.invoke(
        {"messages": [{"role": "user", "content": "What changed in the most recent boto3 release?"}]}
    )
    print(result["messages"][-1].content)
finally:
    toolkit.close()
```

The tool description asks the model to cite the URLs it used. Citing sources is a condition of use for this connector, so keep that instruction in place if you customize the prompt.

## Filtering results

The model can narrow a search by domain and by publication date. Both are arguments on the tool, so the model can set them itself when the question calls for it:

```python
# Only official documentation
search.invoke({
    "query": "S3 multipart upload limits",
    "include_domains": ["docs.aws.amazon.com"],
})

# Only recent pages
search.invoke({
    "query": "python release schedule",
    "published_after": "2026-01-01T00:00:00Z",
})
```

A root domain also matches its subdomains. Pass bare domain names. The Web Search API rejects the whole request when a domain includes a scheme, a path, or a wildcard, such as `https://github.com`, `github.com/boto/boto3`, or `*.github.com`. Both date bounds are inclusive.

`include_domains` can only narrow a search, never widen it: if the gateway target was created with its own include list, the two intersect, and disjoint lists return nothing.

To enforce a policy that the agent cannot relax, set it on the toolkit, as in the next section. Through a gateway, you can also set a domain policy on the target. Those lists are applied server-side and are not visible to the agent:

```python
client.create_web_search_target(
    gateway_identifier=gateway["gatewayId"],
    include_domains=["docs.aws.amazon.com", "boto3.amazonaws.com"],
)
```

## Rules the model cannot change

Rules set on the toolkit apply to every search, on either route. A call from the model can narrow them but never widen them:

```python
toolkit, tools = create_web_search_toolkit(
    region="us-east-1",
    exclude_domains=["example.com"],
    published_after="2026-10-01T00:00:00Z",
    model_filters=False,
    max_searches=4,
    return_sources=True,
)
```

- `include_domains`, `exclude_domains`, `published_after`, and `published_before` apply to every search. The model's exclude list is added to the toolkit's, its include list is intersected with the toolkit's, and its date bounds apply only when they are stricter.
- `model_filters=False` gives the model a query-only argument schema.
- `max_searches` caps the searches one toolkit runs. After that, the tool returns `Search limit of 4 reached. Answer with what you have.`
- `return_sources=True` returns results as a tool artifact: a list of dicts with `title`, `url`, `published_date`, `published_at`, and `text`.

## Error handling

A failed search raises `ToolException`, so a retry wrapper such as `Runnable.with_retry()` sees it as a failure rather than as a successful call that returned an error message.

To let the model read the message and correct its own query instead, opt in per tool:

```python
for tool in tools:
    tool.handle_tool_error = True
```

## Releasing the client

The toolkit holds a client, which `close()` releases. It also works as a context manager:

```python
toolkit, tools = create_web_search_toolkit(region="us-east-1", gateway_id="my-gw-abc123")

with toolkit:
    agent = create_agent(model=llm, tools=tools)
    ...
```
