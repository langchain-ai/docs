## Threads: list traces

Retrieve all traces belonging to a specific thread within a project.

### Main changes

#### Method name

<Tabs>
  <Tab title="Python">
    | Before | After |
    |--------|-------|
    | `client.read_thread()` | `client.threads.list_traces()` |
  </Tab>
  <Tab title="TypeScript">
    | Before | After |
    |--------|-------|
    | `client.readThread()` | `client.threads.listTraces()` |
  </Tab>
  <Tab title="Java">
    <Note>Go and Java never had a dedicated per-thread method. The closest v1 equivalent is the generic run query filtered by the `thread_id` metadata convention.</Note>

    | Before | After |
    |--------|-------|
    | `client.runs().query()` (filtered by `thread_id`) | `client.threads().listTraces()` |
  </Tab>
  <Tab title="Go">
    <Note>Go and Java never had a dedicated per-thread method. The closest v1 equivalent is the generic run query filtered by the `thread_id` metadata convention.</Note>

    | Before | After |
    |--------|-------|
    | `client.Runs.Query()` (filtered by `thread_id`) | `client.Threads.ListTraces()` |
  </Tab>
  <Tab title="cURL">
    | Before | After |
    |--------|-------|
    | `POST /api/v1/runs/query` (`filter=eq(thread_id, ...)`) | `GET /v2/threads/{thread_id}/traces` |
  </Tab>
</Tabs>

#### Query parameters

<Tabs>
  <Tab title="Python">
    `read_thread`'s `is_root` has no v2 equivalent. `list_traces` always returns traces (root runs) only, matching its name. `read_thread`'s `order` (asc/desc) also has no v2 equivalent: results are always sorted by `start_time` ascending, a fixed server-side order.

    | Before (`read_thread`) | After (`list_traces`) | Notes |
    |---|---|---|
    | `thread_id` | `thread_id` (path param) | Unchanged |
    | `project_id` XOR `project_name` | `project_id` | v2 takes only the UUID |
    | `is_root` | *(not available)* | v2 always returns traces (root runs) only |
    | `order` | *(not available)* | No sort/order field on v2 |
    | `filter` | `filter` | Same syntax, now evaluated against each root trace run |
    | `select` (arbitrary run field list) | `selects` | v2 uses `ThreadTraceSelectField`, a 21-value uppercase enum |
    | *(not available)* | `page_size` + `cursor` | v2 adds cursor pagination |
  </Tab>
  <Tab title="TypeScript">
    Same mapping as Python, with `snake_case` field names: `threadId` (path param), `project_id`, `filter`, `selects`, `page_size`, `cursor`. `isRoot` and `order` have no v2 equivalent: results are always sorted by `start_time` ascending, a fixed server-side order.
  </Tab>
  <Tab title="Java">
    No query parameters to map. There was no dedicated method. `listTraces(threadId, params)` takes `projectId`, `filter`, `pageSize`, `cursor`, `selects` (21-value enum). Results are always sorted by `startTime` ascending, a fixed server-side order.
  </Tab>
  <Tab title="Go">
    No query parameters to map. There was no dedicated method. `ListTraces(ctx, threadID, params)` takes `ProjectID`, `Filter`, `PageSize`, `Cursor`, `Selects` (21-value enum). Results are always sorted by `StartTime` ascending, a fixed server-side order.
  </Tab>
  <Tab title="cURL">
    `GET /v2/threads/{thread_id}/traces` query params: `project_id`, `filter`, `page_size`, `cursor`, `selects` (repeatable), all `snake_case`. Results are always sorted by `start_time` ascending, a fixed server-side order.
  </Tab>
</Tabs>

#### Response fields

<Tabs>
  <Tab title="Python">
    v1's `read_thread` returns full `Run` objects (a generator). v2's `ThreadTraceListItem` is lightweight: preview fields (`inputs_preview`/`outputs_preview`) instead of full `inputs`/`outputs`, no embedded child runs. `selects` controls what's populated, the same as `traces.query`.

    | Before (v1 `Run` field, via `read_thread`) | After (v2 `ThreadTraceListItem` field) | Notes |
    |---|---|---|
    | `run.id` | *(not available)* | v1's root run `id` and `trace_id` were identical; v2 exposes only `trace_id` |
    | `run.trace_id` | `trace_id` | Returned by default when `selects` is omitted |
    | `run.name` | `name` | Omitted unless included in `selects` |
    | `run.start_time` | `start_time` | Omitted unless included in `selects` |
    | `run.end_time` | `end_time` | Omitted unless included in `selects` |
    | `run.run_type` | `op` | Renamed; encoded as a number instead of a string |
    | `run.inputs` | `inputs_preview` | Truncated text preview instead of full inputs |
    | `run.outputs` | `outputs_preview` | Truncated text preview instead of full outputs |
    | `run.error` | `error_preview` | Renamed; short error summary instead of the full error |
    | `run.latency` (property) | `latency` | Native field instead of a computed `timedelta` property |
    | `run.total_tokens`, `.prompt_tokens`, `.completion_tokens` | `total_tokens`, `prompt_tokens`, `completion_tokens` | Unchanged |
    | `run.total_cost`, `.prompt_cost`, `.completion_cost` | `total_cost`, `prompt_cost`, `completion_cost` | Unchanged |
    | `run.prompt_token_details`, `.completion_token_details` | `prompt_token_details`, `completion_token_details` | Field now wraps the dict; access `.raw` |
    | `run.prompt_cost_details`, `.completion_cost_details` | `prompt_cost_details`, `completion_cost_details` | Field now wraps the dict; access `.raw` |
    | `run.first_token_time` | `first_token_time` | Omitted unless included in `selects` |
    | *(not available)* | `thread_id` | New: the thread UUID this trace belongs to |
    | `run.child_runs`, `.child_run_ids` | *(not available)* | No embedded child runs; use `traces.list_runs` for descendant runs |
  </Tab>
  <Tab title="TypeScript">
    Same shape as Python: `ThreadTraceListItem` with 21 fields, `selects`-gated.
  </Tab>
  <Tab title="Java">
    `ThreadTraceListItem` has 21 `Optional` fields: `traceId`, `threadId`, `name`, `startTime`, `endTime`, `latency`, `op`, token/cost fields with per-category `_details`, `inputsPreview`/`outputsPreview`, `errorPreview`, `firstTokenTime`.

    | Before (v1 `RunSchema` method) | After (v2 `ThreadTraceListItem` method) | Notes |
    |---|---|---|
    | `run.id()` | *(not available)* | v1's root run `id()` and `traceId()` were identical; v2 exposes only `traceId()` |
    | `run.traceId()` | `traceId()` | Returned by default when `selects` is omitted |

    | `run.runType()` | `op()` | Renamed; encoded as a number instead of a string |
    | `run.inputs()` | `inputsPreview()` | Truncated text preview instead of full inputs |
    | `run.outputs()` | `outputsPreview()` | Truncated text preview instead of full outputs |
    | `run.error()` | `errorPreview()` | Renamed; short error summary instead of the full error |
    | `run.latency()` | `latency()` | Unchanged |
    | `run.totalTokens()`, `.promptTokens()`, `.completionTokens()` | `totalTokens()`, `promptTokens()`, `completionTokens()` | Unchanged |
    | `run.totalCost()`, `.promptCost()`, `.completionCost()` | `totalCost()`, `promptCost()`, `completionCost()` | Unchanged |
    | `run.promptTokenDetails()`, `.completionTokenDetails()` | `promptTokenDetails()`, `completionTokenDetails()` | Unchanged |
    | `run.promptCostDetails()`, `.completionCostDetails()` | `promptCostDetails()`, `completionCostDetails()` | Unchanged |

  </Tab>
  <Tab title="Go">
