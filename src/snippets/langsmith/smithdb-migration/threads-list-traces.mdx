## Threads: list traces

Retrieve all traces belonging to a specific thread within a project.

### Main changes

#### Method name

<Tabs>
  <Tab title="Python">
    | Before | After |
    |--------|-------|
    | `client.read_thread()` | `client.threads.list_traces()` |
  </Tab>
  <Tab title="TypeScript">
    | Before | After |
    |--------|-------|
    | `client.readThread()` | `client.threads.listTraces()` |
  </Tab>
  <Tab title="Java">
    <Note>Go and Java never had a dedicated per-thread method. The closest v1 equivalent is the generic run query filtered by the `thread_id` metadata convention.</Note>

    | Before | After |
    |--------|-------|
    | `client.runs().query()` (filtered by `thread_id`) | `client.threads().listTraces()` |
  </Tab>
  <Tab title="Go">
    <Note>Go and Java never had a dedicated per-thread method. The closest v1 equivalent is the generic run query filtered by the `thread_id` metadata convention.</Note>

    | Before | After |
    |--------|-------|
    | `client.Runs.Query()` (filtered by `thread_id`) | `client.Threads.ListTraces()` |
  </Tab>
  <Tab title="cURL">
    | Before | After |
    |--------|-------|
    | `POST /api/v1/runs/query` (`filter=eq(thread_id, ...)`) | `GET /v2/threads/{thread_id}/traces` |
  </Tab>
</Tabs>

#### Query parameters

<Tabs>
  <Tab title="Python">
    `read_thread`'s `is_root` (default `True`, can be set `False` to get descendant runs too) has no v2 equivalent. `list_traces` always returns traces (root runs) only, matching its name. `read_thread`'s `order` (asc/desc) also has no v2 equivalent. `ThreadListTracesParams` has exactly 5 fields (`project_id`, `cursor`, `filter`, `page_size`, `selects`), with no sort/order field at all.

    | Before (`read_thread`) | After (`list_traces`) | Notes |
    |---|---|---|
    | `thread_id` | `thread_id` (path param) | Unchanged |
    | `project_id` XOR `project_name` | `project_id` | v2 takes only the UUID |
    | `is_root` | *(not available)* | v2 always returns traces (root runs) only |
    | `order` | *(not available)* | No sort/order field on v2 |
    | `filter` | `filter` | Same syntax, now evaluated against each root trace run |
    | `select` (arbitrary run field list) | `selects` | v2 uses `ThreadTraceSelectField`, a 21-value uppercase enum |
    | *(not available)* | `page_size` + `cursor` | v2 adds cursor pagination |
  </Tab>
  <Tab title="TypeScript">
    Same mapping as Python, with `snake_case` field names: `threadId` (path param), `project_id`, `filter`, `selects`, `page_size`, `cursor`. `isRoot` and `order` have no v2 equivalent.
  </Tab>
  <Tab title="Java">
    No query parameters to map. There was no dedicated method. `listTraces(threadId, params)` takes `projectId`, `filter`, `pageSize`, `cursor`, `selects` (21-value enum).
  </Tab>
  <Tab title="Go">
    No query parameters to map. There was no dedicated method. `ListTraces(ctx, threadID, params)` takes `ProjectID`, `Filter`, `PageSize`, `Cursor`, `Selects` (21-value enum).
  </Tab>
  <Tab title="cURL">
    `GET /v2/threads/{thread_id}/traces` query params: `project_id`, `filter`, `page_size`, `cursor`, `selects` (repeatable), all `snake_case`.
  </Tab>
</Tabs>

#### Response fields

<Tabs>
  <Tab title="Python">
    v1's `read_thread` returns full `Run` objects (a generator). v2's `ThreadTraceListItem` is lightweight: preview fields (`inputs_preview`/`outputs_preview`) instead of full `inputs`/`outputs`, no embedded child runs. `selects` controls what's populated; `trace_id` is always present.
  </Tab>
  <Tab title="TypeScript">
    Same shape as Python: `ThreadTraceListItem` with 21 fields, `selects`-gated.
  </Tab>
  <Tab title="Java">
    `ThreadTraceListItem` has 21 `Optional` fields: `traceId` (always present), `threadId`, `name`, `startTime`, `endTime`, `latency`, `op`, token/cost fields with per-category `_details`, `inputsPreview`/`outputsPreview`, `errorPreview`, `firstTokenTime`.
  </Tab>
  <Tab title="Go">
    Same 21 fields as Java/Python, in `PascalCase` Go struct form.
  </Tab>
  <Tab title="cURL">
    JSON response fields match Python `snake_case`.
  </Tab>
</Tabs>
