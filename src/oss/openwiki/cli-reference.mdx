OpenWiki ships as a single `openwiki` binary for interactive chat and one-shot documentation runs. For installation and first use, see [Quickstart](/oss/openwiki/quickstart).

## Core commands

```bash
# Interactive chat in code mode (current repository)
openwiki
openwiki "Please generate documentation for this repository"

# Personal mode
openwiki personal
openwiki personal --init
openwiki personal --update

# Explicit code mode
openwiki code --init
openwiki code --update
openwiki code --update --print

# Defaults to code mode
openwiki --init
openwiki --update

# One-shot print mode
openwiki -p "Summarize what you can do"

# Help
openwiki --help
```

### Common flags

| Flag | Description |
| --- | --- |
| `--init` | Generate initial documentation. Defaults to code mode |
| `--update` | Update existing documentation. Defaults to code mode |
| `--mode <personal\|code>` | Choose personal brain or repository docs |
| `-p`, `--print` | Run once, print the final assistant output, and exit |
| `--modelId` / `--model-id` | Choose a model ID for the run |
| `--telemetry-file=<path>` | Also write the telemetry payload for the run to a local JSON file |
| `-h`, `--help` | Print usage |

`--init` and `--update` cannot be combined. When `--print` is used, provide a message or command.

### Auto-exit for init and update

When `--init` or `--update` runs in a TTY without `--print`, the CLI streams agent output and exits automatically on success. Interactive chat stays open for follow-ups. `--print` writes to stdout and exits.

### Non-interactive runs

If stdin is not a TTY (for example, CI), or you use `--print`, credentials must already be present in `~/.openwiki/.env` or the process environment. OpenWiki errors instead of prompting.

## Auth and connectors

```bash
openwiki auth
openwiki auth gmail
openwiki auth notion
openwiki auth slack
openwiki auth x
openwiki auth configure <provider> [--force]
openwiki auth tools <provider>
openwiki ingest <source|source-instance|all>
openwiki ngrok start [url] [--port <port>]
```

- **`openwiki auth <provider>`**: Run a local browser OAuth flow, save tokens to `~/.openwiki/.env`, and create connector config when possible.
- **`openwiki auth configure <provider>`**: Regenerate connector config that references saved auth env vars.
- **`openwiki auth tools <provider>`**: List live MCP tools for MCP-backed providers.
- **`openwiki ingest`**: Run source-specific ingestion for configured connectors.
- **`openwiki ngrok start`**: Start an ngrok HTTPS tunnel for Slack OAuth. OpenWiki reads ngrok's local inspection API, appends `/callback`, and saves `OPENWIKI_HTTPS_OAUTH_REDIRECT_URI`. Register the printed callback URL in Slack. If you have a fixed ngrok domain, pass it as the URL argument. X/Twitter and Gmail auth ignore that HTTPS override and keep using the local loopback callback.

## Cron (macOS)

```bash
openwiki cron list
openwiki cron pause <source|all>
openwiki cron resume <source|all>
openwiki cron delete <source|all>
```

## Slash commands (interactive)

In chat, use:

- `/api-key`: Update the current provider API key (masked prompt)
- `/langsmith-key`: Update or clear LangSmith tracing credentials (masked prompt)
- `/provider` and `/model`: Change provider or model for the session (persisted to `~/.openwiki/.env`)
- `/init` and `/update`: Launch init or update from the session
- `/exit`: Exit the app
