## Overview

[Kyvvu](https://kyvvu.com) is a runtime AI governance layer. Its LangChain callback handler evaluates every agent action—LLM calls, tool invocations, retrieval, and agent decisions—against your policies **before** the action runs. Actions that violate policy are blocked (the run aborts with an exception), and every step is written to a tamper-evident, hash-chained audit trail suitable for EU AI Act, OWASP, and GDPR evidence.

The same handler works for both LangChain and LangGraph, because LangGraph runs on `langchain_core` callbacks. A LangGraph-specific handler adds node metadata and maps `interrupt()` to a human-in-the-loop gate.

## Why

Observability tools tell you what an agent *did*. Governance tells you what an agent is *allowed* to do. Kyvvu enforces policy inline: a data-exfiltration or destructive-tool call is stopped at evaluation time, not flagged after the fact. Because enforcement and logging share one code path, the audit trail is a faithful record of what was allowed and what was blocked.

## How it works

The handler is a pure adapter over a configured `Kyvvu` client:

1. You construct a `Kyvvu` client (API URL + API key) and register (or attach to) an agent.
2. You pass a `KyvvuLangChainHandler` (or `KyvvuLangGraphHandler`) as a callback.
3. On each callback event, Kyvvu maps the event to an atomic behavior, evaluates it against your loaded policies in-process, and either allows it or raises `KyvvuBlockedError` to abort the run.
4. Completed and blocked steps are recorded and flushed to the Kyvvu API as a hash-chained audit trail.

```shell
pip install kyvvu langchain langchain-openai
```

## Example (LangChain)

Construct a `Kyvvu` client, register the agent, then attach the handler as a callback. The handler does not manage identity or registration—it is a pure adapter over the client you build.

```python
import os

from kyvvu import Kyvvu, Environment, RiskClassification
from kyvvu.integrations.langchain import KyvvuLangChainHandler

from langchain.agents import create_agent

# 1. Configure the Kyvvu client and register the agent.
kv = Kyvvu(
    api_key=os.environ["KV_API_KEY"],
    agent_key="research-agent",
    environment=Environment.DEVELOPMENT,
    risk_classification=RiskClassification.LIMITED,
)
kv.register_agent(
    name="Research Agent",
    purpose="Answer questions using tools",
)

# 2. Build the handler.
handler = KyvvuLangChainHandler(kv)

# 3. Attach it as a callback. Policy is enforced before each step runs;
#    a blocked action raises KyvvuBlockedError and aborts the run.
agent = create_agent(model="gpt-4o", tools=[])
result = agent.invoke(
    {"messages": [{"role": "user", "content": "What is the capital of France?"}]},
    config={"callbacks": [handler]},
)
print(result)
```

<Note>
The handler is a pure adapter: it does not create identity or call the API on its own. Build one `Kyvvu()` instance, call `register_agent()` (or pass a pre-provisioned `agent_id=`), then reuse it across handlers.
</Note>

## Example (LangGraph)

For LangGraph, the shared `KyvvuLangChainHandler` works as-is. Use `KyvvuLangGraphHandler` to additionally capture the active graph node (`langgraph.node_name`) on each step and to map LangGraph's `interrupt()` (a `GraphInterrupt`) to a human-in-the-loop `step.gate` behavior.

```python
import os

from kyvvu import Kyvvu
from kyvvu.integrations.langgraph import KyvvuLangGraphHandler

# Build the same Kyvvu client + registration as above.
kv = Kyvvu(api_key=os.environ["KV_API_KEY"], agent_key="graph-agent")
kv.register_agent(name="Graph Agent")

handler = KyvvuLangGraphHandler(kv)

# graph is a compiled LangGraph StateGraph.
result = graph.invoke(
    {"messages": [{"role": "user", "content": "Research LangChain governance."}]},
    config={"callbacks": [handler]},
)
```

## Handling blocked actions

When a policy blocks an action, the handler raises `KyvvuBlockedError`, which propagates out of the `invoke()` call and aborts the run. Catch it to react to enforcement decisions:

```python
from kyvvu.exceptions import KyvvuBlockedError

try:
    result = agent.invoke(
        {"messages": [{"role": "user", "content": user_input}]},
        config={"callbacks": [handler]},
    )
except KyvvuBlockedError as exc:
    # The offending step is recorded in the audit trail as output.status=blocked.
    print(f"Action blocked by policy: {exc}")
```

## Configuration

The `Kyvvu` client reads configuration from keyword arguments or environment variables (kwargs take precedence):

| Parameter | Env var | Default | Purpose |
| :--- | :--- | :--- | :--- |
| `api_url` | `KV_API_URL` | `https://platform.kyvvu.com` | Kyvvu API base URL |
| `api_key` | `KV_API_KEY` | — | Bearer API key (`KvKey-...`) |
| `agent_key` | `KV_AGENT_KEY` | — | Stable agent identifier for policy fetch |
| `agent_id` | — | — | Pre-provisioned agent ID (skips `register_agent`) |
| `environment` | `KV_ENVIRONMENT` | `development` | Deployment environment |
| `risk_classification` | — | `minimal` | EU AI Act risk tier |
