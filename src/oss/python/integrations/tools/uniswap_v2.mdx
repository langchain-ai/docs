Read-only tools for querying Uniswap V2 (and Uniswap V2-shaped fork, e.g. PancakeSwap) pools on any EVM chain: swap quotes, liquidity previews, and LP token balances. No wallet, private key, or API key required — only an RPC endpoint URL.

## Overview

### Integration details

| Class | Package | Serializable | JS support | Version |
| :--- | :--- | :---: | :---: | :---: |
| `UniswapV2Toolkit` | [`langchain-uniswap-v2`](https://pypi.org/project/langchain-uniswap-v2/) | ❌ | ❌ | ![PyPI - Version](https://img.shields.io/pypi/v/langchain-uniswap-v2?style=flat-square&label=%20) |

### Tool features

- `get_quote_in`: How much of `token_in` is required to receive an exact amount of `token_out`.
- `get_quote_out`: How much of `token_out` will be received for an exact amount of `token_in` spent.
- `get_pool_quote`: Proportional deposit preview before adding liquidity.
- `get_lp_amounts`: Expected token amounts redeemable before removing liquidity.
- `get_liquidity_token_balance`: An address's LP token balance for a given pair.

## Setup

This toolkit needs no API key or credentials — only an RPC endpoint URL for the target chain. A free public endpoint works for prototyping; see the [supported chains registry](https://github.com/Conrad-sudo/langchain-uniswap-v2#supported-chains-built-in-registry) for defaults, or pass your own for production.

### Installation

This toolkit lives in the `langchain-uniswap-v2` package:

<CodeGroup>

## Instantiation

For a chain already in the built-in registry (Ethereum, Arbitrum, Base, Optimism, Polygon, Avalanche, BSC via PancakeSwap, and more), pass just a `chain_id`:

```python Initialize from a known chain icon="robot"
from langchain_uniswap_v2 import UniswapV2Toolkit

toolkit = UniswapV2Toolkit.for_chain(chain_id=1)  # Ethereum mainnet
```

For any other Uniswap V2-shaped DEX on any EVM chain, pass explicit addresses:

```python Initialize with explicit addresses icon="wrench"
from langchain_uniswap_v2 import UniswapV2Toolkit

toolkit = UniswapV2Toolkit(
    rpc_url="https://eth.llamarpc.com",
    router_address="0x7a250d5630B4cF539739dF2C5dAcb4c659F2488D",
    native_wrapped_address="0xC02aaA39b223FE8D0A0e5C4F27eAD9083C756Cc2",  # WETH
)
```

## Tools

View the available tools:

```python
tools = toolkit.get_tools()
for tool in tools:
    print(tool.name)
```

```text
get_quote_in
get_quote_out
get_pool_quote
get_lp_amounts
get_liquidity_token_balance
```

## Invocation

### Directly

```python Call tool icon="rocket"
tool_name = "get_quote_out"
tool = next(t for t in tools if t.name == tool_name)
tool.invoke({
    "token_in": "0xC02aaA39b223FE8D0A0e5C4F27eAD9083C756Cc2",   # WETH
    "token_out": "0xA0b86991c6218b36c1d19D4a2e9Eb0cE3606eB48",  # USDC
    "amount_in": 1,
})
```

```text
{'amount_in': 1.0, 'amount_out': 1737.95055, 'path': ['0xC02aaA39b223FE8D0A0e5C4F27eAD9083C756Cc2', '0xA0b86991c6218b36c1d19D4a2e9Eb0cE3606eB48']}
```

<Note>
`amount_out` reflects the live WETH/USDC price at the time this example was
run (2026-07-09) and will differ when you run it yourself — quotes are read
directly from on-chain pool reserves, not cached.
</Note>

### As a ToolCall

We can also invoke the tool with a model-generated `ToolCall`, in which case a @[`ToolMessage`] will be returned:

```python ToolCall icon="briefcase"
# This is usually generated by a model, but we'll create a tool call directly for demo purposes.
model_generated_tool_call = {
    "args": {
        "token_in": "0xC02aaA39b223FE8D0A0e5C4F27eAD9083C756Cc2",
        "token_out": "0xA0b86991c6218b36c1d19D4a2e9Eb0cE3606eB48",
        "amount_in": 1,
    },
    "id": "1",
    "name": tool.name,
    "type": "tool_call",
}
tool.invoke(model_generated_tool_call)
```

### Within an agent

```python Agent with tool icon="robot"
# pip install -qU "langchain[anthropic]" to call the model
from langchain.agents import create_agent

agent = create_agent(
    model="claude-sonnet-4-6",
    tools=toolkit.get_tools(),
)

agent.invoke(
    {"messages": [{"role": "user", "content": "How much USDC will I get for 1 WETH?"}]}
)
```

## Scope

This toolkit is read-only by design: it answers "how much will I get" / "how much do I need," but does not execute swaps or add/remove liquidity. Wiring up transaction signing and spend-limit guardrails is left to the caller.
