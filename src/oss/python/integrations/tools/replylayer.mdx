[ReplyLayer](https://replylayer.ai) is an email platform for AI agents with governance built in: sends pass recipient-allowlist, quota, human-approval, and content-scanning gates before anything leaves, and inbound mail is security-scanned before an agent reads it. The `langchain-replylayer` package wraps the published [`replylayer`](https://pypi.org/project/replylayer/) SDK as six LangChain tools whose results are governed outcomes an agent can branch on—a refused send comes back as a structured tool result, not a raised exception.

## Overview

### Integration details

| Class | Package | Serializable | [JS support](https://js.langchain.com) | Version |
|:------|:--------| :---: | :---: | :---: |
| `ReplyLayerToolkit` | [`langchain-replylayer`](https://pypi.org/project/langchain-replylayer/) | ❌ | ❌ | ![PyPI - Version](https://img.shields.io/pypi/v/langchain-replylayer?style=flat-square&label=%20) |

### Available tools

| Tool | Description |
|:-----|:------------|
| `send_email` | Send a new outbound email from a mailbox |
| `reply_to_email` | Reply to an inbound message, continuing its thread |
| `list_messages` | List recent messages (cursor-paginated) |
| `read_message` | Read one message in full, with its safety context |
| `wait_for_message` | Long-poll a mailbox for the next inbound message (≤30s) |
| `check_send_quota` | Preflight the remaining daily send budget |

The toolkit deliberately exposes nothing that loosens containment (allowlist changes, quarantine release, approval decisions)—those stay with humans and admin credentials on the ReplyLayer side.

## Setup

Install the package:

```bash
pip install -U langchain-replylayer
```

### Credentials

You need a ReplyLayer API key—use a **mailbox-scoped agent key**, not an admin key, so the credential you hand the agent is limited to its own mailbox. ReplyLayer is currently in private beta; get access at [replylayer.ai](https://replylayer.ai).

```python
import getpass
import os

if not os.environ.get("REPLYLAYER_API_KEY"):
    os.environ["REPLYLAYER_API_KEY"] = getpass.getpass("ReplyLayer API key:\n")
```

## Instantiation

The toolkit owns its HTTP clients, so use it as a context manager (or call `close()` / `aclose()` yourself). `api_key` falls back to the `REPLYLAYER_API_KEY` environment variable:

```python
from langchain_replylayer import ReplyLayerToolkit

with ReplyLayerToolkit(default_mailbox_id="support") as toolkit:
    tools = toolkit.get_tools()
```

## Invocation

### Invoke directly with args

Every tool returns a JSON-serializable dict with a `status` field. Governed outcomes—a policy refusal, a content block, a queue for human approval—are returned as results for the agent to branch on, never raised:

```python
from langchain_replylayer import ReplyLayerToolkit

with ReplyLayerToolkit(default_mailbox_id="support") as toolkit:
    tools = {tool.name: tool for tool in toolkit.get_tools()}

    result = tools["send_email"].invoke(
        {"to": "alice@example.com", "subject": "Hi", "body": "Hello from my agent."}
    )

    if result["status"] == "sent":
        print("accepted for delivery:", result["message_id"])
    elif result["status"] == "rejected_by_policy":
        # A pre-admission gate refused the recipient before any bytes left.
        print("refused by a send gate:", result["code"])
    elif result["status"] == "held_for_human_review":
        print("queued for human approval:", result["message_id"])
    else:
        print("outcome:", result["status"])
```

### Invoke with ToolCall

```python
model_generated_tool_call = {
    "args": {
        "to": "alice@example.com",
        "subject": "Follow up",
        "body": "Just checking in.",
    },
    "id": "1",
    "name": "send_email",
    "type": "tool_call",
}
tool_msg = tools["send_email"].invoke(model_generated_tool_call)
print(tool_msg.content)
```

## Use within an agent

```python
# pip install -qU "langchain[anthropic]" to call the model
from langchain.agents import create_agent
from langchain_replylayer import ReplyLayerToolkit

with ReplyLayerToolkit(default_mailbox_id="support") as toolkit:
    agent = create_agent(
        model="claude-sonnet-4-6",
        tools=toolkit.get_tools(),
    )

    result = agent.invoke(
        {
            "messages": [
                {
                    "role": "user",
                    "content": "Check the mailbox for new messages and summarize the most recent one.",
                }
            ]
        }
    )
```

Async is symmetric—every tool ships both sync `invoke` and async `ainvoke`, backed by the SDK's async client under `async with ReplyLayerToolkit(...)`.

## Governance outcomes

The send tools translate every ReplyLayer decision into a `status` the agent can act on:

| `status` | Meaning |
|----------|---------|
| `sent` | Accepted for delivery. Carries `message_id`. Not a safety judgment. |
| `rejected_by_policy` | A pre-admission gate refused the recipient before any bytes left (allowlist, suppression, recipient verification, sandbox or billing limits). Carries `code`; don't retry unchanged. |
| `rejected` | Post-admission content block—terminal. Edit the content or escalate; never resend the same body. |
| `held_for_human_review` | Queued for human approval before it can go out. Report "awaiting approval"; nothing to fix by editing. |
| `retry_later` | Transient hold. Carries `retry_after` when the server supplied one. |
| `rate_limited` | Throttled—`variant` distinguishes a daily budget, new-account warm-up, or a short-window limit. |
| `error` | A visible client-side error (bad input, unknown id) the agent may be able to fix. |

Scanning reduces risk; a clean verdict is not a trust verdict—`sent` means "accepted for delivery", not "safe".

## Reading inbound email

Inbound message content (senders, subjects, bodies) is third-party data. Read results are labeled `untrusted_content: true`, and `read_message` carries the message's `agent_safety_context` through verbatim so the agent is told, at the moment of reading, to treat the body as data rather than instructions:

```python
msg = tools["read_message"].invoke({"message_id": "..."})
if msg["status"] == "ok":
    print(msg["state"])                 # e.g. "available" or "quarantined"
    print(msg["agent_safety_context"])  # server-supplied handling guidance
    print(msg["body"][:200])            # visible, untrusted data
```

Messages that fail ReplyLayer's inbound scanning arrive in a `quarantined` state—the content stays visible to the agent as untrusted data, and release decisions stay with humans.
