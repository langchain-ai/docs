### Features

- Returns a structured JSON action manifest for any URL — every clickable, fillable, and submittable element, not raw HTML or a screenshot
- Each action carries `type`, `required`, `requires` (dependency ids), and a best-effort `locator` (`css`/`role`/`name`) so an agent can act on it without guessing a selector
- 6-hour response caching by default; pass `fresh=True` to bypass
- Async-first client under the hood (`AsyncManifestClient`), wrapped as a LangChain `StructuredTool`

## Setup

To access the Manifest tool, create an account at [app.manifest.omfang.io](https://app.manifest.omfang.io/login), grab an API key from the dashboard, and install the `manifest-api` package with the `langchain` extra.

### Credentials

```python
import getpass
import os

if "MANIFEST_API_KEY" not in os.environ:
    os.environ["MANIFEST_API_KEY"] = getpass.getpass("Enter your Manifest API key: ")
```

It's also helpful (but not needed) to set up LangSmith for best-in-class observability/tracing of your tool calls. To enable automated tracing, set your [LangSmith](/langsmith/home) API key:

```python
os.environ["LANGSMITH_API_KEY"] = getpass.getpass("Enter your LangSmith API key: ")
os.environ["LANGSMITH_TRACING"] = "true"
```

### Installation

The Manifest tool lives in the `manifest-api` package, under the `langchain` extra:

```python pip
pip install -U "manifest-api[langchain]"
```
```python uv
uv add "manifest-api[langchain]"
```

## Instantiation

Manifest's LangChain support is a factory function rather than a tool class — it binds your API key at creation time so it's never visible to the model:

```python
from manifest_api.integrations.langchain import create_manifest_tool

tool = create_manifest_tool()  # reads MANIFEST_API_KEY from the environment
# or: create_manifest_tool(api_key="...")
```

---

## Invocation

### Directly

```python
tool.invoke({"url": "https://example.com"})
```

### As a ToolCall

We can also invoke the tool with a model-generated `ToolCall`, in which case a `ToolMessage` will be returned:

```python
# This is usually generated by a model, but we'll create a tool call directly for demo purposes.
model_generated_tool_call = {
    "args": {"url": "https://example.com"},
    "id": "1",
    "name": tool.name,
    "type": "tool_call",
}
tool.invoke(model_generated_tool_call)
```

### Within an agent

```python
# pip install -qU "langchain[anthropic]" to call the model
from langchain.agents import create_agent

tools = [tool]
agent = create_agent(
    model="claude-sonnet-4-6",
    tools=tools,
)

agent.invoke(
    {"messages": [{"role": "user", "content": "What can I do on the contact page at https://example.com/contact?"}]}
)
```

## Why not raw HTML or a browser tool?

Browser-access tools get an agent onto a page. Content-extraction tools get it the text. Neither tells the agent what it's allowed to *do* there — which fields are required, what's disabled until a prior step completes, or a selector that survives the next redesign. Manifest sits between those two categories: it returns the action surface of a page as structured, agent-readable JSON.
