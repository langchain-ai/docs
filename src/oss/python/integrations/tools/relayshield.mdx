title: RelayShield
description: Check MCP servers and email addresses for agentic-security risk before an agent acts on them.

[RelayShield](https://relayshield.net) provides identity and agentic-attack-surface threat intelligence. The `langchain-relayshield` package exposes two tools that check for risk *before* a high-impact agent action — connecting to an MCP server, or trusting an identity that may already be compromised — plus an optional mandatory pre-execution gate.

## Overview

### Integration details

| Class | Package | Serializable | JS support | Version |
| :--- | :--- | :---: | :---: | :---: |
| `check_mcp_server_risk`, `check_prompt_injection_breach` | `langchain-relayshield` | ❌ | ❌ | ![PyPI - Version](https://img.shields.io/pypi/v/langchain-relayshield?style=flat-square&label=%20) |

### Tool features

1. **check_mcp_server_risk** — flags known-malicious IOC matches, typosquat domains close to well-known MCP ecosystem names, and newly-registered domains hosting an MCP server, before an agent connects to or installs it.
2. **check_prompt_injection_breach** — checks whether an email address appears in RelayShield's stolen-session corpus with a suspected-agentic-source marker: a session/token exposure that shows signs of having been captured via a compromised or hijacked AI agent, not a conventional phishing/malware path.

### Key features

- **Per-call API key**: both tools take `api_key` as a call argument rather than reading it from the environment implicitly, so a shared agent process can act safely on behalf of multiple callers with different RelayShield keys.
- **Mandatory gate, not just advisory tools**: the optional `[middleware]` extra ships `RelayShieldMCPGateMiddleware`, a `wrap_tool_call` hook that blocks `connect_mcp_server` / `install_mcp_package` calls outright on a risk finding, rather than leaving the check to a tool the model can choose to skip.

## Setup

### Installation

The RelayShield tools live in the `langchain-relayshield` package:

<CodeGroup>
    ```python pip
    pip install -U langchain-relayshield
    ```
    ```python uv
    uv add langchain-relayshield
    ```
</CodeGroup>

The mandatory-gate middleware needs LangChain's agent runtime; install the extra if you want it:

<CodeGroup>
    ```python pip
    pip install -U "langchain-relayshield[middleware]"
    ```
    ```python uv
    uv add "langchain-relayshield[middleware]"
    ```
</CodeGroup>

### Credentials

Get an API key at [api.relayshield.net/developers](https://api.relayshield.net/developers), then pass it per-call:

```python Set API key icon="key"
import getpass
import os

if "RELAYSHIELD_API_KEY" not in os.environ:
    os.environ["RELAYSHIELD_API_KEY"] = getpass.getpass("Enter your RelayShield API key: ")
```

## Instantiation

The tools are plain LangChain `@tool`-decorated functions — no client object to construct:

```python Import tools icon="robot"
from langchain_relayshield import check_mcp_server_risk, check_prompt_injection_breach
```

## Invocation

### Directly

```python Call tool icon="rocket"
import os

result = check_mcp_server_risk.invoke({
    "api_key": os.environ["RELAYSHIELD_API_KEY"],
    "server_url": "https://mcp.example.com/sse",
})
print(result)  # {"verdict": "LOW", "findings": [...]}
```

`check_mcp_server_risk` accepts `server_url`, `package_name`, or both — checks are more limited with `package_name` alone since there's no domain to check. `check_prompt_injection_breach` takes `api_key` and `email`.

### As a ToolCall

```python ToolCall icon="briefcase"
# This is usually generated by a model, but we'll create a tool call directly for demo purposes.
model_generated_tool_call = {
    "args": {"api_key": os.environ["RELAYSHIELD_API_KEY"], "server_url": "https://mcp.example.com/sse"},
    "id": "1",
    "name": check_mcp_server_risk.name,
    "type": "tool_call",
}
check_mcp_server_risk.invoke(model_generated_tool_call)
```

### Within an agent

```python Agent with tool icon="robot"
# pip install -qU "langchain[anthropic]" to call the model
from langchain.agents import create_agent
from langchain_relayshield import check_mcp_server_risk, check_prompt_injection_breach

tools = [check_mcp_server_risk, check_prompt_injection_breach]
agent = create_agent(
    model="claude-sonnet-4-6",
    tools=tools,
)

agent.invoke(
    {"messages": [{"role": "user", "content": "Is it safe to connect to the MCP server at https://mcp.example.com/sse?"}]}
)
```

Both tools return a dict rather than raising on a RelayShield API error, so a failed check surfaces as `{"error": "..."}` content the model can reason about instead of crashing the run.

## Mandatory gate middleware

An advisory tool only helps if the model chooses to call it. `RelayShieldMCPGateMiddleware` is a `wrap_tool_call` hook that intercepts `connect_mcp_server` / `install_mcp_package` calls and runs the registry-risk check itself, before the underlying tool executes:

```python Attach the gate icon="shield"
from langchain.agents import create_agent
from langchain_relayshield.middleware import RelayShieldMCPGateMiddleware

agent = create_agent(
    model="claude-sonnet-4-6",
    tools=[connect_mcp_server, install_mcp_package],  # your own MCP connect/install tools
    middleware=[RelayShieldMCPGateMiddleware()],
)
```

Design properties, all non-negotiable:

- A hook exception defaults to `defer`, never silently to `allow` — a gate failure must not become a pass.
- Bounded retry applies only to transient upstream failures (timeout/429/5xx); auth failures, malformed responses, and payment-required states are terminal after one attempt.
- The audit log records the decision, reason codes, check version, target, and timestamp — never keys, payment proofs, or session material.
- The raw `connect_mcp_server` / `install_mcp_package` tools should never be bound to the model directly in a real deployment — only route access to them through the gate.

Full design writeup and the 12-case protected-action acceptance suite this middleware is tested against: [relayshield-langchain-gate](https://github.com/nzdsf2-gif/relayshield-langchain-gate).
