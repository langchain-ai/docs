[Interven](https://intervensecurity.com) is an open-source policy engine and
audit gateway for AI agents. It scans every tool call your agent makes,
applies your policies (block, sanitize, require human approval, allow),
and records a SIEM-grade audit log of every decision.

It works with any LangChain or LangGraph agent through the
[`interven-langchain`](https://pypi.org/project/interven-langchain/) package.

## Installation and setup

```bash
pip install interven-langchain
```

Sign up at [app.intervensecurity.com](https://app.intervensecurity.com) and
mint an API key (the prefix is `iv_live_`).

```bash
export INTERVEN_API_KEY=iv_live_...
```

The package is MIT licensed. The Interven gateway is also self-hostable via
docker-compose if you don't want to use the SaaS — see the
[self-host guide](https://docs.intervensecurity.com/docs/self-host).

## Callbacks

`InterventCallback` is a `BaseCallbackHandler` you can drop into any agent.
Every `on_tool_start` / `on_tool_end` event flows through your Interven
policies before the tool actually runs.

```python
from langchain_core.messages import HumanMessage
from langgraph.prebuilt import create_react_agent
from interven_langchain import InterventCallback

agent = create_react_agent(model, tools=[your_tools])

agent.invoke(
    {"messages": [HumanMessage("...")]},
    config={"callbacks": [InterventCallback(api_key="iv_live_...")]},
)
```

When a policy decision returns `DENY`, the callback either raises
`InterventBlockedError` or returns a refusal string the LLM can see and
respond to (configurable via `on_block="raise"` or `on_block="return_message"`).

## Tool wrappers

`guard()` wraps a single LangChain `BaseTool`. Stronger than the callback —
it can rewrite the tool's arguments mid-flight on a `SANITIZE` decision, so
PII never reaches the underlying tool.

```python
from interven_langchain import guard

guarded_jira = guard(my_jira_tool, api_key="iv_live_...")
```

## LangGraph integration

For LangGraph agents, the `interven-langchain[langgraph]` extra adds two
patterns:

```python
from interven_langchain.langgraph import interven_tool_node, guard_state_graph

# Pattern A: drop-in replacement for langgraph.prebuilt.ToolNode
graph.add_node("tools", interven_tool_node(tools, api_key="iv_live_..."))

# Pattern B: wrap a compiled graph so every entry point carries the callback
guarded = guard_state_graph(compiled_graph, api_key="iv_live_...")
```

## LangSmith tracing

If you have `LANGSMITH_API_KEY` and `LANGSMITH_TRACING=true` set, every
Interven decision emits a child run named `interven.scan.<tool_name>` under
your existing trace tree. The run includes the decision, reason codes, risk
band, and a deeplink back to the Interven Console — so a security reviewer
can move from a LangSmith trace straight to the policy decision that
produced it.

```bash
pip install 'interven-langchain[langsmith]'
```

## Reference architecture and examples

We maintain four working reference patterns at
[github.com/boltyx0/langchain-reference](https://github.com/boltyx0/langchain-reference):

- **Pattern 1 — Callback** for adding to an existing agent in three lines.
- **Pattern 2 — Tool wrapper** for per-tool control with mid-flight redaction.
- **Pattern 3 — Custom LangGraph node** as a drop-in `ToolNode` replacement.
- **Pattern 4 — Compiled-graph guard** to cover every entry point of a graph
  with a single wrap.

Each example runs end-to-end against the package on PyPI plus the hosted
Interven gateway.
