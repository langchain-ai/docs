[oxidize-pdf](https://github.com/bzsanti/oxidize-python) is a fast, Rust-powered PDF engine with first-class RAG primitives. It parses PDFs natively (no system dependencies — it ships as a wheel for Linux, macOS, and Windows) and produces element-disjoint semantic chunks, so PDFs become retrieval-ready without any post-processing.

This integration provides oxidize-pdf's capabilities via the `OxidizePdfLoader` document loader, distributed as the [`langchain-oxidize-pdf`](https://pypi.org/project/langchain-oxidize-pdf/) package.

## Overview

### Integration details

| Class | Package | Local | Serializable | JS support |
| :--- | :--- | :---: | :---: | :---: |
| `OxidizePdfLoader` | `langchain-oxidize-pdf` | ✅ | ❌ | ❌ |

### Loader features

| Source | Document Lazy Loading | Native Async Support |
| :---: | :---: | :---: |
| `OxidizePdfLoader` | ✅ | ❌ |

`OxidizePdfLoader` supports three export modes via the `mode` argument:

- `mode="rag"` (default): one `Document` per element-disjoint semantic chunk, with
  heading-aware context — ideal for vector-store ingestion.
- `mode="pages"`: one `Document` per page (plain text).
- `mode="markdown"`: a single `Document` containing the whole PDF as markdown.

## Setup

The integration lives in the `langchain-oxidize-pdf` package:

```python
pip install -qU langchain-oxidize-pdf
```

No API key or system dependency is required; the Rust engine is bundled in the wheel.

## Initialization

The file path is bound to the loader instance (following the `PyPDFLoader` convention):

```python
from langchain_oxidize_pdf import OxidizePdfLoader

loader = OxidizePdfLoader(
    "paper.pdf",       # str or pathlib.Path
    mode="rag",        # "rag" (default), "pages", or "markdown"
)
```

`OxidizePdfLoader` accepts the following parameters:

- `file_path`: the source PDF, as `str` or `pathlib.Path`.
- `mode` (optional): `"rag"` (default), `"pages"`, or `"markdown"`.
- `extra_info` (optional): a dict of caller metadata merged into every `Document`'s
  metadata. Keys that collide with base fields (`file_path`, `file_name`, `total_pages`,
  `pdf_version`) override them, reflecting explicit caller intent.

## Load

```python
docs = loader.load()
docs[0]
```

In the default `rag` mode each `Document` carries chunk-level metadata:

| Field | Description |
| :--- | :--- |
| `chunk_index` | 0-based index of the chunk within the document |
| `page_numbers` | list of 1-indexed pages the chunk spans |
| `element_types` | semantic types detected in the chunk (e.g. `title`, `paragraph`) |
| `heading_context` | nearest surrounding heading, or `None` |
| `token_estimate` | rough token count for budget planning |
| `file_path` / `file_name` / `total_pages` / `pdf_version` | source metadata |

```python
print(docs[0].metadata)
```

## Lazy load

`lazy_load()` is the primary entry point and returns a generator, so large PDFs stream
into downstream consumers instead of being materialized all at once:

```python
for doc in loader.lazy_load():
    print(doc.metadata["chunk_index"], doc.metadata["heading_context"])
    print(doc.page_content[:200])
```

## Modes

### One document per page

```python
loader = OxidizePdfLoader("paper.pdf", mode="pages")
for doc in loader.lazy_load():
    print(doc.metadata["page_number"], len(doc.page_content))
```

### Whole PDF as markdown

```python
loader = OxidizePdfLoader("paper.pdf", mode="markdown")
[doc] = loader.load()
print(doc.page_content)
```

### Caller metadata

```python
loader = OxidizePdfLoader(
    "paper.pdf",
    extra_info={"source": "arxiv:2501.12345", "collection": "benchmarks"},
)
```

## Use within a RAG pipeline

The `rag` mode emits chunks that can be embedded and written to a vector store directly,
without an additional text splitter:

```python
from langchain_oxidize_pdf import OxidizePdfLoader

docs = OxidizePdfLoader("paper.pdf").load()  # mode="rag"
# docs -> embeddings -> vector store; no post-chunking needed
```

The disjointness contract (no chunk's text is a substring of another's; each source
element appears in exactly one chunk) is enforced by regression tests in both the loader
and the underlying oxidize-pdf bridge, so no duplicated context leaks into the store.
