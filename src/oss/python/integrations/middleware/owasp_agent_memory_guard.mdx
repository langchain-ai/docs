### Features

- <Icon icon="shield-lock" size={16}/> **Prompt injection detection** — Catches injected instructions hidden in agent memory, tool outputs, and context
- <Icon icon="key" size={16}/> **Secret leakage prevention** — Detects API keys, tokens, and credentials in model responses
- <Icon icon="alert-triangle" size={16}/> **Content anomaly detection** — Flags abnormally large payloads that may indicate stuffing attacks
- <Icon icon="lock" size={16}/> **Protected key enforcement** — Prevents unauthorized modification of critical memory fields
- <Icon icon="terminal" size={16}/> **Tool output scanning** — Scans tool results for injected payloads before they enter the agent loop

This middleware implements the [OWASP Agentic Security Initiative ASI06](https://owasp.org/www-project-agentic-security-initiative/) threat model for memory poisoning defense.

## Setup

No API key or external service is required. The middleware runs entirely locally with zero network calls.

### Installation

<CodeGroup>
    ```python pip
    pip install -U langchain-agent-memory-guard
    ```
    ```python uv
    uv add langchain-agent-memory-guard
    ```
</CodeGroup>

## Instantiation

```python Initialize middleware icon="arrows-shuffle"
from langchain_agent_memory_guard import MemoryGuardMiddleware

# Default: strict policy, block on violation
middleware = MemoryGuardMiddleware()

# Custom: warn instead of blocking
middleware = MemoryGuardMiddleware(on_violation="warn")

# Custom: strip malicious content silently
middleware = MemoryGuardMiddleware(on_violation="strip")
```

## Use with an agent

Pass the middleware to @[`create_agent`] or @[`create_deep_agent`]. It composes with other middleware (runs in order).

```python Agent with memory guard icon="robot"
from langchain.agents import create_agent
from langchain_agent_memory_guard import MemoryGuardMiddleware

agent = create_agent(
    model="openai:gpt-4o",
    tools=[my_search_tool, my_db_tool],
    middleware=[MemoryGuardMiddleware()],
)

# The agent is now protected against memory poisoning
result = agent.invoke({"messages": [{"role": "user", "content": "Search for recent AI news"}]})
```

<Tip>
    Middleware runs in the [agent loop](/oss/langchain/middleware/overview#the-agent-loop). For custom behavior, see [custom middleware](/oss/langchain/middleware/custom).
</Tip>

## Violation handling modes

The middleware supports three modes for handling detected attacks:

| Mode | Behavior | Use case |
|------|----------|----------|
| `"block"` (default) | Raises `MemoryGuardViolation` exception | Production systems where security is critical |
| `"warn"` | Logs warning, continues execution | Development/testing, monitoring without disruption |
| `"strip"` | Removes violating content silently | High-availability systems that must not fail |

```python Error handling icon="shield-lock"
from langchain_agent_memory_guard import MemoryGuardMiddleware
from langchain_agent_memory_guard.middleware import MemoryGuardViolation

middleware = MemoryGuardMiddleware(on_violation="block")

try:
    result = agent.invoke({"messages": [{"role": "user", "content": "Process this data"}]})
except MemoryGuardViolation as e:
    print(f"Attack detected and blocked: {e}")
```

## Custom security policy

Use the core `agent-memory-guard` policy system for fine-grained control:

```python Custom policy icon="settings"
from agent_memory_guard import Policy
from langchain_agent_memory_guard import MemoryGuardMiddleware

# Strict policy (default) — all detectors enabled
middleware = MemoryGuardMiddleware(policy=Policy.strict())

# Permissive policy — detect but don't enforce
middleware = MemoryGuardMiddleware(policy=Policy.permissive())
```

## How it protects your agent

The middleware hooks into three points in the agent loop:

| Hook | What it scans | Threat mitigated |
|------|--------------|-----------------|
| `before_model` | All messages in agent state | Injection planted in memory/context |
| `after_model` | Model's response content | Secret leakage, injection propagation |
| `wrap_tool_call` | Tool output content | **Primary attack vector**: injection via tool results |

Tool outputs are the most dangerous attack surface because an adversary can embed prompt injection payloads in web pages, database records, or API responses that the agent's tools fetch.
