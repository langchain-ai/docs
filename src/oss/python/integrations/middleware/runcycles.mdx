This guide provides a quick overview for getting started with the [Cycles](https://runcycles.io) middleware. The `langchain-runcycles` package exposes three [agent middleware](/oss/langchain/middleware/overview/) classes that put pre-execution budget authority in front of model calls, tool calls, and runaway agent loops. For a detailed listing of all features, parameters, and configurations, head to the [Cycles API reference](https://github.com/runcycles/langchain-runcycles).

### Features

- <Icon icon="cpu" size={16}/> Pre-model-call authorization via `wrap_model_call`: gate every LLM turn before spend, returning an `AIMessage` denial so the agent terminates naturally (v0.1.5+).
- <Icon icon="shield-lock" size={16}/> Pre-tool-call authorization via `wrap_tool_call`: denied calls return a `ToolMessage` so the model can recover gracefully.
- <Icon icon="wallet" size={16}/> Per-tenant budget enforcement: reserve before tool use, commit on success, release on exception.
- <Icon icon="repeat" size={16}/> Fan-out caps via `before_model` with `jump_to: "end"`: stop runaway agents before another model turn.
- <Icon icon="bolt" size={16}/> Sync and async support: pair with `agent.invoke()` or `agent.ainvoke()`.

## Setup

To use the Cycles middleware, you'll need a running [Cycles](https://runcycles.io) server (or a hosted Cycles endpoint), an API key for that server, and the `langchain-runcycles` integration package. Cycles is an open protocol with a reference server you can self-host; you don't need a SaaS account.

### Credentials

```python Set API key icon="key"
import getpass
import os

if "CYCLES_API_KEY" not in os.environ:
    os.environ["CYCLES_API_KEY"] = getpass.getpass("Enter your Cycles API key: ")
if "CYCLES_BASE_URL" not in os.environ:
    os.environ["CYCLES_BASE_URL"] = "http://localhost:7878"
```

It's also helpful (but not required) to set up LangSmith for observability and <Tooltip tip="Log each step of a model's execution to debug and improve it">tracing</Tooltip>. To enable automated tracing, set your [LangSmith](/langsmith/home) API key:

```python Enable tracing icon="flask"
os.environ["LANGSMITH_API_KEY"] = getpass.getpass("Enter your LangSmith API key: ")
os.environ["LANGSMITH_TRACING"] = "true"
```

## Instantiation

All three middleware classes wrap a `runcycles.CyclesClient` (or `AsyncCyclesClient` for async agents). Configure subject and action: these tell Cycles *who* is acting and *what* they're doing.

```python Initialize middleware icon="arrows-shuffle"
import os
from langchain_runcycles import CyclesFanOutGate, CyclesModelGate, CyclesToolGate
from runcycles import Action, CyclesClient, CyclesConfig, Subject

client = CyclesClient(
    CyclesConfig(
        base_url=os.environ["CYCLES_BASE_URL"],
        api_key=os.environ["CYCLES_API_KEY"],
    )
)

model_gate = CyclesModelGate(
    client,
    subject=Subject(tenant="acme", agent="researcher"),
    action=Action(kind="llm.completion", name="research-turn"),
    mode="decide",  # or "reserve", or "decide+reserve"
)

tool_gate = CyclesToolGate(
    client,
    subject=Subject(tenant="acme", agent="researcher"),
    action={"send_email": Action(kind="tool.call", name="send_email")},
    mode="decide",  # or "reserve", or "decide+reserve"
)

fanout_gate = CyclesFanOutGate(
    max_turns=20,
    client=client,
    subject=Subject(tenant="acme"),
    action=Action(kind="model.turn", name="research"),
)
```

## Use with an agent

Pass middleware to @[`create_agent`] in order. Combine the Cycles middleware with built-in middleware like `HumanInTheLoopMiddleware` for production-grade agent governance.

```python Agent with middleware icon="robot"
from langchain.agents import create_agent
from langchain.tools import tool

@tool
def send_email(to: str, body: str) -> str:
    """Send an email to a recipient."""
    return f"Sent to {to}"

agent = create_agent(
    model="claude-sonnet-4-6",
    tools=[send_email],
    middleware=[fanout_gate, model_gate, tool_gate],
)

agent.invoke({"messages": [{"role": "user", "content": "Email alice@example.com to confirm."}]})
```

<Tip>
    Middleware runs in the [agent loop](/oss/langchain/middleware/overview#the-agent-loop). For custom behavior, see [custom middleware](/oss/langchain/middleware/custom).
</Tip>

## CyclesModelGate: pre-model-call authorization (v0.1.5+)

<Note>
    Available in `langchain-runcycles` 0.1.5+.
</Note>

`CyclesModelGate` overrides `wrap_model_call` to gate every LLM invocation. Same three modes as `CyclesToolGate`. On denial in `decide` mode, returns a `ModelResponse` whose `AIMessage` carries the denial reason: the agent terminates naturally because the `AIMessage` has no `tool_calls`.

| Mode | Behavior |
| :--- | :--- |
| `"decide"` | Calls `client.decide()`. Denies the model call on a non-allow decision. No reservation. |
| `"reserve"` | Creates a reservation, calls the model, commits on success (at the configured `estimate`), releases on exception. |
| `"decide+reserve"` | Authorizes via `decide()` first, then reserves and commits at the configured `estimate`. Most strict. |

```python CyclesModelGate icon="cpu"
from langchain_runcycles import CyclesModelGate
from runcycles import Action, Amount, Subject, Unit

model_gate = CyclesModelGate(
    client,
    subject=Subject(tenant="acme", agent="researcher"),
    action=Action(kind="llm.completion", name="claude-sonnet-4-6"),
    mode="reserve",
    estimate=Amount(unit=Unit.USD_MICROCENTS, amount=2_000_000),  # $0.02 per call
    denial_message="Cycles denied this model call: {reason}",
)
```

<Tip>
    v0.1.5 commits at the configured `estimate` rather than extracting actual token usage from the provider response. Provider-specific token extractors (OpenAI, Anthropic) and streaming integration land in v0.2.0. For precise per-call token cost capture today, the `BaseCallbackHandler` recipe in `cycles-client-python` works alongside this middleware.
</Tip>

### Compose all three gates

The full LangChain agent governance triad (fan-out caps, model-spend reservation, and tool-call authorization) uses one `middleware=[...]` list:

```python All three gates icon="layers-linked"
from langchain.agents import create_agent
from langchain_runcycles import CyclesFanOutGate, CyclesModelGate, CyclesToolGate
from runcycles import Action, Amount, Subject, Unit

agent = create_agent(
    model="claude-sonnet-4-6",
    tools=[send_email],  # send_email is defined in the "Use with an agent" snippet above
    middleware=[
        CyclesFanOutGate(
            max_turns=20,
            client=client,
            subject=Subject(tenant="acme"),
            action=Action(kind="model.turn", name="research"),
        ),
        CyclesModelGate(
            client,
            subject=Subject(tenant="acme", agent="researcher"),
            action=Action(kind="llm.completion", name="claude-sonnet-4-6"),
            mode="reserve",
            estimate=Amount(unit=Unit.USD_MICROCENTS, amount=2_000_000),
        ),
        CyclesToolGate(
            client,
            subject=Subject(tenant="acme", agent="researcher"),
            action={"send_email": Action(kind="tool.call", name="send_email")},
            mode="decide+reserve",
        ),
    ],
)
```

This order (fan-out first, then model, then tool) means runaway loops halt before model spend, and model spend is reserved before tool side effects.

## CyclesToolGate: pre-tool-call authorization

`CyclesToolGate` overrides `wrap_tool_call` to gate every tool call. It supports three modes:

| Mode | Behavior |
| :--- | :--- |
| `"decide"` | Calls `client.decide()`. Denies the tool call on a non-allow decision. No reservation. |
| `"reserve"` | Creates a reservation, runs the tool, commits on success (at the configured `estimate`), releases on exception. |
| `"decide+reserve"` | Authorizes via `decide()` first, then reserves and commits at the configured `estimate`. Most strict. |

Denied calls return a `ToolMessage` containing the denial reason: the underlying tool handler is never invoked, but the model sees the denial like any other tool result and can choose another path.

```python CyclesToolGate icon="shield-lock"
from langchain_runcycles import CyclesToolGate
from runcycles import Action, Subject

gate = CyclesToolGate(
    client,
    subject=Subject(tenant="acme", agent="researcher"),
    action={
        "search": Action(kind="tool.call", name="search"),
        "send_email": Action(kind="tool.call", name="send_email"),
    },
    mode="decide+reserve",
    denial_message="Cycles denied {tool} for tenant: {reason}",
)
```

`action` accepts a static `Action`, a per-tool mapping (`Mapping[str, Action]`), or a callable that resolves from request and state. `subject` is more restrictive: static `Subject` or a callable; per-tool mappings aren't supported there (the constructor rejects them). Use the callable form when the tenant comes from per-call agent state.

## CyclesFanOutGate: turn caps and remote policy halts

`CyclesFanOutGate` overrides `before_model` (decorated with `@hook_config(can_jump_to=["end"])`) to halt the agent before another model turn. Two ways to halt:

1. **Local turn cap**: when the number of model turns reaches `max_turns`.
2. **Remote policy**: when an optional `client.decide()` call returns DENY (e.g. a per-tenant burst budget is exhausted).

```python CyclesFanOutGate icon="repeat"
from langchain_runcycles import CyclesFanOutGate
from runcycles import Action, Subject

fanout_gate = CyclesFanOutGate(
    max_turns=20,
    client=client,                                              # optional remote check
    subject=Subject(tenant="acme"),
    action=Action(kind="model.turn", name="research"),
    cap_message="Stopped at {turns} of {max_turns} model turns.",
)
```

When the gate halts, it returns:

```python
{"messages": [AIMessage(content="...")], "jump_to": "end"}
```

…so the LangChain runtime exits the loop cleanly and returns the AIMessage to the user.

## Async support

For async agents, pass an `AsyncCyclesClient` and invoke the agent with `.ainvoke()`. The middleware automatically uses the async hooks: `awrap_model_call` on `CyclesModelGate`, `awrap_tool_call` on `CyclesToolGate`, and `abefore_model` on `CyclesFanOutGate`.

```python Async usage icon="bolt"
import os
from langchain.agents import create_agent
from langchain.tools import tool
from langchain_runcycles import CyclesToolGate
from runcycles import Action, AsyncCyclesClient, CyclesConfig, Subject

@tool
def send_email(to: str, body: str) -> str:
    """Send an email to a recipient."""
    return f"Sent to {to}"

async_client = AsyncCyclesClient(
    CyclesConfig(
        base_url=os.environ["CYCLES_BASE_URL"],
        api_key=os.environ["CYCLES_API_KEY"],
    )
)
gate = CyclesToolGate(
    async_client,
    subject=Subject(tenant="acme", agent="researcher"),
    action=Action(kind="tool.call", name="send_email"),
    mode="decide",
)

agent = create_agent(model="claude-sonnet-4-6", tools=[send_email], middleware=[gate])
await agent.ainvoke({"messages": [{"role": "user", "content": "Email alice@example.com."}]})
```

## Production notes

A few v0.1.x behaviors worth knowing before pointing the middleware at production traffic.

### Reserve mode commits at the configured `estimate`

In `"reserve"` and `"decide+reserve"` modes, the middleware reserves the configured `estimate`, runs the tool, then commits *that same amount* on success, not the tool's actual measured cost. Per-tool actual-cost instrumentation (analogous to `runcycles.stream_reservation`'s `cost_fn`) is on the roadmap. For now: set `estimate` to the worst-case spend per call you're willing to debit, or use `mode="decide"` if you only want policy gating without budget movement.

### Settlement-failure policy

<Note>
    Available in `langchain-runcycles` 0.1.2+.
</Note>

If `commit_reservation` itself fails after a successful tool run, the tool's side effect already happened. `settlement_error_policy` on `CyclesToolGate` controls what happens next:

| Policy | Behavior | When to choose |
| :--- | :--- | :--- |
| `"raise"` (default) | Propagate the commit exception. Tool result is lost; caller reconciles. | Strict governance: no tool-level cost goes unaccounted. |
| `"log"` | Log a warning, return the tool result. The reservation expires via TTL. | UX continuity matters more than per-call settlement guarantees. |

```python Settlement policy icon="scale"
from langchain_runcycles import CyclesToolGate
from runcycles import Action, Subject

gate = CyclesToolGate(
    client,
    subject=Subject(tenant="acme"),
    action=Action(kind="tool.call", name="send_email"),
    mode="reserve",
    settlement_error_policy="log",   # opt out of the strict default
)
```

<Tip>
    `"raise"` surfaces the commit failure as a tool exception, so a LangChain agent may retry. If the tool's side effect (an email send, a payment, a CRM write) is **not safely idempotent on retry**, choose `"log"` instead. Duplicate side effects are usually worse than a one-off accounting miss.
</Tip>

The release path (on tool-side exception) always logs and continues so the original tool exception wins; `settlement_error_policy` applies only to the success-path commit.

### Idempotency keys: deterministic per `tool_call_id`, optionally namespaced

Cycles idempotency keys take the shape `{prefix}-{tool_call_id}` (no random suffix), so a duplicate dispatch (durable workflow replay, middleware retry, process recovery) lands on the *same* reservation rather than creating a second one. If the upstream omits `tool_call_id`, a synthetic `missing-<hex>` id is fabricated and a warning is logged; that fallback path is *not* retry-stable. Conformant LangChain runtimes always supply `id`.

<Note>
    `idempotency_namespace` is available in `langchain-runcycles` 0.1.3+. The callable form's `None`-return per-call opt-out is fully type-correct in 0.1.4+.
</Note>

**Namespace scoping (v0.1.3+):** if your runtime reuses short tool-call ids across runs (`tc_1`, `tc_2`, ...), set `idempotency_namespace` to scope keys by run, workflow, or tenant. Key shape differs per class:

- `CyclesToolGate` is deterministic on the upstream `tool_call_id`: `{prefix}-{namespace}-{tool_call_id}` with a namespace, or `{prefix}-{tool_call_id}` without (the v0.1.2 shape, retained for back-compat).
- `CyclesModelGate` and `CyclesFanOutGate` don't have a stable upstream id (model and fan-out decisions are per-call), so the key uses a fresh UUID: `{prefix}-{namespace}-{uuid}` with a namespace, or `{prefix}-{uuid}` without. The namespace there scopes keys by run/tenant for observability and audit grouping; it doesn't make the key retry-stable.

Accepts a static string or a callable receiving the request (model / tool gate) or state (fan-out gate). A callable returning `None` opts out of namespacing for that call. Errors raised by the callable propagate to the agent (fail-fast on misconfiguration).

```python Idempotency namespace icon="layers-linked"
from langchain_runcycles import CyclesToolGate
from runcycles import Action, Subject

# Static: same namespace every call
gate = CyclesToolGate(
    client,
    subject=Subject(tenant="acme"),
    action=Action(kind="tool.call", name="send_email"),
    idempotency_namespace="run_2026_05_10_abc",
)

# Callable: receives the LangChain ToolCallRequest; pull the run id from
# request state, a contextvar, your own middleware, etc.
def my_run_id(request):
    return request.state["run_id"]

gate = CyclesToolGate(
    client,
    subject=Subject(tenant="acme"),
    action=Action(kind="tool.call", name="send_email"),
    idempotency_namespace=my_run_id,
)
```

### v0.1.x scope: architecture-complete, production polish in v0.2.0

Implemented (v0.1.5+): `wrap_model_call` (`CyclesModelGate`), `wrap_tool_call` (`CyclesToolGate`), and `before_model` (`CyclesFanOutGate`): all three hooks of the LangChain agent governance triad. `CyclesModelGate` and `CyclesToolGate` share the same three modes (`decide` / `reserve` / `decide+reserve`), reservation lifecycle, and `settlement_error_policy`. `CyclesFanOutGate` is a thinner halt-only middleware: it consults `decide()` per turn and counts turns against `max_turns`, but does not reserve, so it shares only the `idempotency_namespace` plumbing with the other two.

Deferred to v0.2.0: provider-specific token-cost extractors (OpenAI / Anthropic response metadata parsing), streaming-aware settlement, and a polished demo agent. Until then, `CyclesModelGate` commits at the configured `estimate`; for precise per-call token cost capture today, use the `BaseCallbackHandler` callback handler from `cycles-client-python` alongside this middleware (the two compose cleanly).
