Real-time governance and observability for [LangGraph](https://github.com/langchain-ai/langgraph) and [Deep Agents](https://github.com/langchain-ai/deepagents) applications. Learn more about [middleware](/oss/langchain/middleware/overview).

| Middleware | Description |
|------------|-------------|
| [LangGraph governance](#langgraph-governance) | Govern any LangGraph agent: policies, guardrails, HITL, OTel hook governance, and behavior rules |
| [Deep Agents governance](#deepagents-governance) | Govern Deep Agents applications with per-subagent policy targeting |

## LangGraph governance

Wrap any compiled LangGraph graph with OpenBox governance. Every tool call, LLM prompt, outbound HTTP request, database query, and file operation is evaluated against your policies before it executes, with no changes to your graph code.

Use this when you need:

- **Policy enforcement**: Block, require approval, or halt based on Rego rules you write
- **Guardrails**: Screen LLM prompts for PII, toxic content, or banned phrases before the model sees them
- **Human-in-the-loop (HITL)**: Pause agent execution for human approval of sensitive operations
- **OTel hook governance**: Per-operation governance on HTTP requests, DB queries, and file I/O made inside tools
- **Behavior Rules**: Detect patterns across tool call sequences within a session
- **Audit trail**: Every governance decision recorded in the OpenBox dashboard

<Info>
    OpenBox requires an account at [platform.openbox.ai](https://platform.openbox.ai/) and an API key (`obx_live_...`). Create an agent in the dashboard matching the `agent_name` you pass here; policies and behavior rules are configured per agent.
</Info>

**Package:** `openbox-langgraph-sdk-python`

```python
import os
import asyncio
from langgraph.prebuilt import create_react_agent
from langchain_openai import ChatOpenAI
from openbox_langgraph import create_openbox_graph_handler

llm = ChatOpenAI(model="gpt-4o-mini")
agent = create_react_agent(llm, tools=[search_web, export_data])

async def main():
    governed = create_openbox_graph_handler(
        graph=agent,
        api_url=os.environ["OPENBOX_URL"],
        api_key=os.environ["OPENBOX_API_KEY"],
        agent_name="MyAgent",
    )
    result = await governed.ainvoke(
        {"messages": [{"role": "user", "content": "Search for AI papers"}]},
        config={"configurable": {"thread_id": "session-001"}},
    )
    print(result["messages"][-1].content)

asyncio.run(main())
```

<Accordion title="Configuration options">

<ParamField body="graph" type="CompiledGraph" required>
    Your compiled LangGraph graph.
</ParamField>

<ParamField body="api_url" type="str" required>
    Base URL of your OpenBox Core instance.
</ParamField>

<ParamField body="api_key" type="str" required>
    API key from the OpenBox dashboard (`obx_live_*` or `obx_test_*`).
</ParamField>

<ParamField body="agent_name" type="str">
    Agent name as configured in the dashboard. Used as `workflow_type` on all governance events. **Must match exactly** for policies and Behavior Rules to fire.
</ParamField>

<ParamField body="validate" type="bool" default="True">
    Validate the API key against the server on startup.
</ParamField>

<ParamField body="on_api_error" type="str" default="fail_open">
    How to behave when OpenBox Core is unreachable. Options:

    - `'fail_open'`: Allow all tool calls if governance is unavailable
    - `'fail_closed'`: Block all tool calls if governance is unavailable
</ParamField>

<ParamField body="governance_timeout" type="float" default="30.0">
    HTTP timeout in seconds for governance calls.
</ParamField>

<ParamField body="hitl" type="dict" default="{}">
    Human-in-the-loop configuration. Keys:

    - `enabled` (bool): Enable HITL polling
    - `poll_interval_ms` (int): How often to poll for a decision, default `5000`
    - `skip_tool_types` (set[str]): Tools that never wait for HITL
</ParamField>

<ParamField body="tool_type_map" type="dict[str, str]" default="{}">
    Map tool names to semantic types (`"http"`, `"database"`, `"builtin"`, `"a2a"`, `"custom"`). Appends an `__openbox` sentinel to `activity_input` for Rego policy matching.
</ParamField>

<ParamField body="enable_telemetry" type="bool" default="True">
    Reserved. OTel hook governance is always active when API credentials are configured. Setting this to `False` has no effect.
</ParamField>

<ParamField body="sqlalchemy_engine" type="Engine" default="None">
    SQLAlchemy `Engine` to instrument for DB governance. Pass this when the engine is created **before** the handler; otherwise only engines created after handler initialization are instrumented.
</ParamField>

<ParamField body="resolve_subagent_name" type="Callable" default="None">
    Hook for framework-specific subagent name detection in multi-agent LangGraph systems. Receives the event and returns a subagent name string or `None`.
</ParamField>

<ParamField body="task_queue" type="str" default="langgraph">
    Task queue label attached to all governance events.
</ParamField>

<ParamField body="send_llm_start_event" type="bool" default="True">
    Send `LLMStarted` event before each model call. Required for prompt guardrails (PII redaction, content filtering).
</ParamField>

<ParamField body="skip_chain_types" type="set[str]" default="set()">
    Chain node names to suppress governance events for. Useful for skipping internal LangGraph plumbing nodes.
</ParamField>

<ParamField body="skip_tool_types" type="set[str]" default="set()">
    Tool names to exclude from governance entirely.
</ParamField>

<ParamField body="session_id" type="str">
    Optional session identifier attached to all governance events.
</ParamField>

</Accordion>

<Accordion title="OTel hook governance">

The SDK uses OpenTelemetry instrumentation to intercept low-level operations made inside your tools. This is Layer 2 of the three-layer governance architecture and runs automatically when `enable_telemetry=True`.

**HTTP hooks** intercept outbound requests via `httpx`, `requests`, `urllib3`, and `urllib`. Each request is evaluated at two stages:

- `started`: before the request is sent (can block)
- `completed`: after the response is received (captures status code, response body)

**Database hooks** intercept queries for all supported libraries:

| Library | Protocol |
|---------|----------|
| `psycopg2` | PostgreSQL |
| `asyncpg` | PostgreSQL (async) |
| `mysql-connector-python` | MySQL |
| `pymysql` | MySQL |
| `sqlite3` | SQLite |
| `pymongo` | MongoDB |
| `redis` | Redis |
| `sqlalchemy` | ORM (any backend) |

**File I/O hooks** intercept `builtins.open()` and `os.fdopen()`. System paths (`/dev/`, `/proc/`, `__pycache__`, `.pyc`) are automatically skipped.

**Custom function tracing** via the `@traced` decorator. Both `traced` and `create_span` are exported from `openbox_langgraph` — Deep Agents users should import from that package directly:

```python
from openbox_langgraph import traced, create_span

@traced
def process_data(input_data):
    return transform(input_data)

@traced(name="fetch-data", capture_args=True, capture_result=True)
async def fetch_data(url):
    return await http_get(url)

# Manual span creation
with create_span("my-operation", {"input": data}) as span:
    result = do_something()
    span.set_attribute("output", result)
```

All hook events include `hook_trigger: true` in the governance payload. **Always add `not input.hook_trigger`** to `BLOCK` and `REQUIRE_APPROVAL` Rego rules to prevent double-firing.

</Accordion>

<Accordion title="Full example">

```python
import os
import asyncio
from langgraph.prebuilt import create_react_agent
from langchain_openai import ChatOpenAI
from openbox_langgraph import (
    create_openbox_graph_handler,
    GovernanceBlockedError,
    GovernanceHaltError,
    GuardrailsValidationError,
    ApprovalRejectedError,
    ApprovalTimeoutError,
)

llm = ChatOpenAI(model="gpt-4o-mini")
agent = create_react_agent(llm, tools=[search_web, export_data, query_db])

async def main():
    governed = create_openbox_graph_handler(
        graph=agent,
        api_url=os.environ["OPENBOX_URL"],
        api_key=os.environ["OPENBOX_API_KEY"],
        agent_name="MyAgent",
        on_api_error="fail_closed",
        tool_type_map={
            "search_web": "http",
            "export_data": "http",
            "query_db": "database",
        },
        hitl={
            "enabled": True,
            "poll_interval_ms": 5_000,
        },
    )

    config = {"configurable": {"thread_id": "session-001"}}
    try:
        result = await governed.ainvoke(
            {"messages": [{"role": "user", "content": "Export the customer list to S3"}]},
            config=config,
        )
        print(result["messages"][-1].content)
    except GovernanceBlockedError as e:
        print(f"Blocked by policy: {e}")
    except GovernanceHaltError as e:
        print(f"Session halted: {e}")
    except GuardrailsValidationError as e:
        print(f"Guardrail triggered: {e}")
    except ApprovalRejectedError as e:
        print(f"Human rejected: {e}")
    except ApprovalTimeoutError as e:
        print(f"HITL timed out: {e}")

asyncio.run(main())
```

**Example Rego policy** (configured in the OpenBox dashboard):

```rego
package org.openboxai.policy

import future.keywords.if
import future.keywords.in

default result = {"decision": "CONTINUE", "reason": null}

restricted_terms := {"nuclear weapon", "bioweapon", "malware synthesis"}

# Block restricted search topics
result := {"decision": "BLOCK", "reason": "Restricted topic."} if {
    input.event_type == "ActivityStarted"
    input.activity_type == "search_web"
    not input.hook_trigger
    count(input.activity_input) > 0
    entry := input.activity_input[0]
    is_object(entry)
    some term in restricted_terms
    contains(lower(entry.query), term)
}

# Require approval for data exports
result := {"decision": "REQUIRE_APPROVAL", "reason": "Data export requires compliance sign-off."} if {
    input.event_type == "ActivityStarted"
    input.activity_type == "export_data"
    not input.hook_trigger
}
```

## Deep Agents governance

Extends OpenBox governance with three things Deep Agents specifically needs: **per-subagent policy targeting**, **HITL conflict detection** with Deep Agents' own `interrupt_on`, and **built-in `a2a` tool classification** for subagent dispatches via the `task` tool.

<Info>
    The Deep Agents middleware implements LangChain's `AgentMiddleware` interface directly, so no graph wrapper is needed. Pass it to `create_deep_agent(middleware=[...])`.
</Info>

**Package:** `openbox-deepagent-sdk-python`

```python
import os
import asyncio
from deepagents import create_deep_agent
from langchain.chat_models import init_chat_model
from openbox_deepagent import create_openbox_middleware

middleware = create_openbox_middleware(
    api_url=os.environ["OPENBOX_URL"],
    api_key=os.environ["OPENBOX_API_KEY"],
    agent_name="ResearchBot",
    known_subagents=["researcher", "analyst", "writer", "general-purpose"],
    tool_type_map={"search_web": "http", "export_data": "http"},
)

agent = create_deep_agent(
    model=init_chat_model("openai:gpt-4o-mini", temperature=0),
    tools=[search_web, write_report, export_data],
    subagents=[
        {"name": "researcher", "description": "Web research.",
         "system_prompt": "You are a research assistant.", "tools": [search_web]},
        {"name": "writer", "description": "Report drafting.",
         "system_prompt": "You are a professional writer.", "tools": [write_report]},
    ],
    middleware=[middleware],
)

async def main():
    result = await agent.ainvoke(
        {"messages": [{"role": "user", "content": "Research recent LangGraph papers"}]},
        config={"configurable": {"thread_id": "session-001"}},
    )
    print(result["messages"][-1].content)

asyncio.run(main())
```

<Accordion title="Configuration options">

The following LangGraph governance options are supported: `on_api_error`, `governance_timeout`, `agent_name`, `session_id`, `task_queue`, `tool_type_map`, `skip_tool_types`, `sqlalchemy_engine`, `send_chain_start_event`, `send_chain_end_event`, `send_llm_start_event`, `send_llm_end_event`, `send_tool_start_event`, `send_tool_end_event`. The following LangGraph options are **not** supported: `hitl`, `skip_chain_types`, `use_native_interrupt`, `root_node_names`, `resolve_subagent_name`, `enable_telemetry`. The following are additional or different for Deep Agents.

<ParamField body="known_subagents" type="list[str]" default='["general-purpose"]'>
    Subagent names from `create_deep_agent(subagents=[...])`. Always include `"general-purpose"` since it's Deep Agents' built-in fallback. The SDK warns on unknown `subagent_type` values at runtime.
</ParamField>

<ParamField body="send_tool_start_event" type="bool" default="True">
    Send a governance event before each tool call.
</ParamField>

<ParamField body="send_tool_end_event" type="bool" default="True">
    Send a governance event after each tool call.
</ParamField>

<ParamField body="sqlalchemy_engine" type="Engine" default="None">
    SQLAlchemy `Engine` to instrument for DB governance. Required when the engine is created before the middleware.
</ParamField>

</Accordion>

<Accordion title="Per-subagent policy targeting">

All subagent dispatches share `activity_type: "task"`. The SDK appends a `__openbox` sentinel to `activity_input` so your Rego policy can distinguish a `writer` dispatch from a `researcher` one:

```json
"activity_input": [
  {"description": "Write a report on AI safety", "subagent_type": "writer"},
  {"__openbox": {"tool_type": "a2a", "subagent_name": "writer"}}
]
```

**Target a specific subagent:**

```rego
package org.openboxai.policy

import future.keywords.if
import future.keywords.in

default result = {"decision": "CONTINUE", "reason": null}

result := {"decision": "REQUIRE_APPROVAL", "reason": "Writer tasks require approval."} if {
    input.event_type == "ActivityStarted"
    input.activity_type == "task"
    not input.hook_trigger
    some item in input.activity_input
    item["__openbox"].subagent_name == "writer"
}
```

</Accordion>

### Known limitations

**Subagent internals are invisible to governance.** Subagents execute inside the `task` tool body via `subagent.invoke()`. Their internal tool calls and LLM calls are not surfaced in the outer event stream. The `task` call is a single atomic governance unit.

- A `search_web` call made by the `researcher` subagent is not a separate `ToolStarted` event
- You cannot apply HITL to a tool call a subagent makes, only to the `task` dispatch itself

**Workaround:** Add the tool to the outer agent's tool list as well. Outer agent tool calls are fully governed.

**Behavior Rules count `task` dispatches, not subagent-internal tool calls.** A rule like "block if `search_web` exceeds 10 calls per session" only counts direct `search_web` calls from the outer agent. Subagent-internal HTTP calls are not captured as spans on the `task` `ToolCompleted`.

**Behavior Rules don't span `ainvoke` calls.** Each `ainvoke` is a separate governance session with a new `workflow_id`. Cross-turn pattern detection is not yet supported.

<Accordion title="Full example">

```python
import os
import asyncio
from deepagents import create_deep_agent
from langchain.chat_models import init_chat_model
from openbox_deepagent import (
    create_openbox_middleware,
    GovernanceBlockedError,
    GovernanceHaltError,
    GuardrailsValidationError,
    ApprovalRejectedError,
    ApprovalExpiredError,
)

middleware = create_openbox_middleware(
    api_url=os.environ["OPENBOX_URL"],
    api_key=os.environ["OPENBOX_API_KEY"],
    agent_name="ResearchBot",
    known_subagents=["researcher", "analyst", "writer", "general-purpose"],
    guard_interrupt_on_conflict=True,
    tool_type_map={
        "search_web": "http",
        "export_data": "http",
    },
    hitl={
        "enabled": True,
        "poll_interval_ms": 5_000,
    },
)

agent = create_deep_agent(
    model=init_chat_model("openai:gpt-4o-mini", temperature=0),
    tools=[search_web, write_report, export_data],
    subagents=[
        {
            "name": "researcher",
            "description": "Web research and summarization.",
            "system_prompt": "You are a research assistant.",
            "tools": [search_web],
        },
        {
            "name": "writer",
            "description": "Drafting reports.",
            "system_prompt": "You are a professional writer.",
            "tools": [write_report],
        },
    ],
    middleware=[middleware],
)

async def main():
    config = {"configurable": {"thread_id": "session-001"}}
    try:
        # Async (preferred)
        result = await agent.ainvoke({"messages": [...]}, config=config)
        # Sync also supported
        # result = agent.invoke({"messages": [...]}, config=config)
        print(result["messages"][-1].content)
    except GovernanceBlockedError as e:
        print(f"Blocked: {e}")
    except GovernanceHaltError as e:
        print(f"Session halted: {e}")
    except GuardrailsValidationError as e:
        print(f"Guardrail: {e}")
    except ApprovalRejectedError as e:
        print(f"Rejected by reviewer: {e}")
    except ApprovalExpiredError as e:
        print(f"HITL expired: {e}")

asyncio.run(main())
```
