**LangGraph v1.1 introduces type-safe streaming and invoke with `version="v2"`.** This opt-in flag gives you a unified, structured output format for `stream()`, `astream()`, `invoke()`, and `ainvoke()` — eliminating the need to handle different tuple shapes depending on your streaming options.

<CardGroup cols={1}>
    <Card title="Unified streaming format" icon="arrows-sort">
        Every stream chunk is a `StreamPart` dict with `type`, `ns`, and `data` keys — regardless of stream mode, subgraphs, or number of modes.
    </Card>
    <Card title="Type-safe invoke" icon="shield-check">
        `invoke()` with `version="v2"` returns a `GraphOutput` object with `.value` and `.interrupts` attributes, separating state from interrupt metadata.
    </Card>
    <Card title="Pydantic and dataclass coercion" icon="database">
        When your state is defined as a Pydantic model or dataclass, v2 streaming and invoke automatically coerce output values to the correct type.
    </Card>
    <Card title="Fully backwards compatible" icon="rotate-left">
        `version="v2"` is opt-in. The default behavior (`v1`) is unchanged, so existing code continues to work without modification.
    </Card>
</CardGroup>

## v2 streaming format

Pass `version="v2"` to `stream()` or `astream()` to get a unified output format. Every chunk is a `StreamPart` dictionary with a consistent shape:

```python
{
    "type": "values" | "updates" | "messages" | "custom" | "debug" | ...,
    "ns": (),           # namespace tuple, populated for subgraph events
    "data": ...,        # the actual payload (type varies by stream mode)
}
```

### Why v2?

With v1 streaming, the output format changes depending on your options:

```python
# v1: single mode — yields raw data
for chunk in graph.stream(inputs, stream_mode="updates"):
    # chunk is a dict like {"node_name": {"key": "value"}}

# v1: multiple modes — yields (mode, data) tuples
for mode, chunk in graph.stream(inputs, stream_mode=["updates", "custom"]):
    # now you need to unpack tuples

# v1: subgraphs — yields (namespace, data) tuples
for ns, chunk in graph.stream(inputs, stream_mode="updates", subgraphs=True):
    # different tuple shape again

# v1: multiple modes + subgraphs — yields (namespace, mode, data) triples
for ns, mode, chunk in graph.stream(
    inputs, stream_mode=["updates", "custom"], subgraphs=True
):
    # yet another shape
```

With v2, the format is always the same:

```python
# v2: always yields StreamPart dicts — same shape regardless of options
for chunk in graph.stream(inputs, stream_mode="updates", version="v2"):
    print(chunk["type"])  # "updates"
    print(chunk["ns"])    # ()
    print(chunk["data"])  # {"node_name": {"key": "value"}}

# Same shape with multiple modes
for chunk in graph.stream(
    inputs, stream_mode=["updates", "custom"], version="v2"
):
    print(chunk["type"])  # "updates" or "custom"
    print(chunk["data"])  # payload

# Same shape with subgraphs
for chunk in graph.stream(
    inputs, stream_mode="updates", subgraphs=True, version="v2"
):
    print(chunk["type"])  # "updates"
    print(chunk["ns"])    # () for root, ("node_name:task_id",) for subgraph
    print(chunk["data"])  # payload
```

### Type narrowing

Each stream mode has a corresponding `StreamPart` type that enables type narrowing:

```python
from langgraph.types import StreamPart

for chunk in graph.stream(inputs, stream_mode=["values", "updates"], version="v2"):
    if chunk["type"] == "values":
        # type checker knows chunk is ValuesStreamPart
        state = chunk["data"]        # full state dict (or Pydantic/dataclass instance)
        interrupts = chunk["interrupts"]  # tuple of Interrupt objects
    elif chunk["type"] == "updates":
        # type checker knows chunk is UpdatesStreamPart
        node_updates = chunk["data"]  # {"node_name": {"key": "value"}}
```

### Pydantic and dataclass state coercion

When your graph state is defined as a Pydantic model or dataclass, v2 automatically coerces `values` stream output to the correct type:

```python
from pydantic import BaseModel
from typing import Annotated
import operator

from langgraph.graph import StateGraph, START, END

class MyState(BaseModel):
    value: str
    items: Annotated[list[str], operator.add]

def my_node(state: MyState):
    return {"value": state.value + "_updated", "items": ["new"]}

graph = (
    StateGraph(MyState)
    .add_node(my_node)
    .add_edge(START, "my_node")
    .add_edge("my_node", END)
    .compile()
)

for chunk in graph.stream({"value": "x", "items": []}, stream_mode="values", version="v2"):
    # chunk["data"] is a MyState instance, not a plain dict
    print(type(chunk["data"]))  # <class 'MyState'>
    print(chunk["data"].value)  # "x_updated"
```

### Interrupt handling in v2 streams

With v1, interrupts are mixed into the state dict under the `__interrupt__` key. With v2, interrupts are surfaced in a dedicated `interrupts` field on `values` stream parts:

```python
from langgraph.types import interrupt

def approval_node(state):
    answer = interrupt("Do you approve?")
    return {"result": answer}
```

<CodeGroup>
```python v2 (new)
for chunk in graph.stream(
    inputs, config=config, stream_mode="values", version="v2"
):
    if chunk["interrupts"]:
        # Interrupts are in a dedicated typed field
        for intr in chunk["interrupts"]:
            print(intr.value)  # "Do you approve?"
    else:
        state = chunk["data"]
```
```python v1 (current default)
for chunk in graph.stream(
    inputs, config=config, stream_mode="values"
):
    if "__interrupt__" in chunk:
        # Interrupts are mixed into the state dict
        for intr in chunk["__interrupt__"]:
            print(intr.value)
    else:
        state = chunk
```
</CodeGroup>

## v2 invoke format

Pass `version="v2"` to `invoke()` or `ainvoke()` to get a `GraphOutput` object instead of a plain dict:

```python
from langgraph.types import GraphOutput

result = graph.invoke({"value": "x", "items": []}, version="v2")

# result is a GraphOutput with .value and .interrupts
print(result.value)       # {"value": "x_a_b", "items": ["a", "b"]}
print(result.interrupts)  # () — empty tuple when no interrupts
```

### Backwards-compatible dict access

`GraphOutput` supports dict-style access for backwards compatibility:

```python
result = graph.invoke(inputs, version="v2")

# Both work:
result.value["key"]   # attribute access (new)
result["key"]         # dict access (backwards compatible)
```

### Pydantic and dataclass state

With v2, `invoke()` automatically coerces the output value to match your state schema:

```python
from pydantic import BaseModel
from typing import Annotated
import operator
from langgraph.graph import StateGraph, START, END

class MyState(BaseModel):
    value: str
    items: Annotated[list[str], operator.add]

def my_node(state: MyState):
    return {"value": state.value + "_done", "items": ["result"]}

graph = (
    StateGraph(MyState)
    .add_node(my_node)
    .add_edge(START, "my_node")
    .add_edge("my_node", END)
    .compile()
)

result = graph.invoke({"value": "x", "items": []}, version="v2")
print(type(result.value))   # <class 'MyState'>
print(result.value.value)   # "x_done"
print(result.value.items)   # ["result"]
```

### Interrupt handling with v2 invoke

With v1, interrupts are embedded in the returned dict under `__interrupt__`. With v2, they are cleanly separated:

<CodeGroup>
```python v2 (new)
from langgraph.types import Command

config = {"configurable": {"thread_id": "thread-1"}}
result = graph.invoke({"input": "data"}, config=config, version="v2")

# Interrupts are on a dedicated attribute
if result.interrupts:
    print(result.interrupts[0].value)  # "Do you approve?"
    # Resume
    graph.invoke(Command(resume=True), config=config, version="v2")
```
```python v1 (current default)
config = {"configurable": {"thread_id": "thread-1"}}
result = graph.invoke({"input": "data"}, config=config)

# Interrupts are mixed into the state dict
if "__interrupt__" in result:
    print(result["__interrupt__"][0].value)
    # Resume
    graph.invoke(Command(resume=True), config=config)
```
</CodeGroup>
