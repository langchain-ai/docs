Migrate this codebase from `@langchain/mcp-adapters` 1.x to 2.0 (requires `@langchain/mcp-adapters` 2.0 or later, `@langchain/core` 1.2.6 or later, and `@langchain/langgraph` 1.4.13 or later, plus `@modelcontextprotocol/client` 2.2 or later wherever the code imports the MCP SDK).

Fetch and follow https://docs.langchain.com/oss/javascript/migrate/langchain-mcp-adapters.md as the source of truth.

Key changes:

1. **Client**: replace `MultiServerMCPClient` with `MCPAdapter`, and replace the `mcpServers` key (or a flat server map) with `servers`.
2. **Discovery**: replace `getTools(...)` with `listTools(...)` (same arguments; `getTools` still works but is deprecated) and `initializeConnections()` with `listToolsets()`. Read `adapter.config.servers` instead of `adapter.config.mcpServers`.
3. **Tool names**: with more than one server, tool names are now `{server}__{tool}`. Update code, prompts, and datasets that reference tool names by name, or set `prefixToolNameWithServerName: false` to keep 1.x names. `listTools()` throws an `MCPClientError` when two tools still share a name.
4. **SDK imports**: replace imports from `@modelcontextprotocol/sdk` with `@modelcontextprotocol/client`.
5. **Removed options**: delete `useStandardContentBlocks`, `onRootsListChanged`, `onCancelled`, and stdio `encoding`.
6. **Callbacks**: move `onMessage`, `onProgress`, `onInitialized`, `onPromptsListChanged`, `onResourcesListChanged`, `onResourcesUpdated`, and `onToolsListChanged` from the top level into each server's definition.
7. **Legacy-only options**: add `mode: "legacy"` to every server that sets `onInitialized`, `automaticSSEFallback`, `reconnect`, or `onElicitation`, or that needs a dropped HTTP stream resumed. Do not set `mode: "modern"`, `elicitation`, or `logLevel` on an SSE server.
8. **Errors**: replace `error.name` comparisons with `isToolException(error)` and `MCPClientError.isInstance(error)`. A server-reported error (`isError`) in a tool call now returns an error `ToolMessage` instead of throwing, so retry middleware and `handleToolErrors` no longer see it.
9. **Content**: read image and audio blocks through `data` and `mimeType` instead of `image_url` data URLs or `mime_type`, and read `mimeType` instead of `mime_type` on `resource_link` file blocks. Read `structuredContent` and `_meta` from the `mcp_structured_content` and `mcp_meta` artifact entries instead of the tool's content. Narrow `readResource()` results with `"text" in content` or `"blob" in content`.
10. **Authentication**: a provider token now replaces a configured `Authorization` header. Complete OAuth redirects with the SDK's `transport.finishAuth(params)`, because the adapter has no `finishAuth`.
11. **Elicitation**: modern servers can now pause a run with a LangGraph interrupt. Resume with `createMCPElicitationResume(interrupt, responses)`, or set `elicitation: false` on a server to opt out. With `toolRetryMiddleware`, upgrade `langchain` to 1.5.15 or later.
12. **Logging**: `DEBUG=@langchain/mcp-adapters:*` prints nothing. Use `onConnectionError` and per-server callbacks.

Search the codebase for `MultiServerMCPClient`, `mcpServers`, `getTools`, `initializeConnections`, `@modelcontextprotocol/sdk`, `useStandardContentBlocks`, `onRootsListChanged`, `onCancelled`, `encoding`, `image_url`, `mime_type`, `structuredContent`, `error.name`, `setLoggingLevel`, and top-level callback options, and apply the necessary changes. Flag anything that cannot be migrated automatically.
</Prompt>

`@langchain/mcp-adapters` 2.0 rebuilds the adapter on the MCP TypeScript SDK 2 client. It negotiates the MCP protocol era for each server and answers modern MCP elicitation with LangGraph interrupts. This guide covers the changes that affect 1.x code. For the feature documentation, see [Model Context Protocol (MCP)](/oss/langchain/mcp).

## Breaking changes

- **Several servers prefix tool names by default.** With more than one server, tools are named `{server}__{tool}` (for example `weather__get_forecast`) unless you set `prefixToolNameWithServerName`; 1.x defaulted it to `false`. A single server keeps its raw names. Set `prefixToolNameWithServerName: false` to keep 1.x names.
- **Duplicate tool names throw.** `listTools()` throws an `MCPClientError` when a name appears more than once in the flattened list; 1.x returned every copy. This happens across servers only with `prefixToolNameWithServerName: false`. When one server lists a tool twice, fix the server or pick tools from `listToolsets()`.
- **Elicitation pauses runs by default.** When a modern server asks for input during a tool call, the adapter raises a LangGraph @[`interrupt`] and the run stops until you resume it with `createMCPElicitationResume`. A checkpointer is needed only when a tool elicits. Set `elicitation: false` on a server to keep the 1.x behavior. See [Elicitation](#elicitation).
- **Tool content is always standard content blocks.** 1.x defaulted `useStandardContentBlocks` to `false`. 2.0 removes the option, rejects it, and always returns standard blocks, so images and audio carry `data` and `mimeType` instead of `image_url` data URLs. See [Tool results](#tool-results).
- **Configuration is strict.** Unknown keys and removed options throw when the adapter is constructed. See [Removed options](#removed-options).
- **Server-reported tool errors no longer throw in agents.** A result with `isError` comes back as a `ToolMessage` with `status: "error"` when the tool is called with a tool call, so `toolRetryMiddleware` and `handleToolErrors` no longer see it. See [Tool results](#tool-results).
- **The model no longer sees `structuredContent` or `_meta` next to a single text block.** 1.x serialized them into the content; 2.0 sends only the text and moves them to the artifact's `mcp_structured_content` and `mcp_meta` entries. See [Tool results](#tool-results).

## Install

Upgrade the adapter and its peer dependencies:

<CodeGroup>
```bash npm
npm install @langchain/mcp-adapters@^2.0.0 @langchain/core @langchain/langgraph
```
```bash pnpm
pnpm add @langchain/mcp-adapters@^2.0.0 @langchain/core @langchain/langgraph
```
```bash yarn
yarn add @langchain/mcp-adapters@^2.0.0 @langchain/core @langchain/langgraph
```
```bash bun
bun add @langchain/mcp-adapters@^2.0.0 @langchain/core @langchain/langgraph
```
</CodeGroup>

- **Peer dependencies**: The adapter requires `@langchain/core` 1.2.6 or later (was 1.0.0) and `@langchain/langgraph` 1.4.13 or later (was 1.4.10).
- **MCP SDK**: The adapter depends on `@modelcontextprotocol/client` 2.2 or later instead of `@modelcontextprotocol/sdk`. Replace imports from `@modelcontextprotocol/sdk` with `@modelcontextprotocol/client`. Add it as a direct dependency only if your code imports it, for example to build a client for `loadMcpTools` or to [complete an OAuth redirect](/oss/langchain/mcp/auth#complete-the-redirect).
- **Auth exports**: The adapter re-exports the `AuthProvider` and `OAuthClientProvider` types and the `UnauthorizedError` class.
- **Zod 4**: The adapter validates configuration with an internal Zod 4 dependency, so configuration errors are Zod 4 errors.
- **Debug logging**: The `debug` dependency is gone, so `DEBUG=@langchain/mcp-adapters:*` prints nothing. Use `onConnectionError` and the per-server notification callbacks instead.

## Renamed APIs

Before:

```typescript
import { MultiServerMCPClient } from "@langchain/mcp-adapters";

const client = new MultiServerMCPClient({
  mcpServers: {
    math: { command: "node", args: ["./math-server.js"] },
  },
});
const tools = await client.getTools();
```

After:

```typescript
import { MCPAdapter } from "@langchain/mcp-adapters";

const adapter = new MCPAdapter({
  servers: {
    math: { command: "node", args: ["./math-server.js"] },
  },
});
const tools = await adapter.listTools();
```

| 1.x | 2.0 |
| --- | --- |
| `MultiServerMCPClient` | `MCPAdapter` (deprecated alias kept) |
| `mcpServers` or a flat server map | `servers` (deprecated alias kept; passing both throws) |
| `getTools(...)` | `listTools(...)`, same arguments (deprecated alias kept) |
| `initializeConnections()` | `listToolsets()`, tools grouped by server (deprecated alias kept) |
| `ClientConfig` type | `MCPAdapterConfig` (deprecated alias kept) |

Other API changes:

- `adapter.config.servers` replaces `adapter.config.mcpServers`, typed `ResolvedMCPAdapterConfig`.
- `SSEConnection` accepts only legacy SSE. Use `StreamableHTTPConnection` for HTTP, or `Connection` for any transport.
- Check errors with `isToolException(error)` or `MCPClientError.isInstance(error)` instead of comparing `error.name`.
- `setLoggingLevel()` works on legacy servers only. Set a per-server `logLevel` on a modern server.

`getClient()`, `listResources()`, `listResourceTemplates()`, `readResource()`, and `close()` keep their names. `getClient()` returns the SDK `Client` from `@modelcontextprotocol/client`, which you can use for prompts. `loadMcpTools(serverName, client)` still converts tools from a client you build yourself.

## Removed options

A configuration that sets any of these options now fails validation:

| Option | Replacement |
| --- | --- |
| `useStandardContentBlocks` | None. Tool content is always standard LangChain content blocks. Delete the option. |
| `onRootsListChanged` | None. Roots notifications come from clients, so the observer never received one. |
| `onCancelled` | None. The SDK cannot report cancellations without replacing its own handler, and replacing it stopped the SDK from aborting the cancelled request. |
| Stdio `encoding` | None. SDK 2 stdio does not support it. |
| Top-level notification callbacks | Set them on each server. See [Move callbacks onto servers](#move-callbacks-onto-servers). |

## Configuration

### Move callbacks onto servers

Notification and progress callbacks move from the top level into the server that should receive them. This applies to `onMessage`, `onProgress`, `onInitialized`, `onPromptsListChanged`, `onResourcesListChanged`, `onResourcesUpdated`, and `onToolsListChanged`.

Before:

```typescript
const client = new MultiServerMCPClient({
  mcpServers: {
    everything: {
      command: "npx",
      args: ["-y", "@modelcontextprotocol/server-everything"],
    },
  },
  onProgress: (progress, source) => {
    console.log(source.type, progress.progress, progress.total);
  },
});
```

After:

```typescript
const adapter = new MCPAdapter({
  servers: {
    everything: {
      command: "npx",
      args: ["-y", "@modelcontextprotocol/server-everything"],
      onProgress: (progress, source) => {
        console.log(source.type, progress.progress, progress.total);
      },
    },
  },
});
```

Tool hooks (`beforeToolCall`, `afterToolCall`), `prefixToolNameWithServerName`, `additionalToolNamePrefix`, `outputHandling`, `defaultToolTimeout`, `throwOnLoadError`, and `onConnectionError` stay adapter options.

### Set a protocol mode

Each server now takes a `mode` of `"auto"` (the default), `"modern"`, or `"legacy"`, and negotiates independently. For what each mode does, see [Protocol eras](/oss/langchain/mcp/connections#protocol-eras).

In `"auto"` mode, the adapter probes each server before it connects. A legacy server that rejects the probe falls back to the legacy protocol at once. One that ignores the probe falls back only after the request timeout (60 seconds by default), and over HTTP a probe that times out or fails with a 403 or 5xx fails the connection. Set `mode: "legacy"` to skip the probe for those servers.

These options require `mode: "legacy"` on the server that sets them:

- `onInitialized`
- `automaticSSEFallback`
- `reconnect`
- `onElicitation`

A 1.x server that sets `automaticSSEFallback` or `reconnect` now fails validation until you add `mode: "legacy"`:

```typescript
const adapter = new MCPAdapter({
  servers: {
    legacy: {
      url: "https://legacy.example.com/sse",
      transport: "sse",
      mode: "legacy", // [!code ++]
      reconnect: { enabled: true, maxAttempts: 3, delayMs: 1000 },
    },
  },
});
```

Streamable HTTP streams resume only in legacy mode. In `"auto"` and `"modern"` mode, `maxRetries` is 0, so a dropped stream is not resumed; 1.x resumed it by default. Add `mode: "legacy"` to keep resumption, and `reconnect` to tune it.

SSE always speaks the legacy protocol, so an SSE server rejects `mode: "modern"`, `elicitation`, and `logLevel`. In `"auto"` mode, only an HTTP 404 or 405 falls back to SSE. `mode: "legacy"` keeps the 1.x fallback on any 4xx response. Authentication and network failures stay errors.

### Expect stricter validation

- **Unknown and conflicting keys**: Unknown keys, conflicting `type` and `transport` values, and an empty server map throw.
- **Retry settings**: In stdio `restart` and legacy `reconnect`, `maxAttempts` must be a nonnegative integer and `delayMs` must be nonnegative.
- **Tool schemas**: Tool input schemas keep the server's JSON Schema, with no automatic simplification.
- **Hooks**: In `beforeToolCall` and `afterToolCall`, `state` is typed `unknown`, so narrow it before use. Argument overrides must be objects.

## Authentication

- **Two provider shapes**: `authProvider` accepts an `AuthProvider` (`{ token, onUnauthorized? }`) as well as an `OAuthClientProvider`. 1.x accepted only OAuth providers.
- **Header precedence**: Once a provider has a token, it replaces a configured `Authorization` header. 1.x sent the configured header instead. The two values are no longer joined into one header.
- **OAuth callback**: Complete a redirect with the SDK's `transport.finishAuth(params)`, using a provider with the same storage. The adapter has no `finishAuth`.
- **Provider methods**: Implement `invalidateCredentials()`, plus `saveDiscoveryState()` and `discoveryState()` persisted alongside the code verifier.
- **Errors**: A discovery that fails on authentication throws an `MCPClientError` whose `cause` is `UnauthorizedError` (a login is needed, or a token provider has no `onUnauthorized`) or an HTTP 401 `SdkHttpError` (the credentials are still rejected).
- **Retries**: A server that failed on authentication is retried on the next discovery, even with `onConnectionError: "ignore"`. In 1.x, a skipped server was never retried.
- **Overrides**: Connections and catalogs are keyed by headers and provider object, so recreate the adapter when the account behind a provider object changes. An `authProvider` or `headers` in a method's options applies to every HTTP and SSE server.

For the full guide, see [Authentication](/oss/langchain/mcp/auth).

## Elicitation

Elicitation is new in 2.0: 1.x had no elicitation support. When a server negotiates the modern protocol, the adapter raises each elicitation request as a LangGraph @[`interrupt`] by default. A tool that requests input now pauses the run.

- **Checkpointer**: A checkpointer is needed only when a tool actually elicits. Without one, the tool call fails with a `ToolException` that explains how to answer.
- **Interrupt payload**: Each interrupt's `value` is an `MCPElicitationInterrupt` with `type: "mcp_elicitation"`, the configured `server` name, the MCP `tool` name without any prefix, the effective `arguments`, and `requests`. `requests` is a record keyed by the server's request key. Each entry is a form request (`message` and `requestedSchema`) or a URL request (`mode: "url"`, `message`, and `url`). The Python adapter's payload has `tool_name` and a list of requests instead, and its resume carries no interrupt ID, so a UI that serves both needs to handle each shape.
- **Resume**: Answer every key in `requests` with `{ action, content? }`, where `action` is `"accept"`, `"decline"`, or `"cancel"`. `createMCPElicitationResume(interrupt, responses)` returns `{ [interrupt.id]: { responses } }`, so each pending interrupt is answered by its ID. A missing or extra key, or content that doesn't match `requestedSchema`, fails the tool call.
- **Retry middleware**: Under `toolRetryMiddleware`, elicitation needs `langchain` 1.5.15 or later. Earlier versions treat the interrupt as a tool failure.
- **Opt out**: Set `elicitation: false` on an individual modern server. A top-level `elicitation` option is rejected.
- **Replays**: A resume replays the tool call from its first round, so N questions cost O(N²) requests. `beforeToolCall` runs on every replay, and the adapter promises no exactly-once effects. Keep servers and hooks replay-safe.
- **Legacy servers**: Set an `onElicitation` handler on a server with `mode: "legacy"`. This handler is also new in 2.0.

```typescript
import { Command } from "@langchain/langgraph";
import {
  createMCPElicitationResume,
  type MCPElicitationInterrupt,
} from "@langchain/mcp-adapters";

const paused = await agent.invoke(
  { messages: [{ role: "user", content: "Book a table for 4." }] },
  config
);
const [pending] = paused.__interrupt__ ?? [];
const { server, tool, requests } = pending.value as MCPElicitationInterrupt;
const [requestKey] = Object.keys(requests);
console.log(`${server}/${tool}: ${requests[requestKey].message}`);

const resume = createMCPElicitationResume(pending, {
  [requestKey]: { action: "accept", content: { date: "2026-09-14" } },
});
await agent.invoke(new Command({ resume }), config);
```

For the full example, see [Elicitation](/oss/langchain/mcp/tools#elicitation).

### Sampling and roots

Only elicitation is answered through interrupts. When a modern server asks for [sampling](https://modelcontextprotocol.io/specification/2025-06-18/client/sampling) or [roots](https://modelcontextprotocol.io/specification/2025-06-18/client/roots) during a tool call, the adapter refuses the request. The tool call fails with a `ToolException` that names the request, instead of waiting for an answer.

## Tool results

- **Standard content blocks**: Tool content is always standard LangChain content blocks. Images and audio expose `data` and `mimeType`. By default, 1.x produced `image_url` blocks with data URLs, and audio blocks with `mime_type`.
- **Artifacts**: Blocks routed to the artifact keep their MCP format, including in `afterToolCall`. The artifact array also carries `mcp_structured_content`, `mcp_meta`, and `mcp_content` provenance entries.
- **Embedded resources**: Converting a result no longer fetches embedded resource URIs, which 1.x fetched eagerly. Call `readResource()` when you need a resource's contents.
- **Resource links**: A `resource_link` block becomes `{ type: "file", url, mimeType, metadata }`, with the link's `uri`, `name`, and `title` in `metadata`, and the artifact keeps the original block as an `mcp_content` entry. 1.x produced `{ type: "file", source_type: "url", url, mime_type }`, so read `mimeType` instead of `mime_type`.
- **Tool errors**: Called with a tool call, as `createAgent` and `ToolNode` do, a result with `isError` returns a `ToolMessage` with `status: "error"`, the call's name and ID, and the server's content, instead of throwing. The server's text always reaches the model, even when `outputHandling` routes text to the artifact, and an error without text gets a one-line placeholder. Called directly with plain arguments, the tool still throws a `ToolException`, which now carries the MCP result in `result`.
- **Error middleware**: Because a server-reported error no longer throws, `toolRetryMiddleware` no longer retries it and a `handleToolErrors` handler no longer sees it.
- **Other failures**: Transport, validation, and elicitation failures still throw a `ToolException`. Under `createAgent`, the model sees each one as an error message and the run continues. The exception fails the run only when a `wrapToolCall` middleware lets it through.
- **Hook results**: A `ToolMessage` or `Command` returned from `afterToolCall` is returned as-is. 1.x flattened a `ToolMessage` to its content blocks and failed on a `Command`.
- **Resource reads**: `readResource()` preserves SDK content metadata. Narrow each item with `"text" in content` or `"blob" in content`.
- **Output schemas**: Each call forwards the discovered tool descriptor. The final result of an eliciting tool is validated against its `outputSchema`.
- **Structured content**: A result with a single text block becomes a string `content`, even when it carries `structuredContent` or `_meta`. 1.x serialized the block with both into the content, so the model saw them. Read them from the `mcp_structured_content` and `mcp_meta` artifact entries.
- **Unchanged**: Tool metadata is still `{ annotations }`, so read hints such as `destructiveHint` from `tool.metadata.annotations`. 2.0 adds no `metadata.mcp` namespace.

## Lifecycle

- **Grouped discovery**: `listToolsets()` returns a map from server name to tools, and `listTools()` flattens it.
- **Reusable close**: `close()` aborts in-flight work, closes clients, and clears caches and failed servers. The adapter stays usable: a later discovery builds fresh clients.
- **Discovery cache**: `listTools([], { cacheMode: "refresh" })` or `"bypass"` controls the SDK discovery cache. A failed refresh keeps the previous catalog.
- **Resource listing**: `listResources()` and `listResourceTemplates()` now throw a server's error, where 1.x logged every error and returned `[]`. A server without resource templates still lists them as `[]`.
- **Reconnect failures**: A background reconnection that exhausts its attempts now reports to an `onConnectionError` function instead of failing silently.
