Deep agents can handle long-running task by making use of effective context management.

Agents have access to several kinds of context, some sources of context are provided to the agent at startup, some sources become available to the agent during runtime, such as user input.

In the following page, you will gain an overview of the different kinds of context your deep agent has access to an manages.

## Input context

Input context consists of sources of information provided to your deep agent at startup.
The following inputs shape the agent's behavior, capabilities, and knowledge base before it begins processing user requests:

- [Prompts](#prompts)
- [Memory](#memory)
- [Long-term memory](#long-term-memory)
- [Skills](#skills)

### Prompts

Deep agents use system prompts to define the agent's role, behavior, and instructions.
If you provide a custom system prompt, this gets appended to the built-in system prompt which includes detailed guidance for using built-in tools like the planning tool, filesystem tools, and subagents.

Middleware that adds tools (such as the filesystem middleware) automatically appends tool-specific instructions to the system prompt, creating tool prompts that explain how to use those tools effectively.

For more information, see [System prompt](/oss/deepagents/customization#system-prompt).

### Memory

Memory files (`AGENTS.md`) are files you can provide to deep agents which provide persistent context that is always loaded at session start.
These files generally contain general coding style, preferences, conventions, and guidelines that help the agent understand how to work with your codebase and follow your preferences.

You can provide memory files at both global and project levels:

- **Global memory**: Stored in `~/.deepagents/<agent_name>/AGENTS.md` and loaded for all sessions
- **Project memory**: Stored in `.deepagents/AGENTS.md` at the project root and loaded when working within that project

Both global and project-level memory files are loaded together and appended to the system prompt at startup.
The agent can update these files based on your interactions, feedback, and identified patterns.

Memory files can also contain references to other files you wish the deep agent to be aware of.
The deep agent can then read these additional files when they become relevant.

For more information, see [Memory](/oss/deepagents/customization#memory).

### Long-term memory

When using the default filesystem, your deep agent stores its working memory files in agent state, which only persists within a single thread.
Long-term memory enables your deep agent to persist information across different threads and conversations.
To use long-term memory, you must use a `CompositeBackend` that routes specific paths (typically `/memories/`) to a LangGraph Store, which provides durable cross-thread persistence.
The `CompositeBackend` is a hybrid storage system where some files persist indefinitely while others remain ephemeral to a single thread.

Files that the agent stores in the long-term memory path (for example, `/memories/preferences.txt`) survive agent restarts and can be accessed from any conversation thread.
Deep agents can use these files for storing user preferences, accumulated knowledge, research progress, or any information that should persist beyond a single session.

For more information, see [Long-term memory](/oss/deepagents/long-term-memory).

### Skills

Skills are reusable agent capabilities that provide specialized workflows and domain knowledge.
Unlike tools, which cover lower-level functionality, skills contain detailed instructions, reference information, scripts, and assets like templates that help the agent complete specific tasks.

Skills make use of progressive disclosure, which means at startup the agent only reads the skill's frontmatter.
The deep agent uses the information from the frontmatter to determine if the skill is relevant to the current task.
If a skill becomes relevant, the agent then reviews the full skill file.

For more information, see [Skills](/oss/deepagents/skills).

## Runtime context

Deep agents use a pattern called context compression which works by reducing the size of the information in an agent's working memory while preserving the details that are relevant to the task.
The following techniques are the built-in features to ensure the context passed to LLMs stays within its context window limit:

- [offloading large tool inputs and results](#offloading-large-tool-inputs-and-results)
- [summarization](#summarization)

### Offloading large tool inputs and results

Deep agents use built-in filesystem tools to access and manipulate files on a virtual filesystem.
These tools allow deep agents to perform actions such as listing files (`ls`), reading files (`read_file`), creating files (`write_file`), editing files (`edit_file`), finding files with matching a pattern (`glob`), and finding and replacing patterns in files (`grep`).

The suite of filesystem tools allow deep agents to automatically offload content and to search and retrieve that offloaded content as needed.
Content offloading happens in two cases:

1. **The inputs for a tool cross a certain threshold**: File write and edit operations leave behind tool calls containing the complete file content in the agent's conversation history.
    Since this content is already persisted to the filesystem, it's often redundant.
    As the session context crosses 85% of the model’s available window, Deep agents will truncate older tool calls, replacing them with a pointer to the file on disk and reducing the size of the active context.

    ![An example of offloading showing a large input which is saved to disk and the truncated version is used for the tool call](/oss/images/deepagents/offloading-inputs.png)

2. **The results of tool calls exceed 20,000 tokens**: When the results exceed the defined threshold, the deep agent offloads the response to the filesystem and substitutes it with a file path reference and a preview of the first 10 lines. Agents can then re-read or search the content as needed.

    ![An example of offloading showing a large tool response that is replacd with a message about the location of the offloaded results an dhte first 10 lines of the result](/oss/images/deepagents/offloading-results.png)

### Summarization

When the context size crosses certain thresholds based on the model's context window size, and there is no more context eligible for offloading, the deep agent summarizes the message history.

This process has two components:

- **In-context summary**: An LLM generates a structured summary of the conversation—including session intent, artifacts created, and next steps—which replaces the full conversation history in the agent's working memory.
- **Filesystem preservation**: The complete, original conversation messages are written to the filesystem as a canonical record.

This dual approach ensures the agent maintains awareness of its goals and progress (via the summary) while preserving the ability to recover specific details when needed (via filesystem search).

![An example of summarization showing an agents conversation history, where several steps get compacted](/oss/images/deepagents/summarization.png)
