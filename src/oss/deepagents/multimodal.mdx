Deep Agents supports multimodal workflows when you use a [chat model](/oss/langchain/models#multimodal) that accepts multimodal inputs and tool results. You can attach images and other media to user messages, read non-text files with the built-in `read_file` tool, and return multimodal content from custom tools.

Built-in [context compression](/oss/deepagents/context-engineering#context-compression) is primarily text-oriented. Plan multimodal workloads accordingly: store large media in a backend and pass references when possible.

## Multimodal user input

Pass multimodal content in the `messages` you send to the agent, using the same [standard content blocks](/oss/langchain/messages#standard-content-blocks) as LangChain chat models:

:::python
```python
result = agent.invoke({
    "messages": [{
        "role": "user",
        "content": [
            {"type": "text", "text": "What is in this screenshot?"},
            {"type": "image", "url": "https://example.com/screenshot.png"},
        ],
    }],
})
```
:::

:::js
```typescript
const result = await agent.invoke({
  messages: [{
    role: "user",
    content: [
      { type: "text", text: "What is in this screenshot?" },
      { type: "image", url: "https://example.com/screenshot.png" },
    ],
  }],
});
```
:::

For block types, provider-specific requirements, and additional examples (PDF, audio, video), see [Multimodal messages](/oss/langchain/messages#multimodal).

## Built-in `read_file` tool

The harness `read_file` tool returns [standard content blocks](/oss/langchain/messages#standard-content-blocks) for supported multimodal files instead of plain text. The agent can inspect images, documents, and media stored in its [virtual filesystem](/oss/deepagents/overview#virtual-filesystem-access) when the selected model supports the corresponding modality. Check the [provider integration page](/oss/integrations/providers) for your model's supported MIME types.

<Accordion title="Supported multimodal file extensions">

| Type | Extensions |
| ---- | ---------- |
| [Image](/oss/langchain/messages#multimodal) | `.png`, `.jpg`, `.jpeg`, `.gif`, `.webp`, `.heic`, `.heif` |
| [Video](/oss/langchain/messages#multimodal) | `.mp4`, `.mpeg`, `.mov`, `.avi`, `.flv`, `.mpg`, `.webm`, `.wmv`, `.3gpp` |
| [Audio](/oss/langchain/messages#multimodal) | `.wav`, `.mp3`, `.aiff`, `.aac`, `.ogg`, `.flac` |
| [File](/oss/langchain/messages#multimodal) | `.pdf`, `.ppt`, `.pptx` |

</Accordion>

For text files, `read_file` returns line-numbered text. For large text results, see [context offloading](/oss/deepagents/context-engineering#offloading).

## Custom tool outputs

Custom tools are not limited to plain text. When the model supports multimodal tool results, a tool can return:

- **Text only**: a string or a single text content block.
- **Text plus media**: a list of content blocks, such as a caption followed by an image.
- **Interleaved blocks**: any ordered mix of text, image, file, audio, or video blocks the model accepts.

:::python
```python
from langchain.tools import tool


@tool
def capture_screenshot() -> list[dict]:
    """Capture a screenshot of the current page."""
    return [
        {"type": "text", "text": "Screenshot of the current page:"},
        {"type": "image", "url": "https://example.com/page.png"},
    ]
```
:::

:::js
```typescript
import { tool } from "langchain";
import { z } from "zod";

const captureScreenshot = tool(
  async () => [
    { type: "text", text: "Screenshot of the current page:" },
    { type: "image", url: "https://example.com/page.png" },
  ],
  {
    name: "capture_screenshot",
    description: "Capture a screenshot of the current page.",
    schema: z.object({}),
  }
);
```
:::

The return value is converted to a `ToolMessage` the model reads on the next turn. Access the normalized representation with `content_blocks` on the resulting message. For return-type options, serialization behavior, and MCP examples, see [Tool return values](/oss/langchain/tools#tool-return-values) and [Multimodal tool content](/oss/langchain/mcp#multimodal-tool-content).

<Tip>
When a tool produces images or other large binary data, save the artifact to a [backend](/oss/deepagents/backends) and return a concise text description plus a path or URL. This keeps message history smaller and works better with [context compression](/oss/deepagents/context-engineering#context-compression).
</Tip>

## Context compression and multimodal content

Built-in offloading and summarization are optimized for text and message history:

- **Offloading** measures text tokens only. Non-text blocks (including images) are preserved in replacement messages rather than compressed. A message that contains only an image is not offloaded based on image size alone.
- **Summarization** replaces older messages with a text summary. Images in the summarized partition are no longer sent as active image blocks after summarization.

For multimodal-heavy workloads:

- Store images, screenshots, and charts in a filesystem backend or external object store, then pass file paths or URLs through messages.
- Prefer references over base64-encoded image blocks in long-running conversations.
- Use [subagents](/oss/deepagents/subagents) for image-heavy inspection so the main agent receives a compact text result.
- Tune summarization thresholds or provide a custom token counter when your provider charges many tokens for images.

See [Context compression](/oss/deepagents/context-engineering#context-compression) for offloading thresholds, summarization triggers, and customization options.
