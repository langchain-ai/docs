A [task](/oss/langgraph/functional-api#task) is a discrete unit of work whose result can be [checkpointed](/oss/langgraph/persistence) on its own. When an [entrypoint](/oss/langgraph/functional-api#entrypoint) or a [Graph API node](/oss/langgraph/graph-api#using-tasks-in-nodes) runs several operations, wrap each operation in a task instead of putting all the work in one function body. With a checkpointer, completed task results are saved, so a resumed thread can skip finished work and continue from the next task.

This page covers retries, timeouts, caching, and error recovery on tasks. For concepts, see the [Functional API overview](/oss/langgraph/functional-api). For an ordered build path, see the [Build checklist for the Functional API](/oss/langgraph/use-functional-api). For the shared retry and timeout lifecycle, see [Fault tolerance](/oss/langgraph/fault-tolerance).

## Set a timeout

Cap how long a single async attempt can run. If a retry policy retries the timeout error, the timer resets on the next attempt.

:::python
Pass `timeout` on `@task` or `@entrypoint` in seconds or as a `datetime.timedelta`. Timeouts apply only to async tasks and entrypoints. Setting `timeout` on a sync function raises an error at declaration.

The first attempt sleeps past the timeout and raises @[`NodeTimeoutError`], which subclasses `TimeoutError`. The retry policy retries that error. The second attempt returns immediately.

<LanggraphFunctionalApiTasksTimeoutPy />
:::

:::js
Pass `timeout` on `task` or `entrypoint` in milliseconds, or as `{ idleTimeout: 30_000 }`. Use `isNodeTimeoutError` to narrow timeout errors. `NodeTimeoutError` is retryable when a retry policy is set.

The first attempt sleeps past the timeout. The retry policy retries. The second attempt returns immediately.

<LanggraphFunctionalApiTasksTimeoutJs />
:::
