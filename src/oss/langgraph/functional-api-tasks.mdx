Attach retries, timeouts, caching, and error recovery to Functional API [tasks](/oss/langgraph/functional-api#task). Completed task results are [checkpointed](/oss/langgraph/persistence), so resume can restore them instead of running the work again.

For concepts, see the [Functional API overview](/oss/langgraph/functional-api). For an ordered build path, see the [Build checklist for the Functional API](/oss/langgraph/use-functional-api). For Graph API nodes and the shared retry/timeout lifecycle, see [Fault tolerance](/oss/langgraph/fault-tolerance).

## Set a timeout

Cap how long a single async attempt can run. If a retry policy retries the timeout error, the timer resets on the next attempt.

:::python
Pass `timeout` on `@task` or `@entrypoint` in seconds or as a `datetime.timedelta`. Timeouts apply only to async tasks and entrypoints. Setting `timeout` on a sync function raises an error at declaration.

The first attempt sleeps past the timeout and raises @[`NodeTimeoutError`], which subclasses `TimeoutError`. The retry policy retries that error. The second attempt returns immediately.

<LanggraphFunctionalApiTasksTimeoutPy />
:::

:::js
Pass `timeout` on `task` or `entrypoint` in milliseconds, or as `{ idleTimeout: 30_000 }`. Use `isNodeTimeoutError` to narrow timeout errors. `NodeTimeoutError` is retryable when a retry policy is set.

The first attempt sleeps past the timeout. The retry policy retries. The second attempt returns immediately.

<LanggraphFunctionalApiTasksTimeoutJs />
:::
