The **Functional API** adds LangGraph features ([persistence](/oss/langgraph/persistence), [memory](/oss/langgraph/add-memory), [human-in-the-loop](/oss/langgraph/interrupts), and [streaming](/oss/langgraph/streaming)) to ordinary functions. Use standard language control flow (`if` / `else`, loops, and function calls) instead of declaring a graph of nodes and edges.

This page is the concept reference for entrypoints, tasks, checkpointing, and resume rules. For a design walkthrough, see [Thinking in the Functional API](/oss/langgraph/thinking-in-functional-api). For an ordered build path, see the [Build checklist for the Functional API](/oss/langgraph/use-functional-api).

The Functional API uses two building blocks:

:::python
* **`@entrypoint`**: Marks a function as the start of a workflow. It manages execution, interrupts, and checkpointing.
* **`@task`**: Marks a discrete unit of work (for example, an API call). Tasks return a future-like object that you can await or resolve with `.result()`.
:::

:::js
* **`entrypoint`**: Encapsulates workflow logic and manages execution, interrupts, and checkpointing.
* **`task`**: Marks a discrete unit of work (for example, an API call). Tasks return a `Promise` that you await inside the entrypoint.
:::

## Functional API vs. Graph API

This comparison is optional if you already chose the Functional API. For a side-by-side decision guide, see [Choosing between Graph and Functional APIs](/oss/langgraph/choosing-apis). Both APIs share the same underlying runtime, so you can use them together in the same application.

High-level differences:

* **Control flow**: The Functional API uses standard language constructs. The [Graph API](/oss/langgraph/graph-api) uses nodes and edges.
* **State**: The Graph API requires declaring [state](/oss/langgraph/graph-api#state) and often [reducers](/oss/langgraph/graph-api#reducers). The Functional API keeps state scoped to the function: tasks pass values as return values, with no shared state schema.
* **Checkpointing**: The Graph API checkpoints after each [super-step](/oss/langgraph/graph-api#super-steps). The Functional API saves task results to the entrypoint checkpoint.
* **Visualization**: The Graph API supports graph diagrams. The Functional API does not, because the graph is built at runtime.

## Entrypoint

:::python
The `@entrypoint` decorator creates a workflow from a function. It manages long-running work and [interrupts](/oss/langgraph/interrupts).
:::

:::js
The `entrypoint` function creates a workflow from a function. It manages long-running work and [interrupts](/oss/langgraph/interrupts).
:::

### Definition

Pass a [checkpointer](/oss/langgraph/persistence) when you need persistence or human-in-the-loop. Identify each run with a `thread_id` in config. A thread is the durable identity for one conversation or workflow run.

:::python
An **entrypoint** is a function decorated with `@entrypoint`.

The function **must accept a single positional argument** as the workflow input. To pass multiple values, use a dictionary (or similar) as that argument.

Decorating the function produces a workflow object (a @[`Pregel`][Pregel.stream] instance). Call `invoke` or `ainvoke` to run it.

<Tabs>
    <Tab title="Sync">
    ```python
    from langgraph.checkpoint.memory import InMemorySaver
    from langgraph.func import entrypoint

    checkpointer = InMemorySaver()

    @entrypoint(checkpointer=checkpointer)
    def my_workflow(name: str) -> str:
        return f"Hello, {name}"

    config = {"configurable": {"thread_id": "1"}}
    my_workflow.invoke("Alice", config)  # "Hello, Alice"
    ```
    </Tab>
    <Tab title="Async">
    ```python
    from langgraph.checkpoint.memory import InMemorySaver
    from langgraph.func import entrypoint

    checkpointer = InMemorySaver()

    @entrypoint(checkpointer=checkpointer)
    async def my_workflow(name: str) -> str:
        return f"Hello, {name}"

    config = {"configurable": {"thread_id": "1"}}
    await my_workflow.ainvoke("Alice", config)  # "Hello, Alice"
    ```
    </Tab>
</Tabs>
:::

:::js
An **entrypoint** is created by calling `entrypoint` with configuration and a function.

The function **must accept a single positional argument** as the workflow input. To pass multiple values, use an object as that argument.

The result is a workflow object. Call `invoke` to run it.

```typescript
import { MemorySaver, entrypoint } from "@langchain/langgraph";

const checkpointer = new MemorySaver();

const myWorkflow = entrypoint(
  { checkpointer, name: "workflow" },
  async (name: string): Promise<string> => {
    return `Hello, ${name}`;
  }
);

const config = { configurable: { thread_id: "1" } };
await myWorkflow.invoke("Alice", config); // "Hello, Alice"
```
:::

<Warning>
**Serialization**
Entrypoint **inputs** and **outputs** must be JSON-serializable when a checkpointer is configured. See [Serialization](#serialization).
</Warning>

### Run and resume

:::python
`@entrypoint` yields a workflow object. Call `invoke` / `ainvoke` for a final result. For streaming patterns (`stream_events`, custom data, message tokens), see [Stream with the Functional API](/oss/langgraph/functional-api-streaming).

```python
from langgraph.checkpoint.memory import InMemorySaver
from langgraph.func import entrypoint
from langgraph.types import Command

checkpointer = InMemorySaver()

@entrypoint(checkpointer=checkpointer)
def my_workflow(name: str) -> str:
    return f"Hello, {name}"

config = {"configurable": {"thread_id": "1"}}
my_workflow.invoke("Alice", config)  # "Hello, Alice"

# Resume after an interrupt with Command(resume=...)
# my_workflow.invoke(Command(resume=True), config)

# After fixing an error, resume the same thread with None
# my_workflow.invoke(None, config)
```
:::

:::js
`entrypoint` returns a workflow with `invoke` and streaming methods. For streaming patterns, see [Stream with the Functional API](/oss/langgraph/functional-api-streaming).

```typescript
import { MemorySaver, Command, entrypoint } from "@langchain/langgraph";

const checkpointer = new MemorySaver();

  { checkpointer, name: "workflow" },
  async (name: string): Promise<string> => {
    return `Hello, ${name}`;
  }
);

await myWorkflow.invoke("Alice", config); // "Hello, Alice"

// Resume after an interrupt with Command
// await myWorkflow.invoke(new Command({ resume: true }), config);

// After fixing an error, resume the same thread with null
// await myWorkflow.invoke(null, config);
```
:::

For full human-in-the-loop recipes, see [Add human-in-the-loop with the Functional API](/oss/langgraph/functional-api-human-in-the-loop). For resume-after-error details, see [Resume after an error](/oss/langgraph/functional-api-tasks#resume-after-an-error).

### Short-term memory

When an `entrypoint` has a `checkpointer`, successive invocations on the same **thread id** store state in [checkpoints](/oss/langgraph/checkpointers#checkpoints).

:::python
Add a `previous` parameter to the entrypoint. LangGraph sets it to whatever the last run on this thread returned. On the first run it is `None`. To save a different value for the next run, see [`entrypoint.final`](#entrypointfinal).

```python
from typing import Any

from langgraph.checkpoint.memory import InMemorySaver
from langgraph.func import entrypoint

checkpointer = InMemorySaver()

@entrypoint(checkpointer=checkpointer)
def my_workflow(number: int, *, previous: Any = None) -> int:
    previous = previous or 0
    return number + previous

config = {"configurable": {"thread_id": "1"}}

my_workflow.invoke(1, config)  # 1 (previous was None)
my_workflow.invoke(2, config)  # 3 (previous was 1)
```
:::

:::js
Call `getPreviousState` inside the entrypoint. It returns whatever the last run on this thread returned. On the first run it is `undefined`. To save a different value for the next run, see [`entrypoint.final`](#entrypointfinal).

```typescript
import { MemorySaver, entrypoint, getPreviousState } from "@langchain/langgraph";

const checkpointer = new MemorySaver();

const myWorkflow = entrypoint(
  { checkpointer, name: "workflow" },
  async (number: number) => {
    const previous = getPreviousState<number>() ?? 0;
    return number + previous;
  }
);

const config = { configurable: { thread_id: "1" } };

await myWorkflow.invoke(1, config); // 1 (previous was undefined)
await myWorkflow.invoke(2, config); // 3 (previous was 1)
```
:::

#### `entrypoint.final`

:::python
@[`entrypoint.final`][entrypoint.final] lets you **decouple** the value returned to the caller from the value saved for the next `previous` read. Annotate as `entrypoint.final[return_type, save_type]`.

```python
from typing import Any

from langgraph.checkpoint.memory import InMemorySaver
from langgraph.func import entrypoint

checkpointer = InMemorySaver()

@entrypoint(checkpointer=checkpointer)
def my_workflow(number: int, *, previous: Any = None) -> entrypoint.final[int, int]:
    previous = previous or 0
    # Return `previous` to the caller; save 2 * number for the next `previous`.
    return entrypoint.final(value=previous, save=2 * number)

config = {"configurable": {"thread_id": "1"}}

my_workflow.invoke(3, config)  # 0 (previous was None)
my_workflow.invoke(1, config)  # 6 (previous was 3 * 2)
```
:::

:::js
@[`entrypoint.final`][entrypoint.final] lets you **decouple** the value returned to the caller from the value saved for the next `getPreviousState` read.

```typescript
import { MemorySaver, entrypoint, getPreviousState } from "@langchain/langgraph";

const checkpointer = new MemorySaver();

const myWorkflow = entrypoint(
  { checkpointer, name: "workflow" },
  async (number: number) => {
    const previous = getPreviousState<number>() ?? 0;
    // Return `previous` to the caller; save 2 * number for the next previous state.
    return entrypoint.final({
      value: previous,
      save: 2 * number,
    });
  }
);

const config = { configurable: { thread_id: "1" } };

await myWorkflow.invoke(3, config); // 0 (previous was undefined)
await myWorkflow.invoke(1, config); // 6 (previous was 3 * 2)
```
:::

### Injectable parameters

You can skip this until you add [memory](/oss/langgraph/functional-api-memory) or [custom streaming](/oss/langgraph/functional-api-streaming).

:::python
When declaring an `entrypoint`, you can request additional parameters that LangGraph injects at runtime:

| Parameter | Description |
| --------- | ----------- |
| **previous** | The return value from the previous invocation on the same thread (requires a checkpointer). See [short-term memory](/oss/langgraph/functional-api-memory#save-state-on-a-thread). |
| **config** | A @[`RunnableConfig`] object with run-time configuration values. |
| **store** | A @[`BaseStore`] instance for [long-term memory](/oss/langgraph/functional-api-memory#save-facts-across-threads). Also available as `runtime.store`. |
| **writer** | A `StreamWriter` for custom streaming. Also available as `runtime.stream_writer`. See [Stream with the Functional API](/oss/langgraph/functional-api-streaming). |
| **runtime** | A @[`Runtime`] object for the current run, including context, store, and writer. |

<Warning>
Declare injectable parameters with the appropriate name and type annotation.
</Warning>

<Accordion title="Requesting injectable parameters">
  ```python
  from typing import Any

  from langchain_core.runnables import RunnableConfig
  from langgraph.checkpoint.memory import InMemorySaver
  from langgraph.func import entrypoint
  from langgraph.runtime import Runtime
  from langgraph.store.memory import InMemoryStore

  checkpointer = InMemorySaver()
  store = InMemoryStore()

  @entrypoint(
      checkpointer=checkpointer,
      store=store,
  )
  def my_workflow(
      some_input: dict,  # The input (for example, passed via `invoke`)
      *,
      previous: Any = None,  # Short-term memory from the previous invocation
      config: RunnableConfig,  # Run-time configuration
      runtime: Runtime,  # Context, store, and writer for the current run
  ) -> dict:
      memory_store = runtime.store
      writer = runtime.stream_writer
      ...
  ```
</Accordion>
:::

:::js
The `entrypoint` function can take a second `config` argument. LangGraph also provides helpers you call inside the function:

| Helper | Description |
| --------- | ----------- |
| **getPreviousState** | The return value from the previous invocation on the same thread (requires a checkpointer). See [short-term memory](/oss/langgraph/functional-api-memory#save-state-on-a-thread). |
| **config** | A `LangGraphRunnableConfig` object with run-time configuration values. |
| **config.store** | A store instance for [long-term memory](/oss/langgraph/functional-api-memory#save-facts-across-threads). |
| **config.writer** | A writer for custom streaming. See [Stream with the Functional API](/oss/langgraph/functional-api-streaming). |

<Accordion title="Requesting injectable parameters">
  ```typescript
  import {
    MemorySaver,
    MemoryStore,
    entrypoint,
    getPreviousState,
  } from "@langchain/langgraph";
  import type { LangGraphRunnableConfig } from "@langchain/langgraph";

  const checkpointer = new MemorySaver();
  const store = new MemoryStore();

  const myWorkflow = entrypoint(
    { checkpointer, store, name: "workflow" },
    async (
      someInput: Record<string, unknown>,
      config: LangGraphRunnableConfig
    ) => {
      const previous = getPreviousState();
      const memoryStore = config.store;
      const writer = config.writer;
      return { previous, someInput };
    }
  );
  ```
</Accordion>

## Task

A **task** is a discrete unit of work (for example, an API call or data step). Tasks have two key properties:

* **Concurrent execution**: Calling a task starts it immediately. The entrypoint blocks only when you wait for the result, so independent tasks can overlap.
* **Checkpointing**: Task results are saved so resume can restore them. See [persistence](/oss/langgraph/persistence).

### Definition

:::python
Define tasks with the `@task` decorator:

```python
from langgraph.func import task

@task
def slow_computation(input_value: int) -> int:
    # Long-running or side-effecting work
    return input_value * 2
```
:::

:::js
Define tasks with the `task` function:

```typescript
import { task } from "@langchain/langgraph";

const slowComputation = task("slowComputation", async (inputValue: number) => {
  // Long-running or side-effecting work
  return inputValue * 2;
});
```
:::

<Warning>
**Serialization**: Task **outputs** must be JSON-serializable to support checkpointing.
</Warning>

### Execution

Call **tasks** only from an **entrypoint**, another **task**, or a [Graph API node](/oss/langgraph/graph-api#nodes). Do not call them from application code outside the workflow.

:::python
Calling a task returns a future immediately. Resolve it with `.result()` (sync) or `await` (async).

<Tabs>
    <Tab title="Sync">
    ```python
    from langgraph.checkpoint.memory import InMemorySaver
    from langgraph.func import entrypoint, task

    checkpointer = InMemorySaver()

    @task
    def slow_computation(input_value: int) -> int:
        return input_value * 2

    @entrypoint(checkpointer=checkpointer)
    def my_workflow(some_input: int) -> int:
        future = slow_computation(some_input)
        return future.result()
    ```
    </Tab>
    <Tab title="Async">
    ```python
    from langgraph.checkpoint.memory import InMemorySaver
    from langgraph.func import entrypoint, task

    checkpointer = InMemorySaver()

    @task
    async def slow_computation(input_value: int) -> int:
        return input_value * 2

    @entrypoint(checkpointer=checkpointer)
    async def my_workflow(some_input: int) -> int:
        return await slow_computation(some_input)
    ```
    </Tab>
</Tabs>
:::

:::js
Calling a task returns a `Promise`. Await it inside the entrypoint:

```typescript
import { MemorySaver, entrypoint, task } from "@langchain/langgraph";

const checkpointer = new MemorySaver();

const slowComputation = task("slowComputation", async (inputValue: number) => {
  return inputValue * 2;
});

const myWorkflow = entrypoint(
  { checkpointer, name: "workflow" },
  async (someInput: number): Promise<number> => {
    return await slowComputation(someInput);
  }
);
```
:::

## When to use a task

Use **tasks** when you need:

* **Checkpointing**: Save a long-running result so resume does not recompute it.
* **Human-in-the-loop**: Wrap work you should not redo after a pause in a task, for example an LLM call. Resume after an [interrupt](/oss/langgraph/interrupts) restores the result. For randomness, see [Determinism](#determinism).
* **Parallel execution**: Run independent I/O-bound work concurrently.
* **Observability**: Track discrete steps in [LangSmith](/langsmith/observability).
* **Retries**: Apply retry policies to discrete units of work. See [Configure Functional API tasks](/oss/langgraph/functional-api-tasks).

## Pause for human review

This workflow writes an essay and [interrupts](/oss/langgraph/interrupts) for human review:

:::python
```python
import time

from langgraph.checkpoint.memory import InMemorySaver
from langgraph.func import entrypoint, task
from langgraph.types import interrupt

@task
def write_essay(topic: str) -> str:
    """Write an essay about the given topic."""
    time.sleep(1)  # Placeholder for a long-running task.
    return f"An essay about topic: {topic}"

@entrypoint(checkpointer=InMemorySaver())
def workflow(topic: str) -> dict:
    """Write an essay and pause for review."""
    essay = write_essay(topic).result()
    is_approved = interrupt({
        # Any JSON-serializable payload. Surfaces as an Interrupt when streaming.
        "essay": essay,
        "action": "Please approve/reject the essay",
    })

    return {
        "essay": essay,
        "is_approved": is_approved,
    }
```
:::

:::js
```typescript
import { MemorySaver, entrypoint, task, interrupt } from "@langchain/langgraph";

const writeEssay = task("writeEssay", async (topic: string) => {
  // Placeholder for a long-running task.
  await new Promise((resolve) => setTimeout(resolve, 1000));
  return `An essay about topic: ${topic}`;
});

const workflow = entrypoint(
  { checkpointer: new MemorySaver(), name: "workflow" },
  async (topic: string) => {
    const essay = await writeEssay(topic);
    const isApproved = interrupt({
      // Any JSON-serializable payload. Surfaces as an Interrupt when streaming.
      essay,
      action: "Please approve/reject the essay",
    });

    return {
      essay,
      isApproved,
    };
  }
);
```
:::

## Serialization

Two rules apply when a checkpointer is configured:

1. `entrypoint` inputs and outputs must be JSON-serializable.
2. `task` outputs must be JSON-serializable.

:::python
Use Python primitives such as dictionaries, lists, strings, numbers, and booleans.
:::

:::js
Use primitives such as objects, arrays, strings, numbers, and booleans.
:::

Serialization is what makes task results and intermediate values restorable for human-in-the-loop, fault tolerance, and parallel execution. Non-serializable values raise a runtime error when a checkpointer is configured.

## Determinism

Resume does **not** continue from the exact line where execution stopped. Execution returns to a checkpoint boundary and **replays** forward until it hits the pause again.

For the Functional API, replay starts at the beginning of the **entrypoint**. LangGraph restores completed [**task**](#task) and [**subgraph**](/oss/langgraph/use-subgraphs) results from the checkpointer instead of recomputing them. That preserves step order across pauses, including for long-running or non-deterministic **task** outputs.

For **human-in-the-loop**, put non-deterministic work (for example, random values) and side effects (for example, file writes or API calls) in [**tasks**](#task).

Different runs can produce different results. Resuming a **specific** thread should replay the same persisted **task** and **subgraph** results.

Guidelines:

* **Avoid repeating work**: Give each side effect in an entrypoint its own **task** so resume restores outputs instead of re-running them.
* **Encapsulate non-deterministic operations**: Keep values that change between attempts (random numbers, wall-clock time) inside **tasks**.
* **Use idempotent operations**: For partial failures and retries, see [Idempotency](#idempotency).

## Idempotency

Idempotency means running the same operation more than once has the same effect as running it once. Place API calls and other writes inside **tasks**, and design those tasks to be safe if they run again.

On resume, LangGraph restores completed **task** results. A **task** that started but did not finish may run again, so use idempotency keys or check existing results before writing.

## Common pitfalls

### Handling side effects

Put side effects (writing a file, sending an email) in tasks so resume does not run them again.

<Tabs>
    <Tab title="Incorrect">
    The file write runs in the entrypoint, so resume executes it a second time.

    :::python
    ```python
    from langgraph.checkpoint.memory import InMemorySaver
    from langgraph.func import entrypoint
    from langgraph.types import interrupt

    checkpointer = InMemorySaver()

    @entrypoint(checkpointer=checkpointer)
    def my_workflow(inputs: dict) -> int:
        # Runs again on resume.
        with open("output.txt", "w") as f:  # [!code highlight]
            f.write("Side effect executed")  # [!code highlight]
        value = interrupt("question")
        return value
    ```
    :::

    :::js
    ```typescript
    import { MemorySaver, entrypoint, interrupt } from "@langchain/langgraph";
    import fs from "fs";

    const checkpointer = new MemorySaver();

    const myWorkflow = entrypoint(
      { checkpointer, name: "workflow" },
      async (inputs: Record<string, any>) => {
        // Runs again on resume.
        fs.writeFileSync("output.txt", "Side effect executed");
        const value = interrupt("question");
        return value;
      }
    );
    ```
    :::
    </Tab>
    <Tab title="Correct">
    The side effect lives in a task, so resume restores the checkpointed result.

    :::python
    ```python
    from langgraph.checkpoint.memory import InMemorySaver

    checkpointer = InMemorySaver()

    @entrypoint(checkpointer=checkpointer)
    def my_workflow(inputs: dict) -> int:
        write_to_file().result()

        return value
    ```

    ```typescript
    import { MemorySaver, entrypoint, task, interrupt } from "@langchain/langgraph";
    import * as fs from "fs";

    const checkpointer = new MemorySaver();

    const writeToFile = task("writeToFile", async () => {

      { checkpointer, name: "workflow" },
    ```

### Non-deterministic control flow

Encapsulate time and randomness in tasks so resume returns the same values.

* In a task: Get random number (5) → interrupt → resume → (returns 5 again) → ...
* Not in a task: Get random number (5) → interrupt → resume → get new random number (7) → ...

With multiple @[`interrupt`] calls, LangGraph matches resume values **by index** to each interrupt. If resume changes the order of interrupts, a resume value can attach to the wrong interrupt. See [Determinism](#determinism).

<Tabs>
    <Tab title="Incorrect">
    Reading the clock in the entrypoint can change which branch runs on resume.

    :::python
    ```python
    import time

    from langgraph.checkpoint.memory import InMemorySaver
    from langgraph.func import entrypoint, task
    from langgraph.types import interrupt

    checkpointer = InMemorySaver()

    @task
    def slow_task(x: int) -> int:
        return x

    @entrypoint(checkpointer=checkpointer)
    def my_workflow(inputs: dict) -> dict:
        t0 = inputs["t0"]
        t1 = time.time()  # [!code highlight]

        delta_t = t1 - t0

        if delta_t > 1:
            result = slow_task(1).result()
            value = interrupt("question")
        else:
            result = slow_task(2).result()
            value = interrupt("question")

        return {"result": result, "value": value}
    ```
    :::

    :::js
    ```typescript
    import { MemorySaver, entrypoint, task, interrupt } from "@langchain/langgraph";

    const checkpointer = new MemorySaver();

    const slowTask = task("slowTask", async (x: number) => x);

    const myWorkflow = entrypoint(
      { checkpointer, name: "workflow" },
      async (inputs: { t0: number }) => {
        const t1 = Date.now();

        const deltaT = t1 - inputs.t0;

        if (deltaT > 1000) {
          const result = await slowTask(1);
          const value = interrupt("question");
          return { result, value };
        } else {
          const result = await slowTask(2);
          const value = interrupt("question");
          return { result, value };
        }
      }
    );
    ```
    :::
