Use these recipes to compose Functional API workflows from @[entrypoint] and @[task] building blocks.

For concepts, see the [Functional API overview](/oss/langgraph/functional-api). For an ordered build path, see the [Build checklist for the Functional API](/oss/langgraph/use-functional-api).

The examples use an in-memory [checkpointer](/oss/langgraph/persistence) so results persist on a thread.

## Run tasks in parallel

:::python
A task starts as soon as you call it and returns a future. Collect those futures first, then wait with `.result()` so the work overlaps.
:::

:::js
A task starts as soon as you call it and returns a `Promise`. Collect those promises first, then wait with `Promise.all` so the work overlaps.
:::

## Call a graph

The Functional API and the [Graph API](/oss/langgraph/graph-api) share the same runtime. A compiled graph is another callable: invoke it from an entrypoint like any other function.

A nested graph does not share the outer thread unless you pass `config` into `invoke`. Request the injected `config` on the entrypoint and forward it.
