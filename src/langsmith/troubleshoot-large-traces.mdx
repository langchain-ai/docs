LangSmith enforces a limit of **25,000 runs per trace**. When a trace reaches this limit, additional runs are rejected. This page explains common causes and how to resolve them.

## Symptoms

- Runs are missing from a trace or rejected by the API
- Traces appear incomplete in the LangSmith UI
- You see errors related to exceeding the maximum number of runs per trace

## Common causes

### Infinite loops or excessive recursion

The most common cause of very large traces is an agent or chain that loops far more times than intended. For example, an agent that repeatedly calls a tool without making progress can generate thousands of runs in a single trace.

**How to fix:**

- Set a `recursion_limit` in LangGraph to cap the number of steps an agent can take:

:::python
```python
config = {"recursion_limit": 100}
result = await graph.ainvoke(input, config=config)
```
:::

:::js
```typescript
const config = { recursionLimit: 100 };
const result = await graph.invoke(input, config);
```
:::

- Add early termination logic to your agent so it stops when it detects it is not making progress.

### Unintended tracing of internal operations

If your application calls other LangSmith-instrumented code (such as LangChain runnables or other `@traceable` functions) inside a loop, each iteration generates additional runs under the same trace.

**How to fix:**

- Move high-volume batch operations outside of the traced context, or use [conditional tracing](/langsmith/conditional-tracing) to disable tracing for inner operations that don't need to be observed.
- Use [sampling](/langsmith/sample-traces) to reduce the volume of traces logged in high-throughput applications.

### Long-running multi-step pipelines

Pipelines that chain many sequential steps (for example, processing hundreds of documents in a single trace) can accumulate a large number of runs.

**How to fix:**

- Break the work into multiple traces instead of running everything under a single trace. For example, process each document or batch of documents as a separate trace.
- Use [threads](/langsmith/threads) to link related traces together for a unified view without combining all runs into one trace.

## Inspect large traces

Use the [trace view filters](/langsmith/filter-traces-in-application#filter-runs-within-the-trace-view) to navigate traces with a large number of runs. You can filter by run type, name, or status to find the runs that are contributing most to the trace size.
