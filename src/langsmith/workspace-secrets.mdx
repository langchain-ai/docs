---
title: Workspace secrets
description: Add, edit, and delete the workspace secrets that LangSmith uses to call model providers and tools, on LangSmith Cloud and self-hosted LangSmith.
---

Workspace secrets store the API keys that LangSmith uses to call model providers and tools on your behalf. Features that read them include the [Playground](/langsmith/playground-model-providers), [evaluators](/langsmith/evaluation), [Fleet](/langsmith/fleet/workspace-admin#workspace-secrets), and the [LLM Gateway](/langsmith/llm-gateway-provider-authentication#add-a-provider-key). Each secret belongs to one workspace. A workspace that calls a provider needs its own copy of that provider's key.

This page is the reference for finding and adding workspace secrets. Pages for individual features link here and describe only the secret names and settings that the feature needs.

## Required permission

Adding, editing, or deleting a workspace secret requires the `workspaces:manage-secrets` permission in that workspace. [Workspace Admins](/langsmith/rbac#workspace-admin) have it by default. Without it, the secrets page lists existing secrets but hides the add button, and shows a notice that asks you to contact a workspace admin. Ask a workspace admin to add the secret for you, or to grant you access.

## Open the secrets page

Where the secrets page sits in **Settings** depends on your LangSmith version:

<Tabs>
<Tab title="Cloud and self-hosted v0.18 or later">
1. Open <Icon icon="settings" /> **Settings**.
1. At the top of the sidebar, select **Workspace**, then pick the workspace that needs the secret.
1. Under **Configuration**, select **Secrets**. On self-hosted v0.18, this item is named **Provider Credentials**.

In a personal organization, the sidebar has no **Workspace** switch. Select **Secrets** under **Configuration**.

The page header reads **Workspace Secrets**. You can also type `secrets` in the **Settings** search box to find it.
</Tab>
<Tab title="Self-hosted v0.16 and v0.17">
1. Open <Icon icon="settings" /> **Settings** for the workspace that needs the secret.
1. Select **Integrations** > **Provider secrets**.
</Tab>
</Tabs>

## Add a secret

1. [Open the secrets page](#open-the-secrets-page).
1. Select **+ Secret**.
1. Under **Provider**, select your model provider. LangSmith names the secret with the environment variable the provider expects, such as `OPENAI_API_KEY`. Enter your key in that field. Some providers, such as Amazon Bedrock, also ask you to choose an authentication method.

   For a tool key, or a provider that is not listed, leave **Custom** as the provider. Enter the environment variable name your provider or tool expects as the **Key**, and your key as the **Value**.
1. Select **Save**.

On self-hosted v0.16, the dialog has no **Provider** list. Enter the environment variable name as the **Key** and your key as the **Value**.

LangSmith does not check a key when you save it. A wrong key shows up as the provider's error on the first request that uses it.

To remove a secret, select the delete icon in its row. When the page shows an **Allowed hosts** column, each row also has an edit icon for changing the secret's value, hosts, or header.

## Secret names and settings by feature

Each feature reads specific secret names. The default name for a provider is the one the **Provider** list fills in. For the full list, and for providers that need more than one secret, see:

- [Provider secret names](/langsmith/llm-gateway-provider-authentication#add-a-provider-key) for the LLM Gateway, including [Amazon Bedrock](/langsmith/llm-gateway-provider-authentication#configure-amazon-bedrock) and [Azure Foundry](/langsmith/llm-gateway-provider-authentication#configure-azure-foundry).
- [Allowed hosts](/langsmith/advanced-code-evaluators#configure-allowed-hosts-for-a-secret) for secrets that advanced code evaluators send to external services.
- [Fleet secrets](/langsmith/fleet/workspace-admin#workspace-secrets), including tool keys and `FLEET_`-prefixed secrets that take priority within Fleet.
- [Decision model providers](/langsmith/decision-model-evaluator) for decision model evaluators.

## Other places to store credentials

- **OAuth client credentials**: if your provider authenticates with OAuth2 `client_credentials`, configure the credentials on the model configuration instead. See [OAuth client credentials](/langsmith/model-configurations#oauth-client-credentials).
- **Organization secrets**: apply only to [organization-scoped model configurations](/langsmith/llm-gateway-model-configurations). For `<provider>/<model>` calls, the LLM Gateway reads workspace secrets and does not fall back to organization secrets.
