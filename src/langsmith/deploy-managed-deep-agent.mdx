Managed Deep Agents lets you deploy a Deep Agents project to a managed LangSmith API. The `deepagents deploy` command packages your agent files and creates or updates a Managed Deep Agent.

<Note>
    Managed Deep Agents is in private preview. [Join the waitlist](https://www.langchain.com/langsmith-managed-deep-agents-waitlist) to request access.
</Note>

<Tip>
    You can also deploy Deep Agents with a standard [LangSmith Deployment](/langsmith/deployment-quickstart). Use that path when you need custom application code, custom routes, advanced authentication, full Agent Server APIs, stronger isolation controls, or maximum scalability.
</Tip>

The CLI and API use the same managed agent model. You can deploy through the CLI, then call the same agent through the Managed Deep Agents API.

## Prerequisites

Before you begin, ensure you have:

- Private preview access to Managed Deep Agents.
- A LangSmith API key for a workspace with access.
- The Deep Agents CLI installed.
- A Deep Agents project with `deepagents.toml` and `AGENTS.md`.

## 1. Install the CLI

Install the Deep Agents CLI or run the deploy command directly with `uvx`:

<CodeGroup>
    ```bash uv
    uv tool install deepagents-cli
    ```

    ```bash uvx
    uvx deepagents-cli deploy
    ```
</CodeGroup>

## 2. Prepare your project

Place the agent files next to `deepagents.toml`. The CLI discovers these files and sends them to the Managed Deep Agents API.

```txt
my-agent/
├── deepagents.toml
├── AGENTS.md
├── tools.json
├── skills/
│   └── <skill-name>/
│       └── SKILL.md
└── subagents/
    └── <subagent-name>/
        ├── deepagents.toml
        └── AGENTS.md
```

| File | Description |
| --- | --- |
| `deepagents.toml` | Required. Configures the managed agent. |
| `AGENTS.md` | Required. Provides the agent instructions loaded at session start. |
| `tools.json` | Optional. Defines tool configuration for the managed agent. |
| `skills/` | Optional. Contains skill definitions. Each skill directory includes a `SKILL.md` file. |
| `subagents/` | Optional. Contains subagent definitions. Each subagent directory includes `deepagents.toml` and `AGENTS.md`. |

## 3. Deploy

Set your LangSmith API key, then run `deepagents deploy` from the project directory:

```bash
export LANGSMITH_API_KEY="lsv2_..."
deepagents deploy
```

By default, `deepagents deploy` looks for `deepagents.toml` in the current directory. Pass `--config` to use a different path:

```bash
deepagents deploy --config path/to/deepagents.toml
```

The command creates or updates a Managed Deep Agent through the Managed Deep Agents API.

## 4. Invoke the agent

After deployment, call the agent through the Managed Deep Agents API. The private preview route shape uses `/v1/deepagents/agents` for agent management and `/v1/deepagents/threads` for thread and run operations.

Use your LangSmith API key with the `X-Api-Key` header:

```txt
X-Api-Key: <LANGSMITH_API_KEY>
```

Use the `/v1/deepagents/threads` endpoint group to create threads and run the agent. For the supported private preview route groups, see [Managed Deep Agents API](/langsmith/managed-deep-agents-api).

## Limitations

Managed Deep Agents does not mirror every LangSmith Deployment endpoint. Non-LangGraph Platform (non-LGP) endpoint groups such as integrations, auth, triggers, skills, and sandboxes are not mirrored yet.

The private preview also does not include standalone LangSmith Deployment behavior such as bundled frontend hosting, custom auth providers, custom routes, A2A, MCP agent exposure, or RemoteGraph endpoints.
