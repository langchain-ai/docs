Evals let you run your Managed Deep Agent against checked-in Harbor-style tasks in isolated environments. Trials can run locally with Docker or remotely on LangSmith. Each task describes what the agent should do, runs the compiled agent once, then verifies the result with a shell entrypoint (`tests/test.sh`) and language tests.

## Prerequisites

- A Managed Deep Agents project created with `mda init` (or an existing project that already has an agent entry).
- For `--environment docker` (the default): [Docker](https://docs.docker.com/get-docker/) running locally.
- For `--environment langsmith`: `LANGSMITH_API_KEY` (or `LANGSMITH_SANDBOX_API_KEY`) in the project `.env` or your shell.
- Model credentials in the project `.env` or your shell (for example `OPENAI_API_KEY` for `openai:…` models).
- The `mda` CLI from `managed-deepagents` (same install as [CLI reference](/langsmith/managed-deep-agents-cli#install)).

`mda evals run` provisions Harbor for you. Override the Harbor binary only if needed with `MDA_HARBOR_BIN`.

## Concepts

| Term | Meaning |
| --- | --- |
| **Task** | One checked-in scenario under `evals/` (instruction + image + verifier). |
| **Trial** | One concrete run: task × model × rollout index. |
| **Rollout** | An independent repeat of the same task/model pair for variance. |
| **Reward** | Score written by the verifier (`reward.txt`). `1` typically means pass. |

## Scaffold tasks

From your project root:

```bash
mda evals init
```

With no path (or with `evals`), the command creates starter tasks under `evals/` when that directory does not already exist. `mda init` also scaffolds starter evals for new projects.

To add one more task later:

```bash
mda evals init evals/my-task
```

## Task layout

Each task is a Harbor-style directory:

```text
evals/
  my-task/
    instruction.md              # Prompt given to the agent
    task.toml                   # Timeouts and environment hints
    identity.json               # Required when the project declares identity
    environment/
      Dockerfile                # Trial image (or extends the default)
    tests/
      test.sh                   # Verifier entry (writes reward.txt)
      answer.test.mjs           # TypeScript: node:test assertions
      # or test_answer.py       # Python: pytest assertions
```

### Instruction

`instruction.md` is the user-facing task prompt. The agent sees it during the trial. Keep it specific and verifiable.

```markdown
Write a file named `answer.txt` in the working directory containing exactly the word PONG and nothing else.
```

### Verifier

`tests/test.sh` is the Harbor verifier entry. The scaffolded scripts run language tests, then write a classic Harbor reward file:

- Pass → `/logs/verifier/reward.txt` contains `1`
- Fail → `/logs/verifier/reward.txt` contains `0` and a non-zero exit

TypeScript tasks use Node's test runner:

```bash
node --test /tests/*.test.mjs
```

Python tasks use pytest:

```bash
pytest -q /tests
```

Assertions run against the trial filesystem. The agent working directory is `/app`.

<CodeGroup>

```js tests/answer.test.mjs
import assert from "node:assert/strict";
import { readFileSync } from "node:fs";
import { test } from "node:test";

test("answer.txt contains exactly PONG", () => {
  const text = readFileSync("/app/answer.txt", "utf8").trim();
  assert.equal(text, "PONG");
});
```

```python tests/test_answer.py
from pathlib import Path


def test_answer_is_pong():
    assert Path("/app/answer.txt").read_text().strip() == "PONG"
```

</CodeGroup>

### Identity-aware projects

If the project exports [identity](/langsmith/managed-deep-agents-identity) (`identity.ts` or `identity.py`), every eval task must include `identity.json`. Scaffolding adds a default fixture automatically. Customize the fixture when your agent or tests depend on a specific actor, tenant, or claims.

```json identity.json
{
  "actor": {
    "type": "user",
    "id": "eval_user_1",
    "email": "eval@example.com"
  },
  "tenant": {
    "id": "acme"
  },
  "source": {
    "provider": "cli"
  },
  "claims": {
    "permissions": ["billing:read"]
  }
}
```

The fixture is injected as the trial identity envelope. It is not left under `/app` as an agent-writable file.

## Check tasks

Validate task discovery and local prerequisites before spending model calls:

```bash
mda evals check .
```

Pass a project root or a specific task directory (`evals/my-task`). Fix any missing `identity.json`, duplicate task names, or layout errors before running.

## Run tasks

```bash
mda evals run .
```

Defaults:

| Setting | Default |
| --- | --- |
| Environment | `docker` (local Harbor + Docker) |
| Model | The model from your agent entry, or a supported CLI default |
| Rollouts | `1` |
| Concurrency | `1` |

Choose where trials run with `--environment`:

| Value | Where trials run |
| --- | --- |
| `docker` | Local Harbor + Docker (default). |
| `langsmith` | Remote Harbor trials on LangSmith sandboxes. |

Useful flags:

| Flag | Purpose |
| --- | --- |
| `--environment docker\|langsmith` | Trial backend. Defaults to `docker`. |
| `--model <provider:model>` | Override the model. Repeat for a matrix. |
| `--rollouts <n>` | Independent repeats per task/model pair. |
| `-j` / `--concurrency <n>` | Max parallel trials after shared image warm-up. |
| `--tasks <pattern>` | Include tasks whose name or path contains the pattern. Repeatable. |
| `--exclude-tasks <pattern>` | Exclude matching tasks. |
| `--gate 'reward.mean>=1'` | Fail the command (exit `2`) when mean reward is below the threshold. |
| `--max-errors <n>` | Fail (exit `3`) when trial errors exceed the budget. |
| `--shard K/N` | Run shard `K` of `N` from the ordered trial plan (1-based `K`). |
| `--dry-run` | Print a redacted job config without running trials. |

Examples:

```bash
# Run the suite once (local Docker)
mda evals run .

# Same tasks on LangSmith sandboxes
mda evals run . --environment langsmith

# Filter to one task, require a perfect mean reward
mda evals run . --tasks my-task --gate 'reward.mean>=1'

# Three rollouts with up to three parallel trials
mda evals run . --rollouts 3 -j 3

# CI matrix sharding
mda evals run . --rollouts 4 --shard 1/3
mda evals run . --rollouts 4 --shard 2/3
mda evals run . --rollouts 4 --shard 3/3
```

Artifacts and per-trial logs land under `.mda/evals/runs/<run-id>/`. That directory is local output; do not commit it.

### Exit codes

| Exit | Meaning |
| --- | --- |
| `0` | Job completed; optional gates passed |
| `1` | Could not start a valid job |
| `2` | Opt-in quality gate failed |
| `3` | Errors exceeded `--max-errors` |

A trial with reward `0` is a completed low score, not automatically exit `2`. Use `--gate` when you want CI to fail on quality.

### Sandbox setup scripts

If the project has `sandbox/setup.sh`, eval trials run it once while preparing the trial environment (with `bash`, so bashisms such as `set -o pipefail` are supported). Authored sandbox provider config is ignored during evals; the trial environment owns isolation.

## Day-one workflow

```bash
# From an existing Managed Deep Agents project
mda evals init
mda evals check .
mda evals run . --gate 'reward.mean>=1'
```

Edit `instruction.md` and the tests under `tests/` for each task, re-check, then re-run. When a project already has `evals/`, add individual tasks with `mda evals init evals/<name>` instead of scaffolding the suite again.
