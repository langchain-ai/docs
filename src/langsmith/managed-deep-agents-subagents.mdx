Give a managed deep agent subagents to delegate specialized or context-heavy work, such as researching a topic, reviewing a change, or running a long task in the background with an async subagent while the agent keeps talking to the user. Each subagent has its own prompt and context window. It can also use its own model and tools.

<ManagedDeepAgentsPublicBetaNote />

There are two types of subagents:

| Type | How the agent uses it | Use it for |
| --- | --- | --- |
| Subagent | Calls it with `task` and waits for its answer | Focused work whose result the agent needs before it continues |
| Async subagent | Starts it with `start_async_task` and keeps working; the agent is notified when it finishes | Long-running or parallel work the agent doesn't need to wait for |

A subagent runs inside the agent's graph. Managed Deep Agents builds each async subagent as its own graph in the same deployment. Both kinds can use the agent's sandbox; see [Share the sandbox and trace](#share-the-sandbox-and-trace). For how subagents work in the open source Deep Agents SDK, see [Subagents](/oss/deepagents/subagents) and [Async subagents](/oss/deepagents/async-subagents).

<Note>
Async subagents require `managed-deepagents>=0.10.0`.
</Note>

## Declare a subagent

Add subagent definitions to `subagents` in the [agent definition](/langsmith/managed-deep-agents-agent-definition). Each one needs a `name` and a `description`; the agent uses the description to decide when to delegate:

:::python
```python agent.py
from managed_deepagents import define_deep_agent

agent = define_deep_agent(
    name="research-assistant",
    model="openai:gpt-5.5",
    subagents=[
        {
            "name": "reviewer",
            "description": "Reviews a draft for accuracy and clarity.",
            "system_prompt": "Review the draft and list concrete fixes.",
        },
    ],
)
```
:::

:::js
```ts agent.ts
import { defineDeepAgent } from "managed-deepagents";

export const agent = defineDeepAgent({
  name: "research-assistant",
  model: "openai:gpt-5.5",
  subagents: [
    {
      name: "reviewer",
      description: "Reviews a draft for accuracy and clarity.",
      systemPrompt: "Review the draft and list concrete fixes.",
    },
  ],
});
```
:::

## Run a subagent in the background

:::python
To make a subagent async, add `"async": True` to its definition:

```python agent.py
from managed_deepagents import define_deep_agent

agent = define_deep_agent(
    name="research-assistant",
    model="openai:gpt-5.5",
    subagents=[
        {
            "name": "researcher",
            "description": "Researches a topic in the background.",
            "system_prompt": "Research the topic and report your findings.",
            "async": True,
        },
    ],
)
```
:::

:::js
To make a subagent async, add `async: true` to its definition:

```ts agent.ts
import { defineDeepAgent } from "managed-deepagents";

export const agent = defineDeepAgent({
  name: "research-assistant",
  model: "openai:gpt-5.5",
  subagents: [
    {
      name: "researcher",
      description: "Researches a topic in the background.",
      systemPrompt: "Research the topic and report your findings.",
      async: true,
    },
  ],
});
```
:::

Each async subagent appears in the deployment as its own graph, named after the agent and the subagent, such as `research-assistant--researcher`. Managed Deep Agents finds async subagents by reading your agent file when it builds, not by running it. Write each one directly in `subagents` or in a variable, with a fixed `name` and `async` value. An async subagent built by a function or a loop gets no graph, and the agent fails to start. A [graph factory](/langsmith/managed-deep-agents-agent-definition#select-configuration-per-run) can declare async subagents too, as long as it returns the agent definition directly.

:::python
Do not set `graph_id`, `url`, `headers`, or `runnable`: Managed Deep Agents builds and launches the graph itself. These options pass through to Deep Agents:

| Option | Default | Description |
| --- | --- | --- |
| `update_strategy` | `"interrupt"` | `"enqueue"` queues a follow-up behind the current run instead of interrupting it |
| `notify_parent` | `True` | Wake the agent when the subagent finishes while the agent is idle. Set to `False` to handle results yourself, such as with `webhook` |
| `webhook` | Not set | URL the Agent Server calls whenever a run of the subagent finishes, with the run's thread ID, run ID, and status. See [Deliver results through your app](/oss/deepagents/async-subagents#deliver-results-through-your-app) |
| `mode` | `"isolated"` | `"fork"` starts the subagent with a copy of the agent's conversation |
:::

| Option | Default | Description |

Every agent also gets a `general-purpose` subagent for delegated work that doesn't match a declared subagent. Agents served by `mda dev` or a deployment get an async version of it too, so the agent can run that work in the foreground or in the background. See [The general-purpose subagent](/oss/deepagents/subagents#the-general-purpose-subagent).

## Subagent tools

Managed Deep Agents gives the agent these tools to work with its subagents:

| Tool | What it does |
| --- | --- |
| `task` | Runs a subagent and waits for its answer |
| `start_async_task` | Starts an async subagent on its own thread and returns a task ID right away |
| `check_async_task` | Gets a task's status and, once it finishes, its result |
| `update_async_task` | Sends new instructions to a task |
| `cancel_async_task` | Stops a running task |
| `list_async_tasks` | Lists the agent's tasks and their statuses |

The async tools come with the async `general-purpose` subagent, so every agent served by `mda dev` or a deployment has them. Agents run with `mda eval` don't.

An async task runs like this:

1. The agent calls `start_async_task` and keeps working.
2. The subagent runs on its own thread, in its own graph.
3. When the subagent finishes, the agent gets the result: before its next model call if it's still working, or in a new run if it's idle. The agent doesn't need to poll with `check_async_task`.
4. If the subagent pauses for approval, the task shows as `waiting` until someone answers on the subagent's thread. See [Answer approvals in channels](#answer-approvals-in-channels).

## What a subagent inherits

A subagent starts from the agent's configuration and replaces what its definition sets:

:::python
| Setting | Behavior |
| --- | --- |
| `model`, `tools`, `permissions`, `interrupt_on` | Uses the agent's setting unless the subagent sets its own |
| `system_prompt` | Uses only the subagent's prompt, not the agent's [instructions](/langsmith/managed-deep-agents-instructions) |
| `skills` | Loads only the skills the subagent lists; list `"/skills/"` to load the agent's |
| `middleware`, `response_format` | Uses only the subagent's own |
| Memory | Not loaded |
:::

:::js
| Setting | Behavior |
| --- | --- |
| `model`, `tools`, `permissions`, `interruptOn` | Uses the agent's setting unless the subagent sets its own |
| `systemPrompt` | Uses only the subagent's prompt, not the agent's [instructions](/langsmith/managed-deep-agents-instructions) |
| `skills` | Loads only the skills the subagent lists; list `"/skills/"` to load the agent's |
| `middleware`, `responseFormat` | Uses only the subagent's own |
| Memory | Not loaded |
:::

A subagent in fork mode starts with a copy of the agent's conversation and also uses the agent's instructions, middleware, skills, and memory. An async subagent in fork mode also starts with a copy of the conversation, but keeps its own prompt, tools, and middleware, so it usually doesn't reuse the agent's [prompt cache](/oss/deepagents/async-subagents#fork-mode). See [Choose a launch mode](/oss/deepagents/async-subagents#choose-a-launch-mode).

## Share the sandbox and trace

A subagent works in the agent's [sandbox](/langsmith/managed-deep-agents-sandboxes).

An async subagent starts on a new thread, separate from the agent's. Because the agent starts it as the same user, it shares the agent's sandbox. With [private threads](/langsmith/managed-deep-agents-identity), a run of the subagent from a different user gets its own sandbox. When it shares the sandbox, it uses the agent's files as they are and only refreshes connector credentials. If the agent hasn't used its sandbox yet, the subagent creates it, and the agent uses the same sandbox later.

When tracing is on, an async subagent's run appears under the agent's run in LangSmith.

## Answer approvals in channels

When an agent runs in a [channel](/langsmith/managed-deep-agents-channels), its async subagents report to the same channel thread:

1. The user asks the agent for work in a channel thread, and the agent starts an async subagent.
2. If the subagent pauses for [approval](/langsmith/managed-deep-agents-tools#human-in-the-loop), Slack shows the request in the thread, and answering it there resumes the subagent. Other channels don't post the request; resume the subagent's thread as you would any [interrupt](/langsmith/managed-deep-agents-tools#respond-to-an-interrupt), in Studio or through the API.
3. When the subagent finishes, the agent gets its result and replies in the thread: in its current run if it's still working, or in a new run the subagent starts if it's idle. Turning off parent notifications stops the new run.

Managed Deep Agents doesn't post a subagent's answer to the channel; the agent decides what to tell the user.

## Evaluate an agent

`mda eval` runs without an Agent Server, so it can't evaluate an agent that declares async subagents. Evaluated agents also don't get the async `general-purpose` subagent or the async task tools.
