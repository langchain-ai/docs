Self-hosted LangSmith uses a Slack app that your operator creates and configures. The deployment exchanges OAuth codes and sends [Engine notifications](/langsmith/engine-notifications) and [alert notifications](/langsmith/alerts) directly to Slack. Its Client Secret and encrypted bot tokens stay in your deployment. This integration does not require backend access to LangSmith Cloud.

If Slack is not configured on your instance, contact your operator. The operator follows the setup instructions below. After setup, users connect a workspace through Slack authorization without supplying app credentials themselves.

<Note>
This connection requires a LangSmith release that supports native Slack notifications on self-hosted deployments. Confirm release availability with your account representative before configuring your deployment.
</Note>

{/* Publication prerequisite: confirm the minimum supported LangSmith release and Helm chart version. */}

This integration requires access to Slack and does not support air-gapped installations or bring-your-own-cloud data-plane workspaces. Connecting or disconnecting a workspace requires the `organization:manage` permission in LangSmith and permission to install apps in Slack.

## Create your Slack app

Your operator creates one Slack app for the deployment. Use the following [app manifest](https://docs.slack.dev/reference/app-manifest/) to configure the bot and its required permissions.

1. Replace the URL in `oauth_config.redirect_urls` with your deployment's exact HTTPS callback URL. For the standard ingress, use `https://<your-langsmith-host>/api/v1/platform/slack/callback`. Include your configured base path before `/api` if your deployment uses one. For a custom ingress, use the URL that reaches the Slack callback on your deployment.
2. Open [Your Apps](https://api.slack.com/apps) and select **Create New App** > **From an app manifest**.
3. Choose your Slack workspace, select the **JSON** tab, and paste the manifest below. Review the app configuration and create the app.
4. Under **Basic Information** > **App Credentials**, find the **Client ID** and **Client Secret**. Store these in your deployment's secret manager. You do not send them to LangChain.

```json
{
  "display_information": {
    "name": "LangSmith Notifications",
    "description": "Engine and alert notifications from your LangSmith deployment"
  },
  "features": {
    "bot_user": {
      "display_name": "LangSmith Notifications",
      "always_online": false
    }
  },
  "oauth_config": {
    "redirect_urls": [
      "https://langsmith.example.com/api/v1/platform/slack/callback"
    ],
    "scopes": {
      "bot": [
        "chat:write",
        "channels:read",
        "channels:join",
        "channels:history",
        "groups:read",
        "groups:history",
        "app_mentions:read",
        "reactions:write",
        "commands",
        "users:read",
        "users:read.email"
      ]
    }
  },
  "settings": {
    "org_deploy_enabled": false,
    "socket_mode_enabled": false,
    "token_rotation_enabled": false
  }
}
```

The manifest contains configuration, not credentials. Slack generates the app credentials after creation. The manifest creates a bot user, sets the callback, and requests the scopes used by the integration.

Keep token rotation disabled. The integration stores bot tokens and does not refresh rotating tokens. Socket Mode and Event Subscriptions are not required for notification delivery.

If your Slack workspace restricts app installation, obtain approval from its administrator.

## Configure your deployment

Configure these variables on the LangSmith backend using your deployment's [environment variable configuration](/langsmith/self-host-environment-variables):

| Variable | Value |
| --- | --- |
| `LANGSMITH_SLACK_CLIENT_ID` | Your Slack app's Client ID. |
| `LANGSMITH_SLACK_CLIENT_SECRET` | Your Slack app's Client Secret, supplied from a secret. |
| `LANGSMITH_SLACK_REDIRECT_URI` | The exact HTTPS callback URL saved in Slack. |
| `LANGSMITH_URL` | Your deployment's browser-facing URL. Notification links and the return after authorization use this URL. |

For Helm deployments, including deployments on EKS, configure the app credentials through `platformBackend.deployment.extraEnv`. For example, provision a Kubernetes Secret named `slack-app-credentials` with keys `client-id` and `client-secret` in the deployment namespace, then reference it:

```yaml
platformBackend:
  deployment:
    extraEnv:
      - name: LANGSMITH_SLACK_CLIENT_ID
        valueFrom:
          secretKeyRef:
            name: slack-app-credentials
            key: client-id
      - name: LANGSMITH_SLACK_CLIENT_SECRET
        valueFrom:
          secretKeyRef:
            name: slack-app-credentials
            key: client-secret
      - name: LANGSMITH_SLACK_REDIRECT_URI
        value: "https://langsmith.example.com/api/v1/platform/slack/callback"
```

Replace the callback URL with your registered URL. The chart sets `LANGSMITH_URL` from its hostname configuration. Configure `config.hostname`, `config.frontendHostname` if the UI uses a separate host, and `config.basePath` as needed. Avoid adding a duplicate `LANGSMITH_URL` through `extraEnv` or `commonEnv`.

Keep the existing `API_KEY_SALT` encryption secret consistent between the API and notification workers. They use it to encrypt and decrypt stored bot tokens. See [Use an existing secret](/langsmith/self-host-using-an-existing-secret).

Restart the affected services and reload LangSmith. The Slack connection controls appear when the backend has its Client ID, Client Secret, and a valid callback URL configured.

## Allow network access

For this integration, allow the following connections:

- **Backend:** Outbound HTTPS to the Slack Web API at `slack.com` for OAuth exchange, channel lookup, and notifications.
- **Browser:** Access to Slack and your deployment's callback URL and UI.

Slack redirects the browser to your callback. Slack does not need inbound network access to your deployment for notification delivery.

## Connect a Slack workspace

A Slack workspace connection belongs to your LangSmith organization, so you can reuse it across projects:

1. Open your LangSmith instance and go to **Settings** > your organization's **General** settings.
2. Under **Slack**, click **Connect Slack**. You can also connect from the channel selector when configuring an Engine or alert notification.
3. Choose the Slack workspace, review your app's requested permissions, and click **Allow**. Complete administrator approval if required.
4. After the browser returns to LangSmith, choose the connected workspace and channel in your notification settings. For a private channel, invite your configured Slack app to the channel first, then refresh the picker. LangSmith automatically joins the public channel you select.
5. Save the destination with the event types and priority you need. See [Configure Engine notifications](/langsmith/engine-notifications#notify-a-slack-channel) or [Configure alert notifications](/langsmith/alerts#step-4-configure-notification-channel).

## Verify delivery

An Engine destination sends notifications for new events that match its event types and minimum priority. Existing issues do not emit a new notification when you save the destination.

To verify an Engine destination:

1. Save a Slack destination for `issue.created` on a test project.
2. Generate a fresh issue that meets the destination's minimum priority.
3. Check that a message arrives in the selected channel and that **View issue** opens your self-hosted instance.

For an alert destination, use **Send Test Notification** as described in [Test the alert integration](/langsmith/alerts#2-test-the-integration).

Slack notifications send content outside your deployment to the selected workspace. Engine messages can include issue titles, descriptions, severity, project information, links, and recurrence charts. Alert messages include alert and workspace names, metric values, thresholds, and links. Choose channels with access appropriate for that content. See [Engine notification format](/langsmith/engine-notifications#notify-a-slack-channel) and [Alert notification format](/langsmith/alerts#notification-format).

## Troubleshoot the connection

- **Slack is not configured:** Contact your operator. Confirm that your release supports the connection and all three Slack environment variables are set. Reload the UI after restarting the backend.
- **Authorization cannot start:** Confirm that the app has a bot user, all listed scopes, and permission to install in the selected workspace.
- **Slack reports a redirect mismatch:** Ensure `LANGSMITH_SLACK_REDIRECT_URI` matches the saved Slack Redirect URL, including scheme, host, port, and path.
- **Authorization fails after returning:** Start **Connect Slack** again. Authorization state expires after 10 minutes. Check browser access to the callback, backend access to Slack, and the configured app credentials. Keep token rotation disabled.
- **A private channel is absent:** Invite your configured Slack app to the channel, then refresh the picker.
- **Messages do not arrive:** Confirm Slack Web API access, matching encryption secrets on the API and workers, and the destination's event and priority filters. If someone removed the app from Slack, reconnect the workspace.
- **Links open the wrong host:** Correct your deployment's browser-facing URL configuration.
