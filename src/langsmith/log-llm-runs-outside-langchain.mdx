---
title: Log LLM runs outside LangChain
description: Log LLM calls to LangSmith with correct token counts, cost tracking, and Playground support when using custom or non-LangChain models.
---

When you call an LLM outside of LangChain or a [supported integration](/langsmith/integrations), you need to provide specific metadata so that LangSmith can:

- Display **token counts** correctly
- Calculate **costs** automatically
- Let you **open the run in the Playground** with the correct provider and model

This guide walks through everything you need to do, with a complete end-to-end example.

<Note>
If you are using LangChain, the [OpenAI wrapper](/langsmith/trace-openai), or the [Anthropic wrapper](/langsmith/trace-anthropic), these details are handled automatically.
</Note>

## Checklist

There are four requirements for a fully functional LLM trace:

| Requirement | What to do | Enables |
|---|---|---|
| 1. Set `run_type="llm"` | Pass `run_type="llm"` to `@traceable` | LLM-specific rendering, token/cost display |
| 2. Format inputs/outputs | Use OpenAI, Anthropic, or LangChain message format | Structured message rendering, Playground support |
| 3. Set `ls_provider` and `ls_model_name` | Pass both in `metadata` | Cost tracking, Playground model selection |
| 4. Provide token counts | Set `usage_metadata` on the run | Token counts and cost calculation |

## Complete example

The following example calls a model directly and logs the trace with all required metadata:

<CodeGroup>

```python Python
import openai
from langsmith import traceable, get_current_run_tree

client = openai.Client()

@traceable(
    run_type="llm",
    metadata={
        "ls_provider": "openai",
        "ls_model_name": "gpt-4.1-mini",
    }
)
def call_model(messages: list) -> dict:
    response = client.chat.completions.create(
        model="gpt-4.1-mini",
        messages=messages,
    )

    run = get_current_run_tree()
    run.set(usage_metadata={
        "input_tokens": response.usage.prompt_tokens,
        "output_tokens": response.usage.completion_tokens,
        "total_tokens": response.usage.total_tokens,
    })

    return {
        "choices": [
            {
                "message": {
                    "role": response.choices[0].message.role,
                    "content": response.choices[0].message.content,
                }
            }
        ]
    }

result = call_model([
    {"role": "system", "content": "You are a helpful assistant."},
    {"role": "user", "content": "What is the capital of France?"},
])
```

```typescript TypeScript
import OpenAI from "openai";
import { traceable, getCurrentRunTree } from "langsmith/traceable";

const client = new OpenAI();

const callModel = traceable(
  async (messages: OpenAI.ChatCompletionMessageParam[]) => {
    const response = await client.chat.completions.create({
      model: "gpt-4.1-mini",
      messages,
    });

    const run = getCurrentRunTree();
    run.metadata.usage_metadata = {
      input_tokens: response.usage?.prompt_tokens ?? 0,
      output_tokens: response.usage?.completion_tokens ?? 0,
      total_tokens: response.usage?.total_tokens ?? 0,
    };

    return {
      choices: [
        {
          message: {
            role: response.choices[0].message.role,
            content: response.choices[0].message.content,
          },
        },
      ],
    };
  },
  {
    run_type: "llm",
    name: "call_model",
    metadata: {
      ls_provider: "openai",
      ls_model_name: "gpt-4.1-mini",
    },
  }
);

await callModel([
  { role: "system", content: "You are a helpful assistant." },
  { role: "user", content: "What is the capital of France?" },
]);
```

</CodeGroup>

The rest of this guide explains each requirement in detail.

## Set `run_type="llm"`

Mark the function as an LLM call by setting `run_type="llm"` on the `@traceable` decorator. This tells LangSmith to render the trace with structured message display and enable token/cost tracking.

<CodeGroup>

```python Python
from langsmith import traceable

@traceable(run_type="llm")
def call_model(messages: list) -> dict:
    ...
```

```typescript TypeScript
import { traceable } from "langsmith/traceable";

const callModel = traceable(
  async (messages) => { ... },
  { run_type: "llm" }
);
```

</CodeGroup>

Without `run_type="llm"`, the run defaults to type `chain` and LangSmith will not display token counts or costs.

## Format inputs and outputs

LangSmith renders messages and enables Playground integration only when inputs and outputs follow a recognized format. Supported formats are:

- **OpenAI Chat Completions** — `{"messages": [...]}` inputs, `{"choices": [{"message": {...}}]}` outputs
- **Anthropic Messages** — standard Anthropic API request/response shapes
- **LangChain** — messages with typed `content` arrays

See [Log LLM calls](/langsmith/log-llm-trace#messages-format) for the full schema of each format.

The most common format is OpenAI Chat Completions:

```python
inputs = {"messages": [{"role": "user", "content": "Hello"}]}

outputs = {
    "choices": [
        {"message": {"role": "assistant", "content": "Hi there!"}}
    ]
}
```

<Tip>
If your model uses a custom I/O format, use `process_inputs` and `process_outputs` on `@traceable` to convert it before logging. See [Converting custom I/O formats](/langsmith/log-llm-trace#converting-custom-io-formats-into-langsmith-compatible-formats).
</Tip>

## Set `ls_provider` and `ls_model_name`

These two metadata fields identify the model provider and model name. They enable:

- **Automatic cost calculation** by matching against the [model pricing table](https://smith.langchain.com/settings/workspaces/models)
- **Playground integration** — when you open an LLM run in the Playground, LangSmith uses these fields to select the correct provider and model

<CodeGroup>

```python Python
@traceable(
    run_type="llm",
    metadata={
        "ls_provider": "openai",
        "ls_model_name": "gpt-4.1-mini",
    }
)
def call_model(messages: list) -> dict:
    ...
```

```typescript TypeScript
const callModel = traceable(
  async (messages) => { ... },
  {
    run_type: "llm",
    metadata: {
      ls_provider: "openai",
      ls_model_name: "gpt-4.1-mini",
    },
  }
);
```

</CodeGroup>

Common `ls_provider` values include: `openai`, `anthropic`, `google_genai`, `google_vertexai`, `bedrock`, `mistral`, `fireworks`, `groq`, `deepseek`.

You can also pass additional model configuration parameters like `ls_temperature`, `ls_max_tokens`, and `ls_stop`. See the [metadata parameters reference](/langsmith/ls-metadata-parameters) for the full list.

<Warning>
Both `ls_provider` and `ls_model_name` must be set together. If either is missing, cost tracking will not work and the Playground may not select the correct model.
</Warning>

## Provide token counts

Token counts enable cost calculation and are displayed in the trace UI. There are two ways to provide them:

### Option A: Set `usage_metadata` on the run tree (recommended)

This approach does not change your function's return value:

<CodeGroup>

```python Python
from langsmith import traceable, get_current_run_tree

@traceable(
    run_type="llm",
    metadata={"ls_provider": "openai", "ls_model_name": "gpt-4.1-mini"}
)
def call_model(messages: list) -> dict:
    response = call_llm(messages)

    run = get_current_run_tree()
    run.set(usage_metadata={
        "input_tokens": response.usage.prompt_tokens,
        "output_tokens": response.usage.completion_tokens,
        "total_tokens": response.usage.total_tokens,
    })

    return format_output(response)
```

```typescript TypeScript
import { traceable, getCurrentRunTree } from "langsmith/traceable";

const callModel = traceable(
  async (messages) => {
    const response = await callLlm(messages);

    const run = getCurrentRunTree();
    run.metadata.usage_metadata = {
      input_tokens: response.usage.prompt_tokens,
      output_tokens: response.usage.completion_tokens,
      total_tokens: response.usage.total_tokens,
    };

    return formatOutput(response);
  },
  {
    run_type: "llm",
    metadata: { ls_provider: "openai", ls_model_name: "gpt-4.1-mini" },
  }
);
```

</CodeGroup>

### Option B: Return `usage_metadata` in the output

Include `usage_metadata` as a top-level key in the returned dictionary:

```python
@traceable(
    run_type="llm",
    metadata={"ls_provider": "openai", "ls_model_name": "gpt-4.1-mini"}
)
def call_model(messages: list) -> dict:
    return {
        "choices": [{"message": {"role": "assistant", "content": "..."}}],
        "usage_metadata": {
            "input_tokens": 25,
            "output_tokens": 10,
            "total_tokens": 35,
        },
    }
```

### Supported `usage_metadata` fields

| Field | Type | Description |
|---|---|---|
| `input_tokens` | `int` | Total input/prompt tokens |
| `output_tokens` | `int` | Total output/completion tokens |
| `total_tokens` | `int` | Sum of input + output (optional, can be inferred) |
| `input_token_details` | `object` | Breakdown: `cache_read`, `cache_creation`, `audio`, `text`, `image` |
| `output_token_details` | `object` | Breakdown: `reasoning`, `audio`, `text`, `image` |

To send costs directly (for non-linear pricing), you can also include `input_cost`, `output_cost`, and `total_cost` fields. See [Cost tracking](/langsmith/cost-tracking) for details.

## Configure model pricing

For automatic cost calculation, the model must have a pricing entry in LangSmith. Pre-built pricing is included for OpenAI, Anthropic, and Google models.

For other providers, add a custom pricing entry at [Model pricing settings](https://smith.langchain.com/settings/workspaces/models). The entry matches against the `ls_provider` and `ls_model_name` values in your trace metadata.

See [Cost tracking](/langsmith/cost-tracking#llm-calls-automatically-track-costs-based-on-token-counts) for full details on configuring model pricing.

## Open a run in the Playground

When an LLM run has properly formatted messages and `ls_provider`/`ls_model_name` metadata, you can open it directly in the [Playground](/langsmith/prompt-engineering-concepts#playground) from the trace view. The Playground will automatically select the correct provider and model, and populate the input messages from the trace.

To use this feature:

1. Navigate to a trace in your [tracing project](https://smith.langchain.com)
2. Select the LLM run in the trace tree
3. Click **Open in Playground**

This lets you iterate on prompts, adjust model parameters, and re-run the call without writing code.

<Note>
The Playground supports a specific set of providers. See [Playground model providers](/langsmith/playground-model-providers) for the full list. If your `ls_provider` does not match a supported Playground provider, you can still view the trace but may not be able to re-run it in the Playground.
</Note>

## Troubleshooting

<AccordionGroup>
  <Accordion title="Token counts are not showing up">
    Verify that:
    - `run_type` is set to `"llm"` (not `"chain"` or omitted)
    - You are setting `usage_metadata` with `input_tokens` and `output_tokens` (either via `run.set()` or in the function output)
    - The `usage_metadata` field uses the [recognized field names](#supported-usage_metadata-fields) (`input_tokens`, not `prompt_tokens`)
  </Accordion>

  <Accordion title="Costs are not showing up">
    Verify that:
    - Both `ls_provider` and `ls_model_name` are set in `metadata`
    - Token counts are present in the trace (costs are derived from tokens + pricing)
    - The model has a pricing entry in [Model pricing settings](https://smith.langchain.com/settings/workspaces/models) — check that the provider and model name regex match your values
  </Accordion>

  <Accordion title="Playground does not select the correct model">
    Verify that:
    - `ls_provider` matches a [supported Playground provider](/langsmith/playground-model-providers)
    - `ls_model_name` matches a model available from that provider
    - Inputs and outputs follow a [recognized message format](/langsmith/log-llm-trace#messages-format)
  </Accordion>

  <Accordion title="Messages are not rendering in the trace UI">
    Verify that:
    - `run_type` is set to `"llm"`
    - Inputs contain a `messages` key with a list of message objects
    - Each message has `role` and `content` fields
    - The format matches one of: OpenAI Chat Completions, Anthropic Messages, or LangChain format
    - See [Log LLM calls](/langsmith/log-llm-trace) for the full format specification
  </Accordion>
</AccordionGroup>
