A sandbox gives a managed deep agent an isolated filesystem and shell for working with files, running code, and executing commands.

<ManagedDeepAgentsPrivateBetaNote />

Put the sandbox declaration under `sandbox/`:

:::python
```text
my-agent/
  agent.py
  sandbox/
    __init__.py
```
:::

:::js
```text
my-agent/
  agent.ts
  sandbox/
    index.ts
```
:::

For the full project layout, see [Project structure](/langsmith/managed-deep-agents-project-structure).

## Configure a sandbox

Use a sandbox when the agent needs to write files, run code, or execute shell commands.

`mda init` scaffolds a sandbox declaration. Managed Deep Agents enables the sandbox only while the `sandbox/` directory is present.

<Steps>
  <Step title="Declare the sandbox" id="declare-the-sandbox">

:::python

Declare the sandbox with `define_sandbox`. Managed Deep Agents uses [LangSmith Sandboxes](/langsmith/sandboxes) for this backend:

```python sandbox/__init__.py
from managed_deepagents import define_sandbox

sandbox = define_sandbox(
    scope="thread",
    idle_ttl_seconds=600,
    default_timeout=600,
)
```
:::

:::js

Declare the sandbox with `defineSandbox`. Managed Deep Agents uses [LangSmith Sandboxes](/langsmith/sandboxes) for this backend:

```ts sandbox/index.ts
import { defineSandbox } from "managed-deepagents";

export const sandbox = defineSandbox({
  scope: "thread",
  idleTtlSeconds: 600,
  defaultTimeout: 600,
});
```
:::

LangSmith uses its default sandbox template unless you pass a custom template or snapshot. For the full option list, see [Parameters](#parameters).

  </Step>
  <Step title="Choose a scope (Optional)" id="choose-a-scope">

| Scope | Behavior |
| --- | --- |
| `thread` (default) | Creates one sandbox for each durable thread and reuses it across runs on that thread. |
| `agent` | Shares one sandbox across threads handled by the agent process. |

<Warning>
An agent-scoped sandbox lets threads read and modify the same files. Use it only for intentionally shared state.
</Warning>

  </Step>
</Steps>

## Parameters

:::python
| Parameter | Description |
| --- | --- |
| `scope=` | Reuse boundary. `"thread"` creates one sandbox per durable thread. `"agent"` shares one sandbox across threads handled by the agent process. Default: `"thread"`. |
| `idle_ttl_seconds=` | Seconds of inactivity before MDA may reclaim the sandbox. |
| `default_timeout=` | Default timeout for each command, in seconds. |
| `template_name=` | _Optional_. LangSmith sandbox template to boot from. Do not set this together with `snapshot_id`. |
| `snapshot_id=` | _Optional_. LangSmith snapshot ID to boot from. Do not set this together with `template_name`. |
| `api_key=` | _Optional_. LangSmith API key for sandbox provisioning. Prefer `.env` when possible. |
:::

:::js
| Parameter | Description |
| --- | --- |
| `scope` | Reuse boundary. `"thread"` (default) creates one sandbox per durable thread. `"agent"` shares one sandbox across threads handled by the agent process. |
| `idleTtlSeconds` | Seconds of inactivity before MDA may reclaim the sandbox. |
| `defaultTimeout` | Default timeout for each command, in seconds. |
| `templateName` | _Optional_. LangSmith sandbox template to boot from. Do not set this together with `snapshotId`. |
| `snapshotId` | _Optional_. LangSmith snapshot ID to boot from. Do not set this together with `templateName`. |
| `apiKey` | _Optional_. LangSmith API key for sandbox provisioning. Prefer `.env` when possible. |
:::

:::python
Do not set `name`, `image`, `snapshot`, or `image_name`. The managed runtime owns those.
:::

:::js
Do not set `name`, `image`, `snapshot`, or `imageName`. The managed runtime owns those.
:::

## How the agent uses the sandbox

The agent uses built-in filesystem tools such as [`ls`](/oss/deepagents/tools#built-in-harness-tools), [`read_file`](/oss/deepagents/tools#built-in-harness-tools), [`write_file`](/oss/deepagents/tools#built-in-harness-tools), [`edit_file`](/oss/deepagents/tools#built-in-harness-tools), [`glob`](/oss/deepagents/tools#built-in-harness-tools), and [`grep`](/oss/deepagents/tools#built-in-harness-tools), and runs shell commands with [`execute`](/oss/deepagents/tools#built-in-harness-tools). Use [instructions](/langsmith/managed-deep-agents-instructions) to specify where the agent should work and what it must not modify.

## Disable the sandbox

Delete the `sandbox/` directory to opt out, such as for an agent that only needs its prompt, memory, and tools.

For existing deployments, deleting the deployment with `mda delete` also deletes the managed sandboxes associated with it.

## Deployment

Managed Deep Agents owns sandbox naming, reuse, recovery, and cleanup. For platform-level lifecycle details, see [Sandboxes](/langsmith/sandboxes).

## When to use a sandbox

| Goal | Use |
| --- | --- |
| Write files, run code, or execute shell commands in isolation | Sandbox |
| Store durable knowledge across threads | [Memory](/langsmith/managed-deep-agents-memory) |
| Always-on behavior without a filesystem | [Instructions](/langsmith/managed-deep-agents-instructions) |

For more information, see [Project structure](/langsmith/managed-deep-agents-project-structure).
