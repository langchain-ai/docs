<Info>
This page applies to self-hosted LangSmith instances that are not running in offline (air-gapped) mode and have operational telemetry metrics turned on.
</Info>

With `config.telemetry.metrics` set to `true` (the default), your LangSmith instance exports operational metrics to `https://beacon.langchain.com` over OpenTelemetry (OTLP) once a minute. For what operational telemetry is and how it differs from billing and usage telemetry, see [Egress for billing and operational telemetry](/langsmith/self-host-egress).

LangChain's telemetry collector keeps only the metrics listed on this page. It drops any other metric it receives, so a metric that is not on this page is not stored. Metrics contain counts, sizes, durations, and status values. They do not contain trace contents, database records, or information about your users.

## How metrics are collected

| Source | Collected by | When it is sent |
| --- | --- | --- |
| LangSmith services | Each LangSmith service, as it handles requests and jobs | Always, while metrics are on |
| PostgreSQL | The `queue` deployment, every minute | Always, while metrics are on |
| Redis | The `queue` deployment, every minute | Always, while metrics are on |
| ClickHouse | The `queue` deployment, every minute | When `clickhouse.enabled` is `true` |
| SmithDB | The `queue` deployment, every minute | LangSmith v0.18 or later, when `smithdb.enabled` is `true` |
| SmithDB migration | The `queue` deployment, every minute | LangSmith v0.18 or later, when `smithdb.langsmith.migration.enabled` is `true` |

To turn off all metrics, set `config.telemetry.metrics` to `false`. To stop sending the metrics of a single datastore, such as SmithDB, see [Disable metrics for one datastore](/langsmith/self-host-egress#disable-metrics-for-one-datastore).

## Attributes

Each metric carries attributes that identify the instance that sent it: `env`, plus `customer.id` and `customer.name`, which come from your license. The collector removes every other resource attribute.

On individual data points, the collector keeps only the following attributes and removes the rest, including request paths:

`app_name`, `cmd`, `collector`, `component`, `dbname`, `error_type`, `fault`, `file_type`, `job_kind`, `kind`, `level`, `maxmemory_policy`, `method`, `mode`, `name`, `op`, `outcome`, `pointer_type`, `quantile`, `queue_name`, `reason`, `redis_mode`, `redis_version`, `replica`, `resource_name`, `resource_type`, `result`, `role`, `rule_owner`, `source`, `state`, `status`, `status_code`, `store_type`, `unit_kind`, `value`, `version`, and `workload_kind`.
