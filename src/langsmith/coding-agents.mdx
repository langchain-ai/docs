LangSmith for Coding Agents gives engineering leaders a single view of what their coding agent budget is buying. It attaches the pull requests a coding agent opens to the traces behind them, so you can see cost across harnesses and model providers next to the outcomes they produced.

<Note>
LangSmith for Coding Agents is in public beta on LangSmith Cloud. Coding agent traces count toward your regular LangSmith tracing usage.
</Note>

## Key concepts

### Outcomes

An outcome links a [thread](/langsmith/threads) to a GitHub pull request or GitLab merge request. One thread can open several PRs, and several threads can contribute to the same PR. LangSmith groups spend by PR state: open, closed, or merged. Spend that never led to a PR appears alongside those groups rather than being dropped.

Cost per merged PR gives engineering and finance a shared unit of measure. A merge does not prove the code is good, and useful agent work does not always become a PR, so the coding agent overview shows comprehensive spend including sessions without a PR outcome.

### Coding agents dashboard

The coding agent overview page aggregates cost across every coding agent you trace and ties it to the pull requests your agents worked on. At the top, a set of high-level metrics reads like an executive summary, and you can click in to see how each one changes over time.

Additional charts break down cost by:

- Model
- GitHub user
- PR status (open, closed, or merged)

Ready-made views highlight:

- Your 20 most expensive attributed PRs
- Cost by thread length

Every outlier links back to the threads and sessions behind it, so you can open the exact conversation and see what the agent did in that session.

## Set up

Setup follows three steps.

<Steps>
  <Step title="Install the LangSmith plugin">
    Install the LangSmith plugin for each coding agent your team uses. Plugins are available for the following agents:

    - Claude Code
    - OpenAI Codex
    - Cursor
    - GitHub Copilot
    - Deep Agents

    For Claude Code, run these commands inside a session:

    ```bash
    /plugin marketplace add langchain-ai/langsmith-claude-code-plugins
    /plugin install langsmith-tracing@langsmith-claude-code-plugins
    /reload-plugins
    ```

    For other agents, see the tracing guide for your specific tool:

    - [Claude Code](/langsmith/trace-claude-code)
    - [OpenAI Codex](/langsmith/trace-with-codex)
    - [Cursor](/langsmith/trace-with-cursor)
    - [GitHub Copilot](/langsmith/trace-with-vscode-copilot)
    - [Deep Agents](/langsmith/trace-deep-agents)
  </Step>
  <Step title="Connect GitHub">
    Connect your GitHub account in LangSmith settings to allow LangSmith to link pull requests to traces. LangSmith reads PR state (open, closed, or merged) and attributes cost to the threads that opened each PR.
  </Step>
  <Step title="Open the coding agent overview page">
    Navigate to the coding agent overview page in LangSmith. Start with one agent and one repository. Spend appears broken out by pull request as soon as the first threads come in.
  </Step>
</Steps>

## What teams use it for

### Find the PRs that cost the most

Sort by attributed cost to see which pull requests were the most expensive to produce. Each one traces back to its threads, the models involved, and the GitHub user behind it. This is also how you catch usage that falls outside expected patterns.

### Set a thread policy and check that it worked

Spend concentrates in long threads, since every new turn carries the conversation so far along with it. Starting a fresh thread avoids paying for that context again. Leadership can set a policy—such as a turn limit—in a custom plugin or at their model gateway. Use the cost-by-thread-length view to see whether behavior actually changed after the policy went into effect.

### Measure a model change

When you move engineers from one model to another, compare usage and cost before and after the switch. Outcomes sit in the same view, so you can also check whether the new model still gets work merged.

### Keep skills current

Skill calls are traced too. You can see which skills your team's agents rely on most and which ones have gone stale and need an update.
