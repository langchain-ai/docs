A Coding agent in LangSmith collects traces from your team's coding agents, such as Claude Code, Codex, and Cursor, and shows their cost on the agent Overview. When you connect GitHub, LangSmith links each [thread](/langsmith/threads) to the pull requests it opened, so you can see the cost of each pull request and the cost per merged pull request.

<Note>
Coding agents are in beta and are available in [agent-based workspaces](/langsmith/migrate-to-agent-based-workspaces).
</Note>

## How LangSmith links cost to pull requests

LangSmith links each thread to the pull requests it opened. One thread can open several pull requests, and several threads can contribute to one pull request. Each pull request is open, closed, or merged. Spend from threads that did not open a pull request is grouped as **Unattributed**, so the totals still include it.

A merged pull request is not proof that the code is good, and useful agent work does not always end in a pull request. Read cost per merged pull request together with total spend.

## Set up a coding agent

### Create a Coding agent

[Create an agent](/langsmith/create-an-agent) and set **Agent type** to **Coding**. To change the type of an existing agent, open the **Agent settings** menu on its Overview and select **Change agent type**.

Only Coding agents show pull request connections and the cost charts on this page.

### Send traces to the agent

Install the LangSmith plugin for each coding agent your team uses, and set `agent_id` to your Coding agent's identifier. Traces from every coding agent can go to the same agent, so its Overview covers all of them.

| Coding agent | Set up tracing | Deploy to your organization |
|---|---|---|
| Claude Code | [Install the plugin](/langsmith/trace-claude-code#install-the-plugin) | [Deploy to your organization](/langsmith/trace-claude-code#deploy-to-your-organization) |
| OpenAI Codex | [Install the plugin](/langsmith/trace-with-codex#install-the-plugin) | [Deploy to your organization](/langsmith/trace-with-codex#deploy-to-your-organization) |
| Cursor | [Install the plugin](/langsmith/trace-with-cursor#install-the-plugin) | [Deploy to your organization](/langsmith/trace-with-cursor#deploy-to-your-organization) |
| GitHub Copilot | [Configure tracing](/langsmith/trace-with-vscode-copilot#configure-tracing) | Not available |
| Deep Agents | [Trace Deep Agents](/langsmith/trace-deep-agents) | Not available |

To trace every engineer's sessions, admins can install the Claude Code, Codex, and Cursor plugins with a mobile device management (MDM) tool such as Jamf or Microsoft Intune. The managed file at `~/.langsmith-plugins/managed.json` can lock `agent_id`, the workspace, and [strict auth](/langsmith/trace-claude-code#require-a-working-sign-in) so traces cannot go anywhere else. For the format and file requirements, see [Lock settings](/langsmith/trace-claude-code#lock-settings).

Until the agent has a production trace, its Overview shows **No traces yet**.

### Connect GitHub

On the agent Overview, click **Track pull requests** and connect a GitHub account. You can reuse a GitHub installation that is already connected to another agent in the workspace. After you connect, the button shows **GitHub Connected**. Click it to add accounts or change repository access.

Cost per merged pull request, merge rate, and the pull request cards appear after you connect.

## Read the agent Overview

A time range picker, a filter, and a **Refresh** button apply to every chart on the page.

The summary cards at the top show **LLM cost**, **Tokens**, **Threads**, **Turns / thread**, **Cache rate**, **Merge rate**, and **Cost / merged PR**, each compared with the period before. Select a card to chart that metric over time. You can group the chart by pull request state, user, Git user, repository, harness, provider, or model.

Below the summary, the Overview shows these cards:

- **Work type**: Threads by the kind of work they ask for: feature, bugfix, refactor, investigation, review, or off topic. This card requires the Coding Work Type evaluator. The card walks you through setting it up.
- **Skill usage**: Which skills the agent calls.
- **Cost per PR by state**: Average cost of open, closed, and merged pull requests.
- **Top PRs by cost**: The most expensive pull requests in the time range, with each one's state, threads, turns, and cost. Each row links to the pull request on GitHub.
- **Cost by conversation length**: Threads grouped by number of turns, with total cost and average cost per thread and per turn.

Charts link to the threads behind each value, so you can open a conversation and see what the agent did.

## Example uses

### Find expensive pull requests

Use **Top PRs by cost** to find the pull requests that cost the most. Open a pull request's threads to see the models and the user behind it.

### Check the effect of shorter threads

Each new turn sends the conversation so far, so long threads cost more per turn. If you ask engineers to start new threads more often, use **Cost by conversation length** to check whether long threads become less common.

### Compare models

When your team switches models, group cost over time by model to compare spend before and after. Check **Merge rate** in the same time range to see whether pull requests still get merged.
