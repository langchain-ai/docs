SmithDB components expose application metrics and can export logs and traces to your existing observability stack. Set this up after you deploy SmithDB services and before you tune capacity or migrate historical data. It provides the signals to validate those changes and investigate failures.

## Metrics

Each SmithDB component exposes application metrics at the fixed `/metrics` path on its HTTP port. Configure your monitoring stack to discover the pods by adding scrape annotations to each component:

<Accordion title="Sample Prometheus configuration">

```yaml
smithdb:
  query:
    deployment:
      annotations:
        prometheus.io/scrape: "true"
        prometheus.io/path: "/metrics"
        prometheus.io/port: "8060"
  ingestion:
    deployment:
      annotations:
        prometheus.io/scrape: "true"
        prometheus.io/path: "/metrics"
        prometheus.io/port: "8050"
  compaction:
    deployment:
      annotations:
        prometheus.io/scrape: "true"
        prometheus.io/path: "/metrics"
        prometheus.io/port: "8070"
  compactionWorker:
    deployment:
      annotations:
        prometheus.io/scrape: "true"
        prometheus.io/path: "/metrics"
        prometheus.io/port: "9000"
  clusterManager:
    deployment:
      annotations:
        prometheus.io/scrape: "true"
        prometheus.io/path: "/metrics"
        prometheus.io/port: "8090"
  migration:
    job:
      annotations:
        prometheus.io/scrape: "true"
        prometheus.io/path: "/metrics"
        prometheus.io/port: "9040"
```

On LangSmith 0.16, set the migration annotations under `smithdb.migration.deployment.annotations`.

With `smithdb.topology: unified`, annotate the unified pod and scrape port `8060` only:

```yaml
smithdb:
  unified:
    deployment:
      annotations:
        prometheus.io/scrape: "true"
        prometheus.io/path: "/metrics"
        prometheus.io/port: "8060"
```

</Accordion>

These are Prometheus-style annotations. Providers with their own discovery format, such as Datadog, need that format applied to the same ports and path.

For which metrics to watch and how to read them, see [Essential SmithDB metrics](/langsmith/self-host-smithdb-metrics).

### Histograms and export sets

Collect histograms with their buckets. Without the buckets, you cannot calculate percentiles, such as the p95 query latency.

The Helm chart sets each SmithDB component to export the `critical` set of metrics. This set includes all SmithDB metrics that the [recommended alerts](/langsmith/self-host-smithdb-alerts) use. To export all metrics, set `SMITHDB_<COMPONENT>__METRICS__MODE=all` in `smithdb.commonEnv` or in the `extraEnv` of one component. Do not set the same variable in both places, because the chart then fails to render.

### LangSmith ingestion metrics

The LangSmith ingestion pipeline sends all runs to SmithDB, and SmithDB problems often show there first. Collect these metrics together with the SmithDB metrics:

| Service | Port | Metrics |
|---|---|---|
| Platform backend | `1986` | `langsmith_asynq_ingestion_queue_pending`, `langsmith_asynq_ingestion_queue_retry`, `langsmith_asynq_ingestion_queue_archived`, `langsmith_asynq_queue_latency_seconds` |
| Ingest queue | `1989` | `langsmith_ingestion_e2e_latency_seconds`, `langsmith_ingestion_api_to_worker_latency_seconds`, `langsmith_ingestion_worker_to_store_latency_seconds`, `langsmith_ingest_task_failures_total` |

Both services expose these metrics at `/metrics`. For the other LangSmith services, see [Export LangSmith telemetry](/langsmith/export-backend).

The [dashboard collection examples](/langsmith/self-host-observability-dashboards#smithdb) do not collect all of these metrics. Add the missing metrics to your collection configuration.

### Infrastructure metrics

Monitor the PostgreSQL metastore, Redis, Kubernetes, and cloud services with your existing infrastructure monitoring. For managed Redis and PostgreSQL, use the metrics of your cloud provider.

## Logs and traces

SmithDB uses the chart-level OpenTelemetry tracing configuration described in [Export LangSmith telemetry to your observability backend](/langsmith/export-backend), with one difference: SmithDB exports over OTLP gRPC only. Set `config.observability.tracing.exporter` to `grpc`. With `http`, SmithDB export stays disabled and SmithDB logs remain console-only. The chart adds SmithDB pod and container names as OpenTelemetry resource attributes automatically.

To customize SmithDB log filtering, set `RUST_LOG` for all SmithDB workloads through `smithdb.commonEnv`:

```yaml
smithdb:
  commonEnv:
    - name: RUST_LOG
      value: "warn,smithdb_query=debug,vortex=warn"
```

Confirm the collector is reachable from the LangSmith namespace, apply the chart, then confirm telemetry arrives. To set up or tune a collector, see [Configure your collector for LangSmith telemetry](/langsmith/langsmith-collector).
