LangSmith Deployment is a workflow orchestration runtime — durable execution, task queues, checkpointing, replay — designed for agent workloads. It handles the infrastructure that agents need to run reliably: long-running stateful execution, human-in-the-loop pauses, real-time streaming, and horizontal scaling.

## Runtime foundation

At its core, LangSmith Deployment is a durable execution engine. Your agents run on a managed task queue with automatic checkpointing, so any run can be retried, replayed, or resumed from the point of failure — not from scratch. Configurable [retry policies](/oss/langgraph/use-graph-api#retry-policies) let you control backoff, max attempts, and which exceptions trigger retries on a per-node basis. Runs survive process restarts, infrastructure failures, and code revisions mid-execution.

For details on how containers, processes, and the task queue work together, see [Agent Server: Runtime architecture](/langsmith/agent-server#runtime-architecture).

## What the runtime provides for agents

### Streaming and real-time interaction

Agents need to show their work while they're working. Resumable streams survive network interruptions — clients reconnect and pick up without losing progress. Multiple [streaming modes](/langsmith/streaming) (`values`, `updates`, `messages`) control what surfaces to the user. When users send new input while the agent is mid-run ([double-texting](/langsmith/double-texting)), the runtime handles concurrent interactions on the same thread without data races or corrupted state.

### Human-in-the-loop

Agents pause for human review, approval, or input — then [resume exactly where they stopped](/langsmith/add-human-in-the-loop), potentially hours or days later. LangGraph's `interrupt()` and `Command(resume=...)` handle the application logic. The runtime manages state persistence and execution resumption underneath, so paused agents don't consume resources and resumed agents don't lose context.

### Background and scheduled execution

Not all agent work is request-driven. [Background runs](/langsmith/background-run) execute asynchronously without blocking the caller. [Cron jobs](/langsmith/cron-jobs) run agents on a schedule — for example, a daily summary agent that emails a digest every evening.

### Agent IDE

[LangGraph Studio](/langsmith/studio) ships with every deployment. Visualize execution graphs, inspect state at any checkpoint, step through runs, modify state mid-execution, and branch to explore alternative paths. Works against your local dev server and production deployments alike.

## Capabilities

| | |
|---|---|
| **Durable task queue** | Checkpoint-based recovery and replay with configurable [retry policies](/oss/langgraph/use-graph-api#retry-policies) |
| **[LangGraph Studio](/langsmith/studio)** | Real-time visualization, state inspection, interactive debugging, time-travel |
| **[Resumable streaming](/langsmith/streaming)** | Network-resilient streams across `values`, `updates`, and `messages` modes |
| **[Scheduled and background runs](/langsmith/cron-jobs)** | Cron schedules and [async dispatch](/langsmith/background-run) |
| **[Double-texting](/langsmith/double-texting)** | Concurrent inputs on the same thread — queuing, cancellation, or parallel execution |
| **[Horizontal scaling](/langsmith/agent-server-scale)** | Distribute long-running agents across workers without dropping in-progress work |
| **[Human-in-the-loop](/langsmith/add-human-in-the-loop)** | Interrupt, inspect, approve, edit, and resume at any checkpoint |
| **[RemoteGraph](/langsmith/use-remote-graph)** | Compose agents across deployments using the same local API |
| **Protocol support** | Native [MCP](/langsmith/server-mcp), [Agent-to-Agent (A2A)](/langsmith/server-a2a) |
| **[Auth and access control](/langsmith/auth)** | [Custom authentication](/langsmith/custom-auth), resource authorization, [agent auth](/langsmith/agent-auth) |
| **Server customization** | [Custom routes](/langsmith/custom-routes), [middleware](/langsmith/custom-middleware), [lifespan hooks](/langsmith/custom-lifespan), [encryption at rest](/langsmith/encryption) |

## Deployment options

- **[Cloud](/langsmith/deploy-to-cloud)** — Fully managed. Push from a git repo.
- **[Hybrid](/langsmith/deploy-with-control-plane)** — Runs in your cloud, managed by the LangSmith [control plane](/langsmith/control-plane).
- **[Self-hosted](/langsmith/deploy-standalone-server)** — Fully self-managed in your own infrastructure.

Same runtime, same APIs. What changes is who manages the infrastructure. See [Platform setup](/langsmith/platform-setup) for a comparison.
