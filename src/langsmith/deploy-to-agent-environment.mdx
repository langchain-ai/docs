Deploying to an agent environment binds a [deployment](/langsmith/deployment) to one [agent](/langsmith/agents) and one of that agent's [environments](/langsmith/agent-environments). Two flags carry the binding, and the LangGraph CLI and the `mda` CLI both accept them.

Use it to keep a staging build and a production build of the same agent apart, so each one reports into its own environment.

<AgentBetaNote />

## Prerequisites

Both CLIs need the following:

- A [LangSmith API key](/langsmith/create-account-api-key) in `.env` or your shell environment.
- A project folder holding `langgraph.json`. Run the CLI from that folder.
- An agent-based workspace, because the flags require agent mode on the workspace.

An org-scoped API key also needs the workspace, and each CLI reads it from a different variable: `LANGSMITH_TENANT_ID` for the LangGraph CLI, and `LANGSMITH_WORKSPACE_ID` for the `mda` CLI. A workspace-scoped key needs neither. The LangGraph CLI prompts for the value when the key is org-scoped and the shell is interactive.

## Addressing flags

Both CLIs take the same two flags:

- **`--agent-id`**: The agent to deploy to. The value is the agent's identifier, not its display name. For which value is which, see [Identifiers and display names](/langsmith/agents#identifiers-and-display-names).
- **`--agent-environment`**: The environment the deployment reports into, and one of `development`, `staging`, or `production`. A deployment cannot take `local`, which is also the one environment that [does not display on deployments](/langsmith/agent-environments#select-an-environment).

The flags name the same pair that [agent addressing](/langsmith/log-traces-to-agent) names on the tracing side, and they read the same two variables, `LANGSMITH_AGENT_ID` and `LANGSMITH_AGENT_ENVIRONMENT`.

## Deploy with the LangGraph CLI

These flags require `langgraph-cli` v0.4.32 or later. To deploy:

1. Install the CLI:

   ```bash
   uv tool install --force "langgraph-cli>=0.4.32"
   ```

1. Deploy, naming the agent and the environment:

   ```bash
   langgraph deploy --agent-id my-agent --agent-environment staging --remote
   ```

Two rules govern the pair. Pass both flags or neither, because either one on its own is rejected. And do not combine them with `--name` or `--deployment-id`, which name a deployment directly and are rejected alongside an agent.

`--remote` forces a remote build. Without it, the CLI builds locally whenever Docker is available. For the rest of the flags, see [`langgraph deploy`](/langsmith/cli#deploy).

## Deploy with the mda CLI

These flags require `managed-deepagents` 0.7.5.dev4, which is a prerelease build. Install that version exactly, because 0.8.0 and later do not accept the flags and a version range resolves to a build that rejects them. To deploy:

1. Install the CLI as a tool, and pin the same version as a project dependency:

   ```bash
   uv tool install --force --prerelease allow "managed-deepagents==0.7.5.dev4"
   uv add --prerelease allow "managed-deepagents==0.7.5.dev4"
   ```

1. Deploy the project in the current folder:

   ```bash
   mda deploy . --agent-id my-agent --agent-environment staging
   ```

Pinning both keeps the global `mda` binary and the project's own dependency on one version. For the rest of the flags, see [Deploy projects](/langsmith/managed-deep-agents-cli#deploy-projects), and for deploying without the agent flags, see [Deploy a Managed Deep Agent](/langsmith/managed-deep-agents-deploy).
