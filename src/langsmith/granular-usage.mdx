<Note>
For LangSmith Cloud, granular billable usage data collection started on January 5, 2026. Data is not available for usage before this date. 

For self-hosted instances, data collection begins when the feature is enabled via the following environment variables, or after [upgrading to a version with it enabled by default](/langsmith/self-hosted-changelog#langsmith-0-13-12).

```env
DEFAULT_ORG_FEATURE_ENABLE_GRANULAR_USAGE_REPORTING=true
GRANULAR_USAGE_TABLE_ENABLED=true
```
</Note>

LangSmith provides granular billable usage APIs that allow you to retrieve detailed usage data broken down by workspace, project, user, or API key. Two billable domains are supported via sibling endpoints:

- **Trace usage** — number of traces ingested. Read via `GET /granular-usage/traces`.
- **LangSmith Deployment usage** — nodes executed, agent runs, and agent uptime for [LangSmith Deployment](/langsmith/billing#langsmith-deployment) (formerly LangGraph Platform). Read via `GET /granular-usage/deployment`.

Both endpoints share the same query parameters (time range, workspace filter, grouping dimension) and respond with the same time-bucketed shape. The data sources are separate, so a record returned by one endpoint will not appear in the other.

These APIs enable you to:

- Track usage across different teams or workspaces
- Identify which users or API keys are consuming the most traces or running the most agents
- Analyze usage patterns over time
- Export usage data for internal reporting

## Prerequisites

- You must have the [`organization:read` permission](/langsmith/organization-workspace-operations) to access granular usage data.
- You can only view usage for workspaces you have read access to.

## View in the UI

You can also view granular usage data in the [LangSmith UI](https://smith.langchain.com):

1. Navigate to **Settings** > **Billing and Usage**
2. Select the **Granular Usage** tab
3. Use the controls to:
   - Select a time range:
      - Last 7 days, 30 days, 3 months, 6 months, 1 year, or custom
   - Choose aggregation level (daily, weekly, or monthly)
   - Group by workspace, project, user, or API key
   - Filter to specific workspaces
4. Click **Export CSV** to download the data

## Shared query parameters

Both the trace and Deployment endpoints accept the same query parameters:

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `start_time` | datetime | Yes | Start of the time range (ISO 8601 format) |
| `end_time` | datetime | Yes | End of the time range (must be after start_time) |
| `workspace_ids` | array of UUIDs | Yes | Filter results to specific workspaces |
| `group_by` | string | No | Dimension to group by. One of: `workspace`, `project`, `user`, `api_key`. Default: `workspace` |

The `stride` field in each response indicates the time bucket size used for aggregation, calculated from the requested time range:

| Time range | Aggregation | Stride |
|------------|-------------|--------|
| Less than 1 day | Hourly (traces only)* | `hours: 1` |
| 1-31 days | Daily | `days: 1` |
| 32-93 days (~3 months) | Weekly | `days: 7` |
| 94-366 days (~1 year) | Monthly | `days: 30` |
| More than 366 days | Yearly | `days: 365` |

*The Deployment endpoint's minimum stride is daily — it reads from a daily aggregate, so sub-day ranges still bucket at one day.

## API endpoints

### Trace usage

Retrieve granular trace usage data.

```
GET /api/v1/orgs/current/billing/granular-usage/traces
```

<Note>
The legacy path `GET /api/v1/orgs/current/billing/granular-usage` is a deprecated alias that returns the same response. Prefer `/granular-usage/traces` in new integrations — it pairs symmetrically with `/granular-usage/deployment`.
</Note>

#### Response

```json
{
  "stride": {
    "days": 1,
    "hours": 0
  },
  "usage": [
    {
      "time_bucket": "2026-01-15T00:00:00Z",
      "dimensions": {
        "workspace_id": "uuid",
        "workspace_name": "My Workspace"
      },
      "traces": 1500
    }
  ]
}
```

#### Example: Get trace usage by workspace

<CodeGroup>
```python Python
import httpx
from datetime import datetime, timedelta, timezone

client = httpx.Client(
    base_url="https://api.smith.langchain.com",
    headers={"x-api-key": "<your-api-key>"}
)

end_time = datetime.now(timezone.utc)
start_time = end_time - timedelta(days=30)

response = client.get(
    "/api/v1/orgs/current/billing/granular-usage/traces",
    params={
        "start_time": start_time.isoformat(),
        "end_time": end_time.isoformat(),
        "workspace_ids": ["<workspace-id>"],
        "group_by": "workspace"
    }
)

data = response.json()
for record in data["usage"]:
    print(f"{record['time_bucket']}: {record['traces']} traces")
```

```typescript TypeScript
const response = await fetch(
  `https://api.smith.langchain.com/api/v1/orgs/current/billing/granular-usage/traces?` +
  new URLSearchParams({
    start_time: new Date(Date.now() - 30 * 24 * 60 * 60 * 1000).toISOString(),
    end_time: new Date().toISOString(),
    workspace_ids: "<workspace-id>",
    group_by: "workspace"
  }),
  {
    headers: {
      "x-api-key": "<your-api-key>"
    }
  }
);

const data = await response.json();
for (const record of data.usage) {
  console.log(`${record.time_bucket}: ${record.traces} traces`);
}
```

```bash cURL
curl -X GET "https://api.smith.langchain.com/api/v1/orgs/current/billing/granular-usage/traces?\
start_time=2026-01-01T00:00:00Z&\
end_time=2026-01-15T00:00:00Z&\
workspace_ids=<workspace-id>&\
group_by=workspace" \
  -H "x-api-key: <your-api-key>"
```
</CodeGroup>

#### Example: Get trace usage by user

<CodeGroup>
```python Python
response = client.get(
    "/api/v1/orgs/current/billing/granular-usage/traces",
    params={
        "start_time": start_time.isoformat(),
```

#### Export trace usage as CSV

```
GET /api/v1/orgs/current/billing/granular-usage/traces/export
```

<Note>
The legacy path `GET /api/v1/orgs/current/billing/granular-usage/export` is a deprecated alias and returns the same CSV.
</Note>

Returns a CSV file with one row per (time bucket, dimension) tuple. All dimension columns are always present; only the columns matching the selected `group_by` are populated.

| Column | Description |
|--------|-------------|
| Time Bucket Start | Start of the time bucket |
| Time Bucket End | End of the time bucket |
| Workspace ID | UUID of the workspace (when grouping by workspace) |
| Workspace Name | Name of the workspace (when grouping by workspace) |
| Project ID | UUID of the project (when grouping by project) |
| Project Name | Name of the project (when grouping by project) |
| User ID | UUID of the user (when grouping by user) |
| User Email | Email of the user (when grouping by user) |
| API Key Short Key | Short key identifier (when grouping by API key) |
| Traces | Number of traces in the time bucket |

<CodeGroup>
```python Python
response = client.get(
    "/api/v1/orgs/current/billing/granular-usage/traces/export",
    params={
        "start_time": start_time.isoformat(),
        "end_time": end_time.isoformat(),
        "workspace_ids": ["<workspace-id>"],
        "group_by": "workspace"
    }
)

with open("trace_usage_report.csv", "wb") as f:
    f.write(response.content)
```

```bash cURL
curl -X GET "https://api.smith.langchain.com/api/v1/orgs/current/billing/granular-usage/traces/export?\
start_time=2026-01-01T00:00:00Z&\
end_time=2026-01-15T00:00:00Z&\
workspace_ids=<workspace-id>&\
group_by=workspace" \
  -H "x-api-key: <your-api-key>" \
  -o trace_usage_report.csv
```
</CodeGroup>

### LangSmith Deployment usage

Retrieve granular usage for [LangSmith Deployment](/langsmith/billing#langsmith-deployment) (formerly LangGraph Platform). Each record carries three metrics together so a single fetch powers the whole Deployment view.

```
GET /api/v1/orgs/current/billing/granular-usage/deployment
```

Data collection for Deployment usage began once the rollup job started running (see [self-hosted changelog](/langsmith/self-hosted-changelog) for the LangSmith version that enables it). The minimum aggregation stride is daily.

#### Response

```json
{
  "stride": {
    "days": 1,
    "hours": 0
  },
  "usage": [
    {
      "time_bucket": "2026-01-15T00:00:00Z",
      "dimensions": {
        "workspace_id": "uuid",
        "workspace_name": "My Workspace"
      },
      "nodes_executed": 12500,
      "agent_runs": 320,
      "agent_uptime_seconds": 86400
    }
  ]
}
```

| Field | Description |
|-------|-------------|
| `nodes_executed` | Total LangGraph nodes executed in the time bucket. |
| `agent_runs` | Total agent runs (graph invocations) in the time bucket. |
| `agent_uptime_seconds` | Total replica uptime, in seconds, summed across deployment replicas. The deduplicated standby minutes used for invoicing is computed separately by the billing pipeline; this field is the raw sum surfaced for breakdown and analysis. |

#### Example: Get Deployment usage by workspace

<CodeGroup>
```python Python
response = client.get(
    "/api/v1/orgs/current/billing/granular-usage/deployment",
    params={
        "start_time": start_time.isoformat(),
        "end_time": end_time.isoformat(),
        "workspace_ids": ["<workspace-id>"],
        "group_by": "workspace"
    }
)

data = response.json()
for record in data["usage"]:
    print(
        f"{record['time_bucket']}: "
        f"{record['nodes_executed']} nodes, "
        f"{record['agent_runs']} runs, "
        f"{record['agent_uptime_seconds']}s uptime"
    )
```

#### Export Deployment usage as CSV

```
GET /api/v1/orgs/current/billing/granular-usage/deployment/export
```

Returns a CSV file with one row per (time bucket, dimension) tuple. The CSV uses the same dimension columns as the trace export but with three metric columns instead of one:

| Column | Description |
|--------|-------------|
| Time Bucket Start | Start of the time bucket |
| Time Bucket End | End of the time bucket |
| Workspace ID | UUID of the workspace (when grouping by workspace) |
| Workspace Name | Name of the workspace (when grouping by workspace) |
| Project ID | UUID of the project (when grouping by project) |
| Project Name | Name of the project (when grouping by project) |
| User ID | UUID of the user (when grouping by user) |
| User Email | Email of the user (when grouping by user) |
| API Key Short Key | Short key identifier (when grouping by API key) |
| Nodes Executed | Total nodes executed in the time bucket |
| Agent Runs | Total agent runs in the time bucket |
| Agent Uptime (seconds) | Total replica uptime, in seconds |

```python Python
response = client.get(
```

## Grouping options

The `group_by` parameter determines how usage data is aggregated. The same four values are supported by both endpoints:

| Value | Description | Dimensions returned |
|-------|-------------|---------------------|
| `workspace` | Group by workspace | `workspace_id`, `workspace_name` |
| `project` | Group by project | `project_id`, `project_name` |
| `user` | Group by user | `user_id`, `user_email` |
| `api_key` | Group by API key | `api_key_short_key` |

For trace usage, "project" refers to the [LangSmith tracer session](/langsmith/observability-concepts). For Deployment usage, "project" refers to the LangSmith Deployment project (a deployed agent).
