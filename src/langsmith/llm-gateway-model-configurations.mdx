[Model configurations](/langsmith/model-configurations) are named, reusable definitions that pair a provider and model with credentials and settings. The LLM Gateway can route a request through a saved configuration when you set the model ID to `custom/<name>`. Use a configuration to reach an endpoint that a provider-prefixed model ID cannot address, such as a custom OpenAI-compatible endpoint.

## Understand what the gateway uses

A bring-your-own-key gateway call normally targets a model with a provider-prefixed ID such as `openai/gpt-5.4-mini`. When the model ID is `custom/<name>`, the gateway reads the following from the saved configuration instead:

- **Provider and model**: The gateway sends the configuration's model name upstream, replacing the `custom/<name>` value in the request body.
- **API key secret**: The gateway authenticates to the provider with the workspace secret named in the configuration.
- **Connection settings**: The base URL, the OpenAI provider API (Chat Completions or Responses), the Vertex AI project and location, and the **Preferred Bedrock Endpoint** for Amazon Bedrock, where the provider uses them. Only the gateway reads the Bedrock endpoint setting.

The gateway ignores generation parameters saved on the configuration, such as temperature, top P, and max output tokens. Pass these in each API request instead.

Workspace admins create configurations under **Settings** > **Model configurations**, and organization admins create [organization-scoped configurations](/langsmith/model-configurations#organization-scoped-model-configurations). For the steps, see [Create a configuration](/langsmith/model-configurations#create-a-configuration).

## Choose a configuration type

The gateway can call configurations for these providers:

- **Custom endpoints**: OpenAI-compatible, Anthropic-compatible, and [TypeSafe-compatible](/langsmith/typesafe-compatible-model) endpoints.
- **Built-in providers**: Anthropic, Amazon Bedrock, Fireworks, Gemini Enterprise Agent Platform, Google Gemini, OpenAI, TypeSafe, and xAI.

A configuration for any other provider returns an error. Each custom endpoint type treats its URL differently:

- **OpenAI-compatible**: the base URL is the API root. The gateway appends the request path, such as `/chat/completions`, without adding `/v1`, so include `/v1` in the base URL if the server expects it.
- **Anthropic-compatible**: the gateway sends requests to the URL exactly as entered, so enter the full Messages endpoint, such as `https://example.com/v1/messages`. Only Messages requests are supported.
- **TypeSafe-compatible**: the gateway appends `/v1/systemone` unless you clear **Append /v1/systemone**, in which case it uses the URL exactly as entered.

## Call a configuration through the gateway

Use `custom/<name>` as the model ID in any standard gateway request, replacing `<name>` with the configuration's exact name as shown in **Settings** > **Model configurations**:

<CodeGroup>

```bash Cloud
curl https://gateway.smith.langchain.com/v1/responses \
    -H "Authorization: Bearer $LANGSMITH_API_KEY" \
    -H "Content-Type: application/json" \
    -d '{"model":"custom/my-openai-config","input":"Hello!"}'
```

```bash BYOC
curl https://<data_plane_host>/gateway/v1/responses \
    -H "Authorization: Bearer $LANGSMITH_API_KEY" \
    -H "Content-Type: application/json" \
    -d '{"model":"custom/my-openai-config","input":"Hello!"}'
```

</CodeGroup>

The gateway looks up the configuration by name in the API key's workspace, including [organization-scoped configurations](/langsmith/model-configurations#organization-scoped-model-configurations), routes the request to the configured provider and endpoint, and returns the response in the [API format](/langsmith/llm-gateway-api-formats) the client used. When a workspace configuration and an organization-scoped configuration share a name, the gateway uses the workspace configuration.

The gateway does not check the [Feature Access](/langsmith/model-configurations#feature-access) table, so an organization-scoped configuration is callable without enabling it in the workspace. It also ignores [OAuth client credentials](/langsmith/model-configurations#oauth-client-credentials) saved on a configuration and authenticates with the configuration's API key secret.

{/* Source for the two facts above: langchainplus smith-go/gateway/custom_openai_provider_config.go loadAnyCustomProviderConfig and findByName (no feature-access filter); the gateway package never calls the smith-go/model_oauth broker. Not tested end to end. X15. */}

Saved configurations do not appear in the `GET /v1/models` list, so share configuration names with developers directly.

If a [model access policy](/langsmith/llm-gateway-model-access-policies#allow-saved-model-configurations) applies to the request, the policy must allow saved model configurations, or the gateway returns a `403` response.

A saved configuration can also be the primary model or a backup model in a fallback chain. For the steps, including how to give a Playground prompt its own fallback behavior, see [Model fallbacks](/langsmith/llm-gateway-fallbacks).
