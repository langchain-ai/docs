**Ask Engine** (formerly LangSmith Chat and Polly) is an interactive agent built into [LangSmith](https://smith.langchain.com) and Slack. Ask questions about your agents in plain language to investigate traces, create LangSmith assets, configure alerts, and schedule follow-ups or recurring reports. Every answer links back to the underlying traces and issues.

On self-hosted and [BYOC](/langsmith/byoc) deployments, Ask Engine runs with your own configured model providers. For setup instructions, see [Configure Insights and Chat on self-hosted LangSmith](/langsmith/self-host-insights-chat).

## Where you can use Ask Engine

Ask Engine brings the same investigation and action toolkit to two surfaces:

- **LangSmith web app**: Select **Ask Engine** in the top-right header anywhere in your [workspace](/langsmith/administration-overview#workspaces). Press `Cmd+I` (Mac) or `Ctrl+I` (Windows/Linux) to toggle the panel, and `Cmd+Shift+O` or `Ctrl+Shift+O` to start a new thread.
- **Slack**: Mention `@langsmith` in any channel where the LangSmith Slack app is installed, or send a direct message to ask questions, set up alerts, and schedule checks.

## Get started

On LangSmith Cloud, Ask Engine works out of the box with LangChain-managed inference and a monthly LangChain Standard Unit (LSU) allowance. You do not need to configure a model API key to start.

<Tabs>
  <Tab title="Web app">
    To start using Ask Engine in LangSmith:

    1. Open an agent, tracing project, dataset, or Playground view in [LangSmith](https://smith.langchain.com).
    2. Select **Ask Engine** in the top-right header, or press `Cmd+I` (Mac) / `Ctrl+I` (Windows/Linux).
    3. Ask a question about your traces, errors, prompts, or evaluations.
  </Tab>
  <Tab title="Slack">

    To set up and use Ask Engine in Slack:

    <Steps>
      <Step title="Install the LangSmith Slack app">
        In LangSmith, go to **Settings** > **General** > **Slack** and select **Connect Slack** to authorize the app for your Slack workspace. Invite the LangSmith app to any private channels where you want to use it.
      </Step>
      <Step title="Mention @langsmith in a channel or DM">
        Start a request in any channel with `@langsmith <request>`, or send a direct message to the LangSmith app.
      </Step>
      <Step title="Link your LangSmith account">
        On your first request, Ask Engine sends a private, visible-only-to-you sign-in link. Complete the one-click LangSmith sign-in, and Ask Engine continues your original request automatically.
      </Step>

## What Ask Engine can do

Ask Engine matches its execution path to your request. It uses lightweight tools for quick metric lookups and starts an isolated sandbox when deeper trace analysis is needed, keeping routine questions fast while supporting multi-step investigations.

<a id="observability"></a>

### Investigate traces, threads, and issues

Ask Engine analyzes [agents and environments](/langsmith/observability-concepts#agents-and-environments), individual [traces](/langsmith/observability-concepts#traces), conversation [threads](/langsmith/observability-concepts#threads), and [Engine issues](/langsmith/engine-issues). Every finding includes links to supporting traces or issues, and Slack replies include native charts or tables when comparing trends or metrics.

<a id="engine"></a>

**Example prompts:**

- `"What is the error rate on this agent today?"`
- `"Why did latency spike yesterday?"`
- `"What are the worst open issues on the support bot?"`
- `"Did the user seem frustrated in this thread, and was the problem resolved?"`
- `"Summarize what happened in this trace and show where time was spent"`

<a id="evaluation"></a>

### Create datasets, evaluators, and custom views

Turn findings directly into LangSmith assets. Ask Engine can create [datasets](/langsmith/manage-datasets) from filtered traces, build LLM-as-judge [evaluators](/langsmith/evaluators), compare [experiments](/langsmith/analyze-an-experiment), assist with [annotation queues](/langsmith/annotation-queues), and build [custom views](/langsmith/annotation-queue-custom-views) or [custom apps](/langsmith/custom-apps).

**Example prompts:**

- `"Make a dataset from this week's thumbs-down traces"`
- `"Add an LLM-as-judge helpfulness evaluator to this agent"`
- `"Which experiment performed best, and what patterns appear in the failures?"`
- `"Show examples with errors in this dataset"`

<a id="prompt-engineering"></a>
<a id="playground"></a>

### Optimize prompts

In the [Playground](/langsmith/prompt-engineering-concepts#playground) and [Prompt Hub](/langsmith/prompt-context-hub#prompts), Ask Engine edits prompts conversationally, generates tools and output schemas, and explains shared prompts.

**Example prompts:**

- `"Simplify the instructions and make the tone more concise"`
- `"Generate an output schema for this prompt"`
- `"What tools does this prompt use?"`

### Hand off long-term goals to Engine

Some requests require ongoing optimization rather than a one-time answer. When you share a broader objective, such as `"Reduce agent cost by 30% this quarter"`, Ask Engine proposes a goal in [LangSmith Engine](/langsmith/engine). After you confirm, Engine tracks that goal over time and files recommendations under it.

## Approvals and permissions

Ask Engine respects your workspace access controls and asks before making changes:

- **Explicit confirmation**: Before creating or modifying a LangSmith asset (such as a dataset, evaluator, alert, or Engine goal), Ask Engine shows a summary of the proposed change, such as the dataset name, filter, and example count. Select **Confirm** to apply the change or **Cancel** to make no changes.
- **Per-user permissions**: Every request runs with the LangSmith permissions of the person who sent the message. Users with read-only access can investigate data, but cannot create datasets, evaluators, or alerts.
- **Private confirmation in Slack**: Confirmation prompts in Slack are visible only to the requester. Teammates cannot confirm actions on another person's behalf.

## Use Ask Engine in Slack

When you mention `@langsmith` in Slack, Ask Engine states which agent it is inspecting, runs the investigation, and replies in the thread with findings and links.

### How Ask Engine selects an agent

| Surface | Default scope | How scope is resolved |
| --- | --- | --- |
| **Web app** | Current page context | Uses the agent, project, trace, dataset, or prompt open in LangSmith. |
| **Slack channel** | Inferred per thread | Uses the first match: (1) an agent named in the message, (2) the agent already used earlier in the thread, or (3) a guess from your most active agents, stated in one line before answering. |
| **Slack DM** | Across your agents | Compares across all agents you have access to (for example, `"Which of my agents got worse this week?"`). |

### Threads, teammates, and Slack Connect

- **Teammate follow-ups**: When a teammate replies in a Slack thread, Ask Engine runs with that teammate's own LangSmith permissions. Teammates without access to the agent receive an access error and see no data beyond what is already posted in the thread.
- **Slack Connect channels**: In channels that include external members, Ask Engine avoids posting workspace data to the shared channel and replies privately or offers direct message delivery.

## Set up alerts, follow-ups, and scheduled reports

Ask Engine handles real-time monitoring, one-time follow-ups, and recurring reports from Slack or LangSmith.

| Request type | Example | Where it posts | Ownership and lifecycle |
| --- | --- | --- | --- |
| **Alert** | `"Tell me if thumbs-down goes above 10%"` | New top-level channel message each time it fires; one confirmation reply in the setup thread | Shared on the project; runs until deleted by anyone with edit access |
| **One-time follow-up** | `"Check again after tomorrow's deploy"` | Same Slack thread, mentioning the requester | Personal; runs once at the confirmed time, then ends |
| **Recurring report or check** | `"Every Monday, summarize feedback on the support bot"` | New top-level channel message each run (replies continue that thread) | Personal; runs on a schedule in your timezone until paused, deleted, or past an optional end date |

### Create and manage alerts

Ask Engine can create, list, update, delete, and test [LangSmith alert rules](/langsmith/alerts) in plain language. For open-ended requests such as `"Keep an eye on feedback"`, Ask Engine inspects recent history and proposes a concrete threshold before asking you to confirm.

Real-time alerts evaluate a single project over windows up to 60 minutes across run count, error count or rate, average latency, cost, and feedback score. Real-time alerts do not support metrics such as p95 latency, token counts, daily budgets, or multi-agent checks. For those requests, Ask Engine explains the limitation and offers either the closest real-time alert or a scheduled hourly or daily check.

### Schedule follow-ups and recurring reports

- **One-time follow-ups**: Ask Engine confirms a concrete time (for example, `"Check again after tomorrow's deploy"`), investigates at that time, posts findings in the same thread mentioning you, and ends.
- **Recurring reports and checks**: Schedule recurring summaries or judgment-based checks on a cadence (minimum hourly) in your timezone. Include an end date for time-boxed monitoring, such as `"Every day until Friday, report on the checkout-v2 rollout"`. Each run starts a new top-level message in the channel, and replies in that thread continue the investigation.
- **List, pause, or stop**: Ask `"What are you watching for me?"` to list your personal schedules, `"What alerts are on the support bot?"` to list shared project alerts, or tell Ask Engine to pause, resume, or stop a specific rule or schedule. Anyone with edit permissions on the project can delete a shared alert. Only the owner can pause or delete a personal schedule.

## Usage and billing

### LangSmith Cloud

Ask Engine usage is measured in **LangChain Standard Units (LSUs)**. Organizations receive a monthly LSU allowance for Ask Engine that resets each month and does not roll over. Once the monthly allowance is exhausted, additional usage draws from your organization's LangChain commitment under its contracted terms.

View your allowance, consumption, and remaining balance in LangSmith. For plan details, see [LangChain pricing](https://www.langchain.com/pricing).

### Existing BYOK organizations

Organizations that completed at least one successful Ask Engine (formerly LangSmith Chat) interaction using their own model credentials in the 90 days before launch continue using bring-your-own-key (BYOK) without consuming Ask Engine LSUs. Configuring a key without qualifying usage in that 90-day window does not qualify. Organizations using LangChain-managed inference draw from the monthly LSU allowance and credit system.

<Note>
When using your own model provider credentials, Ask Engine calls model providers from LangSmith egress IP addresses. If your model provider or proxy restricts traffic by IP, allowlist the addresses listed in [Allowlist IP addresses](/langsmith/cloud-platform-features#allowlist-ip-addresses).
</Note>

### Self-hosted and BYOC deployments

Self-hosted and [BYOC](/langsmith/byoc) deployments continue using your own configured [model providers](/langsmith/model-configurations) and do not consume Ask Engine LSUs. For encryption keys, provider configuration, and Helm settings, see [Configure Insights and Chat on self-hosted LangSmith](/langsmith/self-host-insights-chat).

## Troubleshooting

- **Ask Engine says you do not have permission**: Ask Engine enforces your LangSmith workspace role. Request the required role or permission from a workspace admin to create datasets, evaluators, or alerts.
- **Ask Engine stopped answering on LangSmith Cloud**: Your organization reached its monthly LSU allowance or spend cap. Review usage and billing settings under **Settings** > **Billing and Usage**.
- **Mentioning `@langsmith` gets no response in Slack**: Verify an Organization Admin connected Slack under **Settings** > **General** > **Slack** and invited the LangSmith app to the channel.
- **Scheduled checks stopped running**: Personal schedules pause automatically if their owner loses LangSmith access. Shared project alerts continue running independently of individual users.
