The LLM Gateway is provider-compatible: you route calls through it by pointing your client at a gateway base URL and authenticating with a [LangSmith API key](/langsmith/create-account-api-key) instead of a provider key. How you configure this depends on whether you call models through LangChain or through a provider's native SDK (or another framework).

## Prerequisites

- Your [Organization admin](/langsmith/rbac#organization-admin) has completed [Admin setup](/langsmith/llm-gateway-admin-setup) and added provider API keys to workspace secrets.
- You have a workspace-scoped [LangSmith API key](/langsmith/create-account-api-key) with `gateway:invoke` and `workspaces:read` [permissions](/langsmith/organization-workspace-operations).

## LangChain chat models

When you build with LangChain, you can route every supported provider through the gateway with two environment variables, instead of configuring a base URL for each provider:

```bash
export LANGSMITH_GATEWAY_URL="https://gateway.smith.langchain.com"
export LANGSMITH_GATEWAY_API_KEY="lsv2_..._....cbed3e"
```

<Note>
`LANGSMITH_GATEWAY_URL` and `LANGSMITH_GATEWAY_API_KEY` are recognized by LangChain chat models and Deep Agents only. They are a convenience for LangChain users, so that you do not have to set and keep in sync a separate base URL and key for each provider. Native provider SDKs and other frameworks do not read these variables; use the [standard provider variables](#native-provider-sdks-and-other-frameworks) instead.
</Note>

With these variables set, LangChain routes each model to the correct gateway path based on its `model_provider`, so no per-model `base_url` is required:

```python
from langchain.agents import create_agent
from langchain.chat_models import init_chat_model

# Reads LANGSMITH_GATEWAY_URL and LANGSMITH_GATEWAY_API_KEY from the environment.
# Swap model and model_provider for OpenAI, Gemini, or any other supported provider.
model = init_chat_model(
    model="claude-sonnet-4-6",
    model_provider="anthropic",
)
agent = create_agent(model=model, system_prompt="You are a helpful assistant.")
result = agent.invoke({"messages": [{"role": "user", "content": "ping"}]})
print(result["messages"][-1].content)
```

Because routing is keyed off `model_provider`, using multiple providers in the same application requires no extra configuration. Initialize each model as usual:

```python
from langchain.chat_models import init_chat_model

openai_model = init_chat_model(model="gpt-4o-mini", model_provider="openai")
anthropic_model = init_chat_model(model="claude-sonnet-4-6", model_provider="anthropic")
```

### Set the base URL and key explicitly

If you prefer not to rely on the gateway-specific environment variables, set the gateway base URL and API key directly on each model. Each model points at the gateway path for its provider while sharing the same LangSmith API key:

```python
import os

from langchain.chat_models import init_chat_model

model = init_chat_model(
    model="claude-sonnet-4-6",
    model_provider="anthropic",
    base_url=os.environ["ANTHROPIC_BASE_URL"],
    api_key=os.environ["LANGSMITH_API_KEY"],
)
```

The per-provider `ANTHROPIC_BASE_URL` and related variables are defined in [Native provider SDKs and other frameworks](#native-provider-sdks-and-other-frameworks).

## Native provider SDKs and other frameworks

If you call providers through their native SDKs (or a framework that uses them), you usually do not need any code changes. The provider SDKs read their standard base-URL and API-key environment variables, so setting the variables below is enough to route existing code through the gateway.

Set these in your terminal (or add them to your shell profile to persist across sessions). Each provider has its own gateway path, and the same LangSmith API key authenticates all of them:

```bash
export BASE_URL="https://gateway.smith.langchain.com"

export ANTHROPIC_BASE_URL="$BASE_URL/anthropic"
export OPENAI_BASE_URL="$BASE_URL/openai/v1"
export GOOGLE_GEMINI_BASE_URL="$BASE_URL/gemini"

export LANGSMITH_API_KEY="lsv2_..._....cbed3e"

export ANTHROPIC_API_KEY="$LANGSMITH_API_KEY"
export OPENAI_API_KEY="$LANGSMITH_API_KEY"
export GEMINI_API_KEY="$LANGSMITH_API_KEY"
export GOOGLE_API_KEY="$LANGSMITH_API_KEY"
```

The gateway resolves the real provider keys from your workspace's Provider Secrets, so you never need local copies of provider API keys. For the full list of providers and gateway paths, see [Supported providers](/langsmith/llm-gateway#supported-providers).

## Verify the setup

Make a test call and confirm that:

1. The call succeeds (you get a response).
1. A trace appears in the `gateway` and `gateway-<short_api_key>-<api_key_id>` [tracing projects](/langsmith/llm-gateway-access#where-gateway-traces-appear) in your LangSmith workspace.

If the call fails with a `403`, check that your API key's role includes `gateway:invoke` and `workspaces:read`. If it fails with a `400` mentioning a missing provider key, ask your org admin to add the provider's key to workspace secrets.
