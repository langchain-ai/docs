The LLM Gateway is provider-compatible: you route calls through it by pointing your client at a gateway base URL and authenticating with a [LangSmith API key](/langsmith/create-account-api-key) instead of a provider key. How you configure this depends on whether you call models through LangChain or through a provider's native SDK (or another framework).

## Prerequisites

- Your [Organization admin](/langsmith/rbac#organization-admin) has completed [Admin setup](/langsmith/llm-gateway-admin-setup) and added provider API keys to workspace secrets.
- You have a workspace-scoped [LangSmith API key](/langsmith/create-account-api-key) with `gateway:invoke` and `workspaces:read` [permissions](/langsmith/organization-workspace-operations).

## Base environment variables

Set these in your terminal (or add them to your shell profile to persist across sessions). Each provider has its own gateway path, and the same LangSmith API key authenticates all of them:

```bash
export BASE_URL="https://gateway.smith.langchain.com"

export ANTHROPIC_BASE_URL="$BASE_URL/anthropic"
export OPENAI_BASE_URL="$BASE_URL/openai/v1"
export GOOGLE_GEMINI_BASE_URL="$BASE_URL/gemini"

export LANGSMITH_API_KEY="lsv2_..._....cbed3e"

export ANTHROPIC_API_KEY="$LANGSMITH_API_KEY"
export OPENAI_API_KEY="$LANGSMITH_API_KEY"
export GEMINI_API_KEY="$LANGSMITH_API_KEY"
export GOOGLE_API_KEY="$LANGSMITH_API_KEY"
```

The gateway resolves the real provider keys from your workspace's Provider Secrets—you never need local copies of provider API keys. For the full list of providers and gateway paths, see [Supported providers](/langsmith/llm-gateway#supported-providers).

## Native provider SDKs and other frameworks

If you call providers through their native SDKs (or a framework that uses them), you usually don't need any code changes. The provider SDKs read their standard base-URL and API-key environment variables, so setting the [base environment variables](#base-environment-variables) above is enough to route existing code through the gateway.

<Tabs>
  <Tab title="OpenAI SDK">
    ```python
    import os

    from openai import OpenAI

    # base_url and api_key are read from OPENAI_BASE_URL / OPENAI_API_KEY.
    client = OpenAI()
    response = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[{"role": "user", "content": "ping"}],
    )
    print(response.choices[0].message.content)
    ```
  </Tab>
  <Tab title="Anthropic SDK">
    ```python
    import os

    import anthropic

    # base_url and api_key are read from ANTHROPIC_BASE_URL / ANTHROPIC_API_KEY.
    client = anthropic.Anthropic()
    message = client.messages.create(
        model="claude-sonnet-4-6",
        max_tokens=1024,
        messages=[{"role": "user", "content": "ping"}],
    )
    print(message.content[0].text)
    ```
  </Tab>
  <Tab title="curl">
    ```bash
    curl https://gateway.smith.langchain.com/openai/v1/chat/completions \
        -H "Authorization: Bearer $LANGSMITH_API_KEY" \
        -H "Content-Type: application/json" \
        -d '{"model":"gpt-4o-mini","messages":[{"role":"user","content":"ping"}]}'
    ```
  </Tab>
</Tabs>

## LangChain chat models

When you build with LangChain, set the gateway base URL and API key explicitly on each model. This keeps configuration unambiguous when a single application uses more than one provider—each model points at the gateway path for its provider while sharing the same LangSmith API key.

```python
import os

from langchain.agents import create_agent
from langchain.chat_models import init_chat_model

# Anthropic shown here; OpenAI and Gemini are supported by swapping
# base_url and model_provider.
model = init_chat_model(
    model="claude-sonnet-4-6",
    model_provider="anthropic",
    base_url=os.environ["ANTHROPIC_BASE_URL"],
    api_key=os.environ["LANGSMITH_API_KEY"],
)
agent = create_agent(model=model, system_prompt="You are a helpful assistant.")
result = agent.invoke({"messages": [{"role": "user", "content": "ping"}]})
print(result["messages"][-1].content)
```

To use multiple providers in the same application, initialize one model per provider, each with its own `base_url`:

```python
import os

from langchain.chat_models import init_chat_model

openai_model = init_chat_model(
    model="gpt-4o-mini",
    model_provider="openai",
    base_url=os.environ["OPENAI_BASE_URL"],
    api_key=os.environ["LANGSMITH_API_KEY"],
)

anthropic_model = init_chat_model(
    model="claude-sonnet-4-6",
    model_provider="anthropic",
    base_url=os.environ["ANTHROPIC_BASE_URL"],
    api_key=os.environ["LANGSMITH_API_KEY"],
)
```

## Verify the setup

Make a test call and confirm that:

1. The call succeeds (you get a response).
1. A trace appears in the `gateway` and `gateway-<short_api_key>-<api_key_id>` [tracing projects](/langsmith/llm-gateway-access#where-gateway-traces-appear) in your LangSmith workspace.

If the call fails with a `403`, check that your API key's role includes `gateway:invoke` and `workspaces:read`. If it fails with a `400` mentioning a missing provider key, ask your org admin to add the provider's key to workspace secrets.
