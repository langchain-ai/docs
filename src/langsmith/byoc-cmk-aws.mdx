By default, a BYOC data plane on AWS encrypts data at rest with AWS-managed keys. You can instead encrypt its storage with your own [AWS KMS keys](https://docs.aws.amazon.com/kms/latest/developerguide/concepts.html#kms_keys) when you [create the data plane](/langsmith/byoc-onboarding-aws).

## What the keys encrypt

Each key applies to one service:

| Service | What the key encrypts |
|---------|-----------------------|
| `s3` | The data plane's S3 buckets, with S3 Bucket Keys enabled. |
| `ebs` | Node volumes, and ClickHouse volumes on data planes that run ClickHouse. |
| `eks` | Kubernetes secrets in the EKS cluster. |
| `rds` | RDS storage, the RDS master user secrets in Secrets Manager, and Performance Insights data. |
| `elasticache` | ElastiCache data at rest. |

Other data plane resources keep AWS-managed keys.

You can use one key for every service, or a separate key for each service. Every service is optional: a service without a key keeps AWS-managed encryption.

Keys are set only when you create a data plane. Existing data planes keep their current encryption. After creation, the `ebs`, `eks`, `rds`, and `elasticache` keys cannot change, because changing them replaces the encrypted resource. To change the `s3` key, contact the LangChain team.

## Before you begin

Each key must be a symmetric encryption KMS key in the data plane account and region. Multi-Region keys are supported.

### Allow the LangSmith roles to use the keys

In the [`langsmith-byoc-role` Terraform module](https://github.com/langchain-ai/terraform/tree/main/modules/byoc/aws/langsmith-byoc-role#customer-managed-kms-keys), set `cmk_service_key_arns` to a key ARN for each service. The provisioning role can then use each key only through its own AWS service.

```hcl
cmk_service_key_arns = {
  s3          = "arn:aws:kms:us-east-1:111122223333:key/<data-key-id>"
  rds         = "arn:aws:kms:us-east-1:111122223333:key/<data-key-id>"
  elasticache = "arn:aws:kms:us-east-1:111122223333:key/<data-key-id>"
  ebs         = "arn:aws:kms:us-east-1:111122223333:key/<data-key-id>"
  eks         = "arn:aws:kms:us-east-1:111122223333:key/<infra-key-id>"
}
```

If you [bring your own IAM roles](/langsmith/byoc-byoiam-aws), set the same `cmk_service_key_arns` in the BYOIAM module.

### Update the key policies

With the default key policy statement that enables IAM permissions, the IAM grants from the Terraform modules are enough for the LangSmith roles. The key policies must also allow these AWS principals:

- The `ebs` key: the Auto Scaling service-linked role, so new nodes can start with encrypted volumes.
- The `s3` key: VPC flow log delivery, when LangChain manages the VPC.

The [module README](https://github.com/langchain-ai/terraform/tree/main/modules/byoc/aws/langsmith-byoc-role#customer-managed-kms-keys) lists the exact key policy statements.

## Create the data plane with your keys

In **Settings > Data Planes**, create a data plane and open **Encryption keys** under **Configuration**. Choose one of these options:

- **AWS-managed keys**: The default. No customer-managed key is used.
- **One key for all services**: Enter one KMS key ARN.
- **A key per service**: Enter a KMS key ARN for each service you want to encrypt. Leave the others empty.

When you create the data plane through the API, set `customer_managed_keys` in the request body. `key_arn` covers every service, and `service_key_arns` sets a key per service:

```json
{
  "customer_managed_keys": {
    "key_arn": "arn:aws:kms:us-east-1:111122223333:key/<data-key-id>",
    "service_key_arns": {
      "eks": "arn:aws:kms:us-east-1:111122223333:key/<infra-key-id>"
    }
  }
}
```

An entry in `service_key_arns` overrides `key_arn` for that service. Without `key_arn`, only the services in `service_key_arns` use a customer-managed key.

<Warning>
If you disable or delete a key, or remove the key policy statements, every service that uses the key stops working. For example, without the `ebs` key new nodes cannot start, and without the `rds` key the databases cannot read their data. Data encrypted with a deleted key cannot be recovered.
</Warning>
