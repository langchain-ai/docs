Deploying a Managed Deep Agent compiles a code-first project into a managed LangGraph app, syncs deploy-owned context to [Context Hub](/langsmith/managed-deep-agents-context-hub), uploads the compiled source, and triggers a LangSmith hosted deployment build. The result is an [Agent Server](/langsmith/agent-server) deployment, including the Agent Server API and [MCP endpoint](/langsmith/managed-deep-agents-mcp-endpoint).

<ManagedDeepAgentsPublicBetaNote />

Deploy from a GitHub repository in the LangSmith UI, or upload your local project with the `mda` CLI. This page covers both options and secrets configuration. To test the agent before deploying, see [Develop locally with LangSmith Studio](/langsmith/managed-deep-agents-local-development). For command flags, the deploy step list, and troubleshooting, see the [CLI reference](/langsmith/managed-deep-agents-cli). To deploy a finished open-source project instead, see the [design agent](/langsmith/managed-deep-agents-design-agent) and [paid media agent](/langsmith/managed-deep-agents-paid-media-agent) templates.

## Prerequisites

Before you deploy, make sure you have:

- A LangSmith Cloud workspace or a workspace in a [BYOC data plane](/langsmith/byoc-onboarding-aws).
- For CLI deployments, a [LangSmith API key](/langsmith/create-account-api-key) for that workspace, in `.env` or your shell environment. On an interactive terminal, `mda deploy` prompts for a key or signs you in through the browser instead.
- For CLI deployments, the `mda` CLI installed from `managed-deepagents`.
:::python
- Project dependencies installed with `uv sync` for generated Python projects.
:::

:::js
- Project dependencies installed with `npm install` for TypeScript projects.
:::

- Model provider credentials, such as `OPENAI_API_KEY`. For CLI deployments, set these in `.env`, your shell environment, or LangSmith workspace secrets. For GitHub deployments, add runtime secrets in the deployment form.

## Deploy from GitHub

GitHub deployments build your Managed Deep Agent from a connected repository. You can deploy without running `mda deploy` locally and rebuild automatically when you push to a branch.

This option requires LangSmith Cloud deployment access and permission to create Agent Servers. A GitHub organization owner or admin must authorize the GitHub app to access your repository. See [Cloud deployment setup](/langsmith/deploy-to-cloud#prerequisites) for plan requirements and [Manage GitHub repository access](/langsmith/deploy-to-cloud#manage-github-repository-access) for app configuration.

To deploy from GitHub:

1. Push your [Managed Deep Agent project](/langsmith/managed-deep-agents-project-structure) to a GitHub repository.
1. In the [LangSmith UI](https://smith.langchain.com), open **Agent Servers** and select **+ Agent Server**.
1. If the **Source** selector appears, select **GitHub repository**. Authorize GitHub access if prompted, then select your repository.
1. Enter the Agent Server name and **Git Ref (Branch or Tag)**. Use a branch name or a full tag ref such as `refs/tags/v1.0.0`.
1. Select **This is a Managed Deep Agent project**.
1. Set **Project directory** to the directory containing `agent.py` or `agent.ts`. Use `.` for the repository root. Enter the project directory, not a path to `langgraph.json`.
1. For a branch, choose whether to enable automatic updates on push. Automatic updates are unavailable for tags.
1. Select **Serverless** or **Dedicated** for the [Agent Server type](/langsmith/cloud-platform-features#deployment-types).
1. Add model provider keys and other runtime secrets in the deployment form. Do not commit your `.env` file. See [Environment variables and secrets](/langsmith/env-var-cloud).
1. Select **Submit**, then monitor the build and deployment logs in LangSmith.

LangSmith prepares the Managed Deep Agent project during the hosted build, including compilation and Context Hub synchronization. You do not need to commit generated build output. When automatic updates are enabled, pushes to the selected branch trigger a new revision.

## Select a SaaS region

`LANGSMITH_ENDPOINT` selects the LangSmith region the CLI deploys to. The CLI targets GCP US by default.

Set `LANGSMITH_ENDPOINT` in your project's `.env` or your shell environment before your first deploy:

| Region | Endpoint | Deployment support |
| --- | --- | --- |
| GCP US (`smith.langchain.com`) | `https://api.smith.langchain.com` | Supported |
| GCP EU (`eu.smith.langchain.com`) | `https://eu.api.smith.langchain.com` | Supported |
| GCP APAC (`apac.smith.langchain.com`) | `https://apac.api.smith.langchain.com` | Supported |
| AWS US (`aws.smith.langchain.com`) | `https://aws.api.smith.langchain.com` | Supported |
| Azure US (`azure.smith.langchain.com`) | `https://azure.api.smith.langchain.com` | Supported |

For example, to deploy to GCP EU:

```text .env
LANGSMITH_ENDPOINT=https://eu.api.smith.langchain.com
```

Credentials must belong to the target region. Set `LANGSMITH_ENDPOINT` before the first deploy, because it also selects the region that browser sign-in authenticates against. A non-interactive run cannot fall back to browser sign-in, so in CI set `LANGSMITH_API_KEY` for the target region.

For more information on regions, see the [Regions FAQ](/langsmith/regions-faq).

<Note>
LangSmith managed tools are available in GCP US only.
</Note>

## Select a BYOC data plane

For BYOC, use Managed Deep Agents CLI and SDK v0.10 or later. Set `LANGSMITH_ENDPOINT` to your data plane's API URL, not a SaaS regional endpoint. Find the endpoint in **Settings > Data Planes**. See [BYOC usage](/langsmith/byoc-usage).

Set `LANGSMITH_API_KEY` to a key for a workspace inside that data plane. Set `LANGSMITH_WORKSPACE_ID` to the target workspace ID, or pass `--workspace-id` to `mda deploy`. Configure these values in your project's `.env` or shell environment before deploying.

The CLI derives the Deployment API URL from the data plane endpoint. Do not append `/api-host` to `LANGSMITH_ENDPOINT`.

BYOC data planes do not support Serverless Agent Servers. Run `mda deploy --push-to <image-repository>` to build and push your agent image. The CLI creates a Dedicated Agent Server by default, so you do not need to pass `--agent-server-type dedicated`.

## Deploy to LangSmith

Use the CLI to deploy the local project:

:::python
```bash
uv run mda deploy
```
:::

:::js
<CodeGroup>
    ```bash npm
    npx mda deploy
    ```

    ```bash pnpm
    pnpm exec mda deploy
    ```

    ```bash bun
    bunx mda deploy
    ```
</CodeGroup>
:::

<Tip>
`mda deploy` routes local project inputs to different managed surfaces:

```text
instructions.md + skills/**  -> Context Hub deploy-owned context
.env                         -> deploy auth + non-reserved hosted secrets, not archived
project source files         -> .mda/build source archive -> hosted deployment
schedules/**                 -> LangSmith cron jobs after the deployment is live
```
</Tip>

Set the deployment name explicitly when the directory name is not the name you want:

:::python
```bash
uv run mda deploy --name research-assistant
```
:::

:::js
<CodeGroup>
    ```bash npm
    npx mda deploy --name research-assistant
    ```

    ```bash pnpm
    pnpm exec mda deploy --name research-assistant
    ```

    ```bash bun
    bunx mda deploy --name research-assistant
    ```
</CodeGroup>
:::

`mda deploy` creates a Serverless Agent Server by default. Use `--agent-server-type dedicated` when creating a Dedicated Agent Server. The legacy `--deployment-type` spelling remains accepted. If your CLI does not recognize the Agent Server flag, use the legacy spelling or upgrade.

Serverless is available in every LangSmith Cloud region. Self-hosted and hybrid environments reject Serverless deployments. Use `dedicated` for always-on capacity.

:::python
```bash
uv run mda deploy --agent-server-type dedicated
```
:::

:::js
<CodeGroup>
    ```bash npm
    npx mda deploy --agent-server-type dedicated
    ```

    ```bash pnpm
    pnpm exec mda deploy --agent-server-type dedicated
    ```

    ```bash bun
    bunx mda deploy --agent-server-type dedicated
    ```
</CodeGroup>
:::

Use `--no-wait` to trigger the build without polling for completion:

:::python
```bash
uv run mda deploy --no-wait
```
:::

:::js
<CodeGroup>
    ```bash npm
    npx mda deploy --no-wait
    ```

    ```bash pnpm

    ```

    ```bash bun

    ```
</CodeGroup>
:::

When `--no-wait` is set, schedule reconciliation is skipped for that deploy invocation because the CLI exits before the deployment reaches `DEPLOYED`.

On success, the CLI prints the LangSmith deployment dashboard URL. For the full deploy step list, see the [CLI reference](/langsmith/managed-deep-agents-cli#deploy-projects).

## Set the Python version

<Note>
Configuring the Python version requires `managed-deepagents>=0.8.0`.
</Note>

MDA builds the deployment image on Python 3.11, 3.12, 3.13, or 3.14, and by default selects the newest that `requires-python` allows. To pin a version, add the optional `[tool.mda]` table to `pyproject.toml`:

```toml pyproject.toml
[project]
requires-python = ">=3.11"

[tool.mda]
python-version = "3.14"
```

When set, `python-version` takes a quoted `major.minor` string, with no patch version. MDA writes the resolved version to `python_version` in the generated `langgraph.json` and selects the matching [Agent Server](/langsmith/agent-server) image. `requires-python` remains the project's own compatibility requirement.

Pin it to stay on the same minor version when MDA adds support for a newer Python. To override it for a single build, set `MDA_PYTHON_VERSION`:

```bash
MDA_PYTHON_VERSION=3.12 uv run mda deploy
```

A target that `requires-python` excludes fails the build. One that depends on the image's exact patch version warns instead, because image tags do not pin patch versions.

`python-version` controls the deployment image only. Local builds, `mda dev`, Harbor task images, and [execution sandboxes](/langsmith/managed-deep-agents-sandboxes) select their interpreters separately.
:::

## Secrets and environment files

`mda deploy` reads project `.env` values before shell environment variables. Use `.env` for the LangSmith API key that authenticates the deploy and for runtime secrets the hosted deployment needs:

```text .env
LANGSMITH_API_KEY=<LANGSMITH_API_KEY>
OPENAI_API_KEY=<OPENAI_API_KEY>
GITHUB_MCP_TOKEN=<GITHUB_MCP_TOKEN>
DATABASE_URL=<DATABASE_URL>
MDA_INGRESS_SECRET=<MDA_INGRESS_SECRET>
```

`MDA_INGRESS_SECRET` is required only when the project declares [backend identity](/langsmith/managed-deep-agents-identity#configure-identity-with-your-own-backend). Deploy fails preflight when that declaration is present and the value is missing.

`LANGSMITH_API_KEY`, `LANGGRAPH_HOST_API_KEY`, `LANGCHAIN_API_KEY`, and other platform variables are reserved. They can authenticate the deploy, but they are not uploaded as user-managed deployment secrets.

Non-reserved `.env` entries, such as model provider keys, MCP tokens, and custom tool credentials, are forwarded as hosted deployment secrets when `mda deploy` creates or updates the deployment. If the configured model requires a provider key, deploy fails before upload unless that key is available from `.env`, the shell environment, or LangSmith workspace secrets. When the provider key is only in the shell environment, `mda deploy` forwards it as a secret for that deploy.

Reserved platform variables, empty values, `.env`, and `.env.*` files are not copied into the compiled build archive.

For authentication key order and reserved variables, see the [CLI reference](/langsmith/managed-deep-agents-cli#authentication).
