LangSmith organizes a workspace around its [agents](/langsmith/agents), and one control in the top bar moves between them. This page covers that control, the two views it moves between, the addresses behind those views, and what an agent's Overview shows.

<AgentBetaNote />

## Switch between agents

The agent switcher sits at the left of the top bar, after the workspace switcher and the panel collapse toggle. It reads either **All agents** or the name of the agent you are in. In a section other than the Overview, a breadcrumb follows it and names that section.

The address behind it is `/o/<workspaceId>/a/<agentIdentifier>/...`. The workspace slot takes a UUID, and the agent slot takes the agent's identifier. A hyphen in the agent slot means all agents, so `/a/-` is the agent list and `/a/<agentIdentifier>` is a single agent. Either state can be set from the address bar, which is how to link directly to one of the two views.

## The two views

The switcher moves between two views:

- **All agents**: The agents in the workspace, one card each.
- **A single agent**: That agent's Overview.

The left navigation lists the same items in both views, but two things differ. Its badge counts appear on the agent list, where they count the whole workspace, and are not shown once you select an agent, so a count beside a navigation item never describes the agent you are in. And several sections cannot be opened without an agent.

## Sections that require an agent

**All agents** is a valid state for the Overview and for Deployments, which lists every deployment in the workspace. Tracing, Monitoring, Engine, Build, and Studio each need a specific agent, and what you get when you open one with **All agents** selected depends on whether the workspace has any agents yet.

With agents to choose from, a **Pick an agent to view** screen replaces the section, below the top bar, so the switcher stays available. It holds a searchable list, and what sits under the list depends on the section: **+ New agent** on Tracing and Build, **Connect Agent Server** on Studio, and nothing on Monitoring or Engine. Build also offers a different set of agents from the other sections.

With no agents in the workspace, Build and Studio show that same screen reading **No agents available**, while Tracing, Monitoring, Engine, and Deployments show a get-started screen for the section instead of asking you to pick.

Once you pick an agent, LangSmith remembers it, so moving between these sections does not ask again, and the switcher stops offering **All agents**.

## Settings replaces the shell

Opening Settings replaces the shell: the top bar and the agent switcher are gone, the navigation splits into Organizations and Workspace sections, and a link returns to the agent views, reading **Back to LangSmith** or, from Fleet, **Back to Fleet**.

## Read the agent Overview

Selecting a single agent lands on its Overview, which shows the following, in order:

- **Metrics**: Traces over time as a line chart, then trace count, error rate, token count, and total cost, each over the period named above them.
- **Tracing**: One row per environment the agent has, including environments with no traces, with the most recent run, trace count, error rate, P50 latency, P99 latency, and description.
- **Engine**: How many active issues [Engine](/langsmith/engine-overview) has found across this agent's environments, and a link into Engine. With no issues found, the section describes Engine rather than listing them.
- **Evaluate your agent**: A pointer into [evaluators](/langsmith/evaluators).
- **Monitor your agent**: A pointer into [dashboards](/langsmith/dashboards).
- **Deployments**: The [deployments](/langsmith/deployment) bound to this agent, and a link to all of them. With none, the section describes deployment rather than listing them, as the Engine section does. It does not appear at all for an agent [built in the UI](/langsmith/build-an-agent), which runs on a Studio runtime and cannot have one.

Everything on this screen is scoped to the agent you have selected. A line above the metrics states the window and the scope they cover, reading **Showing data from the last 7 days across all environments**, so the metrics include local and staging runs rather than production alone. The tracing section below them breaks the same period out by environment.

Two names for the same agent appear on this screen, and they are not interchangeable. The heading and the switcher both show the display name. A copyable field labeled **ID** holds the identifier, which is also the value the address bar carries.

Use the copy button beside **ID** when you need the value for tracing. [Agent addressing](/langsmith/log-traces-to-agent) takes the identifier, and reconstructing it from the display name does not work, because the two can differ. For which value is which, see [Identifiers and display names](/langsmith/agents#identifiers-and-display-names).

## Create an agent

Three controls open the **New Agent** panel: **+ Agent** above the agent list, and **+ Create new agent** and **Trace existing agent** on a creation card at the end of the list, also titled **New Agent**. The first two open the panel on its grid of options, while **Trace existing agent** opens it on the Observability option. Choosing an option replaces the grid with a guided setup flow, and an **All options** link returns to the grid. The four options map to four different parts of this documentation:

- **Builder**, "Build with AI inside LangSmith". This opens the **Build** tab, which creates a Managed Deep Agent from a name and a description instead of from code. See [Build an agent in the UI](/langsmith/build-an-agent).
- **Managed Deep Agent**, "Build locally and deploy". See [Managed Deep Agents](/langsmith/managed-deep-agents-overview). This route requires a paid plan. Whether the panel marks it with a **Plus** badge depends on your plan.
- **Open Source**, "Build an agent with our open source frameworks". See [LangChain](/oss/langchain/overview).
- **Observability**, "Trace an existing agent". See the [tracing quickstart](/langsmith/observability-quickstart), or [LangSmith skills](/langsmith/skills) for the prompt-driven setup the panel offers first.

Creating an agent for an application that is traced from outside LangSmith uses a separate control. The agent switcher's **New agent** action opens a **Create a new agent** dialog, which takes an agent name and creates the agent from it. That action requires permission to create projects, and it appears on the tracing project pages, not on the agent views.
