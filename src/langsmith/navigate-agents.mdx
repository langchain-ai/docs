LangSmith organizes a workspace around its [agents](/langsmith/agents), and one control in the top bar moves between them. This page covers that control, the two views it moves between, the addresses behind those views, and what an agent's Overview shows.

<AgentBetaNote />

## Switch between agents

The agent switcher sits at the left of the top bar, after the workspace switcher and the panel collapse toggle. It reads either **All agents** or the name of the agent you are in. In a section other than the Overview, a breadcrumb follows it and names that section.

The address behind it is `/o/<workspaceId>/a/<agentIdentifier>/...`. The workspace slot takes a UUID, and the agent slot takes the agent's identifier. A hyphen in the agent slot means all agents, so `/a/-` is the agent list and `/a/<agentIdentifier>` is a single agent. Either state can be set from the address bar, which is how to link directly to one of the two views.

## The two views

The switcher moves between two views:

- **All agents**: The agents in the workspace, one card each. In an empty workspace it shows a get-started screen instead. That screen names the same four routes and opens the **New Agent** panel from a single **Get started** button.
- **A single agent**: That agent's Overview.

The left navigation lists the same items in both views, though its first row reads **All agents** on the agent list and **Overview** inside an agent. Two things differ. Its badge counts are hidden on the agent list. Once you select an agent they appear and count that agent alone, so a count beside a navigation item always describes the agent you are in. And several sections cannot be opened without an agent.

## Sections that require an agent

**All agents** is a valid state for the Overview and for Deployments, which lists every deployment in the workspace. Tracing, Monitoring, Engine, Build, and Studio each need a specific agent, and what you get when you open one with **All agents** selected depends on whether the workspace has any agents yet.

With agents to choose from, a picker screen replaces the section, below the top bar, so the switcher stays available. Most of these sections head it **Pick an agent to view**. It holds a searchable list, and what sits under the list depends on the section: **+ New agent** on Tracing and Build, **Connect Agent Server** on Studio, and nothing on Monitoring or Engine. Build lists only agents [built in the UI](/langsmith/build-an-agent), while the other sections list every agent in the workspace.

With no agents in the workspace, Build and Studio show that same screen reading **No agents available**, while Tracing, Monitoring, Engine, and Deployments show a get-started screen for the section instead of asking you to pick.

Once you pick an agent, LangSmith remembers it, so moving between these sections does not ask again. The switcher's list holds agents only, so to return to **All agents**, hover over the switcher and select **Clear agent filter**.

## Settings replaces the shell

Opening Settings replaces the shell: the top bar and the agent switcher are gone, the navigation splits into Organizations and Workspace sections, and a link returns to the agent views, reading **Back to LangSmith** or, from Fleet, **Back to Fleet**.

## Read the agent Overview

Selecting a single agent lands on its Overview, which shows the following, in order:

- **Metrics**: Trace count, error rate, token count, and total cost, each over the period named above them. In workspaces where the trace chart is enabled, a sparkline of traces over time leads the row.
- **Tracing**: One row per environment the agent has, including environments with no traces, with the most recent run, trace count, error rate, P50 latency, P99 latency, and description.
- **Engine**: How many active issues [Engine](/langsmith/engine-overview) has found across this agent's environments, and a link into Engine. With no issues found, the section describes Engine rather than listing them. On a BYOC workspace it reports that there are no open issues instead.
- **Evaluate your agent**: A pointer into [evaluators](/langsmith/evaluators).
- **Monitor your agent**: A pointer into [dashboards](/langsmith/dashboards).
- **Deployments**: The [deployments](/langsmith/deployment) bound to this agent, each row linking to that deployment. With none, the section describes deployment rather than listing them, as the Engine section does. An agent [built in the UI](/langsmith/build-an-agent) does not show this section, and neither does one created by [tracing to an identifier that does not exist yet](/langsmith/log-traces-to-agent#addressing-an-agent-that-does-not-exist).

Everything on this screen is scoped to the agent you have selected. A line above the metrics states the window and the scope they cover, reading **Showing data from the last 7 days across all environments**, so the metrics include local and staging runs rather than production alone. The tracing section below them breaks the same period out by environment.

Two names for the same agent appear on this screen, and they are not interchangeable. The switcher shows the display name. A copyable field labeled **ID** holds the identifier, which is also the value the address bar carries, shortened in the middle when it is long.

Use the copy button beside **ID** when you need the value for tracing. [Agent addressing](/langsmith/log-traces-to-agent) takes the identifier, which does not have to match the display name and cannot be derived from it. For which value is which, see [Identifiers and display names](/langsmith/agents#identifiers-and-display-names).

## Create an agent

Three controls open the **New Agent** panel: **+ Agent** above the agent list, and **+ Create new agent** and **Trace existing agent** on a creation card at the end of the list, also titled **New Agent**. The first two open the panel on its grid of options, while **Trace existing agent** opens it on the Observability option. Choosing Managed Deep Agent, Open Source, or Observability replaces the grid with a guided setup flow, and an **All options** button returns to the grid. Choosing Builder leaves the panel for the **Build** tab. The four options map to four different parts of this documentation:

- **Builder**, "Build with AI inside LangSmith". This opens the **Build** tab, which configures a Managed Deep Agent in a form instead of from code. See [Build an agent in the UI](/langsmith/build-an-agent).
- **Managed Deep Agent**, "Build locally and deploy". See [Managed Deep Agents](/langsmith/managed-deep-agents-overview). This route requires a paid plan.
- **Open Source**, "Build an agent with our open source frameworks". See [LangChain](/oss/langchain/overview).
- **Observability**, "Trace an existing agent". See the [tracing quickstart](/langsmith/observability-quickstart), or [LangSmith skills](/langsmith/skills) for the prompt-driven setup the panel offers first.

Creating an agent for an application that is traced from outside LangSmith uses a separate control. The agent switcher's **+ New agent** action opens a **Create a new agent** dialog, which takes an **Agent name** and, in its own field, an **Agent ID**. The dialog notes that the ID is used in URLs and API calls and cannot be changed later. That action requires permission to create projects, and it appears on the tracing project pages, not on the agent views.
