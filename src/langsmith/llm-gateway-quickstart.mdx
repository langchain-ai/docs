The standard LLM Gateway API lets you use the OpenAI Chat Completions, Anthropic Messages, or OpenAI Responses format with models from any configured provider. Choose the format already used by your application, then call models through the gateway root with provider-prefixed model IDs.

Use [direct model access](/langsmith/llm-gateway-direct-model-access) only when you want to access a provider's API directly and avoid the gateway's standardization layer.

## Prerequisites

Before you start, confirm that:

- Your [Organization admin](/langsmith/rbac#organization-admin) has enabled the LLM Gateway and added provider API keys to workspace secrets. To set this up, refer to [Admin setup](/langsmith/llm-gateway-admin-setup).
- You have a workspace-scoped [LangSmith API key](/langsmith/create-account-api-key) attached to a role with `gateway:invoke` and `workspaces:read` [permissions](/langsmith/organization-workspace-operations).

## 1. Choose an API format

The standard API supports these endpoints at the gateway root:

| API format | Endpoint | Base URL for compatible SDKs |
| --- | --- | --- |
| OpenAI Chat Completions | `POST /v1/chat/completions` | `https://gateway.smith.langchain.com/v1` |
| Anthropic Messages | `POST /v1/messages` | `https://gateway.smith.langchain.com` |
| OpenAI Responses | `POST /v1/responses` | `https://gateway.smith.langchain.com/v1` |

The format does not limit which provider you can call. For example, you can call an Anthropic model through the OpenAI Chat Completions or Responses format.

## 2. Set environment variables

This quickstart uses the OpenAI Chat Completions format. Set its base URL and your LangSmith API key:

```bash
export LANGSMITH_API_KEY="lsv2_..._....cbed3e"
export OPENAI_BASE_URL="https://gateway.smith.langchain.com/v1"
export OPENAI_API_KEY="$LANGSMITH_API_KEY"
```

The gateway uses your LangSmith API key for authentication and resolves the selected provider's actual key from your workspace's Provider Secrets.

<Note>
If your LangSmith account is on a regional instance, use the corresponding [regional gateway](/langsmith/llm-gateway#regional-gateways).
</Note>

## 3. List available models

List the models configured for your workspace:

```bash
curl "$OPENAI_BASE_URL/models" \
    -H "Authorization: Bearer $LANGSMITH_API_KEY"
```

The gateway aggregates each configured provider's model catalog. Every model ID includes a provider prefix in the form `<provider>/<model>`, such as `openai/gpt-4o-mini` or `anthropic/claude-sonnet-4-6`.

A provider whose [Provider Secret](/langsmith/llm-gateway-admin-setup#2-add-provider-secrets) is not configured is omitted from the response.

## 4. Make a call

The following examples call `anthropic/claude-sonnet-4-6` through each standard API format:

<CodeGroup>

```bash Chat Completions
curl https://gateway.smith.langchain.com/v1/chat/completions \
    -H "Authorization: Bearer $LANGSMITH_API_KEY" \
    -H "Content-Type: application/json" \
    -d '{"model":"anthropic/claude-sonnet-4-6","messages":[{"role":"user","content":"ping"}]}'
```

```bash Messages
curl https://gateway.smith.langchain.com/v1/messages \
    -H "Authorization: Bearer $LANGSMITH_API_KEY" \
    -H "Content-Type: application/json" \
    -d '{"model":"anthropic/claude-sonnet-4-6","max_tokens":1024,"messages":[{"role":"user","content":"ping"}]}'
```

```bash Responses
curl https://gateway.smith.langchain.com/v1/responses \
    -H "Authorization: Bearer $LANGSMITH_API_KEY" \
    -H "Content-Type: application/json" \
    -d '{"model":"anthropic/claude-sonnet-4-6","input":"ping"}'
```

```python OpenAI SDK
import os

from openai import OpenAI

client = OpenAI(
    base_url=os.environ["OPENAI_BASE_URL"],
    api_key=os.environ["LANGSMITH_API_KEY"],
)
response = client.chat.completions.create(
    model="anthropic/claude-sonnet-4-6",
    messages=[{"role": "user", "content": "ping"}],
)
print(response.choices[0].message.content)
```

</CodeGroup>

You must provider-prefix the `model` field. A bare model name such as `claude-sonnet-4-6` returns a `400` error. A `200` response confirms that the gateway, your API key, your role permissions, and the selected provider secret are configured correctly.

## Understand request translation

The endpoint determines the API format your application sends and receives. The model ID determines the upstream provider.

If the selected provider supports the requested format natively, the request and response pass through without format translation. Otherwise, the gateway translates the request into a format supported by the provider and translates the response back into the format your application selected, including streaming responses.

Regardless of format, every call resolves the same [Provider Secrets](/langsmith/llm-gateway-admin-setup#2-add-provider-secrets), evaluates the same [spend](/langsmith/llm-gateway-spend-policies) and [data protection](/langsmith/llm-gateway-data-protection) policies, and is traced like any other gateway call.

## 5. View your trace

Open the [LangSmith UI](https://smith.langchain.com) and navigate to the tracing project named `gateway` or `gateway-<short_api_key>-<api_key_id>` in the workspace associated with your API key. You should see a new trace for the call you made.

<Note>
If your application also emits its own LangSmith traces, the gateway-side trace and your application trace appear as separate runs. Linking gateway traces to the parent application run is not yet supported.
</Note>

## 6. Set a spend policy (optional)

Go to **Settings → Gateway → LLM Gateway** in LangSmith to create a spend policy. For example, you can set a daily $10 cap on your API key. When the cap is reached, the gateway returns a `402` response with the message: `"Request blocked by gateway policies: R&D Spend Cap"`.

For more information, see [Spend policies](/langsmith/llm-gateway-spend-policies).
