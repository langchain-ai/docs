The LLM Gateway lets you call models across configured providers with one LangSmith API key. This quickstart uses the OpenAI Chat Completions format as the default path.

<Note>
**Beta:** The LLM Gateway is in [beta](/langsmith/release-stages).
</Note>

## Before you start

- **Administrator:** Complete the one-time [admin setup](/langsmith/llm-gateway-admin-setup) to enable the gateway, add provider secrets, and grant access.
- **Developer:** Get a workspace-scoped [LangSmith API key](/langsmith/create-account-api-key) attached to a role with `gateway:invoke` and `workspaces:read` [permissions](/langsmith/organization-workspace-operations).

## 1. Make your first request

Set your LangSmith API key, then use one of the following examples. The selected workspace must have an Anthropic provider secret for this model.

```bash
export LANGSMITH_API_KEY="lsv2_..._....cbed3e"
```

<CodeGroup>

```bash cURL
curl https://gateway.smith.langchain.com/v1/chat/completions \
    -H "Authorization: Bearer $LANGSMITH_API_KEY" \
    -H "Content-Type: application/json" \
    -d '{"model":"anthropic/claude-sonnet-4-6","messages":[{"role":"user","content":"Hello!"}]}'
```

```python Python
import os

from openai import OpenAI

client = OpenAI(
    base_url="https://gateway.smith.langchain.com/v1",
    api_key=os.environ["LANGSMITH_API_KEY"],
)
response = client.chat.completions.create(
    model="anthropic/claude-sonnet-4-6",
    messages=[{"role": "user", "content": "Hello!"}],
)
print(response.choices[0].message.content)
```

```typescript TypeScript
import OpenAI from "openai";

const client = new OpenAI({
  baseURL: "https://gateway.smith.langchain.com/v1",
  apiKey: process.env.LANGSMITH_API_KEY,
});
const response = await client.chat.completions.create({
  model: "anthropic/claude-sonnet-4-6",
  messages: [{ role: "user", content: "Hello!" }],
});
console.log(response.choices[0].message.content);
```

</CodeGroup>

A `200` response confirms that the gateway, your key, your permissions, and the provider secret are configured correctly.

To switch providers, change only the provider-prefixed model ID. For example, use `openai/gpt-5.4-mini` with the same Chat Completions client when the workspace has an OpenAI provider secret.

## 2. Choose another API format

The standard gateway also accepts Anthropic Messages and OpenAI Responses requests. All three formats can access models across configured providers.

| API format | Base URL | Request path |
| --- | --- | --- |
| OpenAI Chat Completions | `https://gateway.smith.langchain.com/v1` | `/chat/completions` |
| Anthropic Messages | `https://gateway.smith.langchain.com` | `/v1/messages` |
| OpenAI Responses | `https://gateway.smith.langchain.com/v1` | `/responses` |

<CodeGroup>

```bash Messages
curl https://gateway.smith.langchain.com/v1/messages \
    -H "Authorization: Bearer $LANGSMITH_API_KEY" \
    -H "Content-Type: application/json" \
    -d '{"model":"anthropic/claude-sonnet-4-6","max_tokens":1024,"messages":[{"role":"user","content":"Hello!"}]}'
```

```bash Responses
curl https://gateway.smith.langchain.com/v1/responses \
    -H "Authorization: Bearer $LANGSMITH_API_KEY" \
    -H "Content-Type: application/json" \
    -d '{"model":"anthropic/claude-sonnet-4-6","input":"Hello!"}'
```

</CodeGroup>

For SDK examples, request translation, and regional URLs, see [API formats](/langsmith/llm-gateway-api-formats).

## 3. Discover available models

List the models available to your workspace across configured providers:

```bash
curl https://gateway.smith.langchain.com/v1/models \
    -H "Authorization: Bearer $LANGSMITH_API_KEY"
```

Every model ID uses the form `<provider>/<model>`. Providers without a configured [Provider Secret](/langsmith/llm-gateway-admin-setup#1-add-provider-secrets) are omitted.

## 4. View your trace

Open the [LangSmith UI](https://smith.langchain.com) and navigate to the tracing project named `gateway` or `gateway-<short_api_key>-<api_key_id>` in the workspace associated with your API key. The request appears as a trace with its model, token, cost, latency, and policy metadata.

<Note>
If your application also emits LangSmith traces, the gateway trace and application trace appear as separate runs. Linking a gateway trace to its parent application run is not yet supported.
</Note>

## 5. Add a policy (optional)

Go to **Settings → Gateway → LLM Gateway** to create a spend, rate-limit, or data-protection policy. Policies apply to standard and direct gateway traffic.

## Troubleshoot your first request

| Symptom | Likely cause | Resolution |
| --- | --- | --- |
| `401 Unauthorized` | The LangSmith API key is missing or invalid. | Verify `LANGSMITH_API_KEY` and retry. |
| `403 Forbidden` | The key's role cannot invoke the gateway. | Ask an administrator to grant `gateway:invoke` and `workspaces:read`. |
| `400` response about `model` | The model ID is missing its provider prefix. | Use `<provider>/<model>`, such as `anthropic/claude-sonnet-4-6`. |
| No models with the provider's prefix appear in `GET /v1/models` | The provider may not be configured for the workspace. | Ask an administrator to verify the corresponding [Provider Secret](/langsmith/llm-gateway-admin-setup#1-add-provider-secrets). |
| Request works in one region but not another | The request uses the wrong regional gateway URL. | Select the URL for your [LangSmith region](/langsmith/llm-gateway-api-formats#use-a-regional-gateway). |
