Agents, experiments, and evaluators each keep their traces in a [tracing project](/langsmith/observability-concepts#tracing-projects). Endpoints that read or manage that data identify the project by its ID. Resolve an agent to its project ID first, then pass the ID wherever an endpoint takes a project (session) ID. For example:

- Querying runs, threads, and traces with `project_ids`
- Reading or updating the project, and its views, insights, and alerts

<Note>
Resolving an agent is in [beta](/langsmith/release-stages). It needs LangSmith `v0.18` or later, and is not supported on BYOC data planes yet. The examples need `langsmith>=0.14.5` in Python, `langsmith@>=0.10.13` in TypeScript, `com.langchain.smith:langsmith-java:0.1.0-beta.26` in Java, or `github.com/langchain-ai/langsmith-go@v0.28.0` in Go.
</Note>

## What you can resolve

Resolve any of the following to get the ID of its project:

| What | Python | TypeScript | Java | Go |
|------|--------|------------|------|----|
| An agent's environment | `ls.AgentAddress("checkout", "production")` | `new AgentAddress("checkout", "production")` | `new AgentAddress("checkout", "production")` | `langsmith.NewAgentAddress("checkout", "production")` |
| An experiment | `ls.ExperimentAddress("<experiment-id>")` | `new ExperimentAddress("<experiment-id>")` | `new ExperimentAddress("<experiment-id>")` | `langsmith.NewExperimentAddress("<experiment-id>")` |
| The workspace's evaluators | `ls.EvaluatorAddress()` | `new EvaluatorAddress()` | `new EvaluatorAddress()` | `langsmith.NewEvaluatorAddress()` |

## Errors

- LangSmith returns a `404` if nothing in the workspace matches, or if you cannot read its project. An agent environment exists once you have sent a trace to it.
- On a BYOC data plane, the endpoint returns a `501`, because resolving is not supported there yet.
