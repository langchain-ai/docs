Agents, experiments, and evaluators each keep their traces in a [tracing project](/langsmith/observability-concepts#tracing-projects). Endpoints that read or manage that data identify the project by its ID. An agent has no project name to look up, so resolve the agent to its project ID first, then pass the ID wherever an endpoint takes a project (session) ID. For example:

- Querying runs, threads, and traces with `project_ids`
- Reading or updating the project, and its views, insights, and alerts

<Note>
Resolving an agent is in [beta](/langsmith/release-stages). It needs LangSmith `v0.18` or later, and is not supported on BYOC data planes yet.
</Note>

## What you can resolve

Resolve any of the following to get the ID of its project:

| What | Python | TypeScript |
|------|--------|------------|
| An agent's environment | `ls.AgentAddress("checkout", "production")` | `new AgentAddress("checkout", "production")` |
| An experiment | `ls.ExperimentAddress("<experiment-id>")` | `new ExperimentAddress("<experiment-id>")` |
| The workspace's evaluators | `ls.EvaluatorAddress()` | `new EvaluatorAddress()` |

## Resolve an agent and query its runs

<CodeGroup>

```python Python
import asyncio

import langsmith as ls

client = ls.Client()
agent = ls.AgentAddress("checkout", "production")


async def main() -> None:
    project = await client.sessions.resolve(**agent.to_api_address())

    async for run in client.runs.query_v2(project_ids=[project.session_id]):
        print(run.id)


asyncio.run(main())
```

```typescript TypeScript
import { AgentAddress, Client } from "langsmith";

const client = new Client();
const agent = new AgentAddress("checkout", "production");

const project = await client.sessions.resolve(agent.toApiAddress());

for await (const run of client.runs.query({
  project_ids: [project.session_id],
})) {
  console.log(run.id);
}
```

</CodeGroup>

## Resolve an experiment and query its runs

Pass the ID of the experiment. An experiment is its own tracing project, so the endpoint returns the experiment's ID.

<CodeGroup>

```python Python
import asyncio

import langsmith as ls

client = ls.Client()
experiment = ls.ExperimentAddress("<experiment-id>")


async def main() -> None:
    project = await client.sessions.resolve(**experiment.to_api_address())

    async for run in client.runs.query_v2(project_ids=[project.session_id]):
        print(run.id)


asyncio.run(main())
```

```typescript TypeScript
import { Client, ExperimentAddress } from "langsmith";

const client = new Client();
const experiment = new ExperimentAddress("<experiment-id>");

const project = await client.sessions.resolve(experiment.toApiAddress());

for await (const run of client.runs.query({

```

</CodeGroup>

## Resolve the evaluators and query their runs

Evaluator traces share one project per workspace, so the evaluators take no ID.

<CodeGroup>

```python Python
import asyncio

import langsmith as ls

client = ls.Client()
evaluators = ls.EvaluatorAddress()


async def main() -> None:
    project = await client.sessions.resolve(**evaluators.to_api_address())

    async for run in client.runs.query_v2(project_ids=[project.session_id]):
        print(run.id)


asyncio.run(main())
```

```typescript TypeScript
import { Client, EvaluatorAddress } from "langsmith";

const client = new Client();
const evaluators = new EvaluatorAddress();

const project = await client.sessions.resolve(evaluators.toApiAddress());

for await (const run of client.runs.query({
  project_ids: [project.session_id],
})) {
  console.log(run.id);
}
```

</CodeGroup>

## Errors

- LangSmith returns a `404` if nothing in the workspace matches, or if you cannot read its project. An agent environment exists once you have sent a trace to it.
- On a BYOC data plane, the endpoint returns a `501`, because resolving is not supported there yet.
