[Studio](/langsmith/studio) builds a [no-code agent](/langsmith/fleet) from a description. You describe what the agent should do, [LangSmith Chat](/langsmith/chat) drafts its configuration, and you review each step before you save.

Use it when you want a working agent without a local project or a deployment. Everything it produces is an [agent](/langsmith/agent-registry#agent) like any other, so its traces, dashboards, and evaluators behave the same as one you instrumented yourself.

<AgentAvailabilityNote />

Creating an agent requires the `fleet-agents:create` [permission](/langsmith/fleet/access-and-oversight). Without it, Studio shows "Ask a workspace admin for permission to create agents." To build an agent from files on your own machine instead, see [Managed Deep Agents](/langsmith/managed-deep-agents-overview).

## Start a new agent

Open the **Build an agent** screen from any of these places:

- **Studio**: In the left navigation, click **Studio**, then click **Build a new agent**.
- **New agent menu**: Under **Build**, click **Without code**.

To open Studio on an agent you already have, click **Select existing agent** on the Studio page instead.

## Describe the agent

The **Build an agent** screen asks you to "Describe the agent you want to create".

To describe the agent:

1. In the box that reads "Build me an agent that…", describe what the agent should do, up to 8,000 characters. To start from an example, click a template card instead. The card fills in the prompt, and you can edit it before you send it.
1. (Optional) Choose the model Chat uses to draft the agent. **Auto** uses the LangSmith-hosted model when it is available. This choice applies to Chat only. You set the agent's own model in the [Basics step](#configure-the-agent).
1. Click **Build with AI**.

The template cards are **Schedule manager**, **Slides designer**, **Support triage**, **Project manager**, **Deep researcher**, and **Data analyst**. Each card lists the apps its agent uses.

**Build in code** opens the **Build with code** pane, with options for building the agent in code instead.

## Review the draft

While Chat works, Studio shows "Generating your agent". Chat drafts the agent's name, description, and instructions first. Once all three are filled in, LangSmith creates the agent and opens its configuration at the **Instructions** step. The agent exists from this point, before you click **Save**.

If generation stalls, click **Retry** to send your original prompt again.

Chat then suggests the remaining steps one at a time: connections, channels, and schedules. You can also edit any step directly.

## Configure the agent

The **Configure agent** view lists the configuration as steps. A step with nothing in it yet says so, and offers a button to add the first item.

- **Basics**: The agent's **Name**, a **Description** of what it does, and the model that powers its responses. The name is the label you see in the agent switcher.
- **Instructions**: What the agent should do and how it should work.
- **Connections**: The apps and tools the agent can use, added with **Add connection**. The **Connection Type** heading shows whose accounts the agent uses: **Shared**, where everyone uses one set of connected accounts, or **Per-user**, where each person connects their own. Account setup takes effect right away, while tool selections stay in the draft until you save. For each tool, choose **Auto**, **Ask**, or **Remove**. For more information, see [Agent identity](/langsmith/fleet/agent-identity).
- **Channels**: Where people can chat with the agent, added with **Add channel**. The options are Slack, Gmail, Outlook, and Microsoft Teams. Microsoft Teams carries an **Admin** badge and is available only for agents with shared connections. Channel setup is saved separately from the rest of the configuration.
- **Schedules**: The [scheduled runs](/langsmith/fleet/schedules) the agent makes on its own, added with **Add schedule**.

When you edit an existing agent, the view also shows **Skills** and **Memory**. For more information, see [Skills](/langsmith/fleet/skills).

## Save or cancel

To save, click **Save** in the **Configure agent** header, or **Save agent** on the card above the Chat composer. The card reads "Ready to save your changes?" and appears only when there is something to save. Saving closes Chat and returns you to Studio, where you can test the agent.

To leave without keeping the agent, click **Cancel**. Because the agent already exists, the **Cancel agent creation?** dialog asks you to confirm. **Delete agent** permanently deletes it and discards its configuration. **Keep building** returns you to the configuration. If you cancel before Chat finishes the first draft, the dialog offers **Discard and leave** instead, and nothing is created.

## Test the agent

After you save, Studio opens a chat with the agent. Send it a message to try it out. The traces panel beside the chat reads "Start chatting with your agent to see live traces appear here", and fills with the run's traces as the agent responds.

A no-code agent supports chat only. **Interact**, which shows a graph view, is unavailable for it.

If your workspace shows the **Get started** checklist, it walks through the same path: **Create your first agent**, **Test your agent**, and **See how your agent is doing**, which opens the agent's [Overview](/langsmith/navigate-agents#read-the-agent-overview).

## Change the configuration later

To edit an agent's configuration, use either control:

- In the Studio chat, click **Edit**.
- On the agent's Overview, open **Agent settings** and click **Edit configuration**.

Both open the configuration at the **Basics** step. Make your changes and click **Save**. **Cancel** discards them and returns you to Studio.

If you ask Chat to change the agent from elsewhere in LangSmith, it offers to open the configuration in Studio and carries the conversation with it.

Without edit access on the agent, the configuration opens with a **Read-only configuration** banner.

## Find the traces

An agent built in Studio is created with a **Production** [environment](/langsmith/agent-environments) alone, and its runs land there. It gains other environments only when something reports into them.

To see its environments, select the agent and open **Tracing**, or read the summary on the [agent Overview](/langsmith/navigate-agents#read-the-agent-overview).

An agent built in Studio has no deployment, because it runs on a Studio runtime instead of one you deployed. It has no **Deployments** section on its Overview, and no deployment can be created for it, so the [agent environment deploy flags](/langsmith/deploy-to-agent-environment) do not apply to it. The workspace's other deployments are hidden while that agent is selected.
