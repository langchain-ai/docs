The **Build** tab creates an agent inside LangSmith instead of in code. You supply a name and a sentence describing what the agent does, and LangSmith creates a [Managed Deep Agent](/langsmith/managed-deep-agents-overview), then interviews you to configure it.

Use it when you want a working agent without a local project or a deployment. Everything it produces is an [agent](/langsmith/agents) like any other, so its traces, dashboards, and evaluators behave the same as one you instrumented yourself.

<AgentBetaNote />

The **Build** tab appears only in an agent-based workspace. To build an agent from files on your own machine instead, see [Managed Deep Agents](/langsmith/managed-deep-agents-overview).

## Create the agent

To create an agent:

1. In the left navigation, click **Build**.
1. Enter an **Agent name**. The name is required, and it is the label you will see in the agent switcher.
1. (Optional) Describe the agent in **Describe your agent**, in a sentence, as you would brief a new colleague. For example, "Review incoming support requests and route them to the right team."
1. Click **Create**.

The description becomes the first message in the setup conversation, so the agent reads it and proposes a role from it.

The panel that opens from **+ New Agent** reaches the same place: its **Builder** option, "Build with AI inside LangSmith", opens this tab. For the other three options, see [Create an agent](/langsmith/navigate-agents#create-an-agent).

Agent creation requires permission to create projects. Once an agent's identifier is set, it cannot be changed.

## Add a model key

The agent cannot run until the workspace has a key for the model it uses. If none is set, **Agent setup** shows a **Missing API key** message with a link to get one, above two controls:

- **Model**: The model that drives the agent.
- **Secret card**: The provider key for that model, with a field to paste or replace the value.

Click **Save** to store it. The key applies to the **whole workspace**, not to this agent, so saving here changes the key every agent in the workspace uses.

## Answer the setup questions

With a key in place, the agent introduces itself, states the role it has inferred from your description, and asks up to three questions to narrow it. Each question is a card with a checklist, and the footer shows your position in the sequence, such as **1 of 3**.

- **Next** saves the answer and advances.
- **Back** returns to the previous question.
- **Skip** moves on without answering, so none of the questions is mandatory.

The questions are generated from your description rather than fixed, so an agent that reviews requests is asked where requests arrive, and a different agent is asked something else.

## Configure the agent

The panel on the right holds the agent's configuration, and you can change any of it later:

- **Connections**: The accounts the agent uses for its tools, such as Slack, Linear, or GitHub. **Connection format** decides whose accounts those are. **Shared** means everyone uses the same accounts.
- **Instructions**: The agent's role, tone, and the rules it always follows.
- **Skills**: Packaged, task-specific workflows the agent pulls in only when it needs them.
- **Memory**: What the agent remembers between runs. **Update memory and instructions** lets the agent revise its own configuration over time, and can be set to run automatically.

**Agent files** opens the files that back the agent, which is the same directory of files a [Managed Deep Agent](/langsmith/managed-deep-agents-project-structure) is built from.

## Find the traces

The setup conversation is itself a traced run, so a newly built agent has trace data before you have used it. Those traces land in the agent's **Production** [environment](/langsmith/agent-environments).

An agent built here shows Production until something reports into another environment. To see its environments, select the agent and open **Tracing**, or read the summary on the [agent Overview](/langsmith/navigate-agents#read-the-agent-overview).

An agent built in the UI has no deployment, because it runs on a Studio runtime instead of one you deployed. Its **Deployments** section is empty, and the workspace's other deployments are hidden while that agent is selected.
