The repository is a complete Managed Deep Agents project. You deploy it with `mda deploy`, and each capability it uses maps to a page in these docs.

## Deploy the agent

Before you start, make sure you have:

- A [LangSmith Cloud](/langsmith/cloud) account and an [API key](/langsmith/create-account-api-key) that can deploy.
- A key for your model provider. On the [LLM Gateway](/langsmith/llm-gateway), the agent uses your LangSmith key instead.

The fastest way is to paste this prompt into a coding agent such as Claude Code, Codex, or Cursor. It installs the agent, checks the setup, and asks you before anything that bills or deploys.

<Prompt
    description="Deploy the design agent with your coding agent"
    icon="rocket"
    actions={["copy"]}
>
Deploy LangChain's open-source design agent to my Slack workspace with Managed Deep Agents.

1. Install it with `curl -fsSL https://raw.githubusercontent.com/langchain-ai/design-agent/main/install.sh | bash`, then work in the `design-agent` folder it creates.
2. Read `AGENTS.md` and follow the `design-agent-deploy` skill.
3. Tell me which keys you need. I'll type them myself with `uv run design-agent config set <KEY>` in my terminal; never ask me to paste a key in chat.
4. Run `uv run design-agent doctor` and fix what it flags. Its `mda-deploy` line lists what a deploy still needs.
5. Ask me before `uv run design-agent sandbox publish`, which bills. Then have me run the first deploy, `uv run mda deploy`, in my own terminal, since it sets up the Slack app.
6. When it's live, walk me through messaging the agent in Slack and sending a first request.
</Prompt>

To deploy it yourself:

<Steps>
  <Step title="Install the project">

The installer gets uv if you need it, then clones the repository and sets it up.

```bash
curl -fsSL https://raw.githubusercontent.com/langchain-ai/design-agent/main/install.sh | bash
cd design-agent
```

  </Step>
  <Step title="Add your keys">

```bash
uv run design-agent config set LANGSMITH_API_KEY ANTHROPIC_API_KEY
```

The command asks for each key and keeps it hidden. On the [LLM Gateway](/langsmith/llm-gateway), skip the provider key and run `uv run design-agent config set DESIGN_AGENT_MODEL=langsmith:anthropic/claude-opus-5-5` instead.

`mda deploy` forwards every key in `.env` as a deployment secret, except `LANGSMITH_API_KEY`, which signs the deploy.

  </Step>
  <Step title="Publish the sandbox">

```bash
uv run design-agent sandbox publish
```

`mda deploy` builds `sandbox/setup.sh` into a snapshot on its own, but a Docker image base gets a 1 GiB filesystem. The design agent's machine, with Chrome, FFmpeg, and HyperFrames, is about 1.3 GiB. This command builds a larger snapshot in your [workspace](/langsmith/administration-overview#workspaces) instead and points `sandbox/__init__.py` at it.

It takes 10 to 15 minutes and runs once per workspace. Publish again only when `sandbox/setup.sh` changes.

  </Step>
  <Step title="Deploy">

```bash
uv run mda deploy
```

The first deploy provisions the agent's Slack app. If the command prints a Slack link, open it, approve the app for your workspace, and press Enter. A workspace admin may need to approve the app first.

  </Step>
  <Step title="Ask it for something">

After the first deploy, the agent sends you a direct message. Reply there, or invite it to a channel and mention it with a quick request, such as a launch graphic for a product. The thread shows its progress step by step, and the files arrive in the same thread.

<Frame caption="A thread in LangChain's Slack. The agent shows its steps, then posts the files and what it decided.">

  />
</Frame>

  </Step>
</Steps>

## Customize the design agent

Most changes are edits to files in the repository. Common ones:

- **Brand pack**: Your colors, fonts, logos, and voice live in `workspace/brand/`. Ask your coding agent to build the pack from your website and brand guide.
- **Skills**: Each workflow is a folder in `skills/`. Add one for a request your team makes often, such as a weekly newsletter header.
- **Instructions**: The always-on prompt is `instructions.md`. Keep it short, and put workflows in skills.
- **MCP servers**: Copy `config/mcp.example.toml` to `config/mcp.toml` and turn on servers such as Notion or GitHub. Each person signs in as themselves through a [workspace connection](/langsmith/managed-deep-agents-connections).
- **Model**: Set `DESIGN_AGENT_MODEL` with `uv run design-agent config set`. Any chat model with tool calling and vision works.

To try a change and ship it, use these [`mda` commands](/langsmith/managed-deep-agents-cli):

| Command | What it does |
| --- | --- |
| `uv run mda dev` | Runs the agent locally and opens it in [LangSmith Studio](/langsmith/studio) |
| `uv run mda deploy --name design-agent-test` | Deploys a separate copy to test changes without touching the one your team uses |
| `uv run mda deploy` | Ships your changes to the deployment your team uses |
| `uv run mda logs` | Tails the logs of the deployed agent |
| `uv run mda build` | Compiles what would ship into `.mda/build/` without deploying |

For more information, see [Customization](https://github.com/langchain-ai/design-agent/blob/main/docs/customization.md) in the repository.

## Explore the project

Each managed capability is a file or folder at the root of the repository. Read them to see how a production agent uses each one.

| Path | In this agent | Learn more |
| --- | --- | --- |
| `agent.py` | Builds the agent with `define_deep_agent` from one shared assembly of model, tools, middleware, and subagents | [Agent definition](/langsmith/managed-deep-agents-agent-definition) |
| `instructions.md` | A short always-on prompt, with workflows kept in skills | [Instructions](/langsmith/managed-deep-agents-instructions) |
| `skills/` | 35 skills and a design wiki, synced to Context Hub and loaded only when a job needs them | [Skills](/langsmith/managed-deep-agents-skills) |
| `sandbox/` | A pinned recipe for the Linux machine each thread clones, with Chrome, FFmpeg, HyperFrames, D2, and your fonts | [Sandboxes](/langsmith/managed-deep-agents-sandboxes) |
| `channels/slack.py` | The managed Slack app for mentions, DMs, thread replies, files, and approval cards | [Slack channel](/langsmith/managed-deep-agents-channels-slack) |
| `memory.py` | Team memory everyone shares and personal memory for each person | [Memory](/langsmith/managed-deep-agents-memory) |
| `tools/mcp.py` | MCP servers from `config/mcp.toml`, with each person signed in as themselves | [MCP connectors](/langsmith/managed-deep-agents-mcp-connectors) |
| `schedules/housekeeping.py` | Runs every 15 minutes to sweep work a restart stopped, with no model call | [Schedules](/langsmith/managed-deep-agents-schedules) |
| `identity.py` | Authenticates API callers with a LangSmith API key | [Identity](/langsmith/managed-deep-agents-identity) |
| `src/design_agent/` | Application code the agent entry imports, such as host tools and middleware | [Tools](/langsmith/managed-deep-agents-tools) |

## See how it works

Managed Deep Agents runs the infrastructure, from the Slack app to a sandbox for every thread. The repository adds the design work on top. The model makes the creative calls, and code does everything that has to be exact.

Long jobs like video generation run in the background. The main agent hands parts to [subagents](/langsmith/managed-deep-agents-subagents) on the same sandbox and stays free to talk. A one-time [schedule](/langsmith/managed-deep-agents-schedules) wakes it when one finishes or stalls.
