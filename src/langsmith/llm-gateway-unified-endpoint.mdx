<Note>
**Beta:** The LLM Gateway is in [beta](/langsmith/release-stages).
</Note>

The unified API is the standard way to access models through the LLM Gateway. Choose one supported API format, point your client at the gateway root, and call any configured model with a provider-prefixed model ID. The gateway translates requests and responses when the selected model uses a different provider-native format.

For example, the same Anthropic model is available through the OpenAI Chat Completions, Anthropic Messages, and OpenAI Responses formats. This lets applications use one API format across providers instead of changing clients when they change models.

Use [direct model access](/langsmith/llm-gateway-direct-model-access) only when you want the provider's API directly and need to bypass the gateway's standardization layer.

## Choose an API format

The unified API supports these endpoints at the gateway root:

| API format | Endpoint | Base URL for compatible SDKs |
| --- | --- | --- |
| OpenAI Chat Completions | `POST /v1/chat/completions` | `https://gateway.smith.langchain.com/v1` |
| Anthropic Messages | `POST /v1/messages` | `https://gateway.smith.langchain.com` |
| OpenAI Responses | `POST /v1/responses` | `https://gateway.smith.langchain.com/v1` |

Choose the format already used by your application. The format does not limit which provider you can call.

Authenticate with your LangSmith API key, passed as the provider API key by your client. For regional base URLs, see [Regional gateways](/langsmith/llm-gateway#regional-gateways).

## Prerequisites

Before using the unified API, confirm that:

- Your [Organization admin](/langsmith/rbac#organization-admin) has added [Provider Secrets](/langsmith/llm-gateway-admin-setup#2-add-provider-secrets) for the providers you want to call. Refer to [Admin setup](/langsmith/llm-gateway-admin-setup).
- You have a workspace-scoped [LangSmith API key](/langsmith/create-account-api-key) attached to a role with `gateway:invoke` and `workspaces:read` [permissions](/langsmith/organization-workspace-operations).

## List available models

Call `GET /v1/models` to list the models available to your workspace across providers:

```bash
curl https://gateway.smith.langchain.com/v1/models \
    -H "Authorization: Bearer $LANGSMITH_API_KEY"
```

The gateway aggregates each provider's model catalog into one OpenAI-compatible list. Every model ID is prefixed with the provider name in the form `<provider>/<model>`:

```json
{
  "object": "list",
  "data": [
    {
      "id": "openai/gpt-4o-mini",
      "object": "model"
    },
    {
      "id": "anthropic/claude-sonnet-4-6",
      "object": "model"
    }
  ]
}
```

Pass the full provider-prefixed ID as `model` when making a call. A provider whose [Provider Secret](/langsmith/llm-gateway-admin-setup#2-add-provider-secrets) is not configured is omitted from the response.

## Call a model

The following examples call `anthropic/claude-sonnet-4-6` through each supported API format:

<CodeGroup>

```bash Chat Completions
curl https://gateway.smith.langchain.com/v1/chat/completions \
    -H "Authorization: Bearer $LANGSMITH_API_KEY" \
    -H "Content-Type: application/json" \
    -d '{"model":"anthropic/claude-sonnet-4-6","messages":[{"role":"user","content":"ping"}]}'
```

```bash Messages
curl https://gateway.smith.langchain.com/v1/messages \
    -H "Authorization: Bearer $LANGSMITH_API_KEY" \
    -H "Content-Type: application/json" \
    -d '{"model":"anthropic/claude-sonnet-4-6","max_tokens":1024,"messages":[{"role":"user","content":"ping"}]}'
```

```bash Responses
curl https://gateway.smith.langchain.com/v1/responses \
    -H "Authorization: Bearer $LANGSMITH_API_KEY" \
    -H "Content-Type: application/json" \
    -d '{"model":"anthropic/claude-sonnet-4-6","input":"ping"}'
```

</CodeGroup>

You must provider-prefix the `model` field. A bare model name such as `claude-sonnet-4-6` returns a `400` error.

## Understand request translation

The endpoint determines the API format your application sends and receives. The model ID determines the upstream provider.

If the selected provider supports the requested format natively, the request and response pass through without format translation. Otherwise, the gateway translates the request into a format supported by the provider and translates the response back into the format your application selected, including streaming responses.

Regardless of format, every call resolves the same [Provider Secrets](/langsmith/llm-gateway-admin-setup#2-add-provider-secrets), evaluates the same [spend](/langsmith/llm-gateway-spend-policies) and [data protection](/langsmith/llm-gateway-data-protection) policies, and is traced like any other gateway call.
