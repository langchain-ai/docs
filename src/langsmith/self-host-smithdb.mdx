<Note>
SmithDB is an opt-in datastore for self-hosted LangSmith. ClickHouse remains required and cannot be removed after you enable SmithDB. The minimum LangSmith version depends on your cloud. See [Check cloud support](#check-cloud-support).
</Note>

SmithDB is a columnar datastore built for agent trace data: deeply nested spans, multi-modal content, and spans that stay open for hours. It keeps durable data in object storage with node-local SSD caching, and serves LangSmith trace ingestion and queries alongside the existing ClickHouse datastore.

The SmithDB launch post reports that it makes "core LangSmith experiences up to 12x faster than before". For the design and the benchmarks behind that number, see [We built SmithDB, the data layer for agent observability](https://www.langchain.com/blog/introducing-smithdb).

This section is for existing self-hosted installations. Complete the [Kubernetes setup guide](/langsmith/kubernetes) first. SmithDB is not part of a new install.

Wait to enable SmithDB until you can provision its supporting infrastructure: a dedicated PostgreSQL 18 instance, a dedicated object-storage bucket, and local SSD-backed node pools.

## Components

Enabling SmithDB adds the following workloads to your cluster. Three of them cache trace data on disk and belong on local SSD nodes; the other two are small and run on general compute. See [Schedule SmithDB workloads](/langsmith/self-host-smithdb-infrastructure#schedule-smithdb-workloads).

| Component | What it does | Node pool | Scaling |
| --- | --- | --- | --- |
| Ingestion | Writes incoming traces to object storage | Local SSD | Horizontal |
| Query | Serves trace reads for the LangSmith UI and API | Local SSD | Horizontal |
| Compaction worker | Reorganizes stored traces in the background so queries stay fast | Local SSD | Horizontal |
| Compaction | Schedules the background work that compaction workers carry out | Compute | Single instance |
| Cluster manager | Coordinates the other SmithDB services | Compute | Single instance |

Two more workloads run as Kubernetes Jobs rather than as services. One prepares the SmithDB metastore during installation. The other backfills history from ClickHouse, and runs only if you choose to [migrate historical data](/langsmith/self-host-smithdb-migrate).

## Storage requirements

A self-hosted LangSmith instance uses ClickHouse for traces and feedback, PostgreSQL for operational data, Redis or Valkey for queuing and caching, and optional blob storage. SmithDB adds its own metastore, object store, and cache nodes. It does not replace those services.

ClickHouse remains required after you enable SmithDB. Keep it configured and running, including after query cutover. Support for disabling ClickHouse is planned for a future release.

For SDK method changes that work with both ClickHouse and SmithDB, see [Migrate to SmithDB-backed SDK methods](/langsmith/smithdb-sdk-migration).
