<Note>
SmithDB is an opt-in datastore for self-hosted LangSmith. The minimum LangSmith version depends on your cloud, and what ClickHouse requires depends on your LangSmith version. See [Check cloud support](#check-cloud-support) and [Storage requirements](#storage-requirements).
</Note>

SmithDB is a columnar datastore built for agent trace data: deeply nested spans, multi-modal content, and spans that stay open for hours. It keeps durable data in object storage with node-local SSD caching, and serves LangSmith trace ingestion and queries alongside the existing ClickHouse datastore.

The SmithDB launch post reports that it makes "core LangSmith experiences up to 12x faster than before". For the design and the benchmarks behind that number, see [We built SmithDB, the data layer for agent observability](https://www.langchain.com/blog/introducing-smithdb).

This section is for existing self-hosted installations. Complete the [Kubernetes setup guide](/langsmith/kubernetes) first. SmithDB is not part of a new install.

Wait to enable SmithDB until you can provision its supporting infrastructure: a dedicated PostgreSQL 18 instance, a dedicated object-storage bucket, and local SSD-backed node pools.

## Check cloud support

SmithDB examples in this section cover managed Kubernetes on AWS, GCP, and Azure. They do not cover self-managed clusters.

| Cloud | SmithDB from |
|---|---|
| AWS (EKS) | LangSmith 0.16, Helm chart `0.16.14` or later |
| GCP (GKE) | LangSmith 0.16, Helm chart `0.16.14` or later |
| Azure (AKS) | LangSmith 0.17 |

## Storage requirements

A self-hosted LangSmith instance uses PostgreSQL for operational data, Redis or Valkey for queuing and caching, and optional blob storage. SmithDB adds its own metastore, object store, and cache nodes. Those services are required whether or not you enable SmithDB.

What ClickHouse requires depends on your LangSmith version:

| LangSmith version | ClickHouse |
| --- | --- |
| 0.16 | Required. Keep it running after enabling SmithDB. Do not disable it. |
| 0.17 | Can be disabled once SmithDB query cutover is complete. |

SmithDB on Azure (AKS) requires LangSmith 0.17, so AKS installations can disable ClickHouse after cutover while EKS and GKE installations on 0.16 cannot.

Migrating history is not a prerequisite for disabling ClickHouse. Any history left in ClickHouse becomes unreachable once you disable it.

For SDK method changes that work with both ClickHouse and SmithDB, see [Migrate to SmithDB-backed SDK methods](/langsmith/smithdb-sdk-migration).
