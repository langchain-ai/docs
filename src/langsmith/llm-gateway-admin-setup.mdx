This page walks an admin through preparing the [LLM Gateway](/langsmith/llm-gateway) for a team: connecting providers, granting access, issuing API keys, and setting policies. Complete the following sections in order. Each one links to the page that covers its topic in full.

<Tip>
Some users can start without this setup. A [Workspace Admin](/langsmith/rbac#workspace-admin) can already call the gateway, and can add a provider key from the Simulator's **Needs key** prompt. If you are the only user in your organization, go to [Send your first LLM Gateway request](/langsmith/llm-gateway-first-request) instead.
</Tip>

## Enable the gateway on self-hosted LangSmith

On self-hosted LangSmith, [enable the gateway in the Helm chart](/langsmith/llm-gateway-self-hosted) before the other steps. Skip this section on other deployments.

## Add provider keys

Adding a provider key requires [permission to manage secrets](/langsmith/rbac#workspace-roles) in that workspace.

The gateway calls each provider with a key stored as a secret in the workspace that the caller's API key belongs to. Add a key for each provider your team calls, in each workspace that calls it. The gateway does not fall back to organization secrets for these calls.

Skip this section if your team calls only [Gateway Credits](/langsmith/llm-gateway-credits) models, which need no provider key.

For the steps and the secret name each provider uses, see [Add a provider key](/langsmith/llm-gateway-provider-authentication#add-a-provider-key).

## Grant permission to call the gateway

An API key needs the `gateway:invoke` and `workspaces:read` permissions to call the gateway. On plans without workspace roles, every user has the Workspace Admin role, which includes both, so no action is needed.

On the Enterprise plan, the built-in Workspace Editor and Workspace Viewer roles include neither permission. As an [Organization Admin](/langsmith/rbac#organization-admin), create a [custom role](/langsmith/rbac#custom-roles) with both permissions and assign it to the users who call the gateway, or assign them the Workspace Admin role.

For more information, see [Grant permission to call the gateway](/langsmith/llm-gateway-authentication#grant-permission-to-call-the-gateway).

## Decide how developers get API keys

Each request authenticates with a workspace-scoped LangSmith API key. Developers can create their own personal access token (PAT), which carries their role, or the Simulator creates one for them. For shared agents or a company-wide rollout through mobile device management (MDM), you can create service keys instead.

For key types and scoping, see [Choose a key type](/langsmith/llm-gateway-authentication#choose-a-key-type). For coding agent rollouts, see [Set up coding agents](/langsmith/llm-gateway-coding-agents).

## Optional: Set policies

Creating policies requires the `organization:gateway:manage` permission, which Organization Admins and Organization Operators have by default. On self-hosted LangSmith earlier than application version 0.18.9 (Helm chart versions before 0.18.0-rc.22), it requires `organization:manage` instead.

Use the tabs on the **LLM Gateway** page to create any of these policy types:

- **[Spend limits](/langsmith/llm-gateway-spend-policies)**: Hard caps at the organization, workspace, API key, or user level. Your organization may already have a default limit on the **Cost Controls** tab.
- **[Rate limits](/langsmith/llm-gateway-rate-limit-policies)**: Request or token limits in a time window.
- **[Model access](/langsmith/llm-gateway-model-access-policies)**: Which models users can call.
- **[Per-customer policies](/langsmith/llm-gateway-header-policies)**: Spend caps and rate limits split by a custom request header, so each end customer gets its own limit.
- **[Data policy](/langsmith/llm-gateway-data-policy)**: Detect and redact PII and secrets before they reach the model, and control whether request and response bodies are traced.

On the Enterprise plan, creating, updating, and deleting policies is recorded in [audit logs](/langsmith/audit-logs).

## Send a test request

To confirm the setup, follow [Send your first LLM Gateway request](/langsmith/llm-gateway-first-request). It sends a request from the Simulator and from code, and shows its trace. Share the same page with developers as their starting guide.
