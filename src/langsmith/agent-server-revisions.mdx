A revision deploys a version of your application to an existing Agent Server on LangSmith Cloud. Create a revision to release code changes without creating another Agent Server.

## Create a revision

When you [create an Agent Server](/langsmith/deploy-to-cloud), LangSmith creates its first revision. Use the LangSmith UI or LangGraph CLI to create subsequent revisions.

<Tabs>
  <Tab title="LangSmith UI">
    From the [LangSmith UI](https://smith.langchain.com), select **Agent Servers**, then select an Agent Server.

    1. In the top-right corner of the **Agent Server** view, select **+ New Revision**.
    1. In the **New Revision** modal, specify the full path to the [API configuration file](/langsmith/cli#configuration-file), including the file name. For example, enter `langgraph.json` if the file is in the repository root.
    1. Choose whether to make the Agent Server shareable through [Studio](/langsmith/studio).
    1. Add, remove, or update environment variables and secrets. Existing values are prepopulated. For more information, see [Environment variables](/langsmith/env-var-cloud).
    1. Select **Submit**. LangSmith queues the revision for deployment.
  </Tab>
  <Tab title="LangGraph CLI">
    Run `langgraph deploy` again from your project directory. The command finds the existing Agent Server by name and creates a revision with your latest code changes:

    ```shell
    langgraph deploy
    ```

    To target an Agent Server by ID, run:

    ```shell
    langgraph deploy --agent-server-id <AGENT_SERVER_ID>
    ```

    To view Agent Server IDs, run:

    ```shell
    langgraph deploy list
    ```

    <Note>
    CLI update support depends on the Agent Server's source and build mode, not only where it was created. Local builds pushed to the managed registry require an `internal_docker` source. For Agent Servers that use a registry you manage, use `--push-to` or `--image-uri`. See the [CLI reference](/langsmith/cli#deploy).
    </Note>
  </Tab>
</Tabs>

## Update an Agent Server with active runs

An update gives active background runs time to stop before the old revision shuts down. You do not need to wait for every run to finish before creating a revision.

Once the new revision is healthy, LangSmith sends a shutdown signal to the old revision. The shutdown grace period defaults to `180` seconds. Configure [`BG_JOB_SHUTDOWN_GRACE_PERIOD_SECS`](/langsmith/env-var-cloud#bg_job_shutdown_grace_period_secs) to give longer runs more time. Cloud pod termination imposes an upper bound of approximately one hour, including shutdown cleanup. Do not rely on a longer value to keep old workers running indefinitely.

### Resume drained runs from a checkpoint

When the old revision shuts down, it drains its active runs instead of waiting for them to finish:

- **Drained runs**: Each run stops at its next superstep boundary and returns to `pending`. A worker on the new revision continues it from the run's latest checkpoint, so completed steps do not run again. A drain does not count against [`BG_JOB_MAX_RETRIES`](/langsmith/env-var-cloud#bg_job_max_retries).
- **Runs still inside a step when the grace period ends**: The server cancels them and returns them to `pending` for retry. The retry continues from the latest checkpoint and runs only the interrupted step again.

<Note>
Drained-run resumption requires `langgraph>=1.2.15` in your application's dependencies. Agent Server v0.17.0 added it behind the [`FF_RESUME_DRAINED_RUNS`](/langsmith/env-var-cloud#ff_resume_drained_runs) flag. In v0.17.0 through v0.19.x, set the flag to `true` to turn it on. From Agent Server v0.20.0, it is on by default.
</Note>

Some runs are not drained, and wait for the grace period instead:

- Runs on JavaScript graphs.
- Stateless runs, which have no checkpoint to resume from.
- Runs that have not completed their first step.

For how graph code can react to a drain request, see [Graceful shutdown](/oss/langgraph/fault-tolerance#graceful-shutdown).

### Retry runs without drained-run resumption

On earlier versions, the old workers wait for active runs to finish within the grace period:

- **Runs that finish within the grace period**: Complete on the old revision.
- **Runs that exceed the grace period**: The server cancels them and returns them to `pending` for retry. A worker on the new revision starts the run again from its original input, repeating model and tool calls already made. Retrying is subject to [`BG_JOB_MAX_RETRIES`](/langsmith/env-var-cloud#bg_job_max_retries), which defaults to `3`.

### Plan a rollout

To prepare an update for long-running agents:

1. Test the new revision before updating production.
1. Keep graph and state changes compatible with checkpoints from the previous revision. A resumed or retried run can execute on the new code.
1. Make external side effects idempotent. Work after the last checkpoint can execute again.
1. Set the shutdown grace period on the currently running revision before a later code rollout needs it. Changing the value only on the incoming revision does not extend the old workers' grace period.
1. Create the revision, then [monitor the Agent Server](/langsmith/monitor-agent-server) for retries and failures.

For changes that cannot resume existing checkpoints safely, pause new run submissions and let active runs finish before updating the Agent Server.

## Interrupt a revision

Interrupt a revision only when it is stuck and prevents you from deploying another revision.

<Warning>
Interrupted revisions have undefined behavior. LangChain might remove this feature in the future.
</Warning>

To interrupt a revision:

1. From the **Agent Servers** view, select an Agent Server.
1. In the **Revisions** table, select the menu icon for the revision.
1. Select **Interrupt**.
1. Review the confirmation message, then select **Interrupt revision**.
