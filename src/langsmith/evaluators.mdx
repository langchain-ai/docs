[Evaluators](/langsmith/evaluation-concepts#evaluators) in LangSmith are [workspace-level](/langsmith/administration-overview#workspaces) resources. You can attach a single evaluator to multiple [trace containers](/langsmith/observability-concepts#trace-containers) and [datasets](/langsmith/evaluation-concepts#datasets), so you can apply consistent evaluation logic across your work without recreating it each time.

What an evaluator attaches to depends on how your workspace is organized.

<AgentBasedNote />

An evaluator attaches to an [environment](/langsmith/agent-environments#environment-names) of an [agent](/langsmith/agents). Attach it to **Production** alone to score production traffic without also scoring local runs.

<ProjectBasedNote />

An evaluator attaches to a [tracing project](/langsmith/observability-concepts#tracing-projects).

<Tip>
Evaluator scores are a high-priority signal for the [LangSmith Engine](/langsmith/engine): it pulls low-scoring traces when choosing what to analyze, so attaching an evaluator to a project sharpens the issues Engine finds there.
</Tip>

## View evaluators

In the [LangSmith UI](https://smith.langchain.com), select **Evaluators** in the left sidebar to view all evaluators in your workspace.

The evaluators table shows the following columns:

| Column | Description |
|--------|-------------|
| Name | The evaluator name |
| Type | **LLM as a judge** or **Code**. Composite score evaluators are scoped to individual tracing projects and datasets and do not appear here. |
| Feedback Key | The feedback key the evaluator produces |
| Projects & Datasets | Tracing projects and datasets this evaluator is attached to. In an agent-based workspace, this column is **Environments & Datasets** and lists agent environments and datasets. |
| Evaluator Trace Count (this week) | Number of traces this evaluator ran on in the past week. Only shown when spend tracking is enabled; **–** for Code evaluators or evaluators with no attached rules. |
| Spend (this week) | Estimated USD spend for this evaluator in the past week. Only shown when spend tracking is enabled; **–** for Code evaluators or evaluators with no attached rules. |
| Spend Status | Whether the evaluator is **Under limits**, **Unlimited**, or has hit one or more configured spend limits. Only shown when spend tracking is enabled; **–** for Code evaluators. |
| Created By | The workspace member who created the evaluator |
| Updated At | When the evaluator was last modified |
| Created At | When the evaluator was created |

## Create an evaluator

You can create an evaluator in the [LangSmith UI](https://smith.langchain.com) or programmatically with the [SDK](#create-an-evaluator-with-the-sdk). Evaluators created either way are workspace-level resources that appear in the **Evaluators** table.

### Create an evaluator in the UI

1. In the [LangSmith UI](https://smith.langchain.com), select **Evaluators** in the left sidebar.
1. Click **+ Evaluator** to open the new evaluator panel.
1. The panel lets you:
   - **Create from scratch**: Build a new [LLM-as-a-Judge](/langsmith/llm-as-judge), [Decision Model](/langsmith/decision-model-evaluator), or [Code](/langsmith/online-evaluations-code) evaluator.
   - **Add a LangChain Tuned Evaluator**: Attach a [specialized judge managed by LangChain](/langsmith/tuned-evaluators) to a compatible tracing project without configuring a prompt, model, or API key.
   - **Create from a template**: Start from a ready-made evaluator (also known as a prebuilt evaluator) for common evaluation patterns. A **Recommended** section lists popular templates first. The rest are grouped by category: Security, Safety, Quality, Conversation, Trajectory, Image Evaluations, and Voice Evaluation. For what each template scores, see [Prebuilt evaluator templates](#prebuilt-evaluator-templates).

You can also add an evaluator directly from a [tracing project](/langsmith/observability-concepts#tracing-projects), an agent environment, or a [dataset](/langsmith/evaluation-concepts#datasets). In that flow, you can additionally **attach an existing evaluator** from your workspace, or create a [Composite](/langsmith/composite-evaluators-ui) evaluator. Refer to [Set up LLM-as-a-judge online evaluators](/langsmith/online-evaluations-llm-as-judge) and [Automatically run evaluators on experiments](/langsmith/bind-evaluator-to-dataset).

### Create an evaluator with the SDK

Use the LangSmith SDK to create evaluators programmatically. The SDK is available for [Python](/langsmith/smith-python-sdk) and [TypeScript](/langsmith/smith-js-ts-sdk). Evaluators created through the SDK appear in the **Evaluators** table alongside those created in the UI.

The SDK does not support [decision model evaluators](/langsmith/decision-model-evaluator) yet. To create one, use the UI.

<Note>
Managing evaluators through the SDK requires `langsmith>=0.9.8` (Python, PyPI) or `langsmith>=0.7.16` (TypeScript, npm).
</Note>

<CodeGroup>
```python Python
import asyncio

from langsmith import Client


async def main():
    client = Client()

    created = await client.evaluators.create(
        name="Correctness evaluator",
        type="code",
        code_evaluator={
            "code": "def perform_eval(run, example):\n    return {'score': 1}",
            "language": "python",
        },
    )
    print("Created evaluator:", created.evaluator.id)


asyncio.run(main())
```
```typescript TypeScript
import { Client } from "langsmith";

const client = new Client();

const created = await client.evaluators.create({
  name: "Correctness evaluator",
  type: "code",
  code_evaluator: {
    code: "def perform_eval(run, example):\n    return {'score': 1}",
    language: "python",
  },
});
console.log("Created evaluator:", created.evaluator?.id);
```
</CodeGroup>

To create an LLM-as-a-judge evaluator and to retrieve, update, list, or delete evaluators, refer to [Manage evaluators with the SDK](/langsmith/manage-evaluators-sdk).

## Prebuilt evaluator templates

Prebuilt evaluator templates are ready-made evaluators for common checks, such as hallucination, prompt injection, and task completion. Each template is a starting point. You can edit its prompt and scoring schema before you save it to your workspace.

Most templates are [LLM-as-a-judge](/langsmith/llm-as-judge) evaluators whose prompts come from the open-source [openevals](https://github.com/langchain-ai/openevals) package. Two are exceptions: Assertions uses a prompt defined in LangSmith, and Exact Match is a [code evaluator](/langsmith/online-evaluations-code).

Each LLM-as-a-judge template writes a score under its feedback key and a `comment` with the judge's reasoning. Language and Support Intent return a label without a `comment`.

A `true` score does not always mean a pass. Templates that detect a problem return `true` when they find it: the Security and Safety templates, Hallucination, Perceived Error, the Image templates, and Audio Quality. The rest return `true` when the output passes. The **Score** column in each table states what `true` means.

Templates differ in the data they read:

- **Whole threads**: Conversation and Trajectory templates read every message in a thread. When you add one to a tracing project, LangSmith configures it as a thread-level evaluator. For more information, see [Set up multi-turn online evaluators](/langsmith/online-evaluations-multi-turn).
- **Reference outputs**: Correctness, Assertions, and Exact Match compare the output against a reference output, which comes from a [dataset](/langsmith/evaluation-concepts#datasets) example.
- **Plan**: Plan Adherence reads a `plan` variable in addition to the thread messages.
- **Attachments**: Image and Voice templates read the run's attachments. For more information, see [Evaluate with attachments](/langsmith/evaluate-with-attachments).

### Security

Security templates detect leaks, injections, and adversarial inputs.

| Template | What it scores | Score |
|----------|----------------|-------|
| PII Leakage | Whether the input or output contains personal information that could identify or harm an individual. | `pii_leakage` (boolean): `true` when PII is found. |
| Prompt Injection | Whether the input contains embedded instructions that target the AI system. Reads the input only. | `prompt_injection` (boolean): `true` when an injection attempt is found. |
| Code Injection | Whether the input contains executable code embedded in data. Reads the input only. | `code_injection` (boolean): `true` when an injection attempt is found. |

### Safety

Safety templates evaluate content safety and moderation.

| Template | What it scores | Score |
|----------|----------------|-------|
| Toxicity | Whether the content contains toxic elements, such as personal attacks or hate speech. | `toxicity` (boolean): `true` when toxic content is found. |
| Bias & Fairness | Whether the content contains stereotyping, exclusionary language, or discriminatory framing. | `fairness` (boolean): `true` when bias or a fairness violation is found. |

### Quality

Quality templates measure output quality and accuracy.

| Template | What it scores | Score |
|----------|----------------|-------|
| Hallucination | Whether the output contains claims the input context does not support, such as contradictions, speculative details, or inaccurate facts. | `hallucination` (boolean): `true` when the output contains a hallucination. |
| Correctness | Whether the output is factually accurate, complete, and consistent with the reference output. | `correctness` (boolean): `true` when the output is correct. |
| Assertions | Whether the output satisfies each assertion in the reference output. The judge reads an `assertions` list from the reference output, where each entry has a `key` and a `comment`. A missing or empty list scores `false`. | `assertions_passed` (boolean): `true` only when every assertion passes. |
| Conciseness | How efficiently the output conveys the requested information, penalizing hedging, pleasantries, meta-commentary, and redundancy. | `conciseness` (number, 0 to 10): `10` when the output contains only essential information. |
| Code Checker | Whether the code solves every requirement in the input, handles edge cases, and would run without errors. | `code_checker` (boolean): `true` when the code is complete and correct. |
| Answer Relevance | Whether the output directly addresses the input question without off-topic tangents. | `answer_relevance` (boolean): `true` when the output is relevant. |
| Exact Match | Whether the run's outputs exactly equal the reference outputs. This template runs as code and makes no LLM call. | `exact_match` (boolean): `true` when the outputs match. |

### Conversation

Conversation templates evaluate conversational quality and user experience across a whole thread.

| Template | What it scores | Score |
|----------|----------------|-------|
| Perceived Error | Whether user signals, such as frustration or repeated corrections, show the user perceived the agent making an error. | `perceived_error` (boolean): `true` when the user perceived an error that caused significant frustration. |
| Language | The primary language of the conversation. | `language` (string): a language name in English, such as `Spanish`. |
| Support Intent | The primary intent of a support conversation. | `intent` (category): one of `Account & Billing`, `Order Management`, `Technical Support`, `Product Inquiry`, `Policy Inquiry`, `Status Check`, `Complaint & Feedback`, `Escalation`, or `Other`. |
| User Satisfaction | Whether the user's tone and satisfaction indicators show the user was satisfied. | `user_satisfaction` (boolean): `true` when the user appears satisfied. |
| Tone | Whether the agent's tone was appropriate for the context and consistent. | `agent_tone` (boolean): `true` when the tone was appropriate. |
| Task Completion | Whether the agent fully completed every user request in the conversation. | `task_completion` (boolean): `true` when every request was completed. |
| Knowledge Retention | Whether the agent retained and applied facts from earlier in the conversation, without contradictions or ignored context. | `knowledge_retention` (boolean): `true` when the agent retained earlier facts. |

### Trajectory

Trajectory templates evaluate agent tool use and decision paths across a whole thread.

| Template | What it scores | Score |
|----------|----------------|-------|
| Plan Adherence | Whether the agent's steps followed its declared plan. | `plan_adherence` (boolean): `true` when the agent followed the plan. |
| Tool Selection | Whether the agent chose the right tools, in a sensible order, without unnecessary calls. | `tool_selection` (boolean): `true` when tool selection was accurate and efficient. |
| Trajectory Accuracy | Whether the agent's path was logical, showed clear progress, and was reasonably efficient. | `trajectory_accuracy` (boolean): `true` when the trajectory was accurate and efficient. |

### Image Evaluations

Image templates evaluate image content quality and safety.

| Template | What it scores | Score |
|----------|----------------|-------|
| Explicit Content | Whether an image contains nudity, sexual content, or graphic violence. | `explicit_content` (boolean): `true` when explicit content is found. |
| Sensitive Imagery | Whether an image contains harmful, offensive, or inappropriate symbols or depictions. | `sensitive_imagery` (boolean): `true` when sensitive imagery is found. |

### Voice Evaluation

Voice templates evaluate voice and audio interaction quality.

| Template | What it scores | Score |
|----------|----------------|-------|
| Audio Quality | Whether the audio contains clipping, distortion, or glitches that degrade the listening experience. | `audio_quality` (boolean): `true` when quality issues are found. |
| Transcription Accuracy | Whether a speech-to-text transcription accurately reflects the spoken content. | `transcription_accuracy` (boolean): `true` when the transcription is accurate. |
| User Interrupts | Whether the agent handled user interruptions gracefully. | `user_interrupts` (boolean): `true` when interruptions were handled gracefully. |
| Vocal Affect | Whether the agent's vocal warmth, prosody, and emotional tone were appropriate and natural. | `vocal_affect` (boolean): `true` when vocal affect was appropriate. |

## View evaluator details

Click any evaluator in the table to open its detail view. The detail view has four tabs:

- **Overview**: The evaluator's feedback configuration and prompt or code definition.
- **Traces**: Traces processed by this evaluator across all attached resources.
- **Logs**: Execution logs for this evaluator across all attached resources.
- **Projects & Datasets** (**Environments & Datasets** in an agent-based workspace): The tracing projects, agent environments, and datasets this evaluator is attached to, with each attachment's [weekly spend and limit](/langsmith/evaluator-spend).

## Edit an evaluator

Open an evaluator. In the **Overview** tab, click the **Edit evaluator** <Icon icon="pencil"/> icon to open the **Configure Evaluator** panel. Update the evaluator's configuration. Click **Save**.

Because the evaluator is shared, changes apply across every trace container and dataset it is attached to.

## Manage evaluator trace retention

When an online evaluator scores a trace, it attaches feedback to the trace. This can auto-upgrade the trace to [extended retention](/langsmith/usage-and-billing#data-retention-auto-upgrades), depending on the evaluator's retention setting. Extended retention keeps the trace longer but costs more. When you set up an online evaluator on a [tracing project](/langsmith/observability-concepts#tracing-projects), or on an agent environment, you can opt out of this upgrade so that scored traces stay at the base retention.

This control is available only when the project's [default retention](/langsmith/billing#change-project-level-default-retention) is the [base tier](/langsmith/usage-and-billing#how-it-works). If the project defaults to extended retention ([set at the project or workspace level](/langsmith/data-purging-compliance#data-retention)), traces scored by the evaluator follow that default and the option is locked.

To opt out of extending retention for scored traces:

1. When you [create](#create-an-evaluator) or [edit](#edit-an-evaluator) an online evaluator, set the source to a [tracing project](/langsmith/observability-concepts#tracing-projects) or an agent environment, rather than a [dataset](/langsmith/evaluation-concepts#datasets).
1. Expand the **Advanced** section in the evaluator configuration panel.
1. Clear **Extend trace retention**.

The change applies to traces scored after you save the evaluator. Existing scored traces keep their current retention tier.

The **Extend trace retention** toggle described above applies to both trace-level and thread-level (multi-turn) online evaluators. For more information on multi-turn evaluators, see [Set up multi-turn online evaluators](/langsmith/online-evaluations-multi-turn).

## Include extended stats

Use **Include extended stats (feedback, costs, tokens)** in a [run-level evaluator](/langsmith/online-evaluations-llm-as-judge) to evaluate feedback statistics, token usage, or cost data from the run. The `feedback_stats` field contains feedback statistics, including the number and average for each feedback key. This option is not available for [multi-turn (thread-level) evaluators](/langsmith/online-evaluations-multi-turn).

LangSmith fetches additional data for evaluators with this option enabled. Enable it only when your evaluation logic or prompt requires these fields.

To include extended stats:

1. When you [create](#create-an-evaluator) or [edit](#edit-an-evaluator) a run-level evaluator, expand the **Advanced** section in the evaluator configuration panel.
1. Select **Include extended stats (feedback, costs, tokens)**.

### Access extended stats

[Code evaluators](/langsmith/online-evaluations-code) receive these fields in the `run` object, including `feedback_stats`, `total_tokens`, and `total_cost`. They also receive [individual feedback records](/langsmith/feedback-data-format) in `run["feedback"]`, regardless of whether you enable extended stats. For [LLM-as-a-judge evaluators](/langsmith/online-evaluations-llm-as-judge), map the corresponding `run.*` field to a prompt variable. For example, map `{{correctness_average}}` to `run.feedback_stats.correctness.avg` to include a `correctness` feedback average in the prompt. The available `run.*` fields also include prompt and completion token, cost, and detail fields. For the full run data schema, see [Run data format](/langsmith/run-data-format).

## Chain evaluators

A chained evaluator is an online evaluator that triggers only on runs another evaluator has already scored. Chaining lets you use a more specific evaluator or reserve a more expensive evaluator for the runs that need it. For example, you can run an [LLM-as-a-judge evaluator](/langsmith/online-evaluations-llm-as-judge) only when an earlier `correctness` score is below a threshold.

The second evaluator must be a run-level evaluator because [multi-turn (thread-level) evaluators](/langsmith/online-evaluations-multi-turn) cannot filter on feedback. The first evaluator can be either type. A multi-turn evaluator attaches its feedback to the last run in the thread, so a second evaluator chained onto it evaluates that run, not the full thread.

To chain a second evaluator onto a first:

1. Create or open the second evaluator and expand its filter. For more information, see [Apply a filter to runs that trigger the evaluator](/langsmith/online-evaluations-llm-as-judge#apply-a-filter-to-runs-that-trigger-the-evaluator) for LLM-as-a-judge evaluators or [Create a filter](/langsmith/online-evaluations-code#3-create-a-filter) for code evaluators.
1. Filter on the first evaluator's feedback key. The filter matches on the key rather than the evaluator that produced it, so feedback from any source with that key triggers the second evaluator, including [user feedback](/langsmith/attach-user-feedback). Use a key that only the first evaluator produces.
   - To trigger on every run the first evaluator scored, filter on the key alone:

     ```text
     eq(feedback_key, "correctness")
     ```

   - To trigger only when the score meets a condition, combine the key with a `feedback_score` comparison. For example, to trigger only when `correctness` is below `0.5`:

     ```text
     and(eq(feedback_key, "correctness"), lt(feedback_score, 0.5))
     ```

1. If the second evaluator reads the first score, [include extended stats](#include-extended-stats). LLM-as-a-judge evaluators require it, and code evaluators use it to read the score reliably. For more information, see [Read the first score](#read-the-first-score).
1. Save the evaluator.

The second evaluator picks up a run only after the first evaluator's score is attached to it, so the order in which the evaluators run does not matter. For the full filter syntax, see [Trace query syntax](/langsmith/trace-query-syntax).

### Read the first score

How the second evaluator reads the first evaluator's score depends on its type:

- **LLM-as-a-judge evaluators**: [Include extended stats](#include-extended-stats), then map a prompt variable to `run.feedback_stats.<feedback_key>.avg`. For example, map `{{correctness_average}}` to `run.feedback_stats.correctness.avg`.
- **Code evaluators**: Read the [feedback record](/langsmith/feedback-data-format) in `run["feedback"]` whose `key` is the first evaluator's feedback key, and use its `score`. `run["feedback"]` holds at most 100 feedback records across each batch of runs the evaluator processes, and the oldest records are dropped first, so the score can be missing when the batch carries many feedback records. To read the score reliably, include extended stats and read the average from `run["feedback_stats"]["<feedback_key>"]["avg"]`.

The `avg` field averages every feedback record with that key on the run, so it equals the first evaluator's score only when the run has one record with that key. Another record with the same key, such as user feedback, changes the average.

## Delete an evaluator

You cannot delete an evaluator while it is attached to a trace container or dataset. To delete an evaluator:

1. In the [LangSmith UI](https://smith.langchain.com), select **Evaluators** in the left sidebar.
1. Select the evaluator you want to delete.
1. Open the **Projects & Datasets** tab (**Environments & Datasets** in an agent-based workspace). For each attachment listed there, select **Detach** in the **Actions** menu at the right of the row.
1. Return to the **Evaluators** page and click **Delete** at the top of the page.
