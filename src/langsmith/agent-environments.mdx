An _environment_ records which deployment of an application produced a trace. Every trace an [agent](/langsmith/agents) records lands in exactly one of its environments, which are drawn from a fixed set of four.

Because the environment travels with the trace, the deployment that produced it is a property of the trace itself, not something to reconstruct from a project name or a saved filter.

<AgentBetaNote />

## The four environments

An agent's environments come from a fixed set of four. Listed most production-like first, they are Production, Staging, Development, and Local, which is the order the environment switcher uses.

How many of the four an agent has depends on how it was created. An agent created in the UI, through [Build](/langsmith/build-an-agent) or Fleet, starts with Production alone, and each of the others appears the first time a trace is addressed to it. An agent created any other way, including one created automatically by tracing to an identifier that does not exist yet, starts with all four.

LangSmith attaches no behavior to the choice beyond keeping each environment's traces apart. An environment does not change how an agent is instrumented, and the same build can report into a different environment through tracing configuration alone.

<Note>
LangSmith ships these four environments at launch. Custom environment names are not supported yet.
</Note>

## Select an environment

Wherever LangSmith needs one environment instead of all of them, it uses the same control: a dropdown labeled **Environment**, with the placeholder **Select environment**. It lists the agent's environments in the order above, most production-like first.

The list holds the environments that exist for the agent, so an agent created in the UI shows Production alone until something reports elsewhere.
