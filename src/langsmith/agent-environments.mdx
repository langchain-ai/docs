An _environment_ records which deployment of an application produced a trace. Every [agent](/langsmith/agents) divides its traces across the same four environments, and every trace an agent records lands in exactly one of them.

Because the environment travels with the trace, the deployment that produced it is a property of the trace rather than something to recover from a project name or a saved filter. A question about production behavior never has to exclude test traffic by hand.

## The four environments

An agent's environments come from a fixed set of four. Listed most production-like first, they are Production, Staging, Development, and Local, which is the order the environment switcher uses.

LangSmith attaches no behavior to the choice beyond keeping each environment's traces apart. An environment does not change how an agent is instrumented, and the same build can report into a different environment through tracing configuration alone.

<Note>
The four environments are the set for the initial release rather than the data model. Custom environment names are out of scope for launch.
</Note>

## Select an environment

Wherever LangSmith needs one environment rather than all of them, it uses the same control: a dropdown whose placeholder reads **Select environment** and whose accessible name is Environment. It lists the four labels in the order above, most production-like first.

The list holds the environments that exist for the agent. If an agent has none, the control does not render, and there is no empty state to read.
