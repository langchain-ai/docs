_Agent addressing_ names the [agent](/langsmith/agents) and the [environment](/langsmith/agent-environments) a trace belongs to, instead of the tracing project it lands in. The agent and the environment travel with every run, so the application that produced a trace and the deployment it ran on are recorded at ingestion instead of being recovered later from a project name.

Agent addressing and [project addressing](/langsmith/log-traces-to-project) are alternatives. A trace uses one or the other, never both.

<Note>
Agent addressing applies to agent-based workspaces, which are in [beta](/langsmith/release-stages) for a private group of customers. No released LangSmith SDK supports it yet, though a pre-release Python surface exists. This page describes the addressing model. For working tracing setup today, see [Log traces to a specific project](/langsmith/log-traces-to-project).
</Note>

## Addressing variables

Two environment variables carry agent addressing. No released LangSmith SDK reads them yet, so setting them today has no effect, and a workspace that is not in the beta rejects agent-addressed runs even when the fields reach it directly:

- **`LANGSMITH_AGENT_ID`**: The agent to address. The value is the agent's identifier, which the browser address bar carries and the **ID** field on the agent's Overview copies. Copy it from the agent rather than reconstructing it from the display name, because the two can differ. It is sent with every run.
- **`LANGSMITH_AGENT_ENVIRONMENT`**: The environment the run belongs to. Required alongside the agent, and one of `local`, `development`, `staging`, or `production`. Use the lowercase form, which maps to the Local, Development, Staging, and Production labels in the UI. There is no default: an agent without an environment does not name a destination, so the backend rejects it instead of choosing one.

Note the asymmetry with the variable it replaces. `LANGSMITH_PROJECT` holds a project's name, while `LANGSMITH_AGENT_ID` holds an agent's identifier. An agent's [display name is a separate, editable value](/langsmith/agents#identifiers-and-display-names) and is not what tracing configuration takes.

## Python SDK support

<Warning>
This surface is pre-release. It exists only on the `langsmith` Python package's `main` branch, not in any published version. The SDK marks it experimental and may change it without notice. There is no TypeScript equivalent. The examples below have not been run against a released package. Do not build on it yet.
</Warning>

The Python SDK takes the agent and the environment as arguments, not only as environment variables. `@traceable` and `tracing_context()` each accept `agent_id` and `agent_environment`, and each argument falls back to its matching environment variable when omitted.

Address one function with the decorator:

```python
from langsmith import traceable


@traceable(agent_id="checkout", agent_environment="production")
def handle_order(order_id: str) -> dict:
    return {"order_id": order_id, "status": "charged"}
```

Address everything traced inside a block with the context manager:

```python
from langsmith import traceable, tracing_context


@traceable
def handle_order(order_id: str) -> dict:
    return {"order_id": order_id, "status": "charged"}


with tracing_context(agent_id="checkout", agent_environment="production"):
    handle_order("A-1")
```

Naming a project in the same call raises `LangSmithUserError` instead of picking one of the two.

The rules in the sections below apply to those arguments as well as to the variables. One behavior is specific to this path: a workspace that does not have agent-based organization rejects agent-addressed runs outright, so those traces are lost rather than landing in a tracing project instead.

## Addressing modes are mutually exclusive

Combining the two modes is an error, not a precedence rule, so there is no case where one silently wins:

- **An agent and a project together** are rejected. Setting `LANGSMITH_AGENT_ID` alongside `LANGSMITH_PROJECT`, `LANGCHAIN_PROJECT`, or `LANGCHAIN_SESSION` names two destinations for the same trace, and the backend rejects the run instead of preferring one.
- **Either one without the other** is rejected. An environment has no meaning on its own, because it belongs to an agent, and an agent without an environment does not identify where traces land. The two travel together or not at all.

## Addressing an agent that does not exist

If an identifier matches no agent in the workspace, LangSmith creates that agent. Traces from a new service therefore arrive under their own agent from the first run, without a setup step.

Agent identifiers are limited to 255 characters. A longer value is rejected.
