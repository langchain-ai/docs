A user in LangSmith is the end user of your application that a trace served. LangSmith reads the user from the `user_id` key in the metadata of the trace's root run, in the same way that it groups traces into [threads](/langsmith/threads) with `thread_id`. Recording users lets you find every trace for a person who reports a problem, and see which users a change affects.

<Note>
`user_id` identifies an end user of your application. It is different from `ls_user_id`, which identifies the LangSmith account member a run is attributed to.
</Note>

## Record the user on a trace

To record the user, add a `user_id` key to the metadata of the root run of each trace. The value can be any string that identifies the user in your application, such as an account ID or an email address. Use the same value for the same user across traces so that filtering by user returns all of their traces.

The LangSmith SDKs copy a run's metadata to the child runs it creates, so setting `user_id` on the root run also records it on every run in the trace.

<CodeGroup>

```python Python
from langsmith import traceable


@traceable
def retrieve_docs(question: str) -> list[str]:
    return ["Traces record each step of a request."]


@traceable
def answer_question(question: str) -> str:
    docs = retrieve_docs(question)
    return f"Found {len(docs)} document."


# Pass the user at invocation time so each request records its own user.
answer_question(
    "What is a trace?",
    langsmith_extra={"metadata": {"user_id": "user_123"}},
)
```

```typescript TypeScript
import { getCurrentRunTree, traceable } from "langsmith/traceable";

const retrieveDocs = traceable(
  async (question: string) => {
    return ["Traces record each step of a request."];
  },
  { name: "retrieve_docs" }
);

const answerQuestion = traceable(
  async (question: string, userId: string) => {
    // Set the user on the root run before creating child runs.
    const runTree = getCurrentRunTree();
    runTree.extra.metadata = { ...runTree.extra.metadata, user_id: userId };
    const docs = await retrieveDocs(question);
    return `Found ${docs.length} document.`;
  },
  { name: "answer_question" }
);

await answerQuestion("What is a trace?", "user_123");
```

</CodeGroup>

For other ways to set metadata, such as `tracing_context` or a wrapped client, see [Add metadata and tags to traces](/langsmith/add-metadata-tags).

## View the user on a trace

LangSmith shows the user ID in the following places:

- **Trace top bar**: When you open a trace that is not part of a thread, the top bar shows a **User** chip with the user ID.
- **Run header**: When a trace belongs to a thread, the header of the selected run shows the user ID recorded on that run. This applies in a thread's **Details** view and when you open the trace from the tracing table.
- **Trajectory view**: Each user message in a thread's **Trajectory** view shows the user ID below it. AI messages and tool responses do not show a user.

Click a user ID to copy the full value. If a trace has no `user_id`, LangSmith does not show a user for it.

For more information on these views, see [View traces](/langsmith/view-traces).

## Filter traces by user

To find the runs, traces, or threads for one user, enter a `user_id` clause in the tracing search bar:

```text
user_id:user_123
```

As you type, the search bar suggests up to 20 user IDs seen in the selected time range. You can also enter any user ID that is not in the list.

`user_id` is a shorthand for `metadata.user_id`, so the following clauses also work:

- `-user_id:user_123` matches runs from every other user, including runs with no `user_id`.
- `user_id:*` matches runs that have a `user_id` key.
- `metadata.user_id:user_123` matches the same runs as `user_id:user_123`. Saved views that use this form keep working.

The `user_id` shorthand works in the search bar filtering experience. In the **Add filter** experience, filter on the `user_id` metadata key instead. See [Filter traces (ClickHouse)](/langsmith/filter-traces-in-application).

For the full query syntax, see [Filter traces](/langsmith/filter-traces).
