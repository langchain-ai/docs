A swarm splits a task across parallel subagents and combines their findings. In this example, a lead agent starts three specialized [async subagents](/langsmith/managed-deep-agents-subagents#async-subagents) to investigate an incident in parallel, then writes one report. When the number of parallel tasks depends on the request, the lead can also [fan out dynamically](#fan-out-dynamically) with the built-in `general-purpose` subagent.

## Declare the subagents

Start with a project from the [quickstart](/langsmith/managed-deep-agents-quickstart) and replace the agent definition:

:::python
```python agent.py
from managed_deepagents import define_deep_agent

agent = define_deep_agent(
    name="incident-investigator",
    subagents=[
        {
            "name": "logs-investigator",
            "description": "Analyzes incident logs.",
            "system_prompt": "Find symptoms and timing in the logs. Cite sources.",
            "async": True,
        },
        {
            "name": "changes-investigator",
            "description": "Analyzes recent changes.",
            "system_prompt": "Find changes that could explain the incident. Cite sources.",
            "async": True,
        },
        {
            "name": "issues-investigator",
            "description": "Analyzes related issues.",
            "system_prompt": "Find similar past issues. Cite sources.",
            "async": True,
        },
    ],
)
```
:::

:::js
```ts agent.ts
import { defineDeepAgent } from "managed-deepagents";

export const agent = defineDeepAgent({
  name: "incident-investigator",
  subagents: [
    {
      name: "logs-investigator",
      description: "Analyzes incident logs.",
      systemPrompt: "Find symptoms and timing in the logs. Cite sources.",
      async: true,
    },
    {
      name: "changes-investigator",
      description: "Analyzes recent changes.",
      systemPrompt: "Find changes that could explain the incident. Cite sources.",
      async: true,
    },
    {
      name: "issues-investigator",
      description: "Analyzes related issues.",
      systemPrompt: "Find similar past issues. Cite sources.",
      async: true,
    },
  ],
});
```
:::

Subagents inherit the lead's model and tools. An async subagent sees only its task description, not the lead's conversation.

## Write the instructions

Replace `instructions.md`:

```markdown instructions.md
# Incident investigator

For an incident, start logs-investigator, changes-investigator, and
issues-investigator as async tasks at the same time. Give each one the
relevant evidence from the request. When all three finish, write one report
that separates confirmed findings from hypotheses and lists missing evidence.
```

The lead launches each task with `start_async_task`. Tasks run in separate threads and notify the lead as each one finishes.

## Try it

Run the agent with `mda dev` or [deploy it](/langsmith/managed-deep-agents-deploy). In a new conversation, describe an incident and paste logs, recent changes, and related issues. Confirm that the lead starts all three tasks at once and combines their findings.

## Fan out dynamically

Declare specialized subagents when each worker needs its own model, tool set, or reusable system prompt. When the number or scope of parallel tasks is known only at runtime, such as investigating an arbitrary list of affected services or projects, fan out to the built-in [`general-purpose`](/oss/deepagents/subagents#the-general-purpose-subagent) subagent instead.

Every agent served by `mda dev` or a deployment includes both a synchronous and an async `general-purpose` subagent by default, even when you omit `subagents` from the agent definition. It inherits the lead's model, tools, and skills, and gets its own context window.

To fan out in one turn, instruct the lead to issue multiple calls targeting `general-purpose` in the same model response, each with a self-contained `description`:

- **`start_async_task`**: Starts background tasks in parallel and returns task IDs immediately, so the lead can continue working while results arrive independently.
- **`task`**: Runs subagent invocations in parallel and waits for every result before the lead's next model step.

```markdown instructions.md
# Multi-service incident investigator

When an incident spans multiple services, delegate one task per affected
service to the general-purpose subagent. Issue the start_async_task calls
together in one model response. Include the service name, time range,
symptoms to look for, and expected output in each description. When the
tasks finish, compare the findings and cite sources.
```

Because each invocation has its own context window and does not see the user's message or the lead's `instructions.md`, put every required detail (such as the service and time range) in each task's `description`. This fans out task invocations at runtime rather than creating new subagent definitions.

## Extend the pattern

- Add read-only [tools](/langsmith/managed-deep-agents-tools) or [MCP servers](/langsmith/managed-deep-agents-mcp-connectors) so the subagents pull live logs, changes, and issues.
- Add a [Slack channel](/langsmith/managed-deep-agents-channels-slack) so people can start an investigation by mentioning the agent.
- Add more async subagents, such as one for metrics, and name them in `instructions.md`.
