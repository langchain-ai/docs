These are estimates, not a quote. AWS changes its prices without notice. Your bill depends on region, usage, and any discount agreement with AWS, such as an Enterprise Discount Program or a Savings Plan.

The ClickHouse tab is a monthly run-rate for a whole default data plane. The SmithDB tab is only what SmithDB adds when it replaces ClickHouse as the trace store. It does not include the EKS control plane, system nodes, Redis, application pods, or networking.

<Warning>
Scaling capacity for any resource can be lowered when required, as long as the deployment remains within safe operating limits. For cost-conscious or pre-production deployments, Multi-AZ can be turned off. That lowers monthly cost but reduces fault tolerance.
</Warning>

<Tabs>
  <Tab title="ClickHouse">
    ClickHouse can also run as a single node instead of a replicated cluster. That lowers monthly cost but reduces fault tolerance.

    | Area | Rough monthly estimate | Notes |
    | --- | --- | --- |
    | RDS PostgreSQL | $100–$150 | `db.t4g.medium`, Multi-AZ, 50 GB starting storage. |
    | ElastiCache Redis | $140–$280 | Lower end without read replicas. Higher end if read replicas are enabled. |
    | EKS control plane | ~$73 | One EKS cluster at standard hourly pricing. |
    | System node group | ~$210 | 3 `m6i.large` on-demand nodes. |
    | Application, ClickHouse, and ZooKeeper worker nodes | $1,000–$1,500 | LangSmith pods and ClickHouse pods. |
    | EBS volumes | $200–$350 | ClickHouse, ZooKeeper, node volumes, and gp3 performance settings. |
    | Networking | $150–$300 | NAT gateways, load balancers, PrivateLink or VPC endpoints, and low-volume data processing. |
    | S3, Secrets Manager, CloudWatch | $50–$200 | Low-volume baseline. Grows with trace payloads, logs, and retention. |

    Estimated total: **$2.2k–$3.2k/month**.
  </Tab>
  <Tab title="SmithDB">
    This is the Small tier from [Configure SmithDB for scale](/langsmith/self-host-smithdb-scale): about 10 runs per second and 10 queries per second. Each environment runs two nodes in two availability zones.

    Production nodes are `m7gd.4xlarge` (16 vCPU, 64 GiB, 950 GB local NVMe) plus a 100 GiB gp3 boot volume. A lower environment can use two `c7g.4xlarge` nodes and put the 600 GiB cache on gp3. That is below the IOPS SmithDB documents for a network-attached cache, so use it only for light traffic.

    | Environment | Nodes | Per month |
    | --- | --- | --- |
    | Lower (gp3 cache) | 2 x `c7g.4xlarge` | $1,251 |
    | Production (local NVMe) | 2 x `m7gd.4xlarge` | $1,752 |

    One lower environment plus two production environments is **$57,062 per year** on demand ($4,755 per month), or **$37,031 per year** reserved ($3,086 per month). Reserved prices are 1-year, all upfront. Aurora Serverless v2 and gp3 volumes stay on demand. The Medium tier (about 100 runs per second) and Large are not priced here.

    ### S3

    At about 2 million traces a month, `us-east-1` standard storage is $0.023 per GB-month for the first 50 TB. Do not add lifecycle or storage-class rules. SmithDB deletes its own segments, and an external rule can delete live data.

    | Stored size per trace | 14-day retention | 400-day retention |
    | --- | --- | --- |
    | 10 KB | $2 per year | $74 per year |
    | 50 KB | $13 per year | $368 per year |
    | 200 KB | $52 per year | $1,472 per year |

    A ClickHouse backfill needs an extra `m7gd.4xlarge` for the migration job at about $728 per month. That cost stops when the backfill finishes (Job finishes in a few days depending on tracing volume).

    See [Prepare SmithDB supporting infrastructure](/langsmith/self-host-smithdb-infrastructure) for the metastore, bucket, and cache disk.
  </Tab>
